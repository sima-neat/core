Use this page to install or update the Palette Neat Library.

:::tip Neat Library within the Neat SDK
When you pair a DevKit during `sima-cli sdk setup`, the SDK installs its included
Neat Library and bundled PyNeat environment at `~/pyneat` on the DevKit automatically.
:::

:::tip When to use offline installation
If the target cannot download packages from SiMa.ai services, use [offline installation](#offline-installation).
Download the package on a computer with internet access.
:::

## Choose Where to Install

Run the installer from the environment where you build or run Neat applications:

| Environment | Use this when |
| --- | --- |
| Neat SDK | You want to upgrade the Neat Library in the Neat SDK without installing a new SDK version. |
| ROS2 SDK | You want to compile ROS 2 applications natively on ARM64 with Neat headers and libraries installed in the container's system paths. |
| DevKit | You want to install or update the runtime directly on the device. |

## C++ development packages

The minimal installation includes the runtime and `sima-neat-dev`. The default
installation offers tutorials and tests as optional extras; `all` includes them.
Shared-library applications need Core's public headers, the matching Scheduler
frontend, and GStreamer, OpenCV, and JSON development files. They do not need the
retired Internals umbrella or Runner, Kernels, Codecs, memory-library, heap, or
LLiMa development APIs. The selected packages supply the required runtime dependencies.

Use the installed shared target:

```cmake
find_package(SimaNeat CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE SimaNeat::sima_neat)
```

The static archive remains in `sima-neat-dev`. Use `COMPONENTS Static` and keep the
matching `simaai-scheduler` package installed. Provision `zlib1g-dev`,
`libcpp-httplib-dev`, and, for LLiMa-enabled builds, `sima-lmm-dev`, with their
dependencies. Core uses Scheduler's installed frontend; do not add Internals or
lower-library development targets to your application:

```cmake
find_package(SimaNeat CONFIG REQUIRED COMPONENTS Static)
target_link_libraries(my_app PRIVATE SimaNeat::sima_neat_static)
```

Static Core still uses shared implementation libraries. Building Core from source
uses the same Scheduler frontend boundary and requires development files for its
other dependencies, including LLiMa when enabled.

## Online installation prerequisites

Install `sima-cli` in the environment where you plan to install the Neat Library.
Use the [sima-cli installation guide](/tools/sima-cli/).

Create an account at [community.sima.ai](https://community.sima.ai) to access
SiMa.ai assets such as precompiled models for testing.

Authenticate the environment so the installer can download SiMa.ai artifacts. See
[sima-cli login](/tools/sima-cli/login/) for details.

<ShellCommand prompt="sdk|devkit">
sima-cli login
</ShellCommand>

Confirm the environment can reach the SiMa.ai artifacts host:

<ShellCommand prompt="sdk|devkit">
curl -fsS https://artifacts.neat.sima.ai/sima-cli/linux-mac.sh -o /dev/null && echo "artifacts reachable"
</ShellCommand>

Printing `artifacts reachable` means the host is reachable. A `curl` error such as
a timeout, connection refused, or "could not resolve host" means outbound access
is blocked — check your host network, proxy, or firewall (see
[Neat SDK Networking](/tools/sima-cli/sdk-networking/) and the
[host setup notes](/reference/elxr-sdk-host-setup/ubuntu)), or use
[Offline Installation](#offline-installation) if
the machine cannot reach SiMa.ai services directly.

## Install the Neat Library

:::note Package compatibility
The installer uses every Debian package listed by the selected Core artifact
and does not select different Scheduler or LLiMa versions. The installed
platform must satisfy dependencies that are not delivered by that artifact. If
APT would remove platform packages to complete the installation, the installer
stops; update the platform instead of substituting packages in Core or LLiMa.
:::

Choose a working directory before running the installer. On the DevKit, install
under `/media/nvme` to avoid filling the root file system. In the SDK container,
use a container-local path such as `$HOME/neat`.

Select your environment, then run the steps in order. Install in the **Neat SDK**
container to cross-compile C++ applications. Install in the **ROS2 SDK** to
compile natively on ARM64; its Debian packages are installed into `/usr` rather
than the Neat cross-compilation sysroot. Install on the **DevKit** to set up the
runtime there, which also provisions PyNeat at `~/pyneat`. The installer command
is the same in every environment.

<CodeTabs>
<CodeTab label="Neat SDK" lang="bash">

Prepare a container-local install directory such as `$HOME/neat`:

<ShellCommand prompt="sdk">
cd $HOME && mkdir -p neat && cd neat
</ShellCommand>

Install the default Neat Library package selected by `sima-cli`. You can
optionally install extras, including prebuilt tutorials, source-code tutorials,
and tests:

<ShellCommand prompt="sdk">
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>

<CodeTab label="ROS2 SDK" lang="bash">

Confirm that the container identifies itself as the native ROS2 SDK and reports
the platform compatibility base expected by the Neat package:

<ShellCommand prompt="sdk">
grep -E '^(SDK Type|Platform Base|Platform Version) =' /etc/sdk-release
</ShellCommand>

Install a compatible Neat package. The installer validates the native ARM64
Debian environment, simulates the APT transaction with package removal disabled,
and installs the runtime and development packages into the container's system
paths. PyNeat is not installed because it remains a DevKit runtime feature:

<ShellCommand prompt="sdk">
cd $HOME &amp;&amp; mkdir -p neat &amp;&amp; cd neat
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>

<CodeTab label="DevKit" lang="bash">

:::note Update DevKit firmware first
Before installing the Neat Library on a DevKit, ensure the DevKit software version is compatible with the Neat Library. See the
[Compatibility Guide](/getting-started/compatibility/) for more information.
:::

Prepare an install directory under `/media/nvme` to avoid filling the root file
system:

<ShellCommand prompt="devkit">
cd /media/nvme && mkdir -p neat && cd neat
</ShellCommand>

Install the default Neat Library package selected by `sima-cli`. You can
optionally install extras, including prebuilt tutorials, source-code tutorials,
and tests:

<ShellCommand prompt="devkit">
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>
</CodeTabs>

## Default PyNeat environment for online installation

Installing the Neat Library on the DevKit also provisions a default PyNeat
virtual environment at `~/pyneat` on the DevKit. This is the supported PyNeat
environment — activate it directly:

<ShellCommand prompt="devkit">
source ~/pyneat/bin/activate
</ShellCommand>

If you run the installer from inside an SDK container paired with DevKit Sync,
the installer provisions PyNeat on the paired DevKit, not only inside the SDK
container. PyNeat is installed into a virtual environment under `~/pyneat` on
the DevKit.

For custom Python virtual environments, see
[Install PyNeat](/getting-started/neat-library/pyneat/).

## Offline installation {#offline-installation}

Neat Library offline packages are available in version 0.6.0 or later.
Use this package for a Modalix DevKit with Platform 3.0 or later.

### 1. Download the package

Install `sima-cli` on the computer with internet access. See the [sima-cli installation guide](/tools/sima-cli/).

Run this command on the computer with internet access:

<ShellCommand prompt="host">
sima-cli neat install core/offline@v%%release.core%% --download-only
</ShellCommand>

The default package includes the runtime, tutorials, and tests.
To download only the runtime, use:

<ShellCommand prompt="host">
sima-cli neat install core/offline@v%%release.core%% -t minimal --download-only
</ShellCommand>

### 2. Install the package

1. Copy the downloaded files to the Modalix DevKit or the Neat SDK workspace.
2. Open a terminal in that directory. For SDK installation, use the SDK shell.
3. Extract the installer archive:

<ShellCommand prompt="sdk|devkit">
tar -xzf neat-core-offline-installer.tar.gz
</ShellCommand>

4. Go to the extracted directory:

<ShellCommand prompt="sdk|devkit">
cd neat-core-offline
</ShellCommand>

5. Start the installer as your regular user. It requests `sudo` permissions when necessary.

<ShellCommand prompt="sdk|devkit">
./install.sh
</ShellCommand>

If you need tutorials or tests, extract the separate extras archive into a directory of your choice.

For offline installation, activate the Python environment with:

<ShellCommand prompt="devkit">
source ~/pyneat/bin/activate
</ShellCommand>

Offline installation uses the same Python paths as online installation. The PCIe host uses `~/pyneatpcie`. A DevKit uses `/media/nvme/pyneat` when `/media/nvme` is writable by the installing user; otherwise, it uses `~/pyneat`. For an NVMe installation, `~/pyneat` links to that environment. If a different environment already exists at `~/pyneat`, the installer keeps it in a `pyneat-before-offline-*` directory in your home directory before creating the link.

### Package options and installer behavior

- The installer checks system compatibility and available disk space before installation.
- The installer uses bundled dependencies. It stops if a required dependency is missing.
- In the SDK, the installer copies Neat Library into `/opt/toolchain/aarch64/modalix`.
- If `DEVKIT_SYNC_DEVKIT_IP` is set, the installer also installs on the paired DevKit through SSH. Both environments must pass checks.

If installation fails, read the log at the printed path: `/tmp/neat-core-offline-*.log`.
For detailed output, use `./install.sh --verbose`.

If SSH disconnects during installation, the remote installer can continue to run.
Check that it has stopped before you retry or remove the temporary directory shown in the report.
