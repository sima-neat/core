Use this page to install or update the Palette Neat Library.

:::tip Neat Library within the Neat SDK
When you pair a DevKit during `sima-cli sdk setup`, the SDK installs its included
Neat Library and bundled PyNeat environment at `~/pyneat` on the DevKit automatically.
:::

## Choose Where to Install

Run the installer from the environment where you build or run Neat applications:

| Environment | Use this when |
| --- | --- |
| Neat SDK | You want to upgrade the Neat Library in the Neat SDK without installing a new SDK version. |
| ROS2 SDK | You want to compile ROS 2 applications natively on ARM64 with Neat headers and libraries installed in the container's system paths. |
| DevKit | You want to install or update the runtime directly on the device. |

## Prerequisites

Install `sima-cli` in the environment where you plan to install the Neat Library.
Use the [sima-cli installation guide](/tools/sima-cli/).

Create an account at [community.sima.ai](https://community.sima.ai) to access
SiMa.ai assets such as precompiled models for testing.

Authenticate the environment so the installer can download SiMa.ai artifacts. See
[sima-cli login](/tools/sima-cli/login/) for details.

<ShellCommand prompt="sdk-or-devkit">
sima-cli login
</ShellCommand>

Confirm the environment can reach the SiMa.ai artifacts host:

<ShellCommand prompt="sdk-or-devkit">
curl -fsS https://artifacts.neat.sima.ai/sima-cli/linux-mac.sh -o /dev/null && echo "artifacts reachable"
</ShellCommand>

Printing `artifacts reachable` means the host is reachable. A `curl` error such as
a timeout, connection refused, or "could not resolve host" means outbound access
is blocked — check your host network, proxy, or firewall (see
[Neat SDK Networking](/tools/sima-cli/sdk-networking/) and the
[host setup notes](/reference/elxr-sdk-host-setup/ubuntu)), or use
[Offline Installation](/getting-started/dev-environment/offline-installation) if
the machine cannot reach SiMa.ai services directly.

## Install the Neat Library

:::note Package compatibility
The installer uses every Debian package listed by the selected Core artifact
and does not select different Internals or LLiMa versions. The installed
platform must satisfy dependencies that are not delivered by that artifact. If
APT would remove platform packages to complete the installation, the installer
stops; update the platform instead of substituting packages in Core or LLiMa.
:::

Choose a working directory before running the installer. On the DevKit, install
under `/media/nvme` to avoid filling the root file system. In the SDK container,
use a container-local path such as `$HOME/neat`.

Select your environment, then run the steps in order. Install in the **Neat SDK**
container to cross-compile C++ applications. Install in the **ROS2 SDK** to
compile natively on ARM64; its Debian packages are installed into `/usr` rather
than the Neat cross-compilation sysroot. Install on the **DevKit** to set up the
runtime there, which also provisions PyNeat at `~/pyneat`. The installer command
is the same in every environment.

<CodeTabs>
<CodeTab label="Neat SDK" lang="bash">

Prepare a container-local install directory such as `$HOME/neat`:

<ShellCommand prompt="username@neat-sdk-latest">
cd $HOME && mkdir -p neat && cd neat
</ShellCommand>

Install the default Neat Library package selected by `sima-cli`. You can
optionally install extras, including prebuilt tutorials, source-code tutorials,
and tests:

<ShellCommand prompt="username@neat-sdk-latest">
sima-cli neat install core@v0.4.0
</ShellCommand>

</CodeTab>

<CodeTab label="ROS2 SDK" lang="bash">

Confirm that the container identifies itself as the native ROS2 SDK and reports
the platform compatibility base expected by the Neat package:

<ShellCommand prompt="username@ros2-sdk-latest">
grep -E '^(SDK Type|Platform Base|Platform Version) =' /etc/sdk-release
</ShellCommand>

Install a compatible Neat package. The installer validates the native ARM64
Debian environment, simulates the APT transaction with package removal disabled,
and installs the runtime and development packages into the container's system
paths. PyNeat is not installed because it remains a DevKit runtime feature:

<ShellCommand prompt="username@ros2-sdk-latest">
cd $HOME &amp;&amp; mkdir -p neat &amp;&amp; cd neat
sima-cli neat install core@release-0.3
</ShellCommand>

</CodeTab>

<CodeTab label="DevKit" lang="bash">

:::note Update DevKit firmware first
Before installing the Neat Library on a DevKit, ensure the DevKit software version is compatible with the Neat Library. See the
[Compatibility Guide](/getting-started/compatibility/) for more information.
:::

Prepare an install directory under `/media/nvme` to avoid filling the root file
system:

<ShellCommand prompt="modalix">
cd /media/nvme && mkdir -p neat && cd neat
</ShellCommand>

Install the default Neat Library package selected by `sima-cli`. You can
optionally install extras, including prebuilt tutorials, source-code tutorials,
and tests:

<ShellCommand prompt="modalix">
sima-cli neat install core@v0.2.2
</ShellCommand>

</CodeTab>
</CodeTabs>

## Default PyNeat Environment

Installing the Neat Library on the DevKit also provisions a default PyNeat
virtual environment at `~/pyneat` on the DevKit. This is the supported PyNeat
environment — activate it directly:

<ShellCommand prompt="modalix">
source ~/pyneat/bin/activate
</ShellCommand>

If you run the installer from inside an SDK container paired with DevKit Sync,
the installer provisions PyNeat on the paired DevKit, not only inside the SDK
container. PyNeat is installed into a virtual environment under `~/pyneat` on
the DevKit.

For custom Python virtual environments, see
[Install PyNeat](/getting-started/neat-library/pyneat/).

## Source Builds

Build from source when you need an unreleased change, a custom build
configuration, or you are contributing to the Neat Library. Most users should
use the packaged install above instead.

If you prefer building from source, follow the
[Build](/develop-apps/contribute/build) guide.

For SDK setup and DevKit Sync onboarding, see
[Neat SDK](/getting-started/dev-environment/).
