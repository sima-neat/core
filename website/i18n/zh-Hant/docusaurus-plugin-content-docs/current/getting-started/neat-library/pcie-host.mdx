請使用此頁面，在已連接至 Modalix PCIe 卡的 Linux 主機上安裝 Neat PCIe 主機套件。

Neat PCIe 主機套件提供協同處理 API，用於將來自主機的輸入傳送到已連接的 Modalix PCIe 卡，並接收推論結果。

:::warning 安裝於 PCIe 主機上。
請在連接到 Modalix PCIe 卡的 **PCIe 主機**上執行此安裝。請勿在 Palette SDK 容器、DevKit 或 Modalix PCIe 卡上執行。
:::

:::tip 何時需要離線安裝
若目標無法從 SiMa.ai 服務下載套件，請使用[離線安裝](#offline-installation)。
在可連上網際網路的電腦上下載套件。
:::

## 支援的主機作業系統

Neat PCIe 主機封裝支援以下經過驗證的主機平台：

| 作業系統 | 架構 | 支援 |
| --- | --- | --- |
| Ubuntu 22.04 | x86_64 | 支援 |
| Ubuntu 24.04 | x86_64 | 支援 |
| Windows 11 | x86_64 | 原生預覽；僅支援視覺推論 |

Arm64 主機上的建置尚未經過驗證。Windows 預覽不支援 PCIe GenAI 傳輸。

## 線上安裝先決條件

在安裝套件之前：

- 在 PCIe 主機上安裝 `sima-cli`。使用
  [sima-cli installation guide](/tools/sima-cli/).
- 請按照以下步驟安裝並驗證 PCIe 主機驅動程式。
  [PCIe Driver Installation guide](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation).
- 連接並設定 Modalix PCIe 卡，使其管理介面為
  可以從主機存取。預設的卡片 0 位址為 `10.0.0.2`。
- 在卡片上安裝相容的 Neat Library 版本。主機和
  卡片套件必須來自相容的版本。

驗證 PCIe 主機，以便它可以下載 SiMa.ai 成品：

<ShellCommand prompt="pcie-host">
sima-cli login
</ShellCommand>

## 安裝 PCIe 主機套件

在 PCIe 主機上選擇一個工作目錄，然後執行適用於已安裝的 Ubuntu 版本的指令。

**x86_64 上的 Ubuntu 22.04：**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu22/amd64@v%%release.core%%
</ShellCommand>

**Ubuntu 24.04 於 x86_64 平台上：**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu24/amd64@v%%release.core%%
</ShellCommand>

安裝程式會新增所有必要的元件，以便開發和執行 Neat PCIe 主機應用程式，包括 C++ API 和位於 `~/pyneatpcie` 的 Python 環境。

安裝程式也會安裝套件內附的 Codex 與 Claude 編碼代理技能 `neat-pcie-application-builder`。重新安裝 PCIe 主機套件時，已安裝的技能也會更新為相符的套件版本。

在第一次安裝期間，SSH 設定程序可以要求提供卡片的 `sima` 帳戶密碼。它會建立或重新使用 `~/.ssh/sima_neat_pcie_ed25519`，並將其公鑰安裝到卡片上。之後，正常的 PCIe 作業會使用無密碼的 SSH 來進行卡片端模型的設定。

## 驗證線上安裝

確認 Python API 和 PCIe 主機外掛程式是否已安裝：

<ShellCommand prompt="pcie-host">
source ~/pyneatpcie/bin/activate
python3 -c "import pyneatpcie; print('pyneatpcie ready')"
gst-inspect-1.0 neatpciehost
</ShellCommand>

## 安裝 Windows 11 原生預覽

Windows 預覽是 `pcie::Model` 視覺 API 的原生 Visual Studio 建置，不支援 `pcie::genai::GenAIModel`。請先安裝相符的 x64 GStreamer MSVC 執行階段、SiMa PCIe 驅動程式，以及現有的 SiMa CLI，然後使用 CLI 將相符的 Scheduler MSI、Core MSI 和 `win_amd64` wheel 安裝為同一組套件。

```powershell
sima-cli neat install core/pciehost/windows/amd64@3.0
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" -m pip check
```

CLI 會在執行 MSI 前檢查 Windows OpenSSH、Platform 服務、GStreamer，以及相容的 Python 安裝。它會建立或重用 `%USERPROFILE%\pyneatpcie` 環境、驗證所有已發布的總和檢查碼、呼叫 Windows Installer 安裝 Scheduler 與 Core，並執行主機診斷及安裝相符的程式設計代理技能和 wheel。如需修復或升級，請再次執行相同指令。若要使用其他環境，請指定 `--python-executable <path>`；若只安裝原生 C++，請使用 `--native-only`。原生元件由 Windows Installer 負責移除；Python 套件則由 pip 負責移除。

安裝完成後，請設定一次連到卡片的免密碼 SSH：

```powershell
& "C:\Program Files\SimaPCIeHost\bin\pcie-setup.cmd"
```

此工具會從本機的 `10.0.N.1` 管理連線探索卡片位址。若無法自動探索，請傳入 `-Hosts 10.0.0.2`。只有在公開金鑰尚未註冊時，OpenSSH 才會提示輸入卡片密碼；工具不會儲存該密碼。

匯入擴充模組前，Python 套件會在預設安裝根目錄和預設 x64 GStreamer 位置尋找 DLL。若使用其他安裝根目錄，請將 `SIMA_PCIE_HOST_LIBRARY_PATH` 設為包含 PCIe 主機及 GStreamer DLL 的目錄。如果必要的 DLL 已從核准位置以外的地方載入，匯入將會失敗。請先讓安裝版本一致並啟動新程序，不要繼續使用混合的執行階段。

請在原始碼和建置樹狀目錄之外驗證已安裝的 wheel 與外掛程式：

```powershell
$venv = "$env:USERPROFILE\pyneatpcie"
$root = "C:\Program Files\SimaPCIeHost"
$gst = "C:\Program Files\gstreamer\1.0\msvc_x86_64\bin\gst-inspect-1.0.exe"
$env:PATH = "$root\bin;$(Split-Path $gst);$env:PATH"
Set-Location $env:TEMP
& "$root\bin\sima-pcie-host-doctor.cmd"
& "$venv\Scripts\python.exe" -c "import pyneatpcie as p; print(p.__version__, p.Model)"
& $gst "$root\bin\gstreamer-1.0\gstneatpciehost.dll"
```

## 疑難排解

如果 SSH 佈線無法自動偵測到卡片，請先確認主機是否能夠連線到其管理位址：

<ShellCommand prompt="pcie-host">
ping -c 1 10.0.0.2
</ShellCommand>

然後以明確指定的位址執行已安裝的設定工具：

<ShellCommand prompt="pcie-host">
pcie-setup.sh --hosts "10.0.0.2"
</ShellCommand>

如果套件安裝或執行階段啟動失敗，請確認 PCIe 主機套件以及安裝在卡上的 Neat Library，是否來自相容的版本。

## 離線安裝 {#offline-installation}

:::caution 安裝前檢查 Python 相依性
離線安裝會保留現有的 Python 環境，以及其中額外的套件與檔案。安裝套件前會執行 `pip check`。如果環境已損壞，安裝會停止，並顯示環境路徑與相依性錯誤。請修復回報的相依性後再重試；離線修復需要額外的 wheel 檔案。安裝後會再次檢查相依性，回報仍存在或新引入的衝突。套件變更不會自動復原。

只有在您要捨棄環境並重新安裝時，才明確執行 `./install.sh --recreate-venv`（獨立 Core）或 `sudo python3 -B install.py --recreate-venv`（PCIe）。這會刪除所選環境中的套件與檔案，且不建立備份。在 SDK 中，此選項適用於已配對的 DevKit，不會變更 SDK 主機的 Python。請先儲存需要的檔案。預先檢查與僅驗證命令都不會重建環境。
:::

Neat PCIe 離線套件自 0.6.0 版本起提供。

PCIe 套件會在主機及所有已連接的相容卡上安裝 Neat。
目標系統不需要 Docker 或網際網路連線即可進行此安裝。
主機必須與每張卡建立可正常運作的 PCIe 網路連線。

### 1. 準備主機和卡

執行 Neat 安裝程式之前，請完成下列工作：

- 安裝相容的 Platform 主機驅動程式。
- 在每張卡上安裝相符的 Platform 3.0 韌體。
- 在每張卡的 PCIe 介面上設定探索功能。
- 為每張卡指派唯一的 PCIe IPv4 位址。
- 在每張卡上啟用 SSH 伺服器，並準備好登入密碼。
- 授予 SSH 帳戶在每張卡上使用 `sudo` 的權限。

Neat 安裝程式不會安裝 Platform 驅動程式或變更 Platform 韌體。
請使用 Platform 版本隨附的系統設定說明。

### 2. 下載套件

在可連上網際網路的電腦上安裝 `sima-cli`。請參閱 [sima-cli 安裝指南](/tools/sima-cli/)。

選擇適用於目標主機的 0.6.0 或更新版本。
套件支援使用 `amd64` 或 `arm64` 處理器的 Ubuntu 22.04 和 24.04 主機。

此範例在可連上網際網路的電腦上下載 %%release.core%% 版本。
對於 Ubuntu 24.04 `amd64` 目標主機，請執行：

<ShellCommand prompt="host">
sima-cli neat install 'core/pciehost/ubuntu24/amd64@v%%release.core%%' -t offline -d ./pcie-offline
</ShellCommand>

對於 Ubuntu 22.04，請將 `ubuntu24` 替換為 `ubuntu22`。
對於 `arm64` 主機，請將 `amd64` 替換為 `arm64`。
此命令會下載並解壓縮套件，不會安裝 Neat。

### 3. 選用：檢查已設定的系統

1. 將完整的 `pcie-offline` 目錄複製到目標主機。請使用不含空格的路徑。
2. 開啟解壓縮後包含 `install.py` 的 `neat-offline` 目錄。
3. 閱讀隨附的 `INSTALL.md`，以瞭解必要的系統工具和 SSH 設定。
4. 如果已設定 SSH 存取，請執行檢查：

<ShellCommand prompt="host">
sudo python3 -B install.py --preflight-only
</ShellCommand>

安裝程式會自動探索所有已連接的卡。請勿提供卡的 IP 位址。
檢查會建立暫存檔案，但不會安裝套件或設定 SSH。
在全新的主機上，請繼續進行安裝，讓安裝程式以互動方式設定 SSH。
安裝之前，請修正其他回報的錯誤。

### 4. 安裝並檢查結果

在同一個目錄中執行此命令：

<ShellCommand prompt="host">
sudo python3 -B install.py
</ShellCommand>

在全新的主機上，安裝程式會為呼叫 `sudo` 的使用者建立或重用 `~/.ssh/sima_neat_pcie_ed25519`，並透過與線上安裝相同的設定指令碼，設定所有已探索卡片的 SSH 存取。請視需要輸入卡片的登入密碼。您不需要另外執行 `ssh-keygen` 或 `ssh-copy-id`，也不需要輸入卡片的 IP 位址。

使用 `--ssh-user` 和 `--ssh-key` 選取現有認證。明確指定的 `--ssh-key` 必須已存在且沒有通關密語。自動註冊使用 `~/.ssh/known_hosts`；自訂的 `--known-hosts` 檔案必須事先設定。無人值守安裝需要事先設定 SSH 存取。密碼透過終端機輸入，不會儲存在記錄中或作為命令引數傳遞。

安裝程式會先檢查所有卡，再安裝套件。
安裝程式會先安裝並驗證主機，再依序處理每張卡。
確認最終摘要顯示主機及每張卡均已成功安裝並通過驗證。
接著執行應用程式驗收測試。

如果安裝失敗，請閱讀所顯示路徑中的診斷記錄。
如果安裝期間與卡的連線失敗，請先確認該卡的安裝程序已停止，再重試。
安裝失敗後，安裝程式不會自動還原先前的安裝狀態。

## 下一步

繼續進行 [PCIe 協同處理](/develop-apps/hello-neat/pcie/)，以驗證主機與卡之間的完整開發路徑。

離線安裝會重用主機上現有的 `~/pyneatpcie`，或卡及 DevKit 上現有的 `~/pyneat`；如果是符號連結，則重用其目標。若家目錄中沒有環境，卡或 DevKit 會在安裝使用者可寫入 NVMe 時使用 `/media/nvme/pyneat`，否則使用 `~/pyneat`。新的 NVMe 安裝會建立 `~/pyneat` 連結，不會取代現有的家目錄環境。
