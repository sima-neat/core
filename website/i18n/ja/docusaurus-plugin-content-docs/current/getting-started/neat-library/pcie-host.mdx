このページを使用して、Modalix PCIeカードに接続された、対応するLinuxまたはWindowsマシンにNeat PCIeホストパッケージをインストールします。

Neat PCIeホストパッケージは、ホストマシンから接続されたModalix PCIeカードにデータを送信し、推論結果を受信するコプロセッシングAPIを提供します。

:::warning PCIeホストマシンにインストールします。
このインストールを、Modalix PCIeカードに接続された**PCIeホストマシン**で実行してください。Palette SDKコンテナ内、DevKit上、またはModalix PCIeカード上で実行しないでください。
:::

:::tip オフラインでのインストールが必要な場合
Ubuntuの対象がSiMa.aiサービスからパッケージをダウンロードできない場合は、[オフラインでのインストール](#offline-installation)を使用してください。
インターネットに接続されたコンピューターでパッケージをダウンロードしてください。Windowsホストでは、オフラインでのインストールはまだ利用できません。
:::

## 対応するホストのオペレーティングシステム

Neat PCIe ホストパッケージは、以下の検証済みのホストプラットフォームをサポートします。

| オペレーティングシステム | アーキテクチャ | サポート |
| --- | --- | --- |
| Ubuntu 22.04 | x86_64 | 対応済み |
| Ubuntu 24.04 | x86_64 | 対応済み |
| Windows 11 HomeまたはPro、ビルド26300 | x86_64 | ネイティブプレビュー |

Arm64ホストでのビルドは、まだ検証されていません。WindowsパッケージにはPCIe GenAI APIが含まれていますが、対応するPlatformプロバイダーとWindows向けC++およびPython GenAIの完全なリリースマトリックスが認定されるまでは、サポート対象の顧客構成ではありません。

Windowsプレビューには、次の制限があります。

- Windows 10、Windows Server、SモードのWindows、およびArm64版Windowsはサポートされていません。
- 現在のPlatform 3.0 Windowsドライバーパッケージはテスト署名されています。Windowsは、セキュアブートが無効で、Windowsのテスト署名モードが有効な場合にのみこのドライバーを読み込みます。セキュアブートを有効のままにする必要があるホストでは、本番署名されたPlatformドライバーが提供されるまでプレビューを使用できません。
- Windowsの再起動後に、カードが見つからなかったり、モデルがタイムアウトしたりすることがあります。再起動ではなく、ホストをシャットダウンしてから電源を入れてください。スリープ、休止状態、高速スタートアップは検証されていません。
- 検証済みの構成は、ホスト1台につきカード1枚です。
- プレビューパッケージはコード署名されていません。Smart App Control、Windows Defender Application Control、および強制適用されたAppLockerポリシーによってブロックされます。
- GenAIモデルフォルダーのパスは、Windowsのシステムコードページで表現できる文字だけで構成する必要があります。
- [オフラインでのインストール](#offline-installation)はUbuntuホストでのみ利用できます。Windowsホストでパッケージをインストールするには、インターネット接続が必要です。

## オンラインインストールの前提条件

パッケージをインストールする前に：

- PCIeホストに`sima-cli`をインストールしてください。
  [sima-cli installation guide](/tools/sima-cli/).
- 以下の手順に従って、PCIeホストドライバーをインストールし、検証してください。
  [PCIe Driver Installation guide](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation).
- Modalix PCIeカードを接続し、設定して、その管理インターフェースが利用できるようにします。
  ホストからアクセス可能な状態。カード0のデフォルトアドレスは`10.0.0.2`です。
- カードにも同じリリースのNeat Libraryをインストールする準備をしてください。ホストと
  カードのパッケージは、互換性のあるリリースのものである必要があります。ホストパッケージをインストールしたら、[カードにNeatをインストールする](#install-neat-on-the-card)の手順に従ってください。

PCIeホストを認証し、SiMa.aiのアーティファクトをダウンロードできるようにします。

<ShellCommand prompt="pcie-host">
sima-cli login
</ShellCommand>

## PCIeホストパッケージをインストールしてください。

PCIeホスト上で作業ディレクトリを選択し、インストールされたUbuntuのバージョンに対応するコマンドを実行します。

**x86_64環境におけるUbuntu 22.04:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu22/amd64@v%%release.core%%
</ShellCommand>

**x86_64 アーキテクチャにおける Ubuntu 24.04:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu24/amd64@v%%release.core%%
</ShellCommand>

インストーラーは、C++ APIや、`~/pyneatpcie` にあるPython環境など、Neat PCIeホストアプリケーションを開発および実行するために必要なものをすべて追加します。

パッケージに同梱された Codex および Claude 向けのコーディングエージェントスキル `neat-pcie-application-builder` もインストールします。PCIe ホストパッケージを再インストールすると、スキルも対応するパッケージバージョンに更新されます。

最初のインストール時、SSH プロビジョニングでは、カードの `sima` アカウントのパスワードを要求できます。これにより、`~/.ssh/sima_neat_pcie_ed25519` が作成または再利用され、その公開鍵がカードにインストールされます。その後、通常の PCIe 動作では、パスワードなしの SSH を使用して、カード側のモデル設定を行います。

## オンラインインストールを確認する

Python API と PCIe ホストプラグインが利用可能であることを確認してください。

<ShellCommand prompt="pcie-host">
source ~/pyneatpcie/bin/activate
python3 -c "import pyneatpcie; print('pyneatpcie ready')"
gst-inspect-1.0 neatpciehost
</ShellCommand>

次に、[カードにNeatをインストールします](#install-neat-on-the-card)。

## Windows 11 ネイティブプレビューをインストールする

Windowsプレビューは、`pcie::Model`ビジョンAPIのネイティブVisual Studioビルドであり、`pcie::genai::GenAIModel`も含まれます。上記のとおり、GenAIのリリースには引き続き認定が必要です。APIをインストールするだけでは、Platformトランスポートやカードモデルは認定されません。次の前提条件を、この順序でインストールしてください。

1. Neatリリースに対応するSiMa Platform 3.0 Windowsパッケージ。[PCIeドライバーインストールガイド](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation)の説明に従ってインストールします。PCIeドライバーと`SiMaMlaDaemon`サービスを提供します。インストーラーが確認するのはドライバーのバージョンであり、**Installed apps**に表示されるパッケージ名ではありません。ドライバーのバージョンを確認するには、PowerShellで`Get-CimInstance Win32_PnPSignedDriver | Where-Object DeviceName -like 'SiMa.ai*' | Select-Object DeviceName, DriverVersion`を実行します。カードが取り付けられていれば、`SiMa.ai MLA Device`と`SiMa.ai Virtual Ethernet Adapter`が表示されます。

   現在のPlatform 3.0 Windowsドライバーパッケージは、本番署名ではなくテスト署名されています。Windowsは、セキュアブートが無効で、Windowsのテスト署名モードが有効な場合にのみこのドライバーを読み込みます。Platformインストーラーはテスト署名を有効にしますが、セキュアブートが有効な間はWindowsがこれを許可しないため、Platformパッケージをインストールする前にセキュアブートを無効にしてください。両方の設定を確認するには、PowerShellを管理者として起動し、次を実行します。

   ```powershell
   Confirm-SecureBootUEFI
   bcdedit
   ```

   `Confirm-SecureBootUEFI`は`False`を出力し、`bcdedit`の出力には`testsigning Yes`が含まれている必要があります。テスト署名が有効な場合、Windowsのデスクトップに**テスト モード**と表示されます。セキュアブートはPCのファームウェア（UEFI）設定で無効にします。手順はPCメーカーによって異なります。詳しくは[セキュアブートを無効にする](https://learn.microsoft.com/windows-hardware/manufacture/desktop/disabling-secure-boot)を参照してください。セキュアブートを変更すると、BitLockerの回復が開始されることがあります。システムドライブでBitLockerまたはデバイスの暗号化を使用している場合は、セキュアブートを変更する前に、組織のデバイス暗号化ポリシーを確認し、BitLockerを一時停止して、回復キーを用意してください。
2. GStreamer 1.28.6 MSVC x64。[gstreamer-1.0-msvc-x86_64-1.28.6.exe](https://gstreamer.freedesktop.org/data/pkg/windows/1.28.6/msvc/gstreamer-1.0-msvc-x86_64-1.28.6.exe)から入手します。パッケージにはこのバージョンが厳密に必要です。C++アプリケーションに必要な開発ファイルを含むセットアップの種類を選択してください。インストール後は、GStreamerインストーラーが設定する`GSTREAMER_1_0_ROOT_MSVC_X86_64`変数が反映されるように、新しいターミナルを開いてください。
3. [python.org](https://www.python.org/downloads/windows/)の64ビットCPython 3.14。すべてのユーザー向けと現在のユーザー向けのどちらのインストールでも使用できます。Pythonは`sima-cli`より先にインストールしてください。フリースレッドビルドではwheelを読み込めません。
4. [sima-cliインストールガイド](/tools/sima-cli/)に従ってインストールした`sima-cli`。その後、`sima-cli login`でサインインします。古い`sima-cli`は`Missing 'script' in 'installation'`で停止します。更新してから再試行してください。

PowerShellを管理者としてではなく通常のユーザーとして開き、ダウンロードしたパッケージとログを保存する作業ディレクトリを作成します。管理者として起動したPowerShellウィンドウは`C:\Windows\System32`で開くため、そこからはインストールしないでください。その後、Windowsパッケージをインストールします。

```powershell
New-Item -ItemType Directory -Force "$HOME\neat-pcie" | Out-Null
Set-Location "$HOME\neat-pcie"
```

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/windows/amd64@v%%release.core%%
</ShellCommand>

Windowsパッケージは、それを含む最初のNeatリリースから公開されます。

このコマンドは、対応するScheduler MSI、Core MSI、および`win_amd64` wheelを1つのコホートとしてインストールします。2つのMSIパッケージのために、Windowsが管理者の承認を1回求めます。ダウンロードしたパッケージとWindows Installerのログは、現在のディレクトリに残ります。

CLIはMSIを実行する前に、Windows OpenSSH、Platformサービス、GStreamer、および互換性のあるPythonを確認します。`%USERPROFILE%\pyneatpcie`環境を作成または再利用し、公開済みのチェックサムを検証して、SchedulerとCoreに対してWindows Installerを実行します。さらに、インストール済みのホスト診断ツールを実行し、パッケージに対応するコーディングエージェントのスキルをインストールして、wheelをそのPython環境にインストールします。修復またはアップグレードする場合は、同じコマンドを再度実行してください。別の環境を使用する場合は`--python-executable <path>`を、ネイティブC++のみをインストールする場合は`--native-only`を使用します。ネイティブコンポーネントの削除はWindows Installerが、Pythonパッケージの削除はpipが管理します。

Ubuntuと同様に、インストールの最後に、インストール済みのセットアップユーティリティでカードへのパスワードなしSSHを設定します。このユーティリティは`%USERPROFILE%\.ssh\sima_neat_pcie_ed25519`を作成または再利用し、公開鍵がまだ登録されていない場合は、OpenSSHがカードの`sima`アカウントのパスワードを1回だけ求めます。ユーティリティはパスワードを保存しません。カードを追加または交換した後などに、もう一度実行するには次のコマンドを使用します。

```powershell
& "$env:ProgramFiles\SimaPCIeHost\bin\pcie-setup.cmd"
```

このユーティリティは、PlatformのPCIeネットワークアダプターに割り当てられたローカルの`10.0.N.1`アドレスから、カードのアドレスを検出します。自動検出できない場合は、`-Hosts 10.0.0.2`を指定してください。実行するたびにカードの現在のSSHホストキーを記録するため、再フラッシュまたは交換したカードも再び信頼されます。`.cmd`ラッパーは、自身のPowerShellプロセスに限ってこのインストール済みスクリプトの実行を許可し、ユーザーやマシンの実行ポリシーは変更しません。

Pythonパッケージは、拡張モジュールをインポートする前に、既定のインストールルートとGStreamerのルートでDLLを検索します。検索順序は、`GSTREAMER_1_0_ROOT_MSVC_X86_64`、`GSTREAMER_ROOT_X86_64`、既定のx64 GStreamerの場所です。別のインストールルートを使用する場合は、`SIMA_PCIE_HOST_LIBRARY_PATH`にPCIeホストとGStreamerのDLLを含むディレクトリを設定してください。必要なDLLが承認済みの場所とは別の場所からすでに読み込まれている場合、インポートは失敗します。混在したランタイムを使い続けず、インストール済みのバージョンを揃えてから新しいプロセスを開始してください。

インストール済みのwheelとプラグインを確認します。診断ツールは`neatpciehost`プラグインを読み込み、使用するGStreamerとPlatformのディレクトリを表示します。`neat.cmd`は、ホストとカードのソフトウェアを表示します。

```powershell
$venv = "$env:USERPROFILE\pyneatpcie"
$root = "$env:ProgramFiles\SimaPCIeHost"
& "$root\bin\sima-pcie-host-doctor.cmd"
& "$venv\Scripts\python.exe" -m pip check
& "$venv\Scripts\python.exe" -c "import pyneatpcie as p; print(p.__version__, p.Model)"
& "$root\bin\neat.cmd"
```

### Windowsでアプリケーションを実行する {#run-applications-on-windows}

[PCIe Co-Processing](/develop-apps/hello-neat/pcie/)の例とPCIeチュートリアルには、Linuxのコマンドが記載されています。Windowsでは、管理対象環境のインタープリターでPythonプログラムを実行します。アクティベーションは不要です。また、既定のPowerShell実行ポリシーでは`Activate.ps1`がブロックされます。

```powershell
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" pcie_host.py
```

C++アプリケーションには、**Desktop development with C++**ワークロードを含むVisual Studio 2022バージョン17.14以降（Visual Studio 2026を含む）が必要です。OpenCVを使用する例には、[opencv.org](https://opencv.org/releases/)のOpenCV 5.0.0 Windowsパッケージも必要です。パッケージが提供するのはReleaseビルド構成のみです。Debugビルドはコンパイラエラーで停止します。`--config RelWithDebInfo`ではデバッグ情報付きでビルドします。お使いのVisual Studioバージョンの**x64 Native Tools Command Prompt**でビルドして実行します。

```bat
call "%ProgramFiles%\SimaPCIeHost\bin\sima-pcie-host-env.cmd"
set "OpenCV_DIR=C:\opencv\build"
cmake -S . -B build
cmake --build build --config Release
set "PATH=%OpenCV_DIR%\x64\vc16\bin;%PATH%"
build\Release\pcie_host.exe
```

`C:\opencv\build`は、展開したOpenCVパッケージの`build`ディレクトリに置き換えてください。`sima-pcie-host-env.cmd`が変更するのは、現在のコマンドプロンプトだけです。別のシェルから独自のプログラムを起動するには、`sima-pcie-host-run.cmd`を介して実行してください。同じ設定がそのプログラムだけに適用されます。

```powershell
& "$env:ProgramFiles\SimaPCIeHost\bin\sima-pcie-host-run.cmd" build\Release\pcie_host.exe
```

ホストパッケージはチュートリアルをインストールディレクトリ内にインストールするため、Windowsではチュートリアルを別途ダウンロードする必要はありません。チュートリアルプログラムは、モデルアーカイブと`share\sima-pcie-host\tutorials`を現在のディレクトリから読み込みます。ソースを書き込み可能なディレクトリにコピーし、[Tutorial Setup](/tutorials/before-you-run)に記載されたモデルアーカイブを追加して、そのディレクトリからプログラムを実行します。

```powershell
$root = "$env:ProgramFiles\SimaPCIeHost"
New-Item -ItemType Directory -Force pcie-tutorials\share\sima-pcie-host | Out-Null
Copy-Item -Recurse "$root\share\sima-pcie-host\tutorials" pcie-tutorials\share\sima-pcie-host\
Set-Location pcie-tutorials
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" share\sima-pcie-host\tutorials\024_run_your_first_model_over_pcie\run_tensor_mode.py
& "$root\bin\sima-pcie-host-run.cmd" "$root\lib\sima-pcie-host\tutorials\tutorial_024_run_tensor_mode.exe"
```

ビルド済みのC++チュートリアルは、その横にインストールされたOpenCVランタイムを読み込むため、OpenCVパッケージは不要です。

### Windowsでアンインストールする

```powershell
sima-cli packages list
sima-cli packages remove gh:sima-neat/core/pciehost/windows/amd64 --version <version> --yes
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" -m pip uninstall -y pyneatpcie
sima-cli playbooks remove neat-pcie-application-builder --yes
```

`sima-cli packages list`に表示されるバージョンを使用してください。このコマンドは、1回の管理者承認でCore、次にSchedulerを削除します。Python環境は削除されません。ほかのアプリケーションで使用していない場合は、`%USERPROFILE%\pyneatpcie`を削除してください。SSHキー`%USERPROFILE%\.ssh\sima_neat_pcie_ed25519`、`%USERPROFILE%\.ssh\known_hosts`内のカードのエントリー、作業ディレクトリ内のダウンロードしたパッケージとログも残ります。

Windows Installerは、パッケージを古いバージョンで置き換えません。古いリリースをインストールするには、先にインストール済みのリリースをアンインストールしてください。

## カードにNeatをインストールする {#install-neat-on-the-card}

カードには、ホストパッケージと同じリリースのNeat Libraryが必要です。カードへのSSHが設定されるように先にホストパッケージをインストールし、その後ホストから各カードにNeatをインストールします。アップグレードする場合は、アプリケーションを再び実行する前に、ホストパッケージをアップグレードしてから、すべてのカードをアップグレードしてください。

ホスト上の空の作業ディレクトリで、次のコマンドを実行します。これらのコマンドは、Neat Libraryのオフラインパッケージをダウンロードして`10.0.0.2`のカードにコピーし、カード上でそのインストーラーを実行します。インストーラーから求められたら、カードの`sima`アカウントのパスワードを入力してください。別のカードの場合は、`10.0.0.2`をそのカードのアドレス`10.0.N.2`に置き換えてください。

Ubuntuの場合:

<ShellCommand prompt="pcie-host">
sima-cli neat install core/offline@v%%release.core%% -t minimal --download-only
scp -i ~/.ssh/sima_neat_pcie_ed25519 neat-core-offline-installer*.tar.gz sima@10.0.0.2:/var/tmp/neat-core-offline-installer.tar.gz
ssh -t -i ~/.ssh/sima_neat_pcie_ed25519 sima@10.0.0.2 "cd /var/tmp && rm -rf neat-core-offline && tar -xzf neat-core-offline-installer.tar.gz && cd neat-core-offline && ./install.sh && ./install.sh --verify"
</ShellCommand>

Windowsの場合は、PowerShellで次のコマンドを実行します。

```powershell
sima-cli neat install core/offline@v%%release.core%% -t minimal --download-only
$bundle = (Get-Item neat-core-offline-installer*.tar.gz).FullName
scp -i "$env:USERPROFILE\.ssh\sima_neat_pcie_ed25519" $bundle sima@10.0.0.2:/var/tmp/neat-core-offline-installer.tar.gz
ssh -t -i "$env:USERPROFILE\.ssh\sima_neat_pcie_ed25519" sima@10.0.0.2 "cd /var/tmp && rm -rf neat-core-offline && tar -xzf neat-core-offline-installer.tar.gz && cd neat-core-offline && ./install.sh && ./install.sh --verify"
```

インストーラーは、何かを変更する前に、カードで互換性のあるPlatform 3.0リリースが動作していることを確認します。`--verify`は、インストール済みのパッケージとPyNeatのインポートを確認します。ホストとカードのNeatのバージョンを比較するには、Ubuntuでは`neat`を、WindowsではPowerShellで`& "$env:ProgramFiles\SimaPCIeHost\bin\neat.cmd"`を実行してください。

## トラブルシューティング {#troubleshooting}

ほとんどのエラーでは、メッセージの最後に次に行う手順が表示されます。次の表は、UbuntuとWindowsでよくあるケースをまとめたものです。セットアップユーティリティは、Ubuntuでは`pcie-setup.sh`、Windowsでは`& "$env:ProgramFiles\SimaPCIeHost\bin\pcie-setup.cmd"`です。

| 症状 | 原因 | 対処方法 |
| --- | --- | --- |
| SSHプロビジョニングでカードが見つからない | カードにアクセスできないか、カードの管理リンクが設定されていない | Ubuntuでは`ping -c 1 10.0.0.2`、Windowsでは`Test-Connection -ComputerName 10.0.0.2 -Count 1`でリンクを確認してから、Ubuntuでは`--hosts 10.0.0.2`、Windowsでは`-Hosts 10.0.0.2`を指定してセットアップユーティリティを実行します。 |
| `REMOTE HOST IDENTIFICATION HAS CHANGED`または`Host key verification failed` | カードが再フラッシュまたは交換され、SSHホストキーが新しくなった | セットアップユーティリティを再度実行します。カードの現在のキーが記録されます。 |
| `Permission denied (publickey)` | カードにこのホストのNeat SSHキーが登録されていない | セットアップユーティリティを実行し、OpenSSHから求められたら、カードの`sima`のパスワードを入力します。 |
| モデルの起動時に`missing_builder`が発生する | カードにNeatがインストールされていない | ホストパッケージと同じリリースを使用して、[カードにNeatをインストールします](#install-neat-on-the-card)。 |
| モデルの起動時に`queue_busy`が発生する | ホストアプリケーションがモデルを閉じずに終了した場合などに、カードのワーカーがキューを保持したままになっている | そのキューをほかのアプリケーションが使用していなければ、下記の手順で残っているワーカーを停止してから、モデルを再度起動します。 |
| アップグレード後に、モデルの起動に失敗するかタイムアウトする | ホストパッケージとカードで異なるリリースが動作している | ホストとカードに同じリリースをインストールします。 |

キュー`0`に残っているカードのワーカーを停止するには、ホストで次のコマンドを実行します。`--queue 0`の`0`をエラーに表示されたキューに、`10.0.0.2`をカードのアドレスに置き換えてください。

Ubuntuの場合:

<ShellCommand prompt="pcie-host">
ssh -i ~/.ssh/sima_neat_pcie_ed25519 sima@10.0.0.2 "pkill -f '[p]cie-pipeline-builder.*--queue 0( |$)'"
</ShellCommand>

Windowsの場合:

```powershell
ssh -i "$env:USERPROFILE\.ssh\sima_neat_pcie_ed25519" sima@10.0.0.2 "pkill -f '[p]cie-pipeline-builder.*--queue 0( |$)'"
```

Windowsでは、次のケースも確認してください。

| 症状 | 原因 | 対処方法 |
| --- | --- | --- |
| `SiMa.ai MLA Device`がデバイスマネージャーに表示されない、または警告付きで表示される。あるいは、Platformドライバーが見つからないとインストーラーが報告する | Platformパッケージがインストールされていない。セキュアブートが有効か、テスト署名が無効なため、Windowsがテスト署名済みドライバーを読み込まない。またはWindowsがカードを検出していない | Platformパッケージをインストールします。管理者として起動したPowerShellで、`Confirm-SecureBootUEFI`が`False`を出力し、`bcdedit`に`testsigning Yes`が表示されることを確認します。セキュアブートが有効な場合は、ファームウェア設定で無効にしてから`bcdedit /set testsigning on`を実行します。両方の設定が正しい場合は、カードが正しく装着され、電源が供給されていることを確認します。その後、ホストをシャットダウンして電源を入れます。 |
| インストール後にWindowsが再起動を求める、または再起動後にカードが見つからない | Windowsの再起動後に、カードが必ず復帰するとは限らない | 再起動ではなく、ホストをシャットダウンしてから電源を入れます。 |
| ほかのモデルを開いているときにモデルの起動に失敗し、Platformがエラー1450を報告する | 開いている各キューがバッファー用に物理的に連続したホストメモリを確保し、その量はキューの深さとテンソルのサイズに応じて増える | 同時に開くモデルを減らし、ほかのアプリケーションを終了します。メモリの少ないホストでは、同時に開けるキューが少なくなります。 |
| インストールが終了コード1625で停止する | Smart App Control、Windows Defender Application Control、またはAppLockerのポリシーが、署名されていないパッケージをブロックしている | そのポリシーでパッケージが許可されているホストにインストールします。 |
| 古いリリースのインストールが終了コード1603で停止する | Windows Installerは新しいバージョンを置き換えない | インストール済みのリリースをアンインストールしてから、古いリリースをインストールします。 |
| 管理者承認のプロンプトが表示されない、またはポリシーによってブロックされる | エンドポイントセキュリティが昇格要求をブロックしている | PowerShellを管理者として起動し、作業ディレクトリに移動して、そこでインストールコマンドを実行します。 |
| 組織が設定した実行ポリシーによって`pcie-setup.cmd`がブロックされる | グループポリシーが、ラッパーのプロセス限定のポリシーより優先される | 下記のとおり、OpenSSHを使用して手動でキーを登録します。 |
| 2枚目のカードが見つからない | カード`N`は`10.0.N.2`を使用する | `-Range 0-1`を指定してセットアップユーティリティを実行し、アプリケーションでは`card_id`でカードを選択します。 |

`pcie-setup.cmd`を使用せずにキーを登録するには、キーを作成し、2回のパスフレーズ入力ではどちらも**Enter**を押してから、公開鍵をカードに追加し、パスワードなしでログインできることを確認します。

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\sima_neat_pcie_ed25519"
Get-Content "$env:USERPROFILE\.ssh\sima_neat_pcie_ed25519.pub" | ssh sima@10.0.0.2 "umask 077; mkdir -p ~/.ssh; tr -d '\r' >> ~/.ssh/authorized_keys"
ssh -i "$env:USERPROFILE\.ssh\sima_neat_pcie_ed25519" -o IdentitiesOnly=yes sima@10.0.0.2 true
```

## オフラインでのインストール {#offline-installation}

:::caution インストール前に Python の依存関係を確認する
オフラインインストールでは、既存の Python 環境と追加のパッケージやファイルを保持します。パッケージのインストール前に `pip check` を実行し、環境がすでに壊れている場合は停止して、環境のパスと依存関係のエラーを表示します。報告された依存関係を修復してから再試行してください。オフラインで修復する場合は、追加の wheel ファイルが必要です。インストール後にも依存関係を確認し、残っている競合や新たに生じた競合を報告します。パッケージの変更は自動的には元に戻されません。

環境を破棄して新規にインストールする場合に限り、明示的に `./install.sh --recreate-venv`（単体 Core）または `sudo python3 -B install.py --recreate-venv`（PCIe）を実行してください。選択された環境内のパッケージとファイルは、バックアップなしで削除されます。SDK では、このオプションはペアリングした DevKit に適用され、SDK ホストの Python には適用されません。必要なファイルを事前に保存してください。事前確認と検証のみのコマンドでは、環境を再作成しません。
:::

Neat PCIe オフラインパッケージは、バージョン 0.6.0 以降で利用できます。

PCIe パッケージは、ホストと接続されている互換カードすべてに Neat をインストールします。
このインストールでは、対象システムに Docker やインターネット接続は必要ありません。
ホストから各カードへの PCIe ネットワーク接続が動作している必要があります。

### 1. ホストとカードを準備する

Neat インストーラーを実行する前に、次の作業を完了してください：

- 互換性のある Platform ホストドライバーをインストールしてください。
- 各カードに対応する Platform 3.0 ファームウェアをインストールしてください。
- 各カードの PCIe インターフェースで検出を設定してください。
- 各カードに一意の PCIe IPv4 アドレスを割り当ててください。
- 各カードで SSH サーバーを有効にし、ログインパスワードを用意してください。
- SSH アカウントに、各カードで `sudo` を使用する権限を付与してください。

Neat インストーラーは、Platform ドライバーのインストールや Platform ファームウェアの変更を行いません。
Platform リリースに付属するシステムセットアップ手順を使用してください。

### 2. パッケージをダウンロードする

インターネットに接続されたコンピューターに `sima-cli` をインストールしてください。[sima-cli インストールガイド](/tools/sima-cli/)を参照してください。

対象ホスト用のバージョン 0.6.0 以降を選択してください。
パッケージは、`amd64` または `arm64` プロセッサーを搭載した Ubuntu 22.04 および 24.04 ホストに対応しています。

この例では、インターネットに接続されたコンピューターでバージョン %%release.core%% をダウンロードします。
Ubuntu 24.04 の `amd64` 対象ホストの場合は、次を実行してください：

<ShellCommand prompt="host">
sima-cli neat install 'core/pciehost/ubuntu24/amd64@v%%release.core%%' -t offline -d ./pcie-offline
</ShellCommand>

Ubuntu 22.04 の場合は、`ubuntu24` を `ubuntu22` に置き換えてください。
`arm64` ホストの場合は、`amd64` を `arm64` に置き換えてください。
このコマンドはパッケージをダウンロードして展開します。Neat はインストールしません。

### 3. 任意：設定済みのシステムを確認する

1. `pcie-offline` ディレクトリ全体を対象ホストにコピーしてください。スペースを含まないパスを使用してください。
2. `install.py` を含む、展開済みの `neat-offline` ディレクトリを開いてください。
3. 必要なシステムツールと SSH 設定について、付属の `INSTALL.md` を読んでください。
4. SSH アクセスが設定済みの場合は、チェックを実行してください：

<ShellCommand prompt="host">
sudo python3 -B install.py --preflight-only
</ShellCommand>

インストーラーは接続されているすべてのカードを自動的に検出します。カードの IP アドレスは指定しないでください。
チェックでは一時ファイルを作成しますが、パッケージのインストールや SSH の設定は行いません。
新しいホストでは、インストールに進むとインストーラーが対話形式で SSH を設定します。
それ以外のエラーはインストール前に修正してください。

### 4. インストールして結果を確認する

同じディレクトリから次のコマンドを実行してください：

<ShellCommand prompt="host">
sudo python3 -B install.py
</ShellCommand>

新しいホストでは、インストーラーが `sudo` を実行したユーザーの `~/.ssh/sima_neat_pcie_ed25519` を作成または再利用し、オンラインインストールと同じ設定スクリプトで、検出されたすべてのカードへの SSH アクセスを設定します。必要に応じてカードのログインパスワードを入力してください。`ssh-keygen` や `ssh-copy-id` を別途実行したり、カードの IP アドレスを入力したりする必要はありません。

既存の認証情報を選択するには `--ssh-user` と `--ssh-key` を使用してください。明示的に指定する `--ssh-key` は、パスフレーズのない既存のキーである必要があります。自動登録は `~/.ssh/known_hosts` を使用します。独自の `--known-hosts` ファイルは事前に設定してください。無人インストールでは、SSH アクセスを事前に設定してください。パスワードは端末から入力し、ログへの保存やコマンド引数での受け渡しは行いません。

インストーラーは、パッケージをインストールする前にすべてのカードを確認します。
最初にホストをインストールして検証し、次に各カードを順番に処理します。
最終サマリーで、ホストとすべてのカードのインストールおよび検証が成功したことを確認してください。
次に、アプリケーションの受け入れテストを実行してください。

インストールに失敗した場合は、表示されたパスの診断ログを読んでください。
インストール中にカードへの接続が失敗した場合は、再試行前にカードのインストールプロセスが停止したことを確認してください。
失敗しても、インストーラーは以前のインストール状態を自動的には復元しません。
