# 튜토리얼 자료 및 모델 아카이브

대부분의 튜토리얼 사용자는 `--model <path>` 및 `--image <path>`만 필요로 합니다. 이 페이지는 소스 트리 실행, 테스트 및 재현 가능한 디버깅 세션을 위해 제공되며, 사용자가 모델 아카이브와 샘플 자산이 어디에서 가져오는지 제어하려는 경우에 유용합니다.

이 자료는 초보자 튜토리얼에서 제외하십시오. 유용하지만 첫 번째 단계는 아닙니다.

## 모델 아카이브 우선 적용

리포지토리 내에서 테스트를 수행하거나 보조 스크립트가 모델 아카이브 경로를 필요로 할 때, 모든 명령어에서 경로를 변경하지 않고 사용할 수 있도록 다음 환경 변수를 사용하세요.

| 변수 | 사용법 |
| --- | --- |
| `SIMA_RESNET50_TAR` | ResNet-50 튜토리얼 및 테스트에 대한 모델별 재정의입니다. |
| `SIMA_MODEL_TAR` | 모델 기반 테스트 및 예제에서 사용되는 공유 기본 모델 아카이브입니다. |
| 스크립트에서 지원하는 경우 YOLO 스타일의 감지 튜토리얼 및 테스트에 대한 모델별 재정의입니다. | `SIMA_YOLO_TAR` |

튜토리얼 명령어는 여전히 명시적인 플래그를 허용합니다. 단일 실행의 경우 `--model <path>`를 사용하는 것이 좋으며, 여러 명령어가 동일한 아티팩트를 공유해야 하는 경우 환경 변수를 사용하십시오.

<ShellCommand prompt="sdk|devkit">
export SIMA_RESNET50_TAR=/path/to/resnet_50.tar.gz
export SIMA_YOLO_TAR=/path/to/yolo_v8s.tar.gz
</ShellCommand>

## 일반적인 소스 트리 경로

일반적으로 리포지토리 내의 테스트 및 예제는 리포지토리 루트 디렉터리의 `tmp/` 폴더를 참조합니다. 가장 일반적인 경로는 다음과 같습니다.

| 자산 | 공통 소스 트리 경로 |
| --- | --- |
| ResNet-50 모델 아카이브 | `tmp/resnet_50.tar.gz` |
| YOLOv8s 모델 아카이브 | `tmp/yolo_v8s.tar.gz` |
| COCO 샘플 이미지 | `tmp/coco_sample.jpg` |

설치된 튜토리얼은 대신 'extras' 폴더에서 실행할 수 있습니다. 이 경우, 모델 및 이미지 경로가 이미 `/tmp`에 포함되어 있지 않다면 해당 경로를 명시적으로 전달해야 합니다.

## 모델 추출 제어

Neat은 실행하기 전에 모델 아카이브를 추출합니다. 이러한 변수는 주로 디버깅 중에 검사 및 정리 작업을 제어하는 데 사용됩니다.

| 변수 | 효과 |
| --- | --- |
| `SIMA_MPK_EXTRACT_ROOT=<dir>` | 추출된 모델 데이터의 기본 디렉터리를 설정합니다. |
| `SIMA_MPK_CLEANUP_EXTRACTED=0` | 프로세스별로 로컬 설정을 유지합니다. `proc_*` 종료 후 검사를 위해 추출된 루트 디렉터리입니다. 다른 프로세스에서는 자동으로 이를 찾거나 재사용하지 않습니다. |
| `SIMA_MPK_EXTRACT_GC_STALE_PROC=0` | 시작 시 오래된 `proc_*` 디렉터리의 정리 작업을 비활성화합니다. |

생성된 구성 파일을 검사하거나 여러 실행 간에 추출된 아티팩트를 비교해야 할 때 사용합니다. 일반적인 튜토리얼 작업 시에는 기본 설정을 그대로 유지하십시오.

## 샘플 이미지 재정의

일부 소스 트리 테스트는 COCO 샘플 이미지를 사용하며, 이미지가 없는 경우 다운로드합니다.
환경에 로컬 미러가 필요한 경우 URL을 재정의하십시오.

<ShellCommand prompt="sdk|devkit">
export SIMA_COCO_URL=https://example.com/path/to/coco_sample.jpg
</ShellCommand>

하나의 튜토리얼 실행에는 `--image <path>`를 사용하는 것이 좋습니다. 테스트 스위트 또는 CI 작업에서 제어된 위치에서 데이터를 가져와야 하는 경우 `SIMA_COCO_URL`을 사용하십시오.

## 누락된 에셋 분류

튜토리얼에서 `SKIP: missing ...`이 출력되거나 모델을 열 수 없는 경우:

1. 메시지에 표시된 경로를 확인하세요.
2. 튜토리얼 플래그와 함께 에셋을 명시적으로 전달하세요.
3. 소스 트리 테스트를 실행하는 경우 해당 환경 변수를 설정하십시오.
4. 만약 해당 에셋이 Model Zoo에서 다운로드된 것이라면, 다운로드한 파일 이름을 확인하십시오.
   튜토리얼에서 실제 `.tar.gz` 파일로 경로를 지정하십시오.

일반적인 실행 시에는 모델 아카이브를 직접 압축 해제하지 마십시오. Neat는 컴파일된 아카이브 경로를 예상하고 자체적으로 압축 해제를 처리합니다.
