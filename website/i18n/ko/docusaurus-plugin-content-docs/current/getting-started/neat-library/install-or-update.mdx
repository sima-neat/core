이 페이지를 사용하여 Palette Neat Library를 설치하거나 업데이트하십시오.

:::tip Neat SDK 내의 Neat Library
`sima-cli sdk setup` 과정에서 DevKit을 연결하면 SDK가 포함된 Neat Library와 함께 제공되는 PyNeat 환경을 DevKit의 `~/pyneat`에 자동으로 설치합니다.
:::

:::tip 오프라인 설치가 필요한 경우
대상에서 SiMa.ai 서비스의 패키지를 다운로드할 수 없으면 [오프라인 설치](#offline-installation)를 사용하세요.
인터넷에 연결된 컴퓨터에서 패키지를 다운로드하세요.
:::

## 설치 위치를 선택하세요

Neat 애플리케이션을 빌드하거나 실행하는 환경에서 설치 프로그램을 실행합니다.

| 환경 | 사용 시점 |
|---|---|
| Neat SDK | 새 SDK 버전을 설치하지 않고 Neat SDK 내에서 Neat Library를 업그레이드하려는 경우. |
| ROS2 SDK | 컨테이너의 시스템 경로에 설치된 Neat 헤더 및 라이브러리를 사용하여 ARM64에서 ROS 2 애플리케이션을 네이티브로 컴파일하려는 경우. |
| DevKit | 장치에 런타임을 직접 설치하거나 업데이트하려는 경우. |

## C++ 개발 패키지

최소 설치에는 런타임과 `sima-neat-dev`가 포함됩니다. 기본 설치에서는 튜토리얼과
테스트를 선택적 추가 항목으로 제공하며, `all`은 이를 포함합니다. 공유 라이브러리
애플리케이션에는 Core 공개 헤더, 일치하는 Scheduler 프런트엔드 및 GStreamer,
OpenCV, JSON 개발 파일이 필요합니다. 폐기된 Internals 통합 패키지나 Runner,
Kernels, Codecs, memory-library, heap 또는 LLiMa 개발 API는 필요하지 않습니다.
선택된 패키지가 필수 런타임 종속성을 제공합니다.

설치된 공유 타깃을 사용합니다.

```cmake
find_package(SimaNeat CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE SimaNeat::sima_neat)
```

정적 아카이브는 `sima-neat-dev`에 계속 포함됩니다. `COMPONENTS Static`을 사용하고
일치하는 `simaai-scheduler` 패키지를 설치된 상태로 유지하세요. `zlib1g-dev`,
`libcpp-httplib-dev` 및 해당 종속성을 준비하세요. LLiMa를 활성화한 빌드에는
`sima-lmm-dev`와 해당 종속성도 필요합니다. Core는 Scheduler의 설치된 프런트엔드를
사용하므로 애플리케이션에 Internals 또는 하위 라이브러리의 개발 타깃을 추가하지 마세요:

```cmake
find_package(SimaNeat CONFIG REQUIRED COMPONENTS Static)
target_link_libraries(my_app PRIVATE SimaNeat::sima_neat_static)
```

정적 Core도 공유 구현 라이브러리를 사용합니다. 소스에서 Core를 빌드할 때도 같은
Scheduler 프런트엔드 경계를 사용하며, 활성화된 LLiMa를 비롯한 다른 종속성의
개발 파일이 필요합니다.

## 온라인 설치 필수 조건

Neat Library를 설치할 환경에 `sima-cli`를 설치합니다.
[sima-cli 설치 안내서](/tools/sima-cli/)를 사용하세요.

[community.sima.ai](https://community.sima.ai)에 계정을 생성하여 테스트용으로 미리 컴파일된 모델과 같은 SiMa.ai 리소스에 액세스하세요.

설치 프로그램이 SiMa.ai 아티팩트를 다운로드할 수 있도록 환경을 인증합니다. 자세한 내용은 [sima-cli 로그인](/tools/sima-cli/login/)를 참조하십시오.

<ShellCommand prompt="sdk|devkit">
sima-cli login
</ShellCommand>

SiMa.ai 아티팩트가 있는 호스트에 접속할 수 있는지 확인합니다.

<ShellCommand prompt="sdk|devkit">
curl -fsS https://artifacts.neat.sima.ai/sima-cli/linux-mac.sh -o /dev/null && echo "artifacts reachable"
</ShellCommand>

`artifacts reachable` 메시지가 출력되면 호스트에 연결 가능하다는 의미입니다. 타임아웃, 연결 거부 또는 "호스트를 확인할 수 없음"과 같은 `curl` 오류는 외부 액세스가 차단되었음을 의미합니다. 호스트 네트워크, 프록시 또는 방화벽을 확인하십시오([Neat SDK 네트워킹](/tools/sima-cli/sdk-networking/) 및 [호스트 설정 참고 사항](/reference/elxr-sdk-host-setup/ubuntu) 참조). 또는 장치가 SiMa.ai 서비스에 직접 연결할 수 없는 경우 [오프라인 설치](#offline-installation)을 사용하십시오.

## Neat Library 설치

:::note 패키지 호환성
설치 프로그램은 선택한 핵심 아티팩트에 나열된 모든 Debian 패키지를 사용하며, 다른 Scheduler나 LLiMa 버전을 선택하지 않습니다. 설치된 플랫폼은 해당 아티팩트에 포함되지 않은 종속성을 충족해야 합니다. APT가 설치를 완료하기 위해 플랫폼 패키지를 제거하는 경우, 설치 프로그램은 중단됩니다. 핵심 또는 LLiMa에서 패키지를 대체하는 대신 플랫폼을 업데이트하십시오.
:::

설치 프로그램을 실행하기 전에 작업 디렉터리를 선택합니다. DevKit에서 설치할 때는 루트 파일 시스템이 가득 차지 않도록 `/media/nvme` 아래에 설치합니다. SDK 컨테이너 내에서는 `$HOME/neat`와 같이 컨테이너 내의 경로를 사용합니다.

원하는 환경을 선택한 다음 단계를 순서대로 실행합니다. C++ 애플리케이션을 크로스 컴파일하기 위해 **Neat SDK** 컨테이너에 설치합니다. ARM64에서 네이티브 컴파일을 수행하려면 **ROS2 SDK**에 설치합니다. Debian 패키지는 Neat 크로스 컴파일 sysroot 대신 `/usr`에 설치됩니다. **DevKit**에 설치하여 해당 환경에 런타임을 설정하고, PyNeat도 `~/pyneat`에 프로비저닝합니다. 설치 명령은 모든 환경에서 동일합니다.

<CodeTabs>
<CodeTab label="Neat SDK" lang="bash">

`$HOME/neat`와 같이 컨테이너 내에 설치할 디렉터리를 준비합니다.

<ShellCommand prompt="sdk">
cd $HOME && mkdir -p neat && cd neat
</ShellCommand>

`sima-cli`에서 선택한 기본 Neat Library 패키지를 설치합니다. 필요에 따라 미리 만들어진 튜토리얼, 소스 코드 튜토리얼, 테스트 등 추가 기능을 설치할 수 있습니다.

<ShellCommand prompt="sdk">
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>

<CodeTab label="ROS2 SDK" lang="bash">

컨테이너가 자체적으로 네이티브 ROS2 SDK로 식별되고, Neat 패키지에서 예상하는 플랫폼 호환성 정보를 보고하는지 확인합니다.

<ShellCommand prompt="sdk">
grep -E '^(SDK Type|Platform Base|Platform Version) =' /etc/sdk-release
</ShellCommand>

호환되는 Neat 패키지를 설치합니다. 설치 프로그램은 기본 ARM64 Debian 환경을 확인하고, 패키지 제거를 비활성화한 상태에서 APT 트랜잭션을 시뮬레이션하며, 런타임 및 개발 패키지를 컨테이너의 시스템 경로에 설치합니다. PyNeat은 여전히 DevKit 런타임 기능으로 남아 있으므로 설치되지 않습니다.

<ShellCommand prompt="sdk">
cd $HOME &amp;&amp; mkdir -p neat &amp;&amp; cd neat
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>

<CodeTab label="DevKit" lang="bash">

:::note 먼저 DevKit 펌웨어를 업데이트하십시오.
DevKit에 Neat Library를 설치하기 전에 DevKit 소프트웨어 버전이 Neat Library와 호환되는지 확인하십시오. 자세한 내용은 [호환성 안내](/getting-started/compatibility/)를 참조하십시오.
:::

루트 파일 시스템이 가득 차지 않도록 `/media/nvme` 아래에 설치 디렉터리를 준비하십시오.

<ShellCommand prompt="devkit">
cd /media/nvme && mkdir -p neat && cd neat
</ShellCommand>

`sima-cli`에서 선택한 기본 Neat Library 패키지를 설치합니다. 필요에 따라 미리 만들어진 튜토리얼, 소스 코드 튜토리얼, 테스트 등 추가 기능을 설치할 수 있습니다.

<ShellCommand prompt="devkit">
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>
</CodeTabs>

## 온라인 설치의 기본 PyNeat 환경

Neat Library를 DevKit에 설치하면 `~/pyneat`의 DevKit에 기본 PyNeat 가상 환경이 설정됩니다. 이는 지원되는 PyNeat 환경이며, 직접 활성화할 수 있습니다.

<ShellCommand prompt="devkit">
source ~/pyneat/bin/activate
</ShellCommand>

DevKit Sync와 함께 구성된 SDK 컨테이너 내에서 설치 프로그램을 실행하면, 설치 프로그램이 SDK 컨테이너 내뿐만 아니라 연결된 DevKit에 PyNeat을 설치합니다. PyNeat은 DevKit의 `~/pyneat` 아래에 있는 가상 환경에 설치됩니다.

사용자 지정 Python 가상 환경에 대해서는 다음을 참조하십시오.
[PyNeat을 설치하세요.](/getting-started/neat-library/pyneat/).

## 소스 빌드

미리 배포되지 않은 변경 사항을 적용하거나, 사용자 지정 빌드 구성을 하거나, Neat Library에 기여해야 할 때에는 소스 코드를 직접 빌드하세요. 대부분의 사용자는 위에 설명된 패키지 설치 방법을 사용하는 것이 좋습니다.

소스 코드에서 직접 빌드하는 것을 선호한다면, 다음 [구축하다](/develop-apps/contribute/build) 가이드를 따르세요.

SDK 설정 및 DevKit Sync 온보딩에 대한 자세한 내용은 [Neat SDK](/getting-started/dev-environment/)를 참조하십시오.

## 오프라인 설치 {#offline-installation}

:::caution 설치 전에 Python 의존성 확인
오프라인 설치는 기존 Python 환경과 추가 패키지 및 파일을 보존합니다. 패키지를 설치하기 전에 `pip check`를 실행합니다. 환경이 이미 손상된 경우 설치를 중단하고 환경 경로와 의존성 오류를 표시합니다. 보고된 의존성을 복구한 후 다시 시도하세요. 오프라인 복구에는 추가 wheel 파일이 필요합니다. 설치 후에도 의존성을 검사하여 남아 있거나 새로 발생한 충돌을 보고합니다. 패키지 변경 사항은 자동으로 롤백되지 않습니다.

환경을 삭제하고 새로 설치하려는 경우에만 `./install.sh --recreate-venv`(독립형 Core) 또는 `sudo python3 -B install.py --recreate-venv`(PCIe)를 명시적으로 실행하세요. 선택한 환경의 패키지와 파일은 백업 없이 삭제됩니다. SDK에서는 이 옵션이 SDK 호스트 Python이 아닌 페어링된 DevKit에 적용됩니다. 필요한 파일을 먼저 저장하세요. 사전 검사 및 검증 전용 명령은 환경을 다시 만들지 않습니다.
:::

Neat Library 오프라인 패키지는 0.6.0 이상 버전에서 사용할 수 있습니다.
Platform 3.0 이상을 사용하는 Modalix DevKit에 이 패키지를 사용하세요.

### 1. 패키지 다운로드

인터넷에 연결된 컴퓨터에 `sima-cli`를 설치하세요. [sima-cli 설치 가이드](/tools/sima-cli/)를 참조하세요.

인터넷에 연결된 컴퓨터에서 다음 명령을 실행하세요:

<ShellCommand prompt="host">
sima-cli neat install core/offline@v%%release.core%% --download-only
</ShellCommand>

기본 패키지에는 런타임, 튜토리얼 및 테스트가 포함됩니다.
런타임만 다운로드하려면 다음을 사용하세요:

<ShellCommand prompt="host">
sima-cli neat install core/offline@v%%release.core%% -t minimal --download-only
</ShellCommand>

### 2. 패키지 설치

1. 다운로드한 파일을 Modalix DevKit 또는 Neat SDK 작업 공간에 복사하세요.
2. 해당 디렉터리에서 터미널을 여세요. SDK에 설치하려면 SDK 셸을 사용하세요.
3. 설치 프로그램 아카이브의 압축을 푸세요:

<ShellCommand prompt="sdk|devkit">
tar -xzf neat-core-offline-installer.tar.gz
</ShellCommand>

4. 압축을 푼 디렉터리로 이동하세요:

<ShellCommand prompt="sdk|devkit">
cd neat-core-offline
</ShellCommand>

5. 일반 사용자로 설치 프로그램을 시작하세요. 필요한 경우 `sudo` 권한을 요청합니다.

<ShellCommand prompt="sdk|devkit">
./install.sh
</ShellCommand>

튜토리얼이나 테스트가 필요하면 별도의 추가 아카이브를 원하는 디렉터리에 압축 해제하세요.

오프라인 설치 후 다음 명령으로 Python 환경을 활성화하세요:

<ShellCommand prompt="devkit">
source ~/pyneat/bin/activate
</ShellCommand>

오프라인 설치는 호스트의 기존 `~/pyneatpcie` 또는 카드나 DevKit의 기존 `~/pyneat`를 재사용하며, 심볼릭 링크인 경우 링크 대상을 재사용합니다. 홈 환경이 없으면 설치 사용자가 NVMe에 쓸 수 있는 경우 `/media/nvme/pyneat`를 사용하고, 그렇지 않으면 `~/pyneat`를 사용합니다. 새 NVMe 설치는 기존 홈 환경을 교체하지 않고 `~/pyneat` 링크를 만듭니다.

### 패키지 옵션 및 설치 프로그램 동작

- 설치 프로그램은 설치 전에 시스템 호환성과 사용 가능한 디스크 공간을 확인합니다.
- 설치 프로그램은 포함된 종속성을 사용합니다. 필요한 종속성이 없으면 중지합니다.
- SDK에서는 Neat Library를 `/opt/toolchain/aarch64/modalix`에 복사합니다.
- `DEVKIT_SYNC_DEVKIT_IP`가 설정되어 있으면 SSH를 통해 페어링된 DevKit에도 설치합니다. 두 환경 모두 검사를 통과해야 합니다.

설치가 실패하면 표시된 경로의 로그를 읽으세요: `/tmp/neat-core-offline-*.log`.
자세한 출력을 보려면 `./install.sh --verbose`를 사용하세요.

설치 중 SSH 연결이 끊어져도 원격 설치 프로그램은 계속 실행될 수 있습니다.
다시 시도하거나 보고서에 표시된 임시 디렉터리를 삭제하기 전에 설치 프로그램이 중지되었는지 확인하세요.
