# Запуск / інференс

Якщо ви вперше використовуєте SiMa.ai Neat, найкоротший шлях до прогнозу — два рядки коду: завантажте модель, а потім запустіть її.

1. Завантажте скомпільований архів моделі (`.tar.gz`) за допомогою [`Model`](/reference/{lsa}/classes/simaai-neat-model).
2. Викличте `model.run(inputs, timeout_ms)`, щоб синхронно виконати інференс і отримати вихідні тензори.

Ось повний процес для однієї моделі. Використовуйте [`Graph`](/reference/{lsa}/classes/simaai-neat-graph), коли однієї моделі недостатньо: об’єднуйте етапи, відокремлюйте виробників і споживачів за допомогою асинхронних операцій `push` / `pull` або керуйте чергами.

## Які припущення лежать в основі наведених прикладів?

Використовуйте фрагменти коду на цій сторінці як заготовки, а не як цілісний застосунок. Робочому застосунку також потрібні:

- скомпільований артефакт моделі, створений за допомогою Model Compiler, скопійований на пристрій, на якому працює Neat;
- Python: `import pyneat`;
- C++: `#include "neat.h"`;
- Збірки C++: `find_package(SimaNeat REQUIRED CONFIG)` та `SimaNeat::sima_neat`;
- зображення або тензор, який відповідає специфікаціям моделі.

Замініть приклади шляхів, наприклад `resnet_50_model.tar.gz`, на шлях до вашого артефакту моделі. Специфікації — це контракт; перевірте їх, перш ніж виділяти пам’ять під реальні вхідні дані.

## Оберіть шлях виконання

Використовуйте найменший API, якого достатньо для задачі. Без зайвих церемоній.

| Якщо вам потрібно... | Використовуйте | Чому |
| --- | --- | --- |
| Запустити одну скомпільовану модель один раз | `Model.run(...)` | Найшвидший димовий тест (smoke test) артефакту, вхідного та вихідного контракту. |
| Скомпонувати модель із вузлами застосунку | `Graph` | Іменує межу й робить топологію видимою. |
| Виконати для графа один запит/відповідь | `Graph.run(...)` | Одноразове виконання графа без керування тривалим процесом. |
| Тримати граф активним для багатьох входів | `graph.build(...)` → `Run` | Повторно використовує середовище виконання й надає push/pull, закриття, спорожнення та вимірювання. |
| Налаштувати кілька потоків або максимальну пропускну здатність | `RunOptions`, `try_push(...)`, `MeasureReport` | Політика черги та лічильники показують, що саме відбувалося під час навантаження. |

Про налаштування, архіви моделей і контекст команд див. контрольний список підготовки в розділі [Навчальні матеріали](/tutorials).

## Запустіть модель безпосередньо

Завантажте модель і викличте `run(...)`. Вона виконується синхронно. Відсутній `Graph`, відсутній `Run`, відсутній цикл середовища виконання.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
simaai::neat::Model model("resnet_50_model.tar.gz");

cv::Mat frame = /* your OpenCV BGR frame */;
simaai::neat::Tensor input = simaai::neat::Tensor::from_cv_mat(
    frame,
    simaai::neat::ImageSpec::PixelFormat::BGR,
    simaai::neat::TensorMemory::CPU);

simaai::neat::TensorList outputs = model.run(
    simaai::neat::TensorList{input},
    /*timeout_ms=*/1000);

// outputs[0] holds the first result; read its bytes with outputs[0].map_read().
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
model = pyneat.Model("resnet_50_model.tar.gz")

tensor = pyneat.Tensor.from_numpy(
    frame,
    copy=True,
    image_format=pyneat.PixelFormat.BGR,
)
outputs = model.run([tensor], timeout_ms=1000)

# outputs[0] holds the first result.
```

</CodeTab>
</CodeTabs>

У Python передайте список або кортеж вхідних даних. `model.run([tensor])` означає «один вхідний тензор для моделі», а не «додати розмірність пакета».

Повну робочу версію див. у навчальному матеріалі [Запустіть свою першу модель](/tutorials/run-your-first-model).

## Створіть граф, коли вам потрібно більше

[`Graph`](/reference/{lsa}/classes/simaai-neat-graph) об’єднує один або кілька етапів моделі разом із вашими власними вузлами в потік, який виконується в [`Run`](/reference/{lsa}/classes/simaai-neat-run). Використовуйте його, коли вам потрібно:

- об’єднувати кілька моделей або етапи попередньої/постобробки;
- розділяти виробників і споживачів за допомогою асинхронних `push` / `pull`; або
- керувати чергами, переповненням і метриками за допомогою [`RunOptions`](/reference/{lsa}/structs/simaai-neat-runoptions).

### Одноразовий запуск графа

Для виконання запитів/отримання відповідей використовуйте `Graph.run(...)`.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
simaai::neat::Model model("resnet_50_model.tar.gz");

simaai::neat::Graph graph("classifier");
graph.add(simaai::neat::nodes::Input("image"));
graph.add(model);
graph.add(simaai::neat::nodes::Output("classes"));

cv::Mat frame = /* your frame (RGB/BGR as configured) */;
auto out = graph.run(std::vector<cv::Mat>{frame});
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
model = pyneat.Model("resnet_50_model.tar.gz")

graph = pyneat.Graph("classifier")
graph.add(pyneat.nodes.input("image"))
graph.add(model)
graph.add(pyneat.nodes.output("classes"))

tensor = pyneat.Tensor.from_numpy(
    frame,
    copy=True,
    image_format=pyneat.PixelFormat.BGR,
)
out = graph.run([tensor])
```

</CodeTab>
</CodeTabs>

### Збірка багаторазового Run

Використовуйте повторно використовуваний `Run`, коли потрібно відокремити виробників і споживачів, контролювати чергу або виконувати операції вводу-виводу та обчислення паралельно. Використовуйте `push(...)` / `pull(...)` разом із `RunOptions`, щоб налаштувати чергу та поведінку відкидання.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
simaai::neat::Model model("resnet_50_model.tar.gz");

simaai::neat::Graph graph("classifier");
graph.add(simaai::neat::nodes::Input("image"));
graph.add(model);
graph.add(simaai::neat::nodes::Output("classes"));

cv::Mat frame = /* your frame */;

auto run = graph.build();
run.push("image", std::vector<cv::Mat>{frame});
auto out = run.pull("classes", /*timeout_ms=*/1000);
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
model = pyneat.Model("resnet_50_model.tar.gz")

graph = pyneat.Graph("classifier")
graph.add(pyneat.nodes.input("image"))
graph.add(model)
graph.add(pyneat.nodes.output("classes"))

tensor = pyneat.Tensor.from_numpy(
    frame,
    copy=True,
    image_format=pyneat.PixelFormat.BGR,
)

run = graph.build()
run.push("image", [tensor])
out = run.pull("classes", timeout_ms=1000)
```

</CodeTab>
</CodeTabs>

Про життєвий цикл, зворотний тиск, багатопотокову пропускну здатність, вимірювання й експорт запуску читайте далі на сторінці [Запуск графа](/develop-apps/development-workflow/pipeline).

## Що повертають C++ і Python

Інтерфейси API узгоджені, але Python використовує явні списки або кортежі, щоб розрізняти
один вхідний порт від кількох вхідних портів. Одиночний `Tensor` або `Sample` навмисно відхиляється.

| Операція | Повернення в C++ | Повернення в Python | Примітки |
| --- | --- | --- | --- |
| `Model::run(TensorList)` або `Model::run(std::vector<cv::Mat>)` | `TensorList` | `model.run([tensor])` повертає список тензорів. | Використовуйте для звичайного введення тензорів/зображень. |
| `Model::run(Sample)` | `Sample` | `model.run([sample])` повертає `Sample`. | Використовуйте, коли потрібні метадані зразка або набори (bundles). |
| `Graph::run(TensorList)` або `Graph::run(std::vector<cv::Mat>)` | `TensorList` | `graph.run([tensor])` повертає список тензорів. | Одноразовий запит/відповідь для графа. |
| `Graph::run(Sample)` | `Sample` | `graph.run([sample])` повертає `Sample`. | Використовуйте для введення даних графа, що базуються на зразках. |
| `Run::run(TensorList)` або `Run::run(std::vector<cv::Mat>)` | `TensorList` | `run.run([tensor])` повертає список тензорів. | Можливість повторного використання запитів/відповідей під час активної сесії `Run`. |
| `Run::run(Sample)` | `Sample` | `run.run([sample])` повертає `Sample`. | Використовуйте для наборів (bundles), ідентифікаторів потоків, ідентифікаторів кадрів або метаданих. |
| `Run::pull(...)` | `std::optional<Sample>` | `Sample` або `None` | `None` означає, що жоден зразок не було отримано до закінчення встановленого часу або вихідний потік закрито. |
| `Run::pull_tensors(...)` | `TensorList` | Список тензорів. | Використовуйте, коли вам потрібні лише дані у форматі тензора. |
| `Run::pull_samples(...)` | `Sample` | `Sample` | Використовуйте, коли відсутність результату — виняткова ситуація і потрібен строгий вивід у вигляді зразка. |

## Ознайомтеся з основними поняттями

- [Модель](/develop-apps/development-workflow/model): завантаження архіву моделі та фрагментів графа, керованих моделлю.
- [Граф](/develop-apps/development-workflow/graph): збірка, перевірка та точка входу для запуску/створення.
- [Запуск графа](/develop-apps/development-workflow/pipeline): параметри середовища виконання, цикли типу «push/pull», багатопотокова пропускна здатність і вимірювання.
- [Вузол](/develop-apps/development-workflow/node): атомарні етапи, попередньо створені групи та граничні вузли графа.
- [Тензор і зразок](/develop-apps/development-workflow/core_types): корисне навантаження та обгортка метаданих.
