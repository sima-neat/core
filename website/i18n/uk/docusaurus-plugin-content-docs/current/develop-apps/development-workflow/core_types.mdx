# Тензор і зразок

Байти не несуть жодного змісту. Метадані несуть зміст.

Neat переміщує дані в середовищі виконання, використовуючи два публічні типи:

- [`Tensor`](/reference/{lsa}/structs/simaai-neat-tensor): числові корисні дані з формою, типом даних, розташуванням даних (layout), місцем зберігання та необов’язковими семантичними метаданими.
- [`Sample`](/reference/{lsa}/structs/simaai-neat-sample): оболонка, що містить один або декілька тензорів, а також дані про потік, кадр, мітку часу, корисні дані та маршрут.

Використовуйте `Tensor`, коли вам потрібні лише вхідні або вихідні дані моделі. Використовуйте `Sample`, коли граф має зберігати ідентичність потоку, мітки часу, caps закодованих медіаданих або структуру з кількома виходами.

## Вибір TensorList або Sample

| Завдання | Форма вхідних даних у C++ | Форма вхідних даних у Python | Повертає |
| --- | --- | --- | --- |
| Запуск моделі з тензорами | `model.run(TensorList{tensor})` | `model.run([tensor])` | `TensorList` / колекція тензорів, подібна до списку Python |
| Запуск моделі з метаданими | `model.run(sample)` | `model.run([sample])` | `Sample` |
| Надсилання тензорів у `Run` | `run.push(TensorList{tensor})` | `run.push([tensor])` | `bool` |
| Надсилання зразків у `Run` | `run.push(sample)` | `run.push([sample])` | `bool` |
| Отримання лише тензорного виходу | `run.pull_tensors(...)` | `run.pull_tensors(...)` | `TensorList` / колекція тензорів, подібна до списку Python |
| Отримання виходу зі збереженням метаданих | `run.pull(...)` або `run.pull_samples(...)` | `run.pull(...)` або `run.pull_samples(...)` | `Sample` |

У Python завжди передавайте вхідні дані моделі або графа у вигляді списку або кортежу. `[tensor]` означає «один вхідний тензор». Це не створює розмірність пакета (batch).

Розмір пакета належить до форми тензора та контракту скомпільованої моделі. Перевірте `model.input_specs()` та `model.compiled_batch_size()` перед тим, як обробляти список вхідних даних як пакет.

## Створення тензорів у Python

Використовуйте конструктор, що відповідає джерелу ваших даних.

| Дані джерела | Використовуйте |
| --- | --- |
| Масив NumPy | `pyneat.Tensor.from_numpy(array, copy=True, layout=..., image_format=...)` |
| Тензор Torch | `pyneat.Tensor.from_torch(tensor, copy=True, layout=..., image_format=...)` |
| Об’єкт, сумісний із DLPack | `pyneat.Tensor.from_dlpack(obj, copy=True, layout=...)` |
| Список Python | `pyneat.Tensor.from_list(data, shape=..., dtype=...)` |
| Байти закодованих медіаданих | `pyneat.Sample.from_encoded(data, caps_string, port_name=...)` |

Використовуйте `copy=True`, коли буфер джерела може бути звільнено до того, як Neat завершить його читання. Використовуйте `copy=False` лише тоді, коли час життя буфера контролює ваш застосунок. Жодних буферів невідомого походження.

<CodeTabs>
<CodeTab label="NumPy" lang="python">

```python
import numpy as np
import pyneat

frame = np.zeros((480, 640, 3), dtype=np.uint8)

tensor = pyneat.Tensor.from_numpy(
    frame,
    copy=True,
    image_format=pyneat.PixelFormat.BGR,
)

outputs = model.run([tensor], timeout_ms=2000)
```

</CodeTab>
<CodeTab label="PyTorch" lang="python">

```python
import torch
import pyneat

torch_tensor = torch.zeros((480, 640, 3), dtype=torch.uint8)

tensor = pyneat.Tensor.from_torch(
    torch_tensor,
    copy=True,
    image_format=pyneat.PixelFormat.RGB,
)

outputs = model.run([tensor], timeout_ms=2000)
```

</CodeTab>
</CodeTabs>

Перетворюйте вихідні дані, коли вашому застосунку потрібні дані в нативному форматі фреймворку:

```python
array = outputs[0].to_numpy(copy=True)
torch_tensor = outputs[0].to_torch(copy=True)
```

Для тензора BF16 метод `to_numpy()` повертає незалежний масив `float32`, навіть за умови `copy=False`.

У коді для першого запуску здебільшого не варто вручну вибирати розміщення в пам’яті. Якщо це потрібно, Python надає `TensorMemory.Auto`, `CPU`, `A65`, `EV74` та `MLA` через аргумент `memory=`.

Використовуйте `byte_format=` лише для тензорних корисних даних у байтовому форматі. Не поєднуйте `byte_format=` з `image_format=`.

### Створення закодованих зразків у Python

Використовуйте `Sample.from_encoded(...)`, коли вхід графа очікує закодовані медіадані, наприклад H.264 або H.265, а байти належать застосунку.

```python
sample = pyneat.Sample.from_encoded(
    data,
    caps_string="video/x-h264,stream-format=byte-stream,alignment=au",
    pts_ns=pts_ns,
    duration_ns=duration_ns,
    port_name="video",
)

run.push("video", [sample])
```

`caps_string` повідомляє графу, яке значення мають ці байти. `port_name` пов’язує зразок із назвою входу графа. Якщо у вас є декодовані пікселі, не використовуйте цей шлях; натомість створіть тензор зображення або зразок зображення.

Для розібраного блоку доступу H.265 використовуйте `video/x-h265,parsed=true,stream-format=byte-stream,alignment=au`. Для шляху декодера H.265 потрібен профіль HEVC Main, 8 біт, вхід 4:2:0.

## Створення тензорів у C++

Використовуйте `TensorList` для вхідних даних, що складаються лише з тензорів. `TensorList` містить по одному тензору на кожен вхід моделі або графа.

```cpp
simaai::neat::Tensor input = simaai::neat::Tensor::from_cv_mat(
    frame,
    simaai::neat::ImageSpec::PixelFormat::BGR,
    simaai::neat::TensorMemory::CPU);

simaai::neat::TensorList outputs = model.run(
    simaai::neat::TensorList{input},
    /*timeout_ms=*/2000);
```

Для моделей із кількома входами передавайте по одному тензору на кожен вхід у тому самому порядку, що й у `model.input_specs()`, якщо тільки граф не надає іменованих входів.

### Використання зображень OpenCV у C++

Зображення OpenCV зазвичай мають порядок каналів BGR. Явно вкажіть це в коді.

Для прямих запусків `Model` явний спосіб — перетворити `cv::Mat` на `Tensor` і передати `TensorList`:

```cpp
cv::Mat image = cv::imread("image.jpg");

auto input = simaai::neat::Tensor::from_cv_mat(
    image,
    simaai::neat::ImageSpec::PixelFormat::BGR,
    simaai::neat::TensorMemory::CPU);

auto outputs = model.run(
    simaai::neat::TensorList{input},
    /*timeout_ms=*/2000);
```

Коли Neat збирається з підтримкою OpenCV, `Model`, `Graph` і `Run` також надають зручні перевантаження для `std::vector<cv::Mat>`. Передавайте по одному `cv::Mat` на кожен вхід:

```cpp
auto model_outputs = model.run(std::vector<cv::Mat>{image});
auto graph_outputs = graph.run(std::vector<cv::Mat>{image});

auto run = graph.build();
run.push("image", std::vector<cv::Mat>{image});
```

Віддавайте перевагу `Tensor::from_cv_mat(...)`, коли приклад має явно задавати формат пікселів, тип пам’яті або час життя. Використовуйте зручне перевантаження для OpenCV, коли параметри графа/моделі вже описують контракт вхідних даних.

## Читання тензорних контрактів

Перевірте специфікації, перш ніж виділяти пам’ять під вхідні дані або декодувати вихідні.

```python
for spec in model.input_specs():
    print(spec.shape, spec.dtype, spec.layout)

for spec in model.output_specs():
    print(spec.shape, spec.dtype, spec.layout)
```

Тензорний контракт може містити:

- форму та розмір у байтах;
- `TensorDType`, наприклад корисні дані з цілими числами, числами з рухомою комою або у форматі BF16;
- `TensorLayout`, наприклад HWC або специфічне для моделі розташування даних тензора;
- формат пікселів зображення через семантичні метадані зображення;
- семантичні метадані квантування, теселяції, виявлення, тексту, аудіо, потоку байтів, закодованих даних або попередньої обробки.

Не припускайте, що кожна публічна межа має тип FP32. Ознайомтеся зі специфікацією.

## Декодування вихідних даних моделі

Почніть із необроблених тензорів. Розкодовуйте лише тоді, коли вихідний контракт вказує на те, що корисні дані мають формат виявлення, пози або сегментації.

| Вихідний контракт | Використовуйте | Результат |
| --- | --- | --- |
| Необроблений тензор | Використовуйте отриманий тензор безпосередньо або перетворіть його за допомогою `to_numpy(...)` / `to_torch(...)` | Дані тензора з типом даних і формою виходу моделі |
| Запаковані рамки (boxes) у вигляді тензорів | `pyneat.decode_bbox(outputs, clamp_to=(width, height), top_k=..., strict=...)` | Один тензор float32 `[N, 6]` на кожен вхід: `x1`, `y1`, `x2`, `y2`, `score`, `class_id` |
| Один тензор запакованих рамок як типізовані записи | `pyneat.detections.decode_bbox_tensor(tensor, width, height, expected_topk=..., strict=...)` | `BoxDecodeResult` із записами `boxes` і збереженими сирими байтами |
| Запакована поза | `pyneat.decode_pose(outputs, clamp_to=(width, height), top_k=..., strict=...)` | Рамки та ключові точки |
| Запакована сегментація | `pyneat.decode_segmentation(outputs, clamp_to=(width, height), top_k=..., strict=...)` | Рамки та маски |

```python
outputs = model.run([tensor], timeout_ms=2000)
boxes = pyneat.decode_bbox(outputs, clamp_to=(image_width, image_height), strict=True)
box_array = boxes[0].to_numpy(copy=True)
```

Використовуйте допоміжні функції декодування лише для тих форматів вихідних даних, які вони підтримують.

## Використання зразка для метаданих {#use-sample-for-metadata}

Використовуйте `Sample`, коли корисні дані потребують ідентифікації або синхронізації.

Загальні конструктори та допоміжні функції:

| Потрібно | C++ | Python |
| --- | --- | --- |
| Обгорнути тензор із назвою порту | `make_tensor_sample("image", tensor)` | `pyneat.make_tensor_sample("image", tensor)` |
| Обгорнути зображення OpenCV | `make_image_sample(image, PixelFormat::BGR, TensorMemory::CPU)` | Створити `Tensor` за допомогою `Tensor.from_numpy(...)`, а потім викликати `make_tensor_sample(...)` |
| Обгорнути байти закодованих медіаданих | `make_encoded_sample(bytes, caps_string, pts_ns, dts_ns, duration_ns)` | `pyneat.make_encoded_sample(...)` або `pyneat.Sample.from_encoded(data, caps_string, port_name=...)` |
| Обгорнути текст | `Tensor::from_text(...)` плюс `make_tensor_sample(...)` | `pyneat.make_text_sample("text", text)` |
| Обгорнути кілька логічних полів | `make_bundle_sample({field0, field1})` | Створити `pyneat.Sample()` і викликати `append(...)` |

Загальні поля:

| Поле | Використовуйте |
| --- | --- |
| `kind` | Вказує, чи є корисні дані `Tensor`, `TensorSet`, `Bundle` або `Unknown`. |
| `tensor` | Корисні дані з одного тензора, коли `kind == Tensor`. |
| `tensors` | Кілька тензорів на одному логічному виході, коли `kind == TensorSet`. |
| `fields` | Вкладені зразки, коли `kind == Bundle`. |
| `stream_id` | Стабільна ідентифікація потоків для графів із багатьма потоками. |
| `frame_id` | Ідентифікатор кадру джерела для об’єднання, візуалізації та обчислення показників. |
| `pts_ns`, `dts_ns`, `duration_ns` | Метадані, що стосуються часу. |
| `port_name` | Ідентифікатор вхідного або вихідного порту. |
| `payload_type`, `media_type`, `payload_tag`, `caps_string` | Сімейство корисних даних та метадані медіа/caps. |
| `logical_output_index` | Логічна ідентифікація вихідних даних для моделей із кількома виходами. |

У Python `Sample` є ітерабельним. Зразок, що не є набором, поводиться як один логічний елемент, а набір ітерується за своїми `fields`.

### Вибір `TensorSet` або `Bundle`

`TensorSet` і `Bundle` містять кілька елементів корисних даних, але вони означають різні речі:

| Форма | Використовуйте його для | Зчитати з |
| --- | --- | --- |
| `TensorSet` | Кілька тензорів, які разом утворюють один логічний вхід або вихід, наприклад, набір обмежувальних рамок і масок на одному вихідному порту. | `sample.tensors` |
| `Bundle` | Кілька логічних полів, які використовуються разом, наприклад, поле для зображення та поле для метаданих. | `sample.fields`, ітерація або `sample[index]` |

Використовуйте `TensorSet`, коли подальший код має обробляти тензори як один результат. Використовуйте `Bundle`, коли подальший код має обробляти або перевіряти поля окремо. Якщо ви переплутаєте їх, дані все ще можуть передаватися, але сенс буде втрачено.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
auto image = simaai::neat::make_tensor_sample("image", image_tensor);
auto metadata = simaai::neat::make_tensor_sample(
    "metadata",
    simaai::neat::Tensor::from_text(metadata_json));

auto bundle = simaai::neat::make_bundle_sample({image, metadata});
bundle.stream_id = "camera-0";
bundle.frame_id = frame_number;

run.push("request", bundle);
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
image = pyneat.make_tensor_sample("image", image_tensor)
metadata = pyneat.make_text_sample("metadata", metadata_json)

bundle = pyneat.Sample()
bundle.append(image)
bundle.append(metadata)
bundle.stream_id = "camera-0"
bundle.frame_id = frame_number

run.push("request", [bundle])
```

</CodeTab>
</CodeTabs>

Коли ви отримуєте `TensorSet`, переберіть `sample.tensors`. Коли ви отримуєте `Bundle`, переберіть сам зразок або `sample.fields`. Зберігайте правильну форму; ви в майбутньому будете кінцевим споживачем даних.

### Надсилання метаданих потоку, що належать застосунку

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
auto sample = simaai::neat::make_tensor_sample("image", input_tensor);
sample.stream_id = "camera-0";
sample.frame_id = frame_number++;

run.push("image", sample);
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
sample = pyneat.make_tensor_sample("image", tensor)
sample.stream_id = "camera-0"
sample.frame_id = frame_number

run.push("image", [sample])
```

</CodeTab>
</CodeTabs>

Якщо в багатопотоковому графі немає `stream_id`, він не зможе відображати справедливу пропускну здатність для кожного потоку. Присвойте кожному потоку назву, перш ніж налаштовувати його.

### Читання отриманих зразків

```python
sample = run.pull("detections", timeout_ms=2000)

if sample is not None:
    print(sample.kind, sample.stream_id, sample.frame_id)
    if sample.kind == pyneat.SampleKind.TensorSet:
        for tensor in sample.tensors:

```

## Сімейства корисних даних

`PayloadType` повідомляє Neat, який тип даних передається через межу графа.

| Сімейство корисних даних | Використовуйте / перевірте |
| --- | --- |
| `PayloadType.Image` | Декодовані пікселі. Перевірте формат зображення, ширину, висоту та метадані пікселів. |
| `PayloadType.Tensor` | Тензори моделі або застосунку. Перевірте тип даних, форму, розташування даних (layout) та семантичні метадані. |
| `PayloadType.Encoded` | Закодовані медіадані, такі як H.264 або H.265. Перевірте `caps_string`, кодек, мітки часу та тег корисних даних. |
| `PayloadType.Auto` | Нехай Neat за можливості робить висновки на основі метаданих тензора/зразка. |

Текст, аудіо, потік байтів і непрозорі байти передаються як семантика тензорів або за допомогою спеціалізованих специфікацій, а не як окремі значення переліку `PayloadType`.

Для явних меж вхідних даних використовуйте `InputOptions` із `payload_type`, `format`, полями розміру, динамічними обмеженнями, fps, перевизначенням caps, поведінкою реального часу та міток часу та політикою пам’яті. У Python задавайте поля формату через `pyneat.Format` / `pyneat.FormatTag`, а не сирими рядками.

## Довідник розширених типів

Ці типи не потрібні для першого інференсу, але вони корисні під час перевірки контрактів або збору даних для діагностики.

| Тип | Використовуйте його, коли |
| --- | --- |
| `TensorConstraint` / `TensorSpec` | Перед відправкою тензора необхідно перевірити тип даних, ранг, форму, пристрій, формат зображення або обмеження сегментів. |
| `DeviceType` | Вам потрібно перевірити, чи пов’язаний тензор із CPU, APU, CVU, MLA або невідомим пристроєм. |
| `StorageKind` | Вам потрібно з’ясувати, чи є пам’ять, що використовується для зберігання даних, власністю процесора, чи це зовнішня пам’ять процесора, чи це зразок GStreamer, чи дескриптор пристрою. |
| `PlaneRole` | Ви перевіряєте багатошарові медіа, наприклад, площини Y, U, V або UV. |
| `BusMessage` | Ви переглядаєте `GraphReport.bus` після збою в середовищі виконання або під час збірки. |
| `BoundaryFlowStats` | Ви перевіряєте, через які межі графа проходили буфери під час діагностичного запуску. |
| `MeasureOptions` / `MeasureReport` | Ви вимірюєте вікно `Run` і вам потрібні лічильники, затримка, необов’язкові вимірювання часу плагінів або споживаної потужності. |

Використовуйте їх як джерело фактів. Не перетворюйте їх на параметри налаштування, якщо завдання справді цього не потребує.
