# Процес розробки

Ця сторінка — загальна карта того, як SiMa.ai Neat використовують у щоденній роботі. З кожного кроку можна перейти на детальнішу сторінку, коли будете готові.

## Цикл

Типовий цикл розробки Neat виглядає так:

1. **Встановлення** — отримайте пакет `sima-neat` і, за бажанням, прив’язки Python `pyneat` на хості або пристрої.
2. **Спробуйте Hello Neat** — переконайтеся, що бібліотека правильно підключена, скомпілювавши мінімальний приклад.
3. **Оберіть скомпільовану модель** — Neat використовує скомпільований архів моделі (`.tar.gz`, який часто називають MPK). Використовуйте один із Model Zoo або скомпілюйте власний за допомогою Model Compiler.
4. **Створіть `Model` / `Graph` / `Run`** — завантажте модель, створіть граф і виконайте його, використовуючи найкоротший шлях у середовищі виконання, який відповідає вимогам завдання.
5. **Запустіть і перевірте** — надайте вхідні дані, отримайте вихідні дані та використовуйте `GraphReport` / `MeasureReport` для перевірки поведінки.
6. **Розвивайте застосунок за навчальними матеріалами** — переходьте від одного інференсу до конвеєрів, моделей із кількома входами, графів із кількома потоками та обробки помилок продакшн-рівня.
7. **Розгорніть** — скомпонуйте (злінкуйте) свій застосунок зі встановленою бібліотекою Neat на цільовому пристрої.

## Вибір між Model, Graph і Run

Почніть із найменшого API, якого достатньо для задачі. Перейти на вищий рівень можна будь-коли, щойно в застосунку з’явиться більше рухомих частин.

| Якщо вам потрібно... | Почніть з | Чому | Наступна зупинка |
| --- | --- | --- | --- |
| Запустити одну скомпільовану модель один раз | `Model.run(...)` | Найкоротший шлях від артефакту до вихідних тензорів. | [Запуск першої моделі](/tutorials/run-your-first-model) |
| Запустити модель на підключеній карті Modalix PCIe | `pcie::Model` / `pyneatpcie.Model` | Співобробка на боці хоста без збирання нативного застосунку для карти. | [Співобробка через PCIe](/develop-apps/development-workflow/pcie-model) |
| Перевірити контракт або маршрут моделі | `Model` | Специфікації, метадані та відомості про маршрут показують, що модель приймає і що видає. | [Модель](/develop-apps/development-workflow/model) |
| Додати модель до схеми застосунку | `Graph` | Надає імена входам і виходам, об’єднує вузли та забезпечує чітке визначення топології. | [Граф](/develop-apps/development-workflow/graph) |
| Повторно використовувати граф протягом тривалого часу | `graph.build(...)` → `Run` | Дає керування push/pull, закриттям і спорожненням (close/drain), вимірюванням і політикою черги. | [Запуск графа](/develop-apps/development-workflow/pipeline) |
| Надсилати кілька потоків або досягти максимальної пропускної здатності | `RunOptions` + вимірювання | Для налаштування пропускної здатності потрібні політика черги, лічильники відкинутих кадрів і дані по кожному потоку. | [Налаштування пропускної здатності та глибини черги](/tutorials/tune-throughput-and-queues) |

Якщо ви вперше працюєте з Neat на практиці, почніть із контрольного списку підготовки в розділі [Навчальні матеріали](/tutorials), а потім запустіть одну модель, перш ніж додавати механізми графа.

## Основні поняття в стислому викладі

Сторінки, присвячені процесу розробки, детально розглядають кожен із цих етапів. Узагальнена інформація:

- [Модель](/develop-apps/development-workflow/model) — завантажте скомпільований пакет моделі та зробіть його доступним як виконуваний модуль.
- [Співобробка через PCIe](/develop-apps/development-workflow/pcie-model) — запустіть скомпільовану модель на підключеній PCIe-карті Modalix із хост-застосунку.
- [Модель GenAI](/develop-apps/development-workflow/genai-model) — запускайте генеративні моделі безпосередньо або надавайте до них доступ через HTTP.
- [Тензор і зразок](/develop-apps/development-workflow/core_types) — корисні дані й обгортка метаданих, що передаються між етапами.
- [Запуск / інференс](/develop-apps/development-workflow/overview) — виконайте синхронно (`run`) або асинхронно (`push` / `pull`).
- [Граф](/develop-apps/development-workflow/graph) — компонуйте етапи моделі, вузли, входи й виходи в граф застосунку.
- [Запуск графа](/develop-apps/development-workflow/pipeline) — зберіть граф в активний `Run`, а потім надсилайте й отримуйте дані, спорожнюйте його, вимірюйте та налаштовуйте пропускну здатність.
- [Вузол](/develop-apps/development-workflow/node) — це базова складова графа.

Якщо ви хочете спочатку ознайомитися лише з однією сторінкою, почніть з огляду [Запуск / інференс](/develop-apps/development-workflow/overview), оскільки він об’єднує `Model`, `Graph` і `Run` в єдину систему.

Покрокова інструкція для нових користувачів:

- [Palette SDK](/getting-started/dev-environment/) — встановіть Palette SDK, під’єднайте DevKit і запустіть на апаратному забезпеченні з `dk`.
- [Збірка](/develop-apps/contribute/build) — збірка Neat з початкового коду за допомогою `build.sh` (процес для контриб’юторів).
- [Hello Neat!](/develop-apps/hello-neat/minimal) — мінімальний застосунок CMake, скомпонований зі встановленою бібліотекою.
- [Навчальні матеріали](/tutorials) — це серія навчальних матеріалів, що охоплює етапи від створення «першої моделі» до розробки «виробничого конвеєра».

Довідкові матеріали, які знадобляться, коли вам потрібна більш глибока інформація:

- [Довідник з C++](/reference/cppapi) — повний набір API для встановлених заголовків.
- [Довідник з Python](/reference/pythonapi) — довідник із прив’язок `pyneat`.

## Що ви пишете і що пропонує Neat

Neat відповідає за середовище виконання: завантаження моделі, перевірку, побудову конвеєра, планування, завершення роботи та діагностику. Ви відповідаєте за код застосунку, який з’єднує входи з виходами та реагує на результати. Межу визначає публічний API у `include/`, який вважається **стабільним** — ви можете оновити Neat, не переписуючи свій застосунок.

Якщо ви запам’ятали лише три рядки коду з Neat, запам’ятайте ці:

```cpp
simaai::neat::Model      model(mpk_path);
simaai::neat::TensorList outputs = model.run(input_tensors, /*timeout_ms=*/2000);
simaai::neat::Mapping    view = outputs[0].map_read();  // inspect the output bytes
```

Усе інше в цій документації — графи, дескриптори запусків, асинхронні черги та застосунки з кількома потоками даних — це контрольоване розширення цієї базової історії з трьох рядків.
