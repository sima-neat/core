# Співобробка через PCIe

Neat PCIe API для хоста дозволяє застосунку на хост-машині надсилати тензори або зображення на підключену PCIe-карту Modalix та отримувати результати інференсу. Використовуйте його, коли хост-машина відповідає за ввід-вивід і оркестрування застосунку, а карта виконує скомпільовану модель і налаштовані процеси попередньої обробки або постобробки.

Цей API відокремлений від Neat Library, яка працює безпосередньо на DevKit.
Публічні типи знаходяться в просторі імен `simaai::neat::pcie` C++ і в пакеті `pyneatpcie` Python.

Для моделей LLM, VLM та ASR використовуйте [GenAI API через PCIe](/develop-apps/development-workflow/genai-model/pcie-api).

:::note Встановлення на хост-машині
Встановіть `core/pciehost` на хост-машині, а не всередині контейнера Palette SDK і не на PCIe-карті Modalix. Перед використанням цієї сторінки виконайте інструкції зі сторінки [Встановлення хоста PCIe](/getting-started/neat-library/pcie-host/).
:::

## Як працює співобробка

Одна `pcie::Model` представляє одну скомпільовану модель, що працює на одній фізичній черзі PCIe:

1. Конструктор зчитує локальний архів моделі та надає контракт її входів і виходів.
2. `build()` завантажує архів на карту через віртуальну мережу PCIe, запускає конвеєр на стороні карти й чекає, доки він буде готовий.
3. `run()` або `push()` надсилає вхідні корисні дані через PCIe.
4. Карта виконує попередню обробку, інференс та налаштовану постобробку.
5. `run()` або `pull()` повертають тензори результатів на хост.
6. `close()` зупиняє конвеєр на стороні карти та звільняє чергу.

Архів моделі передається під час `build()`. Корисні дані для інференсу та результати передаються через транспорт даних PCIe.

## Налаштування з’єднання

`ConnectionOptions` визначає карту та чергу, які використовуються цією моделлю.

| Поле | За замовчуванням | Призначення |
| --- | --- | --- |
| `card_host` | порожній | Явна адреса SSH/SCP. Якщо поле порожнє, карта `N` використовує `10.0.N.2`. |
| `card_id` | `0` | Номер карти, що передається плагіну PCIe на хості. |
| `user` | `sima` | Користувач для SSH і SCP на стороні карти. |
| `queue` | `0` | Черга співобробки, від `0` до `5`. |
| `max_inflight` | `10` | Максимальна кількість вхідних даних, для яких очікується отримання результатів. |

Для однієї карти за адресою `10.0.0.2` і черги 0 використовуйте значення за замовчуванням. Явно вказуйте `card_host`, коли карта має іншу адресу керування.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
#include <simaai/neat/pcie/Model.h>

namespace pcie = simaai::neat::pcie;

pcie::ConnectionOptions connection;
connection.card_host = "10.0.0.2";
connection.card_id = 0;
connection.queue = 0;
connection.max_inflight = 10;
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
import pyneatpcie as pcie

connection = pcie.ConnectionOptions(
    card_host="10.0.0.2",
    card_id=0,
    queue=0,
    max_inflight=10,
)
```

</CodeTab>
</CodeTabs>

## Перегляд і збирання моделі

Конструктор працює локально й не запускає карту. Перевірте `info()`, перш ніж виділяти пам’ять під вхідні дані, а потім один раз викличте `build()`, щоб розпочати сеанс співобробки.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
pcie::Model model("model.tar.gz", {}, connection);

const pcie::ModelInfo info = model.info();
for (const auto& input : info.inputs) {
  std::cout << input.name << " requires " << input.size_bytes << " bytes\n";
}

model.build(/*readiness_timeout_ms=*/180000);
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
model = pcie.Model("model.tar.gz", connection=connection)

info = model.info()
for input_spec in info.inputs:
    print(input_spec.name, "requires", input_spec.size_bytes, "bytes")

model.build(readiness_timeout_ms=180000)
```

</CodeTab>
</CodeTabs>

`input_specs()` та `output_specs()` повертають ті самі списки окремо.
`running()` стає `true` після успішного збирання моделі й повертається до `false` після `close()`.
Він повідомляє лише про стан життєвого циклу й не перевіряє працездатність транспорту хоста або віддаленого конвеєра.

## Синхронний інференс

Використовуйте `run()` для найпростішого сценарію «запит — відповідь». Спочатку зберіть модель і задавайте скінченний тайм-аут, щоб збої застосунку не призводили до нескінченного очікування.
Наступний приклад створює вхідні дані для моделі, для якої вказано тип даних FP32.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
const auto& input_spec = info.inputs.front();
if (input_spec.dtype != "FP32") {
  throw std::runtime_error("this example requires an FP32 model input");
}

std::vector<float> values(input_spec.size_bytes / sizeof(float), 0.0f);
pcie::Tensor input = pcie::Tensor::from_vector(
    std::move(values), input_spec.shape, input_spec.name);

pcie::TensorList outputs = model.run(input, /*timeout_ms=*/30000);

model.close();
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
import numpy as np

input_spec = info.inputs[0]
if input_spec.dtype != "FP32":
    raise RuntimeError("this example requires an FP32 model input")

array = np.zeros(input_spec.shape, dtype=np.float32)
input_tensor = pcie.Tensor.from_numpy(
    array,
    copy=True,
    route_name=input_spec.name,
)

outputs = model.run([input_tensor], timeout_ms=30000)

model.close()
```

</CodeTab>
</CodeTabs>

Для моделі з кількома вхідними даними передавайте по одному `Tensor` для кожного логічного входу в зазначеному порядку та з використанням назв маршрутів, наданих `info().inputs`.

Тайм-аут `run()` зупиняє очікування, але не скасовує вхідні дані, які вже були прийняті картою. Після виникнення тайм-ауту або використовуйте `pull()`, щоб спорожнити цей незавершений результат, або викличте `close()` перед початком нової послідовності запитів.

## Конвеєрна обробка запитів через push і pull

Використовуйте `push()` і `pull()`, коли підготовка вхідних даних має перекриватися з інференсом.
`max_inflight` обмежує обсяг прийнятих завдань, які ще не завершено. Оперативно отримуйте результати, щоб виробники могли продовжувати роботу.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
std::size_t pushed = 0;
std::size_t pulled = 0;
while (pulled < inputs.size()) {
  while (pushed < inputs.size() && pushed - pulled < 10) {
    model.push(inputs[pushed++]);
  }

  auto outputs = model.pull(/*timeout_ms=*/30000);
  if (!outputs) {
    throw std::runtime_error("PCIe inference timed out");
  }
  consume(*outputs);
  ++pulled;
}
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
max_inflight = 10
pushed = 0
pulled = 0
while pulled < len(inputs):
    while pushed < len(inputs) and pushed - pulled < max_inflight:
        model.push(inputs[pushed])
        pushed += 1

    outputs = model.pull(timeout_ms=30000)
    if outputs is None:
        raise TimeoutError("PCIe inference timed out")
    consume(outputs)
    pulled += 1
```

</CodeTab>
</CodeTabs>

`push()` чекає, коли `max_inflight` заповнено, тому не надсилайте більше даних, ніж
вказано в налаштованому вікні, не отримавши результати. `pull()` повертає наступний доступний
результат для цієї моделі. Спорожніть усі результати, надіслані за допомогою `push()`, перш ніж викликати
`run()`.

## Надсилання зображень і налаштування попередньої обробки

Задайте для `preprocess.kind` значення `Image`, коли надсилаєте декодовані дані зображення. Конвеєр Neat на стороні карти може змінювати розмір, перетворювати колір, нормалізувати та декодувати підтримувані результати виявлення об’єктів.

У цьому прикладі надсилається BGR-зображення, яке масштабується з полями (letterbox) до розміру входу моделі, визначеного з архіву моделі, і повертається тензор із декодованими корисними даними YOLOv8 BBOX.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
#include <opencv2/imgcodecs.hpp>

pcie::ModelOptions options;
options.preprocess.kind = pcie::InputKind::Image;
options.preprocess.color_convert.input_format = pcie::ColorFormat::BGR;
options.preprocess.normalize.enable = pcie::AutoFlag::On;
options.preprocess.resize.enable = pcie::AutoFlag::On;
options.preprocess.resize.mode = pcie::ResizeMode::Letterbox;
options.decode_type = pcie::BoxDecodeType::YoloV8;
options.score_threshold = 0.25f;
options.nms_iou_threshold = 0.45f;
options.top_k = 100;

pcie::Model detector("yolo_v8n_mpk.tar.gz", options, connection);
detector.build();

cv::Mat image = cv::imread("image.jpg", cv::IMREAD_COLOR);
pcie::TensorList detections = detector.run(image, /*timeout_ms=*/30000);
detector.close();
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
import cv2
import pyneatpcie as pcie

options = pcie.ModelOptions()
options.preprocess.kind = pcie.InputKind.Image
options.preprocess.color_convert.input_format = pcie.ColorFormat.BGR
options.preprocess.normalize.enable = pcie.AutoFlag.On
options.preprocess.resize.enable = pcie.AutoFlag.On
options.preprocess.resize.mode = pcie.ResizeMode.Letterbox
options.decode_type = pcie.BoxDecodeType.YoloV8
options.score_threshold = 0.25
options.nms_iou_threshold = 0.45
options.top_k = 100

detector = pcie.Model("yolo_v8n_mpk.tar.gz", options, connection)
detector.build()

image = cv2.imread("image.jpg", cv2.IMREAD_COLOR)
detections = detector.run_image(
    image,
    timeout_ms=30000,
    format=pcie.PixelFormat.BGR,
)
detector.close()
```

</CodeTab>
</CodeTabs>

Не задавайте `input_max_width`, `input_max_height` або `input_max_depth` для seedless-моделі, якщо застосунку не потрібне явне обмеження входу. Neat може визначити цільовий розмір масштабування на боці моделі з архіву моделі.

## Запуск лише MLA

За замовчуванням карта перетворює вхід FP32 на dtype MLA, виконує MLA і перетворює результати назад перед їх поверненням як FP32. `mla_only` переносить цю межу перетворення dtype до застосунку: тоді карта виконує лише MLA, хост надсилає тензори, що відповідають кожному запису `info().inputs`, і отримує власні виходи MLA в їхніх логічних формах.

`info()` описує цей контракт. Тензор INT8 містить `quant` з одним `scale` і одним `zero_point`:

```text
x = (q - zero_point) * scale
q = clamp(round(x / scale) + zero_point, -128, 127)
```

Тензор BF16 не містить `quant`: хост округлює FP32 до BF16 з округленням до найближчого парного під час надсилання та розширює виходи BF16 під час отримання. У Python BF16 передається як бітові шаблони `uint16` через `Tensor.from_bytes(..., pcie.TensorDType.BFloat16, ...)` і `to_numpy()`.

Приклад нижче показує випадок INT8:

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
pcie::ModelOptions options;
options.mla_only = true;
pcie::Model model("model_mlatess_int8.tar.gz", options, connection);

const auto& input_spec = model.info().inputs.front();
const pcie::QuantParams& quant = *input_spec.quant;   // INT8 ingress

std::vector<std::int8_t> codes(input_spec.size_bytes);
for (std::size_t i = 0; i < codes.size(); ++i) {
  const float x = /* value in the model's input domain, e.g. [0, 1] */;
  const float q = std::nearbyint(x / quant.scale) + quant.zero_point;
  codes[i] = static_cast<std::int8_t>(std::clamp(q, -128.0f, 127.0f));
}

model.build();
pcie::TensorList outputs = model.run(
    pcie::Tensor::from_vector(std::move(codes), input_spec.shape, input_spec.name),
    /*timeout_ms=*/30000);

const auto& head = model.info().outputs.front();
const std::int8_t* q = reinterpret_cast<const std::int8_t*>(
    static_cast<const std::uint8_t*>(outputs[0].data) + outputs[0].byte_offset);
const float x0 = (q[0] - head.quant->zero_point) * head.quant->scale;
model.close();
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
options = pcie.ModelOptions()
options.mla_only = True
model = pcie.Model("model_mlatess_int8.tar.gz", options, connection)

input_spec = model.info().inputs[0]
scale, zero_point = input_spec.quant.scale, input_spec.quant.zero_point

values = np.zeros(input_spec.shape, dtype=np.float32)  # in the model's input domain, e.g. [0, 1]
codes = np.clip(np.rint(values / scale) + zero_point, -128, 127).astype(np.int8)

model.build()
outputs = model.run(
    [pcie.Tensor.from_numpy(codes, copy=True, route_name=input_spec.name)],
    timeout_ms=30000,
)

head = model.info().outputs[0]
x = (outputs[0].to_numpy().astype(np.int32) - head.quant.zero_point) * head.quant.scale
model.close()
```

</CodeTab>
</CodeTabs>

Маршрут працює за принципом «усе або нічого». Кожен надісланий тензор має відповідати dtype, формі та розміру в байтах відповідного запису `info().inputs`, у тому самому порядку; корисні дані іншого dtype відхиляються замість перетворення на карті. `mla_only` не можна поєднувати з попередньою обробкою зображень чи декодуванням рамок. Конструктор відхиляє архіви, чий етап MLA не скомпільовано для прямого входу та виходу MLA, наприклад збірку `yolo_v8s` з Model Zoo, що виконує теселяцію на CVU (`mla_only does not support stage '...' (tess)`).

Посібник [Run the MLA Only with INT8 Tensors](/tutorials/run-mla-only-int8) показує випадок INT8: він квантує зображення на хості та звіряє деквантовані виходи з маршрутом за замовчуванням.

## Надійне закриття

Викличте `close()`, коли модель більше не знадобиться і перед повторним використанням її черги.
Можна безпечно викликати цю функцію кілька разів:

```python
model = pcie.Model("model.tar.gz", connection=connection)
model.build()
outputs = model.run([input_tensor], timeout_ms=30000)
model.close()
```

Як альтернатива, використовуйте менеджер контексту, щоб автоматично закрити модель:

```python
with pcie.Model("model.tar.gz", connection=connection) as model:
    model.build()
    outputs = model.run([input_tensor], timeout_ms=30000)
```

Менеджер контексту викликає `close()`, коли блок завершує свою роботу, зокрема, коли виникає виняток. Не додавайте ще один явний виклик `close()` всередині блоку `with`.

## Збирання хост-застосунку на C++

Пакет розробки містить пакет CMake під назвою `SimaPCIeHost`:

```cmake title="CMakeLists.txt"
cmake_minimum_required(VERSION 3.16)
project(pcie_model LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(SimaPCIeHost REQUIRED CONFIG)

add_executable(pcie_model main.cpp)
target_link_libraries(pcie_model PRIVATE SimaPCIeHost::sima_neat_pcie_host)
```

Збирайте цей застосунок нативно на хост-машині.

Приклад на C++ для зображень також використовує OpenCV. Додайте його заголовні файли та бібліотеки до цілі цього застосунку:

```cmake
find_package(OpenCV REQUIRED COMPONENTS core imgcodecs)
target_include_directories(pcie_model PRIVATE ${OpenCV_INCLUDE_DIRS})
target_link_libraries(pcie_model PRIVATE ${OpenCV_LIBS})
```

## Поточні можливості та обмеження

- Одна `pcie::Model` володіє однією чергою даних PCIe. Діапазон черг становить від `0` до `5`.
- Одночасні конвеєри спільно використовують обчислювальні ресурси та пам’ять карти; наявність вільної черги не гарантує достатніх ресурсів.
- Не призначайте дві активні моделі для обробки в одній черзі.
- Пакет хоста та Neat Library, встановлена на карті, мають бути із сумісних випусків.
- Після перших надісланих корисних даних не змінюйте тип медіа та геометрію вхідних даних. Пізніші корисні дані, більші за поточний максимальний розмір транспорту, відхиляються.
- API хоста PCIe підтримує обмежену підмножину параметрів попередньої обробки моделей Neat і декодування об’єктів.
- `mla_only` вимагає архіву, скомпільованого для прямого входу та виходу MLA; кожен вхід надсилається в dtype свого запису `info().inputs`, а виходи повертаються неперервними в dtype MLA.
- Цей API співобробки не надає на стороні хоста композиції `Graph`, `Node` чи `Run`. Для нативних графів застосунків використовуйте звичайну Neat Library на DevKit.

Для перевірки встановлення та підключення поверніться до сторінки [Встановлення хоста PCIe](/getting-started/neat-library/pcie-host/).
