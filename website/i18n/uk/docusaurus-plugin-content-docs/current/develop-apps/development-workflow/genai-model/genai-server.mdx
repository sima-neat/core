# Сервер GenAI

Використовуйте `GenAIServer`, коли браузер, інтерфейс користувача, сервіс або віддалений клієнт мають викликати одну або кілька моделей GenAI через HTTP. Сервер відповідає за реєстрацію моделей, маршрутизацію запитів, потокову передачу відповідей і скасування. Для логіки застосунку, що виконується в тому самому процесі, що й модель, використовуйте [прямі GenAI API](/develop-apps/development-workflow/genai-model/direct-api).

## Створення та запуск сервера

За замовчуванням сервер прив’язується до `0.0.0.0:9998`. Зареєструйте кожну теку розгорнутої моделі LLiMa під стабільною назвою, за якою сервер її обслуговуватиме, перш ніж запускати сервер:

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
#include <neat/genai.h>

int main() {
  simaai::neat::genai::GenAIServer server;
  server.add_model(
      "/media/nvme/llima/models/Qwen3-4B-Instruct-2507-GPTQ-a16w4",
      "llm");
  server.add_model(
      "/media/nvme/llima/models/Qwen3-VL-4B-Instruct-GPTQ-a16w4",
      "vlm");
  server.serve();
}
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
import pyneat as neat

server = neat.genai.GenAIServer()
server.add_model(
    "/media/nvme/llima/models/Qwen3-4B-Instruct-2507-GPTQ-a16w4",
    "llm",
)
server.add_model(
    "/media/nvme/llima/models/Qwen3-VL-4B-Instruct-GPTQ-a16w4",
    "vlm",
)
server.start()
try:
    input("Press Enter to stop the server\n")
finally:
    server.stop()
```

</CodeTab>
</CodeTabs>

У C++ використовуйте `serve()` для блокувального сервера на передньому плані. Використовуйте `start()` і `stop()`, коли часом життя сервера керує ваш застосунок на C++ або Python. Налаштуйте `GenAIServerOptions`, якщо хост або порт за замовчуванням не підходять. Перед початком прослуховування сервер виконує тихий розігрівальний інференс для кожної зареєстрованої моделі, щоб перший клієнтський запит не витрачав повний час ініціалізації. Розігрів не виводить згенерований текст або статистику продуктивності. Виклик `stop()` також видаляє всі зареєстровані моделі; додайте моделі знову перед повторним запуском того самого об’єкта сервера. `start()` чекає, доки сервер почне прослуховування. Якщо налаштований порт зайнятий, він викидає виняток і зберігає зареєстровані моделі. Повторіть спробу, коли порт звільниться, або створіть новий сервер, щоб використати інший порт.

`GenAIServer` не забезпечує автентифікацію або завершення TLS і дозволяє запити CORS з будь-якого джерела. Прив’язуйте його лише до надійного інтерфейсу або розміщуйте за мережевим рівнем, який забезпечує необхідний контроль доступу та шифрування.

## Перегляд обслуговуваних моделей

Перелічіть назви зареєстрованих моделей перед надсиланням запиту на генерацію:

```bash
curl http://<modalix-ip>:9998/v1/models
```

У відповіді використовується формат списку моделей OpenAI:

```json
{
  "object": "list",
  "data": [
    {"id": "llm", "object": "model", "owned_by": "simaai"},
    {"id": "vlm", "object": "model", "owned_by": "simaai"}
  ]
}
```

Кожен запит на генерування та кожен аудіозапит має містити в полі `model` одну з цих назв обслуговуваних моделей.

## Кінцеві точки

| Метод | Маршрут | Призначення |
| --- | --- | --- |
| `GET` | `/v1/models` | Перелік назв зареєстрованих обслуговуваних моделей. |
| `POST` | `/v1/chat/completions` | Сумісний з OpenAI чат із підтримкою тексту, зображень, інструментів і потокової передачі. |
| `POST` | `/v1/completions` | Сумісне з OpenAI доповнення промпту (completion). |
| `POST` | `/v1/audio/transcriptions` | Транскрибування аудіо, переданого як multipart-форма. |
| `POST` | `/v1/audio/translations` | Переклад мовлення з multipart-форми англійською. |
| `POST` | `/api/chat` | Сумісний з Ollama чат; за замовчуванням передає потік NDJSON. |
| `POST` | `/api/generate` | Сумісна з Ollama генерація за промптом; за замовчуванням передає потік NDJSON. |
| `POST` | `/stop` | Скасування активних потоків для однієї моделі або для всіх моделей. |
| `POST` | `/set_lora` | Активація або заміна динамічного адаптера LoRA. |
| `POST` | `/unset_lora` | Повернення динамічно адаптованої моделі до її базових ваг. |

Також приймаються альтернативні назви для забезпечення сумісності: `/audio/transcriptions` та `/audio/translations`. У нових клієнтах рекомендується використовувати маршрути `/v1/audio/...`.

Сумісність стосується маршрутів і форматів відповідей, реалізованих у `GenAIServer`; вона не означає підтримки всіх полів оригінальних API OpenAI або Ollama. Підтримувані поля запитів описано нижче.

## Запити, сумісні з OpenAI

Надсилайте `model` та `messages` до кінцевої точки чату. Встановіть `stream` на значення `true` для
технології Server-Sent Events; за замовчуванням встановлено значення `false`:

```bash
curl http://<modalix-ip>:9998/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llm",
    "messages": [
      {"role": "user", "content": "Explain an API gateway in one sentence."}
    ],
    "max_tokens": 64,
    "stream": false
  }'
```

`/v1/chat/completions` приймає `max_tokens` або `max_completion_tokens`,
`tools` та `tool_choice` на додаток до `model`, `messages` та `stream`.
Для визначення інструментів використовується формат функціональних інструментів OpenAI. `tool_choice` підтримує
`"auto"` та `"none"`; якщо його не вказано або встановлено значення `null`, залишається поведінка інструменту за замовчуванням.

`/v1/completions` приймає рядок `prompt` або масив рядків, а також
`model`, `max_tokens` або `max_completion_tokens` та `stream`, значення за замовчуванням для якого становить
`false`. Коли `prompt` є масивом, сервер об’єднує його рядкові елементи символами нового рядка та виконує один запит на доповнення (completion).

Для запитів VLM частина вмісту OpenAI chat `image_url` повинна містити URI даних у форматі base64, наприклад `data:image/jpeg;base64,...`. Для декодування зображення потрібна збірка Neat з підтримкою OpenCV.

Якщо промпт не залишає місця для відповіді в скомпільованому контексті, повертається `context_length_exceeded` (HTTP 400 або помилка SSE, якщо потокове передавання вже почалося). Досягнення межі контексту чи кількості вихідних токенів повертає `finish_reason: "length"`, а звичайне завершення — `"stop"`. Історія розмови зберігається.

## Запити, сумісні з Ollama

Використовуйте `/api/chat` для запитів з історією повідомлень або `/api/generate` для одного промпту:

```bash
curl http://<modalix-ip>:9998/api/generate \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llm",
    "prompt": "Give me three API design tips.",
    "options": {"num_predict": 96},
    "stream": false
  }'
```

Обидві сумісні з Ollama кінцеві точки за замовчуванням передають JSON-дані, розділені символом нового рядка. Встановіть
`stream` на `false`, щоб отримати одну повну відповідь у форматі JSON. `/api/chat` також приймає
`tools` та `tool_choice`. Для запитів VLM розміщуйте необроблені рядки зображень у форматі base64 у масиві
`images` кожного повідомлення `/api/chat` або у верхньому масиві `images`
для `/api/generate`.

## Моделі з міркуваннями

Моделі з міркуваннями, як-от Qwen3 або Gemma 4 E2B/E4B, можуть повертати міркування окремо від остаточної відповіді. Для запиту, сумісного з OpenAI, задайте `enable_thinking` на верхньому рівні запиту:

```bash
curl http://<modalix-ip>:9998/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llm",
    "messages": [
      {"role": "user", "content": "Which is larger: 9.11 or 9.9? Explain."}
    ],
    "enable_thinking": true,
    "max_tokens": 256,
    "stream": false
  }'
```

У відповіді без потокової передачі міркування розміщуються в
`choices[0].message.reasoning_content`, а остаточна відповідь – у
`choices[0].message.content`. У випадку з `stream: true`, для частин відповіді використовуються
`choices[0].delta.reasoning_content` та `choices[0].delta.content`.

Для запиту, сумісного з Ollama, використовуйте `think`:

```bash
curl http://<modalix-ip>:9998/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llm",
    "messages": [
      {"role": "user", "content": "Which is larger: 9.11 or 9.9? Explain."}
    ],
    "think": true,
    "options": {"num_predict": 256},
    "stream": false
  }'
```

`/api/chat` повертає міркування в `message.thinking` та остаточну відповідь у `message.content`. `/api/generate` приймає те саме поле верхнього рівня `think` і повертає міркування в полі верхнього рівня `thinking` та відповідь у `response`.

Поля міркувань не повертаються, якщо вони порожні. Вони призначені лише для виведення: вхідні поля `reasoning_content` або `thinking` не відтворюються як історія розмови.

### Рівень міркувань

Для GPT-OSS задайте `reasoning_effort` як `low` (за замовчуванням), `medium` або `high`; інші значення повертають HTTP 400. `enable_thinking` визначає, чи повертати міркування.

`reasoning_effort` також можна задати в `chat_template_kwargs`, де його значення має пріоритет над полем верхнього рівня.

## Аудіозапити

Кінцеві точки для аудіо приймають дані форми у форматі multipart із назвою обслуговуваної моделі ASR та аудіофайлом. За замовчуванням `language` має значення `auto`, а `stream` — `false`:

```bash
curl http://<modalix-ip>:9998/v1/audio/transcriptions \
  -F model=asr \
  -F file=@speech.wav \
  -F language=auto \
  -F stream=false
```

Використовуйте `/v1/audio/translations` з тими ж полями форми, щоб перекласти мовлення на
англійську мову. Обидва способи підтримують `stream=true`. Результати містять згенерований текст, визначену мову та показники впевненості ASR, якщо модель їх надає.

## Потокова передача та скасування

Сумісні з OpenAI потоки чату, доповнення (completion) та аудіо використовують `text/event-stream`, генерують події `data:` і завершуються подією `data: [DONE]`.
Сумісні з Ollama потоки використовують `application/x-ndjson`. Потокові відповіді містять `ttft` і `tps`, якщо вони доступні. Для підрахунку згенерованих токенів у потоках, сумісних з OpenAI, використовується `generated_tokens`, а в потоках, сумісних з Ollama, – `eval_count`.

Скасуйте активні потоки для однієї обслуговуваної моделі:

```bash
curl http://<modalix-ip>:9998/stop \
  -H "Content-Type: application/json" \
  -d '{"model": "llm"}'
```

Пропустіть `model`, щоб скасувати всі активні потоки. Цей HTTP-маршрут скасовує активне потокове генерування; він не скасовує синхронні запити й не зупиняє процес сервера. Щоб зупинити сервер, запущений через `server.start()`, викличте `server.stop()` із застосунку, якому цей сервер належить.

## Перемикання адаптера LoRA

Для моделі, скомпільованої з використанням режиму `LORA_BRANCH` від LLiMa, активуйте адаптер із
теки `npy_files/<adapter-name>` моделі:

```bash
curl http://<modalix-ip>:9998/set_lora \
  -H "Content-Type: application/json" \
  -d '{"model":"llm","name":"customer-adapter"}'
```

Поверніться до початкових значень ваг за допомогою:

```bash
curl http://<modalix-ip>:9998/unset_lora \
  -H "Content-Type: application/json" \
  -d '{"model":"llm"}'
```

Поле `model` можна опустити лише тоді, коли зареєстровано рівно одну текстову модель або модель, що поєднує обробку зображень і мови. Перемикання чекає завершення активного запиту до цієї моделі та не впливає на інші обслуговувані моделі. Назва адаптера має бути назвою однієї теки; шляхи та переходи заборонені. Динамічне перемикання не підтримується для ASR, пакетів спекулятивного декодування або остаточно злитих ваг `LORA_MERGED`.

## Помилки

У разі явних помилок під час перевірки кінцевої точки повертається HTTP 400, зокрема, якщо відсутнє поле
`model`, якщо конфігурація інструментів недійсна, якщо можливості моделі несумісні із запитом або якщо в multipart-формі відсутнє аудіополе `file`. Для невідомої обслуговуваної моделі повертається HTTP 404.

Перш ніж буде встановлено потік відповіді, винятки, що виникають під час обробки запиту або виконання моделі, призводять до повернення HTTP 500.

Перед початком потокової передачі помилки використовують JSON-обгортку
`{"error":{"message":"...","type":"invalid_request_error"}}`. Після початку потокової відповіді помилки передаються в потоці SSE або NDJSON кінцевої точки, а не змінюють HTTP-статус.
