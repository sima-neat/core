# Атрибути окремих кадрів

Деякі камери описують кожен кадр у транспорті, який його доставляє: номер у послідовності, мітку часу захоплення, назву каналу. Neat може пронести вибраний набір цих значень через декодування й повернути їх у `Sample` того кадру, якому вони належать.

`Sample::attributes` — це звичайне зіставлення рядків із рядками. Neat копіює його, зберігає прив’язаним до його кадру й очищає, коли буфер призначення використовується повторно. Neat ніколи не розбирає, не об’єднує й не переінтерпретує значення. Ключі та значення мають бути коректним UTF-8 і не можуть містити вбудованого байта NUL, бо рядкове подання GStreamer не може їх зберегти.

## Що гарантовано

> Вибрані заголовки частин multipart залишаються прив’язаними до свого декодованого кадру на шляху за замовчуванням `HttpMjpegDecodedInput`, через Queue/Branch і через матеріалізовані межі Core між Sample і GStreamer.

Це вся обіцянка для цього випуску. Усе, що виходить за її межі, перелічено в розділі [Непідтримувані шляхи](#unsupported-paths), і в таких випадках Neat не дає побудувати граф, а не відкидає атрибути непомітно.

## Увімкнення захоплення

За замовчуванням захоплення вимкнено. Щоб його ввімкнути, перелічіть потрібні заголовки.

```cpp
#include "nodes/groups/HttpMjpegDecodedInput.h"

simaai::neat::nodes::groups::HttpMjpegDecodedInputOptions opt;
opt.url = "http://camera.local/stream";
opt.header_capture.headers = {"Image-Index", "Image-Time"};

auto source = simaai::neat::nodes::groups::HttpMjpegDecodedInput(opt);
```

Зчитування значень:

```cpp
simaai::neat::Sample sample;
if (run.pull(1000, sample) == simaai::neat::PullStatus::Ok) {
  const auto it = sample.attributes.find("image-index");
  if (it != sample.attributes.end()) {
    // it->second is the value this frame was sent with.
  }
}
```

Те саме в Python, де `attributes` — живе зіставлення: присвоєння елемента змінює
базовий `Sample`, а присвоєння словника замінює весь вміст:

```python
import pyneat

opt = pyneat.HttpMjpegDecodedInputOptions()
opt.url = "http://camera.local/stream"
opt.header_capture.headers = ["Image-Index", "Image-Time"]
source = pyneat.groups.http_mjpeg_decoded_input(opt)

# ... later, on a pulled sample:
index = sample.attributes["image-index"] if "image-index" in sample.attributes else None

sample.attributes["image-index"] = "42"     # reaches the Sample
sample.attributes = {"image-time": "..."}   # replaces the whole map
```

## Правила для заголовків

Налаштований список є **списком дозволених заголовків** (allowlist). Порожній список повністю вимикає захоплення й залишає наявну топологію та поведінку без змін.

| Правило | Поведінка |
| --- | --- |
| Регістр | Налаштовані назви та видані ключі приводяться до нижнього регістру ASCII; зіставлення не залежить від регістру. Зчитуйте атрибути за ключами в нижньому регістрі. |
| Дублікати в списку дозволених | Після нормалізації зливаються в один. |
| Заголовок повторюється в межах однієї частини | Діє останнє значення. |
| Заголовок відсутній у частині | Ключ пропускається. Він ніколи не успадковується від попереднього кадру. |
| Заголовок наявний, але порожній | Зберігається як порожній рядок. |
| Пробіли | Обрізаються лише SP/HTAB на краях. Інакше значення не переінтерпретуються. |
| Тип MIME | Якщо `Content-Type` наявний, він має бути `image/jpeg` (параметри дозволені). Якщо його немає, тип частини визначає перевірка корисних даних JPEG. |
| Корисні дані JPEG | Частина має містити рівно одне повне зображення JPEG від SOI до EOI. Обрізані, порожні або склеєні зображення спричиняють помилку потоку. |
| Некоректний вхід | Некоректні назви заголовків, згорнуті рядки заголовків і впровадження CR/LF/NUL відхиляються: потік завершується помилкою, а не нормалізується до чогось на вигляд безпечного. |

У Python перевіряйте наявність ключа за допомогою `in`, а в C++ — за допомогою `count()`. Значення наявного ключа може бути порожнім рядком.

### Обмеження

Якщо будь-яке з цих обмежень перевищено, розбір завершується помилкою, а не обрізає дані:

| Обмеження | Значення |
| --- | --- |
| `kMultipartHeaderCaptureMaxHeaders` | 64 вибрані назви заголовків |
| `kMultipartHeaderCaptureMaxNameBytes` | 128 байтів на назву |
| `kMultipartHeaderCaptureMaxLineBytes` | 8 КіБ на рядок заголовка |
| `kMultipartHeaderCaptureMaxBlockBytes` | 64 КіБ на блок заголовків частини |
| Тіло JPEG у multipart | 64 МіБ на частину MIME |

Некоректний список дозволених заголовків відхиляється під час створення винятком `std::invalid_argument`.

## Непідтримувані шляхи

Коли захоплення ввімкнено, `HttpMjpegDecodedInput` відмовляється будувати граф, що містить
`use_videoconvert`, `use_videoscale`, `use_videorate` або `extra_fragment`. Збереження атрибутів
під час проходження цих елементів не доведено, а зрозуміла помилка під час створення краща за
метадані, які непомітно зникають посеред потоку.

Атрибути також не визначено для вузлів, які створюють новий логічний Sample з кількох
входів, — моделей, з’єднань, агрегаторів. Такі вузли не об’єднують атрибути.

## Як зберігається прив’язка

Графи з увімкненим захопленням використовують приватний внутрішньопроцесний елемент, який розбирає межі частин **і**
заголовки частин в одному скінченному автоматі, тому заголовки частини прикріплюються саме до того буфера,
що містить її байти; немає жодного побічного каналу, який міг би розсинхронізуватися. Цей елемент видає повні
розібрані кадри JPEG, тому на шляху з увімкненим захопленням `jpegparse` не вставляється.
Якщо прикріпити вибрані атрибути не вдається, кадр не доставляється, а потік
повідомляє про помилку.

Під час декодування плагін робить знімок атрибутів кожного прийнятого закодованого зображення й
відновлює їх на тому декодованому виході, який декодер зіставляє саме з цим зображенням, — а не на виході,
який просто надійде наступним. Кожне прийняте зображення дає рівно один кінцевий результат,
тому перевпорядкування, відкидання й повторне використання пулу виходів не можуть перенести значення на інший кадр.
Механізм не залежить ні від кодека, ні від транспорту, і саме тому його можна буде пізніше поширити на інші
закодовані джерела без перепроєктування.

## Сумісність

`Sample` і структури параметрів джерел отримали нові поля, додані в кінець. Початковий код, який звертається до них за
назвою поля або використовує агрегатну ініціалізацію, і далі компілюється.

Двійкова розкладка цих публічних структур змінилася, тому **вже зібраних споживачів
потрібно перезібрати**. Поточна версія ABI/SOVERSION Neat — **6**; версія пакета —
**%%release.core%%**. Установлюйте відповідні одне одному заголовки,
бібліотеки середовища виконання та прив’язки Python.

## Додавання іншого джерела в майбутньому

Шлях декодера універсальний. Новому закодованому джерелу потрібно лише прикріпити вкладену структуру атрибутів
до буфера, який воно передає декодеру; ні в декодері, ні на межах Sample немає нічого, що залежало б від транспорту.
За кожним новим джерелом і далі залишається власне правило вилучення значень
і власне явне твердження про те, які форми графів воно гарантує.
