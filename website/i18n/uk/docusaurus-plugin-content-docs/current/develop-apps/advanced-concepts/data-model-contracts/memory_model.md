# Модель пам’яті

Core планує сховище; Scheduler готує його пули через Runner, який володіє ідентичністю виділень, відображеннями DMA-BUF і доступом CPU та пристрою.

## Виділення та подання

Кожен етап має один незмінний `FrameLayout`: список об’єктів `FrameAllocation`, локальні для виділень значення `FrameSpan`, вхідні маршрути та володіння виходами. Діапазон визначає виділення, зсув і зарезервовану місткість. Логічні форми тензорів, кроки й опубліковані байти залишаються окремими; апаратне доповнення MLA має вміщатися в зарезервовану місткість.

Подання спільно використовують кореневий носій. Індекси виділень належать групі буферів: нульовий зсув у двох різних групах не означає, що буфери перекриваються. Імпортоване базове сховище зберігає свого експортера, перевірені зсуви, геометрію площин і позики виробника.

Для щільного числового `Tensor` із прив’язаним сховищем форма `{}` означає скаляр рангу нуль: його щільний розмір дорівнює одному елементу `dtype`. Він відрізняється від форми з нульовою довжиною виміру, як-от `{0,256}`, щільний розмір якої дорівнює нулю. Щільне копіювання байтів і `clone()` зберігають значення скаляра, перевіряючи зсув подання та межі сховища. Для Tensor, створеного за замовчуванням і не прив’язаного до сховища, `dense_bytes_tight()` повертає нуль; щільне копіювання та клонування його відхиляють. Явно задані кодовані, байтопотокові, тесельовані й текстові носії зберігають свою семантику байтів носія. Це не змінює діапазону байтів, який повертає публічний `map()`.

## Розміщення

Core вибирає маршрути й визначає виконавців, компілює перевірені рецепти, визначає носії та володіння, а потім пакує їх на основі свідчень про доступ і час життя. Розкладки етапів і публікацію він остаточно визначає один раз.

- Будь-який доступ EV74 потребує CMA.
- Власні носії лише для MLA/A65 за замовчуванням використовують DMS.
- Відповідні нові публічні кінцеві виходи A65 можуть використовувати сховище HostCpu.
- Імпортоване сховище залишається закріпленим. Розгалуження враховує всіх споживачів; подання зберігають політику свого носія.

`AllocationPolicy::PreferDmsThenCma` явно дозволяє відповідним власним DMS-виділенням перейти на CMA за браку місткості. Перехід на звичайну пам’ять Linux ця політика не дозволяє. Межі Queue, окремі виклики моделі та утримані виходи зберігають свої обмеження володіння й часу життя.

Для EV74 Preproc → MLA → A65 BoxDecode вхід інференсу використовує CMA, а вихід MLA — окреме DMS-виділення. Фактичне розміщення залежить від визначених виконавців усіх споживачів.

## Володіння та відображення для CPU

Вихід без копіювання утримує своє базове сховище й позику виробника, доки застосунок його утримує. Scheduler і Runner утримують входи пристрою до остаточного завершення; самі лише тайм-аут чи скасування не дозволяють повторного використання.

Використовуйте [`TensorBuffer::map()`](/reference/cppapi/structs/simaai-neat-tensorbuffer) із відповідним [`MapMode`](/reference/cppapi/namespaces/simaai-neat). `Mapping` утримує перевірений доступ і сховище, доки його не закрито. Сумісні читання можуть спільно використовувати доступ; для записів доступ залишається виключним. Потрібне обслуговування кешу виконується перед читанням CPU та після запису, зі збереженням сусідніх байтів кеш-лінії. Невдала синхронізація переводить відповідне сховище в карантин.

Власні кешовані CMA і DMS використовують допущений діапазонний API SimaHeap. Імпортовані буфери зберігають контракт свого експортера. Наступні етапи, що працюють лише на пристрої, не відкривають епоху читання CPU; доступ CPU не виводиться з назви вузла чи його позиції в графі. Приватні пакети CPU утримують батьківський об’єкт до вивільнення всіх дочірніх доступів.

Оболонки метаданих можуть спільно використовувати пам’ять без копіювання вмісту, але перетворення dtype, явні передавання та вихід Owned можуть копіювати байти. Режим без копіювання не означає, що кожен етап працює на місці.

## Буфери камери

[`CameraInput`](/reference/nodes/camera-input) перевіряє розкладку захопленого DMA-BUF і утримує батьківський буфер камери, доки його використовують наступні споживачі. Сумісні буфери зберігають своє базове сховище й геометрію площин. Якщо розкладку потрібно адаптувати й увімкнено `allow_cpu_fallback`, міст створює явну копію в CMA. Адаптація джерела залишається окремою від попередньої обробки моделі.

## Пов’язані типи

- [`TensorBuffer`](/reference/cppapi/structs/simaai-neat-tensorbuffer): базове сховище та подання.
- [`Segment`](/reference/cppapi/structs/simaai-neat-segment): утриманий діапазон виділення.
- [`Mapping`](/reference/cppapi/structs/simaai-neat-mapping): доступ CPU в обмеженій області дії.
- [`MemoryContract`](/reference/cppapi/files/include-contracts-contracttypes-h): оголошені вимоги вузла до пам’яті.
