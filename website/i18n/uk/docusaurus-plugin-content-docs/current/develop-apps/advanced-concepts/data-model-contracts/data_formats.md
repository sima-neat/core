# Формати даних і семантика тензорів

На цій сторінці пояснено публічний словник форматів, який використовують `InputOptions::format`, `OutputTensorOptions::format`, метадані зображень у тензорах і теги вмісту зразків.

Для використання на рівні завдань почніть зі сторінки [Тензор і зразок](/develop-apps/development-workflow/core_types). Повертайтеся сюди, коли межа графа потребує явного контракту формату.

## Теги форматів

`FormatTag` / `FormatSpec` визначає формат вмісту. У Python для полів формату використовуйте значення `pyneat.Format` або `pyneat.FormatTag`. Не присвоюйте полям формату в Python звичайні рядки.

Python надає поширені теги форматів, з якими працюють користувачі. Деякі низькорівневі теги C++, як-от `BBOX`, `MLA`, `ARGMAX` і `DETESSDEQUANT`, зазвичай трапляються в семантичних метаданих тензорів, тегах вмісту чи діагностиці, а не як значення `pyneat.Format`, які можна присвоїти.

Поширені теги:

| Тег | Типовий вміст | Значення |
| --- | --- | --- |
| `RGB` | зображення | Упакований RGB, 8 бітів на канал. |
| `BGR` | зображення | Упакований BGR, 8 бітів на канал. OpenCV використовує його за замовчуванням. |
| `GRAY8` | зображення | 8-бітні відтінки сірого. |
| `NV12` | зображення/відео | Площина Y і площина UV з чергуванням. Ширина й висота мають бути парними. |
| `I420` | зображення/відео | Площини Y, U та V. Ширина й висота мають бути парними. |
| `H264` | закодований | Одиниця доступу / потік NAL H.264. `AVC` — псевдонім. |
| `H265` | закодований | Одиниця доступу / потік NAL H.265 / HEVC. `HEVC` — псевдонім. |
| `ENCODED` | закодований | Загальний закодований вміст. Кодеки без окремого тегу формату визначає рядок caps. |
| `FP32` | тензор | Вміст тензора Float32. |
| `INT8` | тензор | Вміст тензора INT8 зі знаком. |
| `UINT8` | тензор | Вміст тензора UINT8 без знака. |
| `BF16` | тензор | Вміст тензора BF16. |
| `BBOX` | виявлення | Упакований вміст обмежувальних рамок. |
| `ByteStream` | семантика тензорів | Непрозорий потік байтів, який інтерпретують відповідно до контракту наступного етапу. |

## Сімейства вмісту

`PayloadType` вибирає загальне сімейство даних, що перетинають межу графа.

| Сімейство вмісту | Внутрішнє/медійне значення | Поширені метадані |
| --- | --- | --- |
| `Image` | декодовані пікселі | формат пікселів, ширина, висота, розкладка, семантичні метадані зображення |
| `Tensor` | тензор моделі або застосунку | dtype, форма, розкладка, семантичні метадані тензора |
| `Encoded` | закодовані медіадані, як-от H.264, H.265 або JPEG | рядок caps, формат кодека, мітки часу |
| `Auto` | визначити автоматично, коли можливо | використовуйте, лише коли метаданих тензора/зразка достатньо |

Вміст із текстом, аудіо, потоком байтів чи непрозорими байтами використовує семантику тензорів або спеціалізовані специфікації. Це не окремі значення переліку `PayloadType` у публічному API, перевіреному для цього випуску.

## Зіставлення необроблених зображень

| Формат | PayloadType | Розкладка / форма тензора | Примітки |
| --- | --- | --- | --- |
| `RGB` | `Image` | `HWC`, `[H, W, 3]` | Щільно упаковані пікселі. |
| `BGR` | `Image` | `HWC`, `[H, W, 3]` | Використовуйте для `cv2.imread` або кадрів BGR з OpenCV. |
| `GRAY8` | `Image` | `HW`, `[H, W]` | Одноканальні відтінки сірого. |
| `NV12` | `Image` | `HW`, `[H, W]` плюс метадані площин | Складені площини Y + UV. |
| `I420` | `Image` | `HW`, `[H, W]` плюс метадані площин | Складені площини Y + U + V. |

Для упакованих форматів глибина — це кількість каналів. Для тензорного вмісту глибина випливає з вибраної розкладки та форми.

## Читайте формат, розкладку й семантику осей разом

Не читайте поле окремо від інших:

| Поле | Що воно повідомляє |
| --- | --- |
| `PixelFormat` / метадані формату зображення | Як інтерпретувати піксельні канали, наприклад RGB, BGR, GRAY8, NV12 чи I420. |
| `TensorLayout` | У якому порядку йдуть виміри тензора, наприклад HWC, CHW чи HW. |
| `TensorAxisSemantic` | Що означає вісь, коли тензор містить розширені семантичні метадані. |
| `TensorDType` | Як зберігається кожен елемент, наприклад UInt8, INT8, FP32 чи BF16. |
| `ByteFormat` / метадані потоку байтів | Як наступний етап має інтерпретувати непрозорі байти. |

Байти самі по собі нічого не означають. Перш ніж інакше інтерпретувати буфер, використовуйте поля метаданих разом.

## Приклад формату в InputOptions

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
simaai::neat::InputOptions input;
input.payload_type = simaai::neat::PayloadType::Image;
input.format = simaai::neat::FormatTag::BGR;
input.width = 640;
input.height = 480;
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
input_options = pyneat.InputOptions()
input_options.payload_type = pyneat.PayloadType.Image
input_options.format = pyneat.Format.BGR
input_options.width = 640
input_options.height = 480
```

</CodeTab>
</CodeTabs>

Задавайте лише ті поля, які потрібні межі. Якщо тензор або зразок уже містить достатньо метаданих, не додавайте дублювальних здогадок.

Для H.264 і H.265 є окремі теги `H264` і `H265`. Задайте відповідний тег
на вхідній межі; тип медіаданих визначається за ним. Використовуйте `ENCODED` з
явним рядком caps лише для кодеків, які не мають окремого тегу.

## Розширений адаптер виходу зображень і відео

Для звичайного виходу моделі використовуйте `nodes.output(...)` і отримуйте тензори за допомогою `pull_tensors(...)`. Використовуйте `OutputTensorOptions`, лише коли вихід зображення чи відео перед отриманням у застосунку потрібно перетворити на зручний для CPU тензор `UInt8`, змінивши за потреби розмір або частоту кадрів.

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
simaai::neat::OutputTensorOptions output;
output.format = simaai::neat::FormatTag::BGR;
output.target_width = 640;
output.target_height = 480;

graph.add_output_tensor(output);
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
output = pyneat.OutputTensorOptions()
output.format = pyneat.Format.BGR
output.target_width = 640
output.target_height = 480

graph.add_output_tensor(output)
```

</CodeTab>
</CodeTabs>

`add_output_tensor(...)` приймає `TensorDType::UInt8` — типовий dtype виходу. Для тензорів моделі та виходів, у яких потрібна повна обгортка `Sample`, залишайте звичайний шлях `nodes.output(...)`. Коли потрібен інший dtype, додайте явне перетворення в графі або на боці застосунку.

## Теги вмісту зразка

`Sample::payload_tag` — рекомендована мітка для споживачів нижче за потоком. Вона замінює застаріле поле `Sample::format`.

Під час налагодження закодованих медіаданих або узгодження на межі графа використовуйте `payload_tag`, `payload_type`, `media_type` і `caps_string` разом.

## Метадані попередньої обробки та сліди ROI

Декодуванню результатів виявлення, рендерингу та сценаріям роботи з ROI потрібні метадані попередньої обробки, щоб перетворювати координати з простору моделі назад у координати кадру джерела.

Ці метадані можуть містити:

- цільові ширину й висоту;
- ширину й висоту масштабованого вмісту;
- режим зміни розміру або letterbox;
- значення й геометрію доповнення;
- вхідний і вихідний формати кольору;
- перестановку осей;
- прапорці нормалізації, квантування й теселяції;
- вікна ROI, розмір зображення джерела, розмір пакета ROI та афінні перетворення для кожної ROI.

Якщо рамки чи маски опиняються не на своєму місці, перш ніж змінювати порогові значення, перевірте, чи дійшли метадані попередньої обробки до етапу декодування або рендерингу. Докладніше про попередню обробку зі списками ROI див. на сторінці [Попередня обробка списків ROI](/reference/preproc_roi).
