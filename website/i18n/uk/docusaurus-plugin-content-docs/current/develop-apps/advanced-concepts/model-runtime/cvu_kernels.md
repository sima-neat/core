# Каталог ядер і графів CVU

Фреймворк постачається з невеликим каталогом ядер CVU (EV74), які поєднуються в графи попередньої обробки та постобробки, що їх планувальник вибирає для кожної моделі. На цій сторінці описано ядра та сімейства графів, які з них компонуються.

## Сімейства ядер

### Ядра попередньої обробки

Виконуються на EV74 між входом і MLA. Стандартне сімейство:

- **Зміна розміру** — білінійне масштабування або масштабування за найближчим сусідом, з необов’язковим letterbox чи обрізанням по центру.
- **Перетворення кольору** — RGB ↔ BGR, NV12 → RGB, I420 → RGB, GRAY8 ↔ упакований формат.
- **Перетворення розкладки** — HWC ↔ CHW, перестановка осей.
- **Нормалізація** — середнє та стандартне відхилення для кожного каналу (вхід FP32, вихід FP32).

### Граничні ядра

Перетворюють FP32 / BF16 / INT8 на межі MLA:

- **Quant** — FP32 → INT8 із масштабом і нульовою точкою.
- **Dequant** — INT8 → FP32 із масштабом і нульовою точкою.
- **Cast** — FP32 ↔ BF16 (без масштабу та нульової точки).
- **Tess** / **Detess** — перестановка розкладки в геометрію плиток MLA і назад. Ті самі байти, інший порядок.

### Об’єднані ядра

Комбінації, які вибирає планувальник, коли контракт моделі вимагає граничних ядер, але не включає їх до етапу MLA:

- **QuantTess** — об’єднує Quant і Tess.
- **DetessDequant** — об’єднує Detess і Dequant.
- **CastTess** / **DetessCast** — об’єднують Cast і Tess на шляху BF16.

### Універсальний Preproc

Коли застосунок задає довільні користувацькі перетворення, планувальник переводить граф попередньої обробки на універсальний варіант, який об’єднує ці перетворення в одне ядро CVU. Контракт на межі MLA не змінюється.

### BoxDecode

Ядро постобробки, яке об’єднує NMS і декодування для моделей виявлення. Створює `DetectionMeta` у вихідному зразку. Див. [`BoxDecodeType.h`](/reference/cppapi/files/include-pipeline-boxdecodetype-h).

## Як компонуються графи

Чотири значення `PreprocessGraphFamily` відповідають чотирьом ланцюжкам ядер:

| Сімейство графів | Ланцюжок (вхід → MLA) |
|--------------|---------------------|
| `Preproc` | Resize → ColorConvert → Normalize → MLA (виконує теселяцію всередині) |
| `Quant` | Resize → ColorConvert → Normalize → Quant → MLA (виконує теселяцію всередині) |
| `Tess` | Resize → ColorConvert → Normalize → Tess → MLA |
| `QuantTess` | Resize → ColorConvert → Normalize → QuantTess → MLA |

Дзеркальний варіант на боці виходу — `Postproc` / `Detess` / `DetessDequant` / пряме передавання — залежить від того, чи включає скомпільоване вихідне ядро MLA detess/dequant.

Чому існують саме ці чотири сімейства, див. на сторінці [Контракт dtype](/develop-apps/advanced-concepts/dtype_contract).

## Правила іменування ядер

Усередині фреймворку на ядра посилаються за стабільними рядковими іменами, які з’являються в рішеннях `RoutePlanner`
і в рядках часових показників плагінів/ядер у `MeasureReport`:

- `cvu/preproc/<variant>` — ядра попередньої обробки.
- `cvu/quant/<dtype>` — варіанти Quant.
- `cvu/tess/<geometry>` — варіанти Tess.
- `cvu/postproc/box_decode_<type>` — варіанти BoxDecode.

Точний каталог міститься в `core/src/pipeline/internal/sima/` (рівень фреймворку з прямим доступом до нижчих шарів).
