# Надсилання метаданих JSON

Використовуйте `MetadataSender`, коли зовнішній переглядач, засіб запису або сервіс приймає метадані JSON у кодуванні UTF-8 через UDP. Insight — один із приймачів, що розуміють цей мережевий контракт.

## Мережевий контракт

- Типовий хост: `127.0.0.1`
- Типовий базовий порт метаданих: `9100`
- Правило порту каналу: `metadata_port_base + channel`
- Типовий режим надсилання: неблокувальний (`MSG_DONTWAIT`)
- Кодування вмісту: текст JSON у кодуванні UTF-8
- Обов’язкові поля верхнього рівня: `type`, `data`
- Максимальний логічний вміст: 65 507 байтів

`MetadataSender` обмежує вміст кожної датаграми UDP 1200 байтами. Вміст JSON
розміром до 1200 байтів залишається однією незмінною датаграмою. Більший вміст розбивається на
фрагменти з таким 12-байтовим двійковим заголовком:

| Байт | Розмір | Значення |
| --- | --- | --- |
| 0 | 1 | Магічний байт `0x4e` |
| 1 | 1 | Версія протоколу `0x01` |
| 2 | 8 | Ідентифікатор повідомлення як беззнакове 64-бітне ціле число в порядку big-endian |
| 10 | 1 | Індекс фрагмента, починаючи з нуля |
| 11 | 1 | Загальна кількість фрагментів |

Кожен фрагмент містить до 1188 байтів JSON. Перед розбором JSON приймач збирає фрагменти з
однаковою адресою відправника й однаковим ідентифікатором повідомлення в порядку їхніх індексів. Доставка UDP
і далі відбувається без гарантій (best effort): відправник не надсилає повторно фрагмент, який не вдалося надіслати,
а `send_raw_json(...)` або `send_metadata(...)` повертає `false` після
першої невдалої локальної спроби надсилання.

Приймачі мають приймати як незмінні датаграми JSON, так і версійовані фрагменти.
Оновіть Insight до випуску зі збиранням фрагментів раніше за цю версію
Neat Library або одночасно з нею. Старіші версії Insight і далі отримують вміст
розміром до 1200 байтів, але не можуть декодувати більший вміст, розбитий на фрагменти.

Для Insight поєднуйте канал метаданих `N` з відеопотоком UDP на порту `9000 + N`.
Якщо Insight або інший приймач працює за перепризначенням портів контейнера, явно передайте із застосунку зіставлені хост і порт.

Дані відстеження, треклети та інші власні метадані можна надсилати як довільний JSON. Підтримка накладань у переглядачі залежить від приймача; візуалізацію відстеження в Insight розглядають окремо в `sima-neat/insight#8`.

## C++

```cpp
simaai::neat::MetadataSenderOptions opt;
opt.host = "127.0.0.1";
opt.channel = 0;
opt.metadata_port_base = 9100;

std::string err;
simaai::neat::MetadataSender sender(opt, &err);

sender.send_metadata(
    "tracking",
    R"({"tracks":[{"id":"trk-1","bbox":[10,20,30,40]}]})",
    12345,
    "frame-7",
    &err);
```

`send_metadata(...)` перевіряє `data_json` і формує таку обгортку:

```json
{
  "type": "tracking",
  "timestamp": 12345,
  "frame_id": "frame-7",
  "data": {
    "tracks": [
      {
        "id": "trk-1",
        "bbox": [10, 20, 30, 40]
      }
    ]
  }
}
```

Використовуйте `send_raw_json(...)` лише тоді, коли код, що викликає метод, уже сформував повний вміст верхнього рівня:

```cpp
sender.send_raw_json(
    R"({"type":"object-detection","data":{"objects":[{"id":"obj_1","label":"car","confidence":0.92,"bbox":[120,80,96,64]}]}})",
    &err);
```

## Неблокувальне надсилання в реальному часі за замовчуванням

`MetadataSender` за замовчуванням застосовує `MSG_DONTWAIT` до кожної датаграми, щоб переповнений
локальний буфер надсилання не міг затримати потік, який також запускає обробку відео чи
інференс. Коли ядро не може одразу прийняти датаграму, надсилання
повертає `false`, а не чекає. Вважайте такий пакет метаданих відкинутим і
продовжуйте роботу в реальному часі; доставка UDP не гарантована.

Конструктор за замовчуванням і параметри надсилання за замовчуванням рівнозначні:

```cpp
simaai::neat::MetadataSenderSendOptions send_opt;
simaai::neat::MetadataSender sender(opt, send_opt, &err);
```

Код, якому явно потрібні блокувальні спроби доставки, може ввімкнути їх:

```cpp
simaai::neat::MetadataSenderSendOptions send_opt;
send_opt.nonblocking = false;
simaai::neat::MetadataSender sender(opt, send_opt, &err);
```

Використовуйте `stats()`, щоб відрізнити перевантаження від інших збоїв, а в явному
блокувальному режимі — щоб виявляти повільні виклики:

```cpp
const auto stats = sender.stats();
std::cerr << "sent=" << stats.datagrams_sent
          << " would_block=" << stats.would_block
          << " enobufs=" << stats.no_buffer_space
          << " max_send_ns=" << stats.max_send_duration_ns << '\n';
```

`stats()` можна безпечно читати, поки триває надсилання. Сприймайте результат як
діагностичний знімок, зібраний паралельно з роботою, а не як транзакційний знімок одного моменту.

## Python

```python
import json
import pyneat

opt = pyneat.MetadataSenderOptions()
opt.host = "127.0.0.1"
opt.channel = 0
opt.metadata_port_base = 9100

sender = pyneat.MetadataSender(opt)

sender.send_metadata(
    "object-detection",
    json.dumps(
        {
            "objects": [
                {
                    "id": "obj_1",
                    "label": "car",
                    "confidence": 0.92,
                    "bbox": [120, 80, 96, 64],
                }
            ]
        }
    ),
    12345,
    "frame-7",
)

stats = sender.stats()
print(stats.datagrams_sent, stats.would_block, stats.max_send_duration_ns)
```

Як і в C++, явно встановлюйте `send_opt.nonblocking = False` і передавайте цей об’єкт
другим аргументом конструктора лише тоді, коли потрібна блокувальна поведінка.
