# Карта істини JSON для плагінів SIMA (історична)

_Дата знімка: 2026-02-17_

Цей документ зберігає результати перевірки використання JSON-полів етапами конвеєра моделі SIMA станом на лютий 2026 року. Згадки про «поточну» поведінку нижче стосуються саме цього знімка.

> **Історичний контракт:** Наведені нижче назви плагінів та обов’язкові JSON-поля не є контрактом розгортання Platform 3.0.0. Універсальний BoxDecode тепер використовує `neatobjectdecode`, який налаштовується через типізований етап маніфесту та властивості середовища виконання. Старі вимоги `simaaiboxdecode` нижче не визначають конфігурацію на рівні застосунку. Актуальні вимоги до конфігурації та сумісних пакетів див. у [контракті контексту статичного маніфесту SIMA](../start-here/architecture.md#sima-static-manifest-context-contract).

## 1. Фіксація обсягу та матриця плагінів

### 1.1 У межах обсягу (конвеєр моделі)

- `simaaiprocesscvu` використовується як:
  - етап попередньої обробки (`kernel=preproc`)
  - етап quant/tess (`kernel=quanttess`)
  - обгортка етапу постобробки для detess/dequant (`kernel=detessdequant` у послідовності моделі; елементом бекенду все одно є `simaaiprocesscvu` у `src/nodes/sima/DetessDequant.cpp`)
- `simaaiprocessmla`
- `simaaiboxdecode` (універсальний boxdecode)
- payload-етапи detess/dequant/tess у `tmp/gst/*`:
  - `detessdequant`
  - `detessellate`
  - `quantize`
  - `slicedequant`

### 1.2 Поза межами обсягу

Універсальні плагіни застосунків CVU та власні утиліти графа не входять до обсягу цієї карти істини, зокрема, але не виключно:

- `overlay`, `genericrender`, `argmax`, `nms*`, `groupkeypoints`, `distancecalculation`, `cv_process`, `cvresize`, `fastbev*`, `PyGast-plugins/*`, застарілі плагіни та власні каркаси застосунків/тестів.

### 1.3 Охоплені дерева початкового коду

Статичне вилучення охоплювало обидва запитані дерева:

- `tmp/gst_plugins_source/gst/*`
- `tmp/gst/*`

Перевірка дзеркальності:

- Однакові в обох деревах: `genericboxdecode`, `detessdequant`, `detessellate`, `quantize`, `slicedequant`
- Розбіжність: `processcvu`, `processmla`

### 1.4 Матриця плагінів

| Плагін / етап | Наразі обов’язкові ключі JSON (поточні шляхи коду) | Ключі, які можна вивести | Властивості середовища виконання (не слід задавати статичним JSON) | Ключі лише для MLA |
|---|---|---|---|---|
| `simaaiprocesscvu` (обгортка preproc/quanttess/post) | спершу виведення: зв’язування береться з `ConfigManager::getBuffers()`, коли це можливо; JSON `input_buffers`/`output_memory_order` — лише резервний варіант. | `input_width`/`input_height` можуть надходити з caps/середовища виконання для графів 200/202; масиви зв’язування можна синтезувати з метаданих CM | розміри під час виконання повторно узгоджуються для кожного кадру; збірка фреймворку більше не переписує поля зв’язування в JSON кожного етапу | шляхи quant/tess і post опосередковано використовують поля форми тензора MLA (`input_depth`, `slice_*`) |
| `simaaiprocessmla` | `simaai__params`, `model_path`, `batch_size`; `outputs[*]` бажаний, але більше не строго обов’язковий, коли розміри сегментів можна вивести з полів форми виходу | розміри вихідних сегментів можна вивести з `output_*`/`slice_*` + dtype | `input_segment_name` — необов’язкова допомога для зв’язування під час виконання; шлях до моделі можна отримати з пакета | `outputs`, `data_type`, `output_*`, `slice_*`, параметри квантування |
| `simaaiboxdecode` | Фактично обов’язкові для завантажувача конфігурації бекенду: `buffers.output.size`, `memory.next_cpu`, `system.out_buf_queue`; визначення кількості класів наразі залежить від версії реалізації | `num_classes` можна вивести з `input_depth`/`slice_depth` + `num_in_tensor` + `decode_type` (нова логіка у початковому коді) | `buffers.input[*].name` перезв’язується від попереднього етапу; пороги/topk часто є параметрами часу виконання | `input_*`, `slice_*`, `data_type`, `num_in_tensor` |
| `detessdequant` (застарілий автономний елемент GST) | `simaai__params` плюс поля парсера: `orig_img_width`, `orig_img_height`, `frame_width`, `frame_height`, `num_in_tensor`, `next_cpu`, `no_of_outbuf`, `out_sz`, `input_*`, `slice_*`, `q_scale`, `q_zp` | у плагіні немає; виведення форми на вищому рівні є в `StageConfig` | іменування буферів попереднього етапу та маршрутизація CPU задаються під час виконання у сценаріях з обгорткою | `input_*`, `slice_*`, `q_scale`, `q_zp`, `num_in_tensor` |
| payload `detessellate` (`tmp/gst/detessellate`) | приймає `de_tess.*` або еквіваленти з кореня / статичного контракту (`input_*`, `slice_*`/`output_*`); `buffers.input[0].offset` необов’язковий (за замовчуванням 0) | кількість і розміри тензорів можна синтезувати зі статичних полів етапу маніфесту | назву/шлях входу слід зв’язувати під час виконання, а не задавати статично | контракт форми/зрізу |
| payload `quantize` (`tmp/gst/quantize`) | `quant_scale`, `zero_point` (резервний JSON) | кількість вхідних елементів виводиться з розміру вхідного буфера | тепер спершу використовує метадані `q_scale`/`q_zp` від попереднього етапу, потім резервний JSON | н/д (загальне квантування) |
| payload `slicedequant` (`tmp/gst/slicedequant`) | читає секцію (`slice_dequant`/`simaai__params`/корінь) для резервного визначення форми; JSON квантування — лише резервний варіант | параметри квантування спершу з метаданих середовища виконання; розміри можна синтезувати зі статичного контракту маніфесту | метадані середовища виконання (`q_scale`/`q_zp`) — бажаний спосіб передавання | контракт форми/квантування виходу MLA |

### 1.5 Передача контексту маніфесту (поточна)

- Тип контексту конвеєра: `sima.model.manifest.v1`
- ABI-безпечний доступ плагінів: `manifest_accessor_v1` у `include/gst/SimaPluginStaticManifestAbi.h`
- Ключі пошуку етапу:
  - `element_name` (за замовчуванням)
  - `logical_stage_id` (з властивості конвеєра `stage-id` або `stage_id`, якщо її задано)
- Застарілий рядок `manifest_json` залишається як резервний варіант на перехідний період.
- Код фреймворку, що будує фрагменти вузлів/моделей, тепер видає `stage-id=<element-name>` для плагінів SIMA
  на шляху моделі, тож логічний пошук детермінований, навіть коли застосовуються додаткові перетворення назв.

## 2. Карта істини для обов’язкових ключів

### 2.1 Метод статичного вилучення

Вилучено з явних точок доступу:

- `json["..."]`
- `contains("...")`
- допоміжні функції парсера (`parser_get_int`, `parser_get_double_array` тощо)

Основні місця доказів:

- `tmp/gst/processcvu/gstsimaaiprocesscvu.cpp:1667`
- `tmp/gst/processmla/gstsimaaiprocessmla.cpp:579`
- `tmp/gst/genericboxdecode/payload.cpp:61`
- `tmp/gst/detessdequant/gstsimaaidetessdequant.cpp:276`
- `tmp/gst/detessellate/detessellate.cpp:361`
- `tmp/gst/quantize/payload.cpp:124`
- `tmp/gst/slicedequant/payload.cpp:57`

Докази зв’язування/виведення під час виконання:

- `src/nodes/sima/Preproc.cpp:245`
- `src/nodes/sima/DetessDequant.cpp:238`
- `src/nodes/sima/SimaBoxDecode.cpp:158`
- `src/pipeline/runtime/StageConfig.cpp:296`
- `src/pipeline/runtime/StageConfig.cpp:411`

### 2.2 Використаний метод динамічного впровадження збоїв

Для зареєстрованих плагінів (`simaaiprocesscvu`, `simaaiprocessmla`, `simaaiboxdecode`, `detessdequant`):

- базовий запуск: `gst-launch-1.0 ... num-buffers=0`
- змінювати по одному ключу за раз (видаляти поле)
- записувати поведінку та повідомлення збою під час запуску або виконання
- примітка: динамічні результати відображають плагіни середовища виконання, наразі зареєстровані на цьому хості

Для незареєстрованих payload-етапів (`detessellate`, `quantize`, `slicedequant`):

- у цьому середовищі виконання немає відповідного елемента GST (`gst-inspect-1.0` повідомляє про його відсутність)
- тому в цьому проході динамічне видалення ключів обмежилося статичною класифікацією за початковим кодом

### 2.3 Класифікована карта (зафіксована)

### `simaaiprocesscvu`

- строго обов’язкові:
  - або успішне виведення буферів із CM, або резервний JSON з:
    - `input_buffers`
    - `output_memory_order`
    - кожен вхідний `memories[*].segment_name`
    - кожен вхідний `memories[*].graph_input_name`
- необов’язкові / зі значенням за замовчуванням:
  - `graph_name`
  - `input_width`, `input_height` (необов’язкові розміри в JSON)
- дублікати / похідні:
  - `input_buffers[*].name` (зв’язується під час виконання)
  - `sink_pad_tensor_index_map` з контексту маніфесту тепер є бажаним для детермінованого зіставлення кількох входів
  - розміри попередньої обробки з caps/середовища виконання
- лише для налагодження:
  - поля на кшталт `debug`, не потрібні для виконання

Динамічні докази:

- якщо виведення з CM не вдається і зв’язування в JSON відсутнє -> запуск завершується з помилкою на шині GStreamer
- якщо виведення з CM вдається -> `input_buffers`/`output_memory_order` можна пропустити
- якщо контекст указує на етап із кількома входами, яким керує модель, а `sink_pad_tensor_index_map` відсутній або неоднозначний -> запуск завершується з помилкою на шині GStreamer

### `simaaiprocessmla`

- строго обов’язкові:
  - `simaai__params`
  - `model_path`
  - `batch_size`
  - `outputs[*].name`
  - `outputs[*].size`
  - `batch_sz_model`, коли `batch_size != 1`
- необов’язкові / зі значенням за замовчуванням:
  - `input_segment_name`
- дублікати / похідні:
  - розміри/типи виходів можна вивести з метаданих моделі на вищих рівнях
- лише для налагодження:
  - нічого критичного

Динамічні докази:

- видалити `model_path` -> неперехоплена помилка типу `nlohmann::json` (`ec=134`)
- `batch_size=2` і видалити `batch_sz_model` -> неперехоплена помилка типу (`ec=134`)
- видалити `outputs` -> запуск може пройти з `num-buffers=0`, але виконання (`num-buffers=1`) потрапляє на шлях SIGSEGV із зацикленням

### `simaaiboxdecode`

- строго обов’язкові (поточна поведінка середовища виконання):
  - `buffers.output.size`
  - `memory.next_cpu`
  - `system.out_buf_queue`
- необов’язкові / зі значенням за замовчуванням (залежить від версії реалізації):
  - `num_classes` у новішому початковому коді може виводитися або мати резервне значення, але поточне середовище виконання може лише попереджати
  - `decode_type` у поточному середовищі виконання може зводитися до попередження про невідповідність типу
- дублікати / похідні:
  - `buffers.input[*].name` зв’язується під час виконання
  - `num_classes` можна вивести з форми тензора (`input_depth`/`slice_depth`) для відомих сімейств декодування
- лише для налагодження:
  - `system.debug`, `system.dump_data`

Динамічні докази:

- видалити `memory.next_cpu` -> аварійне завершення через неперехоплену помилку типу (`ec=134`)
- видалити `system.out_buf_queue` -> аварійне завершення через неперехоплену помилку типу (`ec=134`)
- видалити `num_classes` -> некритичне попередження `JSON type mismatch` (`ec=0`)

### `detessdequant` (застарілий автономний плагін GST)

- строго обов’язкові:
  - об’єкт `simaai__params`
  - ключі парсера: `orig_img_width`, `orig_img_height`, `frame_width`, `frame_height`,
    `num_in_tensor`, `next_cpu`, `no_of_outbuf`, `out_sz`,
    `input_height`, `input_width`, `input_depth`,
    `slice_height`, `slice_width`, `slice_depth`,
    `q_scale`, `q_zp`
- необов’язкові / зі значенням за замовчуванням:
  - жодних у поточному коді
- дублікати / похідні:
  - деякі поля розмірів кадру/оригінального зображення належать до рівня метаданих і мали б бути похідними
- лише для налагодження:
  - `debug`, `dump_data`, `inpath`, `ibufname`, `n_request` тощо

Динамічні докази:

- видалити `simaai__params` -> шлях SIGSEGV із зацикленням (тайм-аут)
- видалити `num_in_tensor` -> шлях SIGSEGV із зацикленням (тайм-аут)

### Payload `detessellate`

- строго обов’язкові:
  - визначені поля тензорів входу/зрізу (з `de_tess.*` або з ключів, синтезованих з кореня / статичного контракту)
- необов’язкові / зі значенням за замовчуванням:
  - `buffers.input[0].offset` (за замовчуванням — `0`)
  - `num_in_tensor` (виводиться з розмірів векторів, якщо не задано)
- дублікати / похідні:
  - вектори форми можна вивести зі статичних тензорів етапу маніфесту
- лише для налагодження:
  - немає

### Payload `quantize`

- строго обов’язкові:
  - `quant_scale`
  - `zero_point`
- необов’язкові / зі значенням за замовчуванням:
  - жодних у поточному коді
- дублікати / похідні:
  - кількість елементів тензора виводиться з розміру входу в байтах
- лише для налагодження:
  - немає

### Payload `slicedequant`

- строго обов’язкові:
  - параметри квантування для деквантування (`q_scale`, `q_zp`), визначені з метаданих середовища виконання або з резервної конфігурації
  - розміри зрізу тензора (`input_*`, `output_depth`/`slice_depth`), визначені синтезом із секції / кореня / статичного контракту
- необов’язкові / зі значенням за замовчуванням:
  - скалярне чи векторне кодування для ключів квантування та форми
- дублікати / похідні:
  - параметри квантування бажано брати з метаданих середовища виконання; JSON залишається лише резервним варіантом
- лише для налагодження:
  - н/д

## 3. Контрольований допуск до видалення (за цією зафіксованою картою)

Будь-яке видалення поля JSON має містити всі такі кроки:

1. Оновіть класифікацію цього поля в цій карті істини.
2. Додайте/оновіть тестовий сценарій із впровадженням збою:
   - збій під час запуску має бути явним (помилка на шині GStreamer) і ніколи не призводити до аварійного завершення.
3. Для полів, які можна вивести, і похідних полів:
   - спочатку реалізуйте виведення,
   - збережіть резервний варіант через caps/параметр плагіна,
   - залишайте JSON останнім резервним варіантом лише там, де він досі потрібен.
4. Мінімізуйте JSON, специфічний для MLA:
   - залишаються тільки невизначені метадані MLA (параметри форми/розміру/квантування).
5. Не вимикайте сувору перевірку CI:
   - `unit_sima_plugin_manifest_strict_model_pipeline_test`
   - `unit_sima_plugin_manifest_strict_fallback_test`
   - а також відповідну тестову групу Vulcan CI у `.github/workflows/vulcan-ci.yml`.

## 4. Виявлені поточні ризики

- Кілька шляхів із відсутніми ключами досі аварійно завершуються через неперехоплені винятки `nlohmann::json` або SIGSEGV замість помилок на шині GStreamer.
- Застарілий шлях `detessdequant` схильний до аварійних збоїв, коли бракує ключів парсера.
- `slicedequant` повністю ігнорує JSON і використовує скомпільовані константи.
- Розбіжність між середовищем виконання та початковим кодом може знову виникати щоразу, коли перезібрані файли `.so` не копіюються з `tmp/gst/*/build` до `deps/gst-plugins`.
