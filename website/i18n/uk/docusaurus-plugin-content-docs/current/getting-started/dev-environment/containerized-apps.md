Контейнер пакує застосунок разом із потрібними йому бібліотеками, тому
застосунок працює на DevKit без встановлення цих бібліотек на самому DevKit.
За допомогою Palette SDK ви збираєте образ контейнера для ARM64 на хості,
надсилаєте його до локального реєстру контейнерів і запускаєте на DevKit
командою `dk container`.

## Коли використовувати контейнер

Використовуйте контейнер для програмного забезпечення, яке працює на Arm-процесорах DevKit, наприклад:

- Служба або інструмент, яким потрібні бібліотеки, яких немає в eLxr.
- Застосунок, зібраний для іншого дистрибутива Linux, наприклад Ubuntu. Скажімо,
  застосунок ROS 2, зібраний для іншого випуску ROS 2, ніж той, що доступний
  для eLxr.
- Кілька застосунків, яким потрібні різні версії однієї бібліотеки.

:::note Доступ до прискорювача потребує налаштування
Застосунки Neat можуть використовувати MLA з контейнера за наявності потрібних вузлів пристроїв і сумісних бібліотек середовища виконання. Звичайний образ Ubuntu не містить цих залежностей. Вимоги наведено в розділі [Доступ до прискорювача](/reference/devkit-containers/#accelerators).
:::

## Як це працює

Робочий процес використовує ті самі три середовища, що й решта Palette SDK:

| Де | Що відбувається |
| --- | --- |
| Хост | `sima-cli sdk setup --devkit` створює пару DevKit із SDK і налаштовує локальний реєстр контейнерів на хості. |
| Контейнер SDK | Ви збираєте образ для ARM64 за допомогою `docker buildx` і надсилаєте його до локального реєстру. |
| DevKit | `dk container deploy` завантажує образ із локального реєстру та запускає його за допомогою Docker. |

Якщо Docker немає, перша команда `dk container` запропонує його встановити.

## Перш ніж почати

Вам знадобиться:

- Palette SDK %%release.sdk_series%% або новіший на хості.
- Modalix DevKit із версією платформи 3.0, доступний із хоста. Щоб перевірити
  версію, виконайте на DevKit `cat /etc/buildinfo`.
- Доступ до Інтернету на DevKit для завантаження Docker.
- Вільне місце в `/data` на DevKit, де Docker зберігає свої образи та
  контейнери. Розмір `/data` становить близько 3 ГБ, тому образи мають бути невеликими.

## Збирання та запуск контейнеризованого застосунку

### 1. Створіть пару DevKit із локальним реєстром

На хості створіть пару DevKit із SDK:

<ShellCommand prompt="host">
sima-cli sdk setup --devkit {devkit-ip}
</ShellCommand>

Коли налаштування запитає **Set up a local container registry so the DevKit can download
images built in the SDK?**, дайте відповідь `y`. Створення пари налаштовує доступ до `sudo` без пароля, потрібний для встановлення Docker. Потім відкрийте нову оболонку SDK:

<ShellCommand prompt="host">
sima-cli sdk neat
</ShellCommand>

Якщо раніше ви створили пару DevKit без реєстру, знову виконайте команду
налаштування й дайте відповідь `y`.

### 2. Налаштуйте Docker на DevKit

В оболонці SDK виконайте:

<ShellCommand prompt="sdk">
dk container setup
</ShellCommand>

Дайте відповідь `y` на пропозицію налаштувати Docker на DevKit. Якщо Docker уже працює, команда використає його повторно. Зміни під час встановлення описано в розділі [Встановлення Docker на DevKit](/reference/devkit-containers/#install).

### 3. Зберіть і надішліть образ

Створіть каталог із файлом `Dockerfile` для вашого застосунку. Наприклад, цей `Dockerfile` виводить повідомлення в Ubuntu 24.04:

```dockerfile
FROM ubuntu:24.04
CMD ["sh", "-c", "echo Hello from the DevKit"]
```

В оболонці SDK, перебуваючи в цьому каталозі, зберіть образ для ARM64 і надішліть
його до локального реєстру:

<ShellCommand prompt="sdk">
docker buildx build --platform linux/arm64 -t "$SIMA_CONTAINER_REGISTRY/my-app:latest" --push .
</ShellCommand>

DevKit запускає лише образи ARM64. Завжди виконуйте збирання з параметром
`--platform linux/arm64`.

### 4. Запустіть образ на DevKit

В оболонці SDK завантажте образ на DevKit і запустіть його:

<ShellCommand prompt="sdk">
dk container deploy my-app:latest --detach --name my-app
</ShellCommand>

Адресу реєстру в назві образу вказувати не потрібно: її додає `dk`. Параметри
після назви образу є параметрами `docker run`.

Приклад завершує роботу після виведення повідомлення. Прочитайте вивід і видаліть зупинений контейнер:

<ShellCommand prompt="sdk">
dk container logs my-app --follow
dk container remove my-app
</ShellCommand>

Для тривалих застосунків стежте за виводом за допомогою `dk container logs my-app --follow` і зупиніть контейнер командою `dk container stop my-app` перед видаленням.

## Наступні кроки

- Опис усіх команд `dk container`, встановлення Docker вручну, запуску контейнера
  Ubuntu та усунення несправностей див. у розділі
  [Контейнери DevKit](/reference/devkit-containers/).
- Як SDK і DevKit спільно використовують файли та виконують команди, див. у розділі
  [DevKit Sync](/getting-started/dev-environment/devkit-sync/).
