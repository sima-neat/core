:::tip Коли слід використовувати автономну установку.
Використовуйте автономне встановлення, коли цільовий комп’ютер не може завантажувати пакети безпосередньо з сервісів SiMa.ai. Це поширене явище в корпоративних мережах, які блокують великі завантаження, обмежують доступ до реєстру, вимагають ручного підтвердження артефактів або відокремлюють комп’ютери, підключені до Інтернету, від хостів для розробки.
:::

У цьому робочому процесі використовуйте пристрій, підключений до Інтернету, щоб отримати пакет встановлення, а потім перемістіть завантажений каталог на цільовий хост за допомогою USB-накопичувача, внутрішньої мережевої теки або внутрішнього розташування, де розміщено пакет.

## Завантажте автономний пакет SDK.

Виконайте команду для цільової архітектури хоста на машині, яка має доступ до служб пакета SiMa.ai.

Для хостів `amd64`:

<ShellCommand prompt="host">
sima-cli neat install sdk@v2.1.3.0 -t offline-amd64
</ShellCommand>

Для хостів `arm64`:

<ShellCommand prompt="host">
sima-cli neat install sdk@v2.1.3.0 -t offline-arm64
</ShellCommand>

Скопіюйте завантажену теку на цільовий хост. З цієї теки запустіть:

<ShellCommand prompt="host">
bash ./install_offline_sdk.sh
</ShellCommand>

:::note
Офлайн-пакети SDK підтримуються для SDK версії 2.1.3.0 або новішої.
:::

## Завантажте автономний пакет Model Compiler.

Завантажте пакет Model Compiler, який відповідає цільовому середовищу та вимогам сумісності з SDK. Щоб отримати детальну інформацію про сумісність, див. [Сумісність](/getting-started/compatibility/#model-compiler).

Для Model Compiler 2.1.3 на хостах `amd64`:

<ShellCommand prompt="host">
sima-cli neat install model-compiler/amd64@v2.1.3 -t offline
</ShellCommand>

Для Model Compiler версії 2.1.3 на хостах `arm64`:

<ShellCommand prompt="host">
sima-cli neat install model-compiler/arm64@v2.1.3 -t offline
</ShellCommand>

:::note
Офлайн-пакети підтримуються для Model Compiler, версії 2.1.3 або новішої, для Model Compiler.
:::

Щоб встановити Model Compiler у Neat SDK, скопіюйте завантажену теку до теки робочого простору хоста, яка пов’язана з контейнером SDK, а саме до теки `/workspace`. Потім відкрийте командний рядок SDK і запустіть інсталятор із відповідного шляху `/workspace`:

<ShellCommand prompt="sdk">
cd /workspace/model-compiler-offline-amd64
bash ./install_modelsdk_wheels.sh
</ShellCommand>

Якщо ви завантажили пакет для ARM64, використовуйте назву каталогу `arm64`.

Для автономної інсталяції на хості скопіюйте завантажений каталог безпосередньо до цільового хосту та запустіть той самий інсталятор із цього каталогу.

Після інсталяції перезавантажте середовище вашої оболонки або перезапустіть оболонку SDK. Потім активуйте Model Compiler за допомогою:

<ShellCommand prompt="sdk|host">
activate-model-compiler
</ShellCommand>

Щоб вийти з середовища Model Compiler, виконайте команду:

<ShellCommand prompt="sdk|host">
deactivate-model-compiler
</ShellCommand>

## Внутрішні пакети хостингу

Якщо ваша організація використовує затверджені артефакти внутрішньо, зберігайте структуру завантаженої директорії з пакетом під час публікації у внутрішньому сховищі. Очікується, що файл метаданих, скрипт встановлення, контрольні суми та ресурси пакета залишатимуться разом.

Користувачі зможуть завантажити внутрішню директорію з пакетом і запустити той самий скрипт встановлення на цільовому хості.

## Автономні пакети Core

Завантажте архіви на комп’ютері з доступом до мережі та скопіюйте їх на підготовлений Modalix DevKit. Типовий профіль містить пакет середовища виконання та додаткові навчальні матеріали й тести. Використовуйте `-t minimal`, щоб виключити додаткові матеріали. Інсталятор на цільовому пристрої перевіряє сумісність ОС, архітектури та Platform.

```bash
sima-cli neat install core/offline@v0.6.0 --download-only
sima-cli neat install core/offline@v0.6.0 -t minimal --download-only
```

Розпакуйте `neat-core-offline-installer.tar.gz`, а потім виконайте `cd neat-core-offline && sudo ./install.sh`. За потреби розпакуйте окремий архів із навчальними матеріалами й тестами у вибрану теку.

Інсталятор підтримує лише Neat eLxr SDK або підготовлений Modalix DevKit. Він порівнює `/etc/sdk-release` або `/etc/buildinfo` з маніфестом пакета в архіві; завантажені метадані публікації не потрібні. Інші середовища й несумісні версії Platform відхиляються до встановлення. У SDK Core копіюється до `/opt/toolchain/aarch64/modalix`. Якщо задано `DEVKIT_SYNC_DEVKIT_IP`, той самий автономний пакет передається через SSH на спарований DevKit. Перед початком встановлення обидва середовища мають пройти попередню перевірку. На DevKit встановлення виконується локально.

Автономному інсталятору в стандартному контейнері SDK не потрібні `unshare`, привілейований режим або додаткові можливості контейнера. Він розпаковує пакети в sysroot та дозволяє лише локальні методи APT `file`, `copy` і `store`. HTTP, HTTPS та інші мережеві транспорти вимкнено; відсутні залежності спричиняють помилку без переходу до онлайн-джерел. Встановлення безпосередньо на DevKit зберігає ізольований мережевий простір імен.

Нативний інсталятор використовує план офлайн-транзакції APT і резервує потрійний розмір розпакованих пакетів Debian, вибраних для встановлення або перевстановлення, та всіх Python wheel, а також 128 MiB для метаданих і середовища Python. Залежності, які APT не змінює, не входять до цього бюджету місця. Уже розміщені архіви, зокрема на NVMe або tmpfs, повторно не враховуються. У разі нестачі місця повідомлення показує доступний, потрібний і додатково необхідний простір кореневої файлової системи в MiB.

Для передавання на спарений DevKit використовується приватний каталог у `/tmp`, який на стандартному DevKit розміщений у RAM. Каталог видаляється після завершення операції, зокрема в разі повідомленої помилки встановлення або незавершеного передавання. Якщо SSH розриває з’єднання або перевищує час очікування під час встановлення, каталог зберігається, а його шлях виводиться, оскільки віддалений інсталятор може ще працювати.
