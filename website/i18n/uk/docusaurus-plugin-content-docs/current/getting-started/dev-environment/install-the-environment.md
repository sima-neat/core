Встановіть останню версію Palette SDK. Palette SDK працює як контейнер на вашому хості.

## Передумови

- Переконайтеся, що ваш хост відповідає
  [вимогам до хоста](/getting-started/dev-environment/#host-requirements),
  зокрема що у вас є права адміністратора/`sudo` для встановлення.
- Встановіть `sima-cli` на хост-машину за
  [посібником із встановлення sima-cli](/tools/sima-cli/).
- Виконайте налаштування хоста, потрібне для вашої платформи:
  - [Нотатки щодо хоста Ubuntu](/reference/elxr-sdk-host-setup/ubuntu)
  - [Нотатки щодо хоста Windows](/reference/elxr-sdk-host-setup/windows)
  - [Нотатки щодо хоста macOS](/reference/elxr-sdk-host-setup/macos)

Щоб пізніше використовувати DevKit Sync, вам також знадобляться:

- DevKit із програмним забезпеченням, сумісним із Palette SDK. Докладніше див. у [посібнику із сумісності](/getting-started/compatibility/).
- Хост-машина та DevKit в одній мережі, де дозволено трафік NFS.
- IP-адреса вашого DevKit.

## Встановлення

Встановіть поточний випуск Palette SDK %%release.sdk%% із серії %%release.sdk_series%%:

<ShellCommand prompt="host">
sima-cli neat install sdk@v%%release.sdk%%
</ShellCommand>

Перше встановлення може тривати кілька хвилин, оскільки завантажується образ контейнера Palette SDK. Після завантаження образу програма встановлення запускає налаштування SDK і запитує, чи хочете ви під’єднати Modalix DevKit і чи встановлювати відповідний Model Compiler усередині SDK.

Якщо ви вирішите під’єднати DevKit, введіть його IP-адресу, коли з’явиться запит. Під час налаштування буде сконфігуровано робочий простір SDK, запущено контейнер SDK і налаштовано DevKit Sync. Якщо ви пропустите під’єднання, робочий простір SDK однаково буде створено, і ви зможете під’єднати DevKit пізніше.

Для встановлення SDK використовуйте опублікований тег `v%%release.sdk%%`. Образ гілки `%%release.sdk_channel%%` може спричинити помилку, коли налаштування встановлює необов’язкові розширення Codex і Claude. Сумісну версію програмного забезпечення DevKit наведено в [посібнику із сумісності](/getting-started/compatibility/).

Під час налаштування `sima-cli` також пропонує встановити відповідний Model Compiler усередині SDK — погодьтеся, якщо самостійно компілюєте або квантуєте моделі; окремо вибирати версію не потрібно. Пропустіть цей крок, якщо ви запускаєте лише попередньо скомпільовані пакети моделей. Щоб встановити його пізніше, зафіксувати конкретну патч-версію або використати окремий хост, див. [Встановлення Model Compiler](/getting-started/dev-environment/install-model-compiler/) і [посібник із сумісності](/getting-started/compatibility/).

### Встановлення конкретної версії SDK {#install-a-specific-sdk-version}

Для SDK 2.1.3.0 і новіших версій використовуйте опублікований тег `v<version>`, щоб встановити конкретну версію, зокрема старіший випуск із виправленнями. Наприклад, виконайте на хості:

<ShellCommand prompt="host">
sima-cli neat install sdk@v2.1.3.0
</ShellCommand>

Префікс `v` обов’язковий. Не використовуйте `release-<full-version>` як тег конкретної версії. Канал `release-<series>` відстежує останній опублікований випуск у цій серії. Якщо обидва способи вибирають той самий пакет SDK, вони виконують однакові кроки встановлення та налаштування SDK.

Опубліковані теги можна знайти у [випусках SDK](https://github.com/sima-neat/sdk/releases); виберіть версію, сумісну з програмним забезпеченням вашого DevKit, за допомогою [посібника із сумісності](/getting-started/compatibility/).

:::note Застаріле двоетапне встановлення
SDK 2.0.0, 2.1.2.0 і 2.1.2.1 потребують окремих команд для завантаження образу та налаштування. Лише для цих випусків див. [Двоетапне встановлення SDK](/reference/two-step-sdk-installation/).
:::

Щоб змінити налаштування SDK після встановлення, див.
[Налаштування SDK](/getting-started/dev-environment/configure-sdk/). Для мережевих середовищ з обмеженим доступом див.
[Офлайн-встановлення](/getting-started/dev-environment/offline-installation/).

## Доступ до SDK

Після успішного налаштування ви можете працювати з SDK через термінал, браузер Chrome або VS Code.

### Використання оболонки SDK

Відкрийте оболонку Palette SDK командою:

<ShellCommand prompt="host">
sima-cli sdk neat
</ShellCommand>

### Використання браузера Chrome

Neat Insight працює всередині SDK, і його можна відкрити в браузері.
В оболонці SDK виконайте:

<ShellCommand prompt="sdk">
neat
</ShellCommand>

Вивід `neat` містить розділ **Web Access** із локальними та віддаленими URL-адресами для Insight і браузерного VS Code. Якщо браузер працює на хості SDK, відкрийте локальну URL-адресу `127.0.0.1`. З іншого комп’ютера використовуйте віддалену URL-адресу на основі `NFS_SERVER_HOST_IP`. URL-адреса VS Code відкриває налаштований робочий простір; використовуйте облікові дані, які `neat` показує для встановленого сервера. Див. [Вебдоступ SDK](/reference/environment-variables/) та [Insight](/tools/insight/).

### Використання VS Code

Виконайте `neat` в оболонці SDK та відкрийте URL-адресу **VS Code (local)** у браузері на хості SDK. З іншого комп’ютера використовуйте **VS Code (remote)**. Для образів із code-server команда `neat` також показує **VS Code password**:

```text
VS Code (local)    https://127.0.0.1:10000/?folder=/workspace
VS Code password   <password shown by neat>
```

Введіть показаний пароль на екрані входу code-server. Пароль не міститься в URL-адресі.

Застарілі образи OpenVSCode натомість використовують URL-адресу з токеном; відкрийте адресу, яку показує `neat`. SDK містить попередньо встановлені розширення Codex і Claude Code для браузерного Code UI.

Якщо ви віддаєте перевагу нативному VS Code замість браузера, можна використати і його. Підключіть VS Code до контейнера SDK за допомогою [Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers).

Один раз виконайте `sima-cli login` у контейнері SDK, щоб SDK міг отримувати ресурси, як-от попередньо зібрані моделі.

## Оновлення

Щоб перевстановити SDK або оновити його до поточного пакета, повторно виконайте на хості наведену вище команду встановлення:

<ShellCommand prompt="host">
sima-cli neat install sdk@v%%release.sdk%%
</ShellCommand>

Щоб оновити Neat Library в наявному контейнері Palette SDK, запустіть Neat
CLI в оболонці контейнера:

<ShellCommand prompt="sdk">
neat update
</ShellCommand>

Ця команда оновлює встановлені компоненти Neat Library в поточному Palette SDK. Вона не замінює повного оновлення образу контейнера, якщо вам потрібні зміни на рівні контейнера.

Якщо пізніше ви видалите або створите заново контейнер Palette SDK, знову виконайте `neat update` у новому контейнері.

## Видалення

Щоб видалити встановлений контейнер SDK, виконайте:

<ShellCommand prompt="host">
sima-cli sdk remove
</ShellCommand>

## Наступний крок

- **Компілюєте модель у SDK?** Перейдіть до сторінки
  [Компіляція моделі](/compile-a-model/) — компіляція повністю виконується в SDK, DevKit не потрібен.
- **Під’єднуєте DevKit?** Налаштуйте
  [DevKit Sync](/getting-started/dev-environment/devkit-sync/), щоб спільно використовувати робочий простір SDK і виконувати команди `dk` на апаратному забезпеченні.
