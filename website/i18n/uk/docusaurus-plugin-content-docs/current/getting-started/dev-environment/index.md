Palette SDK — рекомендований робочий простір на стороні хоста для створення масштабних застосунків Neat і їх перевірки на Modalix DevKit. Він об’єднує в одному контейнеризованому робочому процесі інструменти збірки, інструменти для моделей, підключення до апаратного забезпечення та контекст початкового коду, готовий для агентів.

SDK поєднує три місця:

- **Хост-машина:** тут ви встановлюєте та запускаєте контейнер SDK.
- **Контейнер SDK:** тут ви збираєте застосунки, компілюєте моделі, користуєтеся інструментами для агентів
  і переглядаєте спільні файли.
- **Modalix DevKit:** тут скомпільовані артефакти моделей і застосунки Neat працюють
  на апаратному забезпеченні.

DevKit Sync поєднує ці місця спільним `/workspace`, тому результати збірки, журнали, артефакти моделей і файли застосунків видно з хоста, контейнера SDK і DevKit без ручного копіювання. Цей спільний робочий простір — центр робочого процесу SDK.

<div class="overview-section-label">Почніть тут</div>

Почніть із встановлення SDK. До інших тем про SDK звертайтеся, коли потрібно змінити налаштування, пізніше додати Model Compiler, розібратися, як працює DevKit Sync, або підготувати пакети для офлайн-встановлення в мережах з обмеженим доступом.

[Встановлення SDK](/getting-started/dev-environment/install-the-environment/),
потім [Компіляція моделі](/compile-a-model/) — компіляція моделі повністю виконується в

:::

## Що входить до складу

- **Середовище крос-компіляції:** збирайте застосунки Neat на C++ для Modalix
  у контейнері Linux на вашому хості.
- **DevKit Sync:** під’єднайте SDK до Modalix DevKit і відкрийте той самий
  робочий простір в обох місцях.
- **Інструменти для моделей:** встановіть відповідний Model Compiler у SDK. Він
  потрібен, щоб самостійно компілювати або квантувати моделі ONNX чи GenAI, і необов’язковий
  лише тоді, коли ви використовуєте виключно попередньо скомпільовані пакети моделей.
- **Insight:** переглядайте в браузері файли робочого простору, джерела медіа, доставку потоків
  і поведінку середовища виконання.
- **Контекст для агентів:** використовуйте вбудовані навички Codex і Claude з актуальними
  посиланнями на початковий код Neat і прикладами.

## Вимоги до хоста

Перш ніж встановлювати SDK, переконайтеся, що ваш хост відповідає цим мінімальним вимогам.
Права адміністратора (`sudo`) потрібні для встановлення SDK на кожному підтримуваному хості, а не лише для необов’язкового налаштування мережі DevKit, оскільки встановлення `sima-cli`, Docker Engine, образу SDK і пакетів NFS потребує підвищених прав.

| ОС хоста | Процесор | Оперативна пам’ять | Вільне місце на диску | Права адміністратора / sudo |
| --- | --- | --- | --- | --- |
| Ubuntu 22.04 / 24.04 (`x86_64` або `arm64`) | щонайменше 4 ядра | щонайменше 16 ГБ | 100 ГБ | `sudo` для встановлення SDK (`sima-cli`, Docker, образ SDK), встановлення й налаштування NFS, а також налаштування спільної мережі та брандмауера |
| Windows 11 через WSL (`x86_64`) | щонайменше 4 ядра | щонайменше 16 ГБ | 100 ГБ | Права адміністратора для встановлення SDK у WSL (Docker, `sima-cli`), налаштування мережі WSL і правил брандмауера для NFS |
| macOS 15.5+ на Apple Silicon (`arm64`) | щонайменше 4 ядра | щонайменше 16 ГБ | 100 ГБ | Права адміністратора для встановлення SDK (Homebrew, Colima, `sima-cli`), повного доступу до диска (`nfsd`) і спільного доступу до Інтернету |

:::note Компіляція моделей GenAI потребує більше ресурсів
Компіляція моделей GenAI за допомогою LLiMa значно вимогливіша, ніж базовий SDK: рекомендовано 128 ГБ оперативної пам’яті, бажано мати 512 ГБ дискового простору, а більша кількість ядер теж допомагає.
Повні вимоги див. у розділі [Налаштування GenAI](/genai-llima/setup/).
:::

## Підтримувані платформи

| Платформа | Архітектура | SDK | Model Compiler |
| --- | --- | --- | --- |
| Ubuntu 22.04 і 24.04 через Docker Engine | `x86_64` | Так | Так |
| Windows 11 через WSL і Docker Engine | `x86_64` | Так | Так |
| Ubuntu 22.04 і 24.04 через Docker Engine | `arm64` | Так | Model Compiler 2.1.2 і новіші |
| macOS 15.5 або новіша через Colima | `arm64` | Так | Model Compiler 2.1.2 і новіші; встановлюйте його всередині Palette SDK |

:::note Назви архітектур
`arm64` і `aarch64` — це одна й та сама 64-бітна архітектура Arm: macOS називає її `arm64`, а Linux — `aarch64`. Так само `x86_64` і `amd64` — одна й та сама архітектура. Виконайте `uname -m` на хості (або всередині SDK), щоб дізнатися, яка у вас. Команди встановлення Model Compiler використовують `arm64` і `amd64` — див. [Встановлення Model Compiler](/getting-started/dev-environment/install-model-compiler/).
:::

:::note Встановлення певної версії
На сторінці [Встановлення SDK](/getting-started/dev-environment/install-the-environment/) використовується опублікований тег `v%%release.sdk%%` для поточного випуску серії %%release.sdk_series%%. Інші версії SDK, Neat Library або Model Compiler наведено в [посібнику із сумісності](/getting-started/compatibility/).
:::

## Інструменти в SDK

SDK — рекомендоване місце для встановлення та оновлення
[Neat Library](/getting-started/neat-library/), коли ви розробляєте
застосунки для під’єднаного DevKit.

Як отримати доступ до SDK з терміналу, VS Code або браузера через Neat Insight, див.
[Встановлення SDK](/getting-started/dev-environment/install-the-environment/#access-the-sdk).

Під час налаштування SDK `sima-cli` пропонує автоматично встановити відповідний Model Compiler. Встановіть його, якщо самостійно компілюєте або квантуєте моделі; якщо ви використовуєте лише попередньо скомпільовані пакети моделей, його можна пропустити. Про налаштування й використання компілятора див. [Компіляція моделі](/compile-a-model/).
