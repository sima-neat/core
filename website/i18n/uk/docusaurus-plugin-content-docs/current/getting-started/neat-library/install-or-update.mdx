На цій сторінці описано, як установити або оновити Neat Library.

:::tip Neat Library у складі Palette SDK
Якщо під час `sima-cli sdk setup` ви під’єднуєте DevKit, SDK автоматично встановлює на DevKit власну Neat Library та вбудоване середовище PyNeat у `~/pyneat`.
:::

:::tip Коли використовувати офлайн-встановлення
Якщо цільова система не може завантажувати пакети зі служб SiMa.ai, скористайтеся [офлайн-встановленням](#offline-installation).
Завантажте пакет на комп’ютері з доступом до інтернету.
:::

## Вибір місця встановлення

Запускайте програму встановлення в тому середовищі, де ви збираєте або запускаєте застосунки Neat:

| Середовище | Коли використовувати |
| --- | --- |
| Palette SDK | Ви хочете оновити Neat Library у Palette SDK, не встановлюючи нову версію SDK. |
| ROS2 SDK | Ви хочете компілювати застосунки ROS 2 нативно на ARM64 із заголовками та бібліотеками Neat, встановленими в системні шляхи контейнера. |
| DevKit | Ви хочете встановити або оновити середовище виконання безпосередньо на пристрої. |

## Пакети для розробки на C++

Мінімальне встановлення містить середовище виконання та `sima-neat-dev`. Встановлення за замовчуванням пропонує навчальні посібники й тести як необов’язкові доповнення; `all` містить їх.
Застосункам, що використовують динамічні бібліотеки, потрібні публічні заголовки Core,
відповідний фронтенд Scheduler і файли для розробки GStreamer, OpenCV
та JSON. Їм не потрібні виведений з ужитку парасольковий пакет Internals чи API для розробки
Runner, Kernels, Codecs, бібліотеки пам’яті, heap або LLiMa. Вибрані пакети
постачають потрібні залежності середовища виконання.

Використовуйте встановлену динамічну ціль:

```cmake
find_package(SimaNeat CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE SimaNeat::sima_neat)
```

Статичний архів залишається в `sima-neat-dev`. Використовуйте `COMPONENTS Static`
і не видаляйте відповідний пакет `simaai-scheduler`. Встановіть
`zlib1g-dev`, `libcpp-httplib-dev`, а для збірок з LLiMa — `sima-lmm-dev`, разом
з їхніми залежностями. Core використовує встановлений фронтенд
Scheduler; не додавайте до свого застосунку цілі для розробки Internals чи бібліотек нижчого рівня:

```cmake
find_package(SimaNeat CONFIG REQUIRED COMPONENTS Static)
target_link_libraries(my_app PRIVATE SimaNeat::sima_neat_static)
```

Статичний Core усе одно використовує динамічні бібліотеки реалізації. Збирання
Core з початкового коду спирається на ту саму межу фронтенду Scheduler і
потребує файлів для розробки інших його залежностей, зокрема LLiMa, якщо її ввімкнено.

## Передумови встановлення через інтернет

Встановіть `sima-cli` у середовищі, де ви плануєте встановити Neat Library.
Скористайтеся [посібником зі встановлення sima-cli](/tools/sima-cli/).

Створіть обліковий запис на [community.sima.ai](https://community.sima.ai), щоб отримати доступ до ресурсів SiMa.ai, як-от попередньо скомпільованих моделей для тестування.

Автентифікуйте середовище, щоб програма встановлення могла завантажувати артефакти SiMa.ai. Докладніше див. у розділі [sima-cli login](/tools/sima-cli/login/).

<ShellCommand prompt="sdk|devkit">
sima-cli login
</ShellCommand>

Переконайтеся, що середовище має доступ до хоста артефактів SiMa.ai:

<ShellCommand prompt="sdk|devkit">
curl -fsS https://artifacts.neat.sima.ai/sima-cli/linux-mac.sh -o /dev/null && echo "artifacts reachable"
</ShellCommand>

Якщо виведено `artifacts reachable`, хост доступний. Помилка `curl`, наприклад перевищення часу очікування, відмова в з’єднанні або «could not resolve host», означає, що вихідний доступ заблоковано, — перевірте мережу хоста, проксі-сервер або брандмауер (див. [Мережа Palette SDK](/tools/sima-cli/sdk-networking/) і [нотатки щодо налаштування хоста](/reference/elxr-sdk-host-setup/ubuntu)) або скористайтеся [офлайн-встановленням](#offline-installation), якщо машина не має прямого доступу до служб SiMa.ai.

## Встановлення Neat Library

:::note Сумісність пакетів
Програма встановлення використовує всі пакети Debian, перелічені у вибраному артефакті Core, і не підбирає інших версій Scheduler або LLiMa. Встановлена платформа має задовольняти залежності, які цей артефакт не постачає. Якщо для завершення встановлення APT довелося б видалити пакети платформи, програма встановлення зупиняється; у такому разі оновіть платформу, а не підміняйте пакети в Core чи LLiMa.
:::

Перед запуском програми встановлення виберіть робочу теку. На DevKit встановлюйте в `/media/nvme`, щоб не заповнити кореневу файлову систему. У контейнері SDK використовуйте локальний для контейнера шлях, наприклад `$HOME/neat`.

Виберіть своє середовище, а потім виконайте кроки по порядку. Встановлюйте в контейнер **Palette SDK**, щоб виконувати крос-компіляцію застосунків C++. Встановлюйте в **ROS2 SDK**, щоб компілювати нативно на ARM64; його пакети Debian встановлюються в `/usr`, а не в sysroot крос-компіляції Neat. Встановлюйте на **DevKit**, щоб налаштувати середовище виконання на ньому; при цьому також розгортається PyNeat у `~/pyneat`. Команда програми встановлення однакова в усіх середовищах.

<CodeTabs>
<CodeTab label="Palette SDK" lang="bash">

Підготуйте локальну для контейнера теку встановлення, наприклад `$HOME/neat`:

<ShellCommand prompt="sdk">
cd $HOME && mkdir -p neat && cd neat
</ShellCommand>

Встановіть пакет Neat Library за замовчуванням, вибраний `sima-cli`. За бажанням можна встановити доповнення, зокрема попередньо зібрані навчальні посібники, навчальні посібники з початковим кодом і тести:

<ShellCommand prompt="sdk">
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>

<CodeTab label="ROS2 SDK" lang="bash">

Переконайтеся, що контейнер ідентифікує себе як нативний ROS2 SDK і повідомляє базу сумісності платформи, яку очікує пакет Neat:

<ShellCommand prompt="sdk">
grep -E '^(SDK Type|Platform Base|Platform Version) =' /etc/sdk-release
</ShellCommand>

Встановіть сумісний пакет Neat. Програма встановлення перевіряє нативне середовище Debian для ARM64, імітує транзакцію APT із забороненим видаленням пакетів і встановлює пакети середовища виконання та для розробки в системні шляхи контейнера. PyNeat не встановлюється, оскільки він і надалі залишається функцією середовища виконання DevKit:

<ShellCommand prompt="sdk">
cd $HOME &amp;&amp; mkdir -p neat &amp;&amp; cd neat
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>

<CodeTab label="DevKit" lang="bash">

:::note Спочатку оновіть прошивку DevKit
Перш ніж встановлювати Neat Library на DevKit, переконайтеся, що версія програмного забезпечення DevKit сумісна з Neat Library. Докладніше див. у
[Посібнику із сумісності](/getting-started/compatibility/).
:::

Підготуйте теку встановлення в `/media/nvme`, щоб не заповнити кореневу файлову
систему:

<ShellCommand prompt="devkit">
cd /media/nvme && mkdir -p neat && cd neat
</ShellCommand>

Встановіть пакет Neat Library за замовчуванням, вибраний `sima-cli`. За бажанням можна встановити доповнення, зокрема попередньо зібрані навчальні посібники, навчальні посібники з початковим кодом і тести:

<ShellCommand prompt="devkit">
sima-cli neat install core@v%%release.core%%
</ShellCommand>

</CodeTab>
</CodeTabs>

## Середовище PyNeat за замовчуванням під час встановлення через інтернет

Встановлення Neat Library на DevKit також створює на DevKit віртуальне середовище PyNeat за замовчуванням у `~/pyneat`. Це підтримуване середовище PyNeat — активуйте його безпосередньо:

<ShellCommand prompt="devkit">
source ~/pyneat/bin/activate
</ShellCommand>

Якщо ви запускаєте програму встановлення всередині контейнера SDK, під’єднаного до DevKit через DevKit Sync, програма встановлення розгортає PyNeat на під’єднаному DevKit, а не лише всередині контейнера SDK. PyNeat встановлюється у віртуальне середовище в `~/pyneat` на DevKit.

Про власні віртуальні середовища Python див. у розділі
[Встановлення PyNeat](/getting-started/neat-library/pyneat/).

## Збирання з початкового коду

Збирайте з початкового коду, коли вам потрібна ще не випущена зміна, власна конфігурація збирання або коли ви робите внесок у Neat Library. Більшості користувачів натомість варто використовувати пакетне встановлення, описане вище.

Якщо ви віддаєте перевагу збиранню з початкового коду, дотримуйтеся посібника
[Збирання](/develop-apps/contribute/build).

Про налаштування SDK і початок роботи з DevKit Sync див. у розділі
[Palette SDK](/getting-started/dev-environment/).

## Офлайн-встановлення {#offline-installation}

:::caution Перевірте залежності Python перед встановленням
Офлайн-встановлення зберігає наявні середовища Python разом із додатковими пакетами та файлами в них. Перед встановленням пакетів виконується `pip check`. Якщо середовище вже пошкоджене, встановлення зупиняється й повідомляє шлях до середовища та помилки залежностей. Виправте зазначені залежності (в офлайн-режимі — за допомогою додаткових wheel-пакетів), а потім повторіть спробу. Перевірка залежностей після встановлення повідомляє про конфлікти, що залишилися або щойно виникли; зміни пакетів автоматично не відкочуються.

Щоб відкинути середовище й установити все з нуля, явно виконайте `./install.sh --recreate-venv` (окремий Core) або `sudo python3 -B install.py --recreate-venv` (PCIe). Це видаляє пакети та файли у вибраному середовищі без резервної копії. У SDK цей параметр застосовується до під’єднаного DevKit, а не до Python на хості SDK. Спочатку збережіть потрібні файли. Команди попередньої перевірки та команди лише для перевірки ніколи не створюють середовища заново.
:::

Офлайн-пакети Neat Library доступні у версії 0.6.0 і новіших.
Використовуйте цей пакет для Modalix DevKit із Platform 3.0 або новішою.

### 1. Завантажте пакет

Встановіть `sima-cli` на комп’ютері з доступом до інтернету. Див. [посібник зі встановлення sima-cli](/tools/sima-cli/).

Виконайте цю команду на комп’ютері з доступом до інтернету:

<ShellCommand prompt="host">
sima-cli neat install core/offline@v%%release.core%% --download-only
</ShellCommand>

Пакет за замовчуванням містить середовище виконання, навчальні посібники та тести.
Щоб завантажити лише середовище виконання, використовуйте:

<ShellCommand prompt="host">
sima-cli neat install core/offline@v%%release.core%% -t minimal --download-only
</ShellCommand>

### 2. Встановіть пакет

1. Скопіюйте завантажені файли на Modalix DevKit або в робочий простір Palette SDK.
2. Відкрийте термінал у цій теці. Для встановлення в SDK використовуйте оболонку SDK.
3. Видобудьте архів програми встановлення:

Назва завантаженого архіву може мати 8-символьний суфікс SHA-256 перед `.tar.gz`. Перед видобуванням залиште в цій теці лише вибраний архів програми встановлення.

<ShellCommand prompt="sdk|devkit">
tar -xzf neat-core-offline-installer*.tar.gz
</ShellCommand>

4. Перейдіть до видобутої теки:

<ShellCommand prompt="sdk|devkit">
cd neat-core-offline
</ShellCommand>

5. Запустіть програму встановлення від імені звичайного користувача. За потреби вона запитає дозволи `sudo`.

<ShellCommand prompt="sdk|devkit">
./install.sh
</ShellCommand>

Якщо вам потрібні навчальні посібники або тести, видобудьте окремий архів доповнень у будь-яку теку на ваш вибір.

Після офлайн-встановлення активуйте середовище Python так:

<ShellCommand prompt="devkit">
source ~/pyneat/bin/activate
</ShellCommand>

Офлайн-встановлення повторно використовує наявне `~/pyneatpcie` на хості або `~/pyneat` на карті чи DevKit, зокрема ціль його символічного посилання. Якщо середовища в домашній теці немає, карта або DevKit використовує `/media/nvme/pyneat`, коли користувач, який виконує встановлення, має право запису на NVMe; інакше використовується `~/pyneat`. Нове встановлення на NVMe створює посилання `~/pyneat`, не замінюючи наявного середовища в домашній теці.

### Параметри пакета та поведінка програми встановлення

- Перед встановленням програма встановлення перевіряє сумісність системи та доступне місце на диску.
- Програма встановлення використовує вбудовані залежності. Якщо потрібна залежність відсутня, вона зупиняється.
- У SDK програма встановлення копіює Neat Library до `/opt/toolchain/aarch64/modalix`.
- Якщо задано `DEVKIT_SYNC_DEVKIT_IP`, програма встановлення також встановлює пакет на під’єднаний DevKit через SSH. Обидва середовища мають пройти перевірки.

Якщо встановлення завершилося помилкою, прочитайте журнал за виведеним шляхом: `/tmp/neat-core-offline-*.log`.
Для докладного виводу використовуйте `./install.sh --verbose`.

Якщо під час встановлення SSH-з’єднання розірветься, віддалена програма встановлення може продовжити роботу.
Перш ніж повторювати спробу або видаляти тимчасову теку, зазначену у звіті, переконайтеся, що програма зупинилася.
