На цій сторінці описано, як установити пакет Neat для PCIe-хоста на Linux-машину, під’єднану до
карти Modalix PCIe.

Пакет Neat для PCIe-хоста надає API співобробки, які дають змогу надсилати вхідні дані з
хост-машини на під’єднану карту Modalix PCIe та отримувати результати інференсу.

:::warning Встановлюйте на хост-машині PCIe
Виконуйте це встановлення на **хост-машині PCIe**, до якої під’єднано карту Modalix PCIe. Не запускайте його всередині контейнера Palette SDK, на DevKit або на самій карті Modalix PCIe.
:::

:::tip Коли використовувати офлайн-встановлення
Якщо цільова система не може завантажувати пакети зі служб SiMa.ai, скористайтеся [офлайн-встановленням](#offline-installation).
Завантажте пакет на комп’ютері з доступом до інтернету.
:::

## Підтримувані операційні системи хоста

Пакет Neat для PCIe-хоста підтримує такі перевірені платформи хоста:

| Операційна система | Архітектура | Підтримка |
| --- | --- | --- |
| Ubuntu 22.04 | x86_64 | Підтримується |
| Ubuntu 24.04 | x86_64 | Підтримується |

Збірки для хостів Arm64 ще не перевірено. Windows 11 не підтримується.

## Передумови встановлення через інтернет

Перед встановленням пакета:

- Встановіть `sima-cli` на PCIe-хост. Скористайтеся
  [посібником зі встановлення sima-cli](/tools/sima-cli/).
- Встановіть і перевірте драйвер PCIe-хоста, дотримуючись
  [посібника зі встановлення драйвера PCIe](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation).
- Під’єднайте та налаштуйте карту Modalix PCIe так, щоб її інтерфейс керування був
  доступний із хоста. Адреса для карти 0 за замовчуванням — `10.0.0.2`.
- Встановіть на карту сумісну версію Neat Library. Пакети для хоста й
  карти мають походити із сумісних випусків.

Автентифікуйте PCIe-хост, щоб він міг завантажувати артефакти SiMa.ai:

<ShellCommand prompt="pcie-host">
sima-cli login
</ShellCommand>

## Встановлення пакета для PCIe-хоста

Виберіть робочу теку на PCIe-хості, а потім виконайте команду для встановленої версії Ubuntu.

**Ubuntu 22.04 на x86_64:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu22/amd64@v%%release.core%%
</ShellCommand>

**Ubuntu 24.04 на x86_64:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu24/amd64@v%%release.core%%
</ShellCommand>

Програма встановлення додає все потрібне для розробки та запуску застосунків Neat для PCIe-хоста, зокрема API C++ і середовище Python у `~/pyneatpcie`.

Вона також встановлює вбудовану в пакет навичку агента програмування `neat-pcie-application-builder` для Codex і Claude. Повторне встановлення пакета для PCIe-хоста оновлює встановлену навичку до відповідної версії пакета.

Під час першого встановлення налаштування SSH може запитати пароль облікового запису `sima` на карті. Воно створює або повторно використовує `~/.ssh/sima_neat_pcie_ed25519` і встановлює його відкритий ключ на карту. Далі під час звичайної роботи з PCIe для налаштування моделі на боці карти використовується SSH без пароля.

## Перевірка встановлення через інтернет

Переконайтеся, що API Python і плагін PCIe-хоста доступні:

<ShellCommand prompt="pcie-host">
source ~/pyneatpcie/bin/activate
python3 -c "import pyneatpcie; print('pyneatpcie ready')"
gst-inspect-1.0 neatpciehost
</ShellCommand>

## Усунення несправностей

Якщо налаштування SSH не може автоматично виявити карту, спочатку перевірте, чи доступна з хоста її адреса керування:

<ShellCommand prompt="pcie-host">
ping -c 1 10.0.0.2
</ShellCommand>

Потім запустіть встановлену утиліту налаштування, явно вказавши адресу:

<ShellCommand prompt="pcie-host">
pcie-setup.sh --hosts "10.0.0.2"
</ShellCommand>

Якщо встановлення пакета або запуск середовища виконання завершується помилкою, переконайтеся, що пакет для PCIe-хоста й Neat Library, встановлена на карті, походять із сумісних випусків.

## Офлайн-встановлення {#offline-installation}

:::caution Перевірте залежності Python перед встановленням
Офлайн-встановлення зберігає наявні середовища Python разом із додатковими пакетами та файлами в них. Перед встановленням пакетів виконується `pip check`. Якщо середовище вже пошкоджене, встановлення зупиняється й повідомляє шлях до середовища та помилки залежностей. Виправте зазначені залежності (в офлайн-режимі — за допомогою додаткових wheel-пакетів), а потім повторіть спробу. Перевірка залежностей після встановлення повідомляє про конфлікти, що залишилися або щойно виникли; зміни пакетів автоматично не відкочуються.

Щоб відкинути середовище й установити все з нуля, явно виконайте `./install.sh --recreate-venv` (окремий Core) або `sudo python3 -B install.py --recreate-venv` (PCIe). Це видаляє пакети та файли у вибраному середовищі без резервної копії. У SDK цей параметр застосовується до під’єднаного DevKit, а не до Python на хості SDK. Спочатку збережіть потрібні файли. Команди попередньої перевірки та команди лише для перевірки ніколи не створюють середовища заново.
:::

Офлайн-пакети Neat PCIe доступні у версії 0.6.0 і новіших.

Пакет PCIe встановлює Neat на хост і на всі під’єднані сумісні карти.
Для цього встановлення цільовій системі не потрібні ні Docker, ні доступ до інтернету.
Хост повинен мати робоче мережеве з’єднання PCIe з кожною картою.

### 1. Підготуйте хост і карти

Перед запуском програми встановлення Neat виконайте такі завдання:

- Встановіть сумісний драйвер хоста Platform.
- Встановіть на кожну карту відповідну прошивку Platform 3.0.
- Налаштуйте виявлення на PCIe-інтерфейсі кожної карти.
- Призначте кожній карті унікальну адресу IPv4 для PCIe.
- Увімкніть сервер SSH на кожній карті та підготуйте пароль для входу.
- Надайте обліковому запису SSH дозвіл використовувати `sudo` на кожній карті.

Програма встановлення Neat не встановлює драйвер Platform і не змінює прошивку Platform.
Користуйтеся інструкціями з налаштування системи, що постачаються з вашим випуском Platform.

### 2. Завантажте пакет

Встановіть `sima-cli` на комп’ютері з доступом до інтернету. Див. [посібник зі встановлення sima-cli](/tools/sima-cli/).

Виберіть для цільового хоста версію 0.6.0 або новішу.
Пакети підтримують хости Ubuntu 22.04 та 24.04 із процесорами `amd64` або `arm64`.

У цьому прикладі версію %%release.core%% завантажують на комп’ютері з доступом до інтернету.
Для цільового хоста Ubuntu 24.04 `amd64` виконайте:

<ShellCommand prompt="host">
sima-cli neat install 'core/pciehost/ubuntu24/amd64@v%%release.core%%' -t offline -d ./pcie-offline
</ShellCommand>

Для Ubuntu 22.04 замініть `ubuntu24` на `ubuntu22`.
Для хоста `arm64` замініть `amd64` на `arm64`.
Команда завантажує та видобуває пакет. Вона не встановлює Neat.

### 3. Необов’язково: перевірте підготовлену систему

1. Скопіюйте всю теку `pcie-offline` на цільовий хост. Використовуйте шлях без пробілів.
2. Відкрийте видобуту теку `neat-offline`, яка містить `install.py`.
3. Прочитайте наданий файл `INSTALL.md`, щоб дізнатися про потрібні системні інструменти та налаштування SSH.
4. Якщо доступ SSH уже налаштовано, виконайте перевірки:

<ShellCommand prompt="host">
sudo python3 -B install.py --preflight-only
</ShellCommand>

Програма встановлення автоматично виявляє всі під’єднані карти. Не вказуйте IP-адреси карт.
Перевірки створюють тимчасові файли, але не встановлюють пакети й не налаштовують SSH.
На новому хості переходьте до встановлення, щоб програма встановлення налаштувала SSH в інтерактивному режимі.
Інші виявлені помилки виправте перед встановленням.

### 4. Встановіть пакет і перевірте результати

Виконайте цю команду з тієї самої теки:

<ShellCommand prompt="host">
sudo python3 -B install.py
</ShellCommand>

На новому хості програма встановлення створює або повторно використовує `~/.ssh/sima_neat_pcie_ed25519`
для користувача, який викликав `sudo`, і налаштовує доступ SSH до кожної виявленої карти
тим самим сценарієм налаштування, що й онлайн-встановлення. За запитом введіть пароль для входу на карту. Не потрібно окремо запускати `ssh-keygen` чи `ssh-copy-id` або вводити IP-адреси карт.

Щоб вибрати наявні облікові дані, використовуйте `--ssh-user` і `--ssh-key`. Явно вказаний
`--ssh-key` має існувати й не мати парольної фрази. Автоматична реєстрація використовує
`~/.ssh/known_hosts`; власний файл `--known-hosts` потрібно підготувати заздалегідь.
Для встановлення без участі користувача доступ SSH потрібно налаштувати заздалегідь.
Запити пароля виводяться в терміналі; паролі не зберігаються в журналах і не передаються як аргументи команд.

Програма встановлення перевіряє всі карти, перш ніж встановлювати пакети.
Спочатку вона встановлює та перевіряє хост, а потім по черзі кожну карту.
Переконайтеся, що підсумковий звіт повідомляє про успішне встановлення та перевірку для хоста й кожної карти.
Потім виконайте приймальний тест свого застосунку.

Якщо встановлення завершилося помилкою, прочитайте діагностичний журнал за виведеним шляхом.
Якщо під час встановлення з’єднання з картою обірвалося, перед повторною спробою переконайтеся, що процес встановлення на карті зупинився.
Після збою програма встановлення не відновлює попереднє встановлення автоматично.

## Наступний крок

Перейдіть до розділу [Співобробка через PCIe](/develop-apps/hello-neat/pcie/), щоб перевірити
повний шлях розробки від хоста до карти.

Офлайн-встановлення повторно використовує наявне `~/pyneatpcie` на хості або `~/pyneat` на карті чи DevKit, зокрема ціль його символічного посилання. Якщо середовища в домашній теці немає, карта або DevKit використовує `/media/nvme/pyneat`, коли користувач, який виконує встановлення, має право запису на NVMe; інакше використовується `~/pyneat`. Нове встановлення на NVMe створює посилання `~/pyneat`, не замінюючи наявного середовища в домашній теці.
