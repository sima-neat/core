Використовуйте цю сторінку для встановлення пакета Neat PCIe для хоста на комп’ютері Linux, підключеному до
PCIe-карти Modalix.

Пакет Neat PCIe для хоста надає API для спільної обробки даних, що дозволяє надсилати вхідні дані з
хост-машини на підключену PCIe-карту Modalix і отримувати результати обчислень.

:::warning Встановіть на хост-машині з інтерфейсом PCIe.
Запустіть цю програму встановлення на **хост-машині PCIe**, підключеній до PCIe-карти Modalix. Не запускайте її всередині контейнера Neat SDK, на DevKit або на PCIe-карті Modalix.
:::

:::tip Коли потрібне автономне встановлення
Якщо цільова система не може завантажити пакети зі служб SiMa.ai, використовуйте [автономне встановлення](#offline-installation).
Завантажте пакет на комп’ютері з доступом до інтернету.
:::

## Підтримувані операційні системи для хоста.

Пакет Neat PCIe для хоста підтримує такі перевірені платформи для хоста:

| Операційна система | Архітектура | Підтримка |
| --- | --- | --- |
| Ubuntu 22.04 | x86_64 | Підтримується |
| Ubuntu 24.04 | x86_64 | Підтримується |

Збірки для хоста Arm64 ще не були перевірені. Windows 11 не підтримується.

## Передумови встановлення через інтернет

Перед встановленням пакета:

- Встановіть `sima-cli` на хост PCIe. Використовуйте
  [sima-cli installation guide](/tools/sima-cli/).
- Встановіть і перевірте драйвер хоста PCIe, виконавши наступні дії:
  [PCIe Driver Installation guide](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation).
- Під’єднайте та налаштуйте плату Modalix PCIe, щоб її інтерфейс керування був доступним.
  доступний з хоста. Адреса за замовчуванням для карти 0: `10.0.0.2`.
- Встановіть сумісну версію Neat Library на картку. Хост і
  пакети карт повинні надходити з сумісних версій.

Авторизуйте хост PCIe, щоб він міг завантажувати артефакти SiMa.ai:

<ShellCommand prompt="pcie-host">
sima-cli login
</ShellCommand>

## Встановіть пакет PCIe Host.

Оберіть робочу директорію на хості PCIe, а потім виконайте команду для встановленої версії Ubuntu.

**Ubuntu 22.04 на x86_64:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu22/amd64@v%%release.core%%
</ShellCommand>

**Ubuntu 24.04 для архітектури x86_64:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu24/amd64@v%%release.core%%
</ShellCommand>

Програма встановлення додає все необхідне для розробки та запуску PCIe-застосунків Neat, зокрема, API C++ та середовище Python у `~/pyneatpcie`.

Також встановлюється включений до пакета навик агента програмування `neat-pcie-application-builder` для Codex і Claude. Повторне встановлення пакета PCIe-хоста оновлює встановлений навик до відповідної версії пакета.

Під час першого встановлення, SSH-конфігурація може запросити пароль облікового запису `sima` для карти. Вона створює або повторно використовує `~/.ssh/sima_neat_pcie_ed25519` і встановлює його відкритий ключ на карті. Подальша звичайна робота PCIe використовує SSH без пароля для налаштування моделі на стороні карти.

## Перевірте встановлення через інтернет

Підтвердіть, що API Python і плагін PCIe для хоста доступні:

<ShellCommand prompt="pcie-host">
source ~/pyneatpcie/bin/activate
python3 -c "import pyneatpcie; print('pyneatpcie ready')"
gst-inspect-1.0 neatpciehost
</ShellCommand>

## Усунення несправностей

Якщо SSH-конфігурація не може автоматично виявити карту, спочатку перевірте, чи може хост отримати доступ до її адреси керування:

<ShellCommand prompt="pcie-host">
ping -c 1 10.0.0.2
</ShellCommand>

Потім запустіть встановлену програму налаштування, вказавши в ній відповідну адресу:

<ShellCommand prompt="pcie-host">
pcie-setup.sh --hosts "10.0.0.2"
</ShellCommand>

Якщо встановлення пакета або запуск у середовищі виконання завершується невдало, переконайтеся, що пакет PCIe host і Neat Library, встановлені на карті, належать до сумісних версій.

## Автономне встановлення {#offline-installation}

:::caution Перевірте залежності Python перед установленням
Офлайн-встановлення зберігає наявні середовища Python, додаткові пакети та файли в них. Перед установленням пакетів виконується `pip check`. Якщо середовище вже пошкоджене, встановлення зупиняється та повідомляє шлях до середовища й помилки залежностей. Виправте зазначені залежності та повторіть спробу. Для офлайн-виправлення потрібні додаткові файли wheel. Перевірка після встановлення повідомляє про наявні або нові конфлікти. Зміни пакетів автоматично не відкочуються.

Лише якщо ви хочете видалити середовище та встановити все заново, явно виконайте `./install.sh --recreate-venv` (окремий Core) або `sudo python3 -B install.py --recreate-venv` (PCIe). Це видаляє пакети та файли у вибраному середовищі без резервної копії. У SDK цей параметр застосовується до спареного DevKit, а не до Python хоста SDK. Спочатку збережіть потрібні файли. Команди попередньої перевірки та перевірки без установлення ніколи не створюють середовище заново.
:::

Автономні пакети Neat PCIe доступні у версії 0.6.0 або новішій.

Пакет PCIe встановлює Neat на хості та всіх підключених сумісних картах.
Для цього встановлення цільовій системі не потрібні Docker або доступ до інтернету.
Хост повинен мати робоче мережеве з’єднання PCIe з кожною картою.

### 1. Підготуйте хост і карти

Виконайте ці завдання перед запуском програми встановлення Neat:

- Встановіть сумісний драйвер хоста Platform.
- Встановіть відповідну мікропрограму Platform 3.0 на кожній карті.
- Налаштуйте виявлення на інтерфейсі PCIe кожної карти.
- Призначте кожній карті унікальну адресу PCIe IPv4.
- Увімкніть сервер SSH на кожній карті та підготуйте пароль для входу.
- Надайте обліковому запису SSH дозвіл використовувати `sudo` на кожній карті.

Програма встановлення Neat не встановлює драйвер Platform і не змінює мікропрограму Platform.
Використовуйте інструкції з налаштування системи, що постачаються з вашим випуском Platform.

### 2. Завантажте пакет

Встановіть `sima-cli` на комп’ютері з доступом до інтернету. Див. [посібник зі встановлення sima-cli](/tools/sima-cli/).

Виберіть версію 0.6.0 або новішу для цільового хоста.
Пакети підтримують хости Ubuntu 22.04 та 24.04 з процесорами `amd64` або `arm64`.

У цьому прикладі версію %%release.core%% завантажують на комп’ютері з доступом до інтернету.
Для цільового хоста Ubuntu 24.04 `amd64` виконайте:

<ShellCommand prompt="host">
sima-cli neat install 'core/pciehost/ubuntu24/amd64@v%%release.core%%' -t offline -d ./pcie-offline
</ShellCommand>

Для Ubuntu 22.04 замініть `ubuntu24` на `ubuntu22`.
Для хоста `arm64` замініть `amd64` на `arm64`.
Команда завантажує та розпаковує пакет. Вона не встановлює Neat.

### 3. Необов’язково: перевірте підготовлену систему

1. Скопіюйте всю теку `pcie-offline` на цільовий хост. Використовуйте шлях без пробілів.
2. Відкрийте розпаковану теку `neat-offline`, яка містить `install.py`.
3. Прочитайте наданий файл `INSTALL.md`, щоб дізнатися про необхідні системні інструменти та налаштування SSH.
4. Якщо доступ SSH уже налаштовано, виконайте перевірки:

<ShellCommand prompt="host">
sudo python3 -B install.py --preflight-only
</ShellCommand>

Програма встановлення автоматично виявляє всі підключені карти. Не вказуйте IP-адреси карт.
Перевірки створюють тимчасові файли, але не встановлюють пакети й не налаштовують SSH.
На новому хості перейдіть до встановлення: програма налаштує SSH в інтерактивному режимі.
Інші повідомлені помилки виправте перед встановленням.

### 4. Встановіть пакет і перевірте результати

Виконайте цю команду з тієї самої теки:

<ShellCommand prompt="host">
sudo python3 -B install.py
</ShellCommand>

На новому хості програма встановлення створює або повторно використовує `~/.ssh/sima_neat_pcie_ed25519` користувача, який викликав `sudo`, і налаштовує доступ SSH до всіх виявлених карт.
За запитом перевірте й підтвердьте відбиток кожного нового ключа хоста, а потім за потреби введіть пароль для входу на карту. Змінені ключі хоста відхиляються. Наявні ключі та записи довірених хостів зберігаються. Не потрібно окремо запускати `ssh-keygen` чи `ssh-copy-id` або вводити IP-адреси карт.

Щоб вибрати наявні облікові дані, використовуйте `--ssh-user`, `--ssh-key` і `--known-hosts`. Явно вказаний `--ssh-key` має існувати й не мати парольної фрази. Для встановлення без участі користувача доступ SSH потрібно налаштувати заздалегідь. Паролі вводяться через термінал; вони не зберігаються в журналах і не передаються як аргументи команд.

Програма встановлення перевіряє всі карти перед встановленням пакетів.
Спочатку вона встановлює та перевіряє хост, а потім послідовно кожну карту.
Переконайтеся, що підсумковий звіт підтверджує успішне встановлення та перевірку хоста й кожної карти.
Потім виконайте приймальне тестування застосунку.

Якщо встановлення завершилося помилкою, прочитайте діагностичний журнал за вказаним шляхом.
Якщо під час встановлення з’єднання з картою втрачено, перед повторною спробою переконайтеся, що процес встановлення на карті зупинився.
Після помилки програма встановлення не відновлює попередній стан автоматично.

## Наступний крок

Продовжуйте роботу з [PCIe – спільна обробка даних](/develop-apps/hello-neat/pcie/), щоб перевірити повний процес розробки, що охоплює взаємодію між хостом і платою.

Офлайн-встановлення повторно використовує наявне `~/pyneatpcie` на хості або `~/pyneat` на карті чи DevKit, зокрема ціль символічного посилання. Якщо середовища в домашній теці немає, карта або DevKit використовує `/media/nvme/pyneat`, коли користувач, який виконує встановлення, може записувати на NVMe; інакше використовується `~/pyneat`. Нове встановлення на NVMe створює посилання `~/pyneat`, не замінюючи наявне середовище в домашній теці.
