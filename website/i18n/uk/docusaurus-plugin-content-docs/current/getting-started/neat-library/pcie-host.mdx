Використовуйте цю сторінку для встановлення пакета Neat PCIe для хоста на підтримуваному комп’ютері Linux або Windows, підключеному до PCIe-карти Modalix.

Пакет Neat PCIe для хоста надає API для спільної обробки даних, що дозволяє надсилати вхідні дані з
хост-машини на підключену PCIe-карту Modalix і отримувати результати обчислень.

:::warning Встановіть на хост-машині з інтерфейсом PCIe.
Запустіть цю програму встановлення на **хост-машині PCIe**, підключеній до PCIe-карти Modalix. Не запускайте її всередині контейнера Palette SDK, на DevKit або на PCIe-карті Modalix.
:::

:::tip Коли потрібне автономне встановлення
Якщо цільова система не може завантажити пакети зі служб SiMa.ai, використовуйте [автономне встановлення](#offline-installation).
Завантажте пакет на комп’ютері з доступом до інтернету.
:::

## Підтримувані операційні системи для хоста.

Пакет Neat PCIe для хоста підтримує такі перевірені платформи для хоста:

| Операційна система | Архітектура | Підтримка |
| --- | --- | --- |
| Ubuntu 22.04 | x86_64 | Підтримується |
| Ubuntu 24.04 | x86_64 | Підтримується |
| Windows 11 | x86_64 | Нативна попередня версія |

Збірки для хоста Arm64 ще не були перевірені. Пакет для Windows містить PCIe GenAI API, але не є підтримуваною конфігурацією для клієнтів, доки відповідний постачальник Platform і повна матриця випуску GenAI для C++ та Python у Windows не пройдуть кваліфікацію.

## Передумови встановлення через інтернет

Перед встановленням пакета:

- Встановіть `sima-cli` на хост PCIe. Використовуйте
  [sima-cli installation guide](/tools/sima-cli/).
- Встановіть і перевірте драйвер хоста PCIe, виконавши наступні дії:
  [PCIe Driver Installation guide](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation).
- Під’єднайте та налаштуйте плату Modalix PCIe, щоб її інтерфейс керування був доступним.
  доступний з хоста. Адреса за замовчуванням для карти 0: `10.0.0.2`.
- Встановіть сумісну версію Neat Library на картку. Хост і
  пакети карт повинні надходити з сумісних версій.

Авторизуйте хост PCIe, щоб він міг завантажувати артефакти SiMa.ai:

<ShellCommand prompt="pcie-host">
sima-cli login
</ShellCommand>

## Встановіть пакет PCIe Host.

Оберіть робочу директорію на хості PCIe, а потім виконайте команду для встановленої версії Ubuntu.

**Ubuntu 22.04 на x86_64:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu22/amd64@v%%release.core%%
</ShellCommand>

**Ubuntu 24.04 для архітектури x86_64:**

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/ubuntu24/amd64@v%%release.core%%
</ShellCommand>

Програма встановлення додає все необхідне для розробки та запуску PCIe-застосунків Neat, зокрема, API C++ та середовище Python у `~/pyneatpcie`.

Також встановлюється включений до пакета навик агента програмування `neat-pcie-application-builder` для Codex і Claude. Повторне встановлення пакета PCIe-хоста оновлює встановлений навик до відповідної версії пакета.

Під час першого встановлення, SSH-конфігурація може запросити пароль облікового запису `sima` для карти. Вона створює або повторно використовує `~/.ssh/sima_neat_pcie_ed25519` і встановлює його відкритий ключ на карті. Подальша звичайна робота PCIe використовує SSH без пароля для налаштування моделі на стороні карти.

## Перевірте встановлення через інтернет

Підтвердіть, що API Python і плагін PCIe для хоста доступні:

<ShellCommand prompt="pcie-host">
source ~/pyneatpcie/bin/activate
python3 -c "import pyneatpcie; print('pyneatpcie ready')"
gst-inspect-1.0 neatpciehost
</ShellCommand>

## Установлення нативної попередньої версії для Windows 11

Попередня версія для Windows — це нативна збірка Visual Studio для API обробки зображень `pcie::Model`, яка також містить `pcie::genai::GenAIModel`. Як описано вище, GenAI і надалі потребує кваліфікації для випуску; саме лише встановлення API не кваліфікує транспорт Platform або моделі на карті. Встановіть такі передумови в зазначеному порядку:

1. Пакет SiMa Platform 3.0 для Windows, що відповідає випуску Neat, згідно з [посібником зі встановлення драйвера PCIe](https://developer.sima.ai/hardware/getting-started/pcie-mode/driver-installation). Він надає драйвери PCIe і службу `SiMaMlaDaemon`.
2. GStreamer 1.28.6 MSVC x64 (`gstreamer-1.0-msvc-x86_64-1.28.6.exe` зі [сторінки завантаження GStreamer](https://gstreamer.freedesktop.org/download/)). Він також надає файли для розроблення застосунків C++.
3. 64-розрядний CPython 3.14 з [python.org](https://www.python.org/downloads/windows/), установлений для всіх користувачів або лише для поточного. Установіть Python перед `sima-cli`. Збірки з вільною багатопотоковістю (free-threaded) не можуть завантажити wheel.
4. `sima-cli` згідно з [посібником зі встановлення sima-cli](/tools/sima-cli/). Потім увійдіть за допомогою `sima-cli login`. Старіша версія `sima-cli` зупиняється з повідомленням `Missing 'script' in 'installation'`; оновіть її та повторіть спробу.

Виберіть робочий каталог на хості PCIe, а потім установіть пакет для Windows:

<ShellCommand prompt="pcie-host">
sima-cli neat install core/pciehost/windows/amd64@v%%release.core%%
</ShellCommand>

Пакети для Windows публікуються, починаючи з першого випуску Neat, який їх містить.

Ця команда встановлює узгоджені пакети Scheduler MSI, Core MSI та wheel `win_amd64` як єдиний набір. Windows один раз запитує дозвіл адміністратора для двох пакетів MSI. Завантажені пакети й журнали Windows Installer залишаються в поточному каталозі.

Перед запуском MSI CLI перевіряє Windows OpenSSH, службу Platform, GStreamer і сумісний Python. Він створює або повторно використовує середовище `%USERPROFILE%\pyneatpcie`, перевіряє опубліковані контрольні суми, запускає Windows Installer для Scheduler і Core, виконує діагностику хоста та встановлює узгоджені навичку агента й wheel. Для відновлення або оновлення повторно виконайте ту саму команду. Щоб вибрати інше середовище, використайте `--python-executable <path>`; щоб установити лише нативну версію C++, використайте `--native-only`. Видаленням нативних компонентів керує Windows Installer, а видаленням пакета Python — pip.

Після встановлення один раз запустіть програму налаштування, щоб налаштувати SSH-доступ до карти без пароля. Вона один раз запитує пароль облікового запису `sima` на карті:

```powershell
& "C:\Program Files\SimaPCIeHost\bin\pcie-setup.cmd"
```

Програма знаходить адресу карти через локальне з'єднання керування `10.0.N.1`. Якщо автоматичне виявлення недоступне, передайте `-Hosts 10.0.0.2`. OpenSSH запитує пароль карти лише тоді, коли відкритий ключ ще не зареєстровано, і не зберігає цей пароль. Обгортка `.cmd` дозволяє виконувати цей встановлений сценарій лише у власному процесі PowerShell; вона не змінює політику виконання для користувача чи комп’ютера.

Перед імпортом розширення пакет Python шукає DLL у стандартному корені встановлення та стандартному розташуванні x64 GStreamer. Для іншого кореня встановлення задайте в `SIMA_PCIE_HOST_LIBRARY_PATH` каталоги з DLL хоста PCIe та GStreamer. Імпорт завершується помилкою, якщо потрібну DLL уже завантажено не зі схваленого розташування. Узгодьте версії встановлених компонентів і запустіть новий процес замість роботи зі змішаним середовищем виконання.

Перевірте встановлені wheel і плагін поза деревом вихідного коду та збірки:

```powershell
$venv = "$env:USERPROFILE\pyneatpcie"
$root = "C:\Program Files\SimaPCIeHost"
$gst = "C:\Program Files\gstreamer\1.0\msvc_x86_64\bin\gst-inspect-1.0.exe"
$env:PATH = "$root\bin;$(Split-Path $gst);$env:PATH"
Set-Location $env:TEMP
& "$root\bin\sima-pcie-host-doctor.cmd"
& "$venv\Scripts\python.exe" -m pip check
& "$venv\Scripts\python.exe" -c "import pyneatpcie as p; print(p.__version__, p.Model)"
& $gst "$root\bin\gstreamer-1.0\gstneatpciehost.dll"
```

### Запуск застосунків у Windows

Приклад [PCIe Co-Processing](/develop-apps/hello-neat/pcie/) і навчальні посібники PCIe містять команди для Linux. У Windows запускайте програми Python інтерпретатором керованого середовища. Активація не потрібна, а типова політика виконання PowerShell блокує `Activate.ps1`:

```powershell
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" pcie_host.py
```

Для застосунків C++ потрібна Visual Studio 2022 версії 17.14 або новіша, зокрема Visual Studio 2026, із робочим навантаженням **Desktop development with C++**. Прикладам, що використовують OpenCV, також потрібен пакет OpenCV 5.0.0 для Windows з [opencv.org](https://opencv.org/releases/). Пакет надає лише конфігурацію Release: збірка Debug зупиняється з помилкою компілятора, а `--config RelWithDebInfo` збирає з налагоджувальною інформацією. Збирайте й запускайте в **x64 Native Tools Command Prompt** для вашої версії Visual Studio:

```bat
call "C:\Program Files\SimaPCIeHost\bin\sima-pcie-host-env.cmd"
set "OpenCV_DIR=C:\opencv\build"
cmake -S . -B build
cmake --build build --config Release
set "PATH=%OpenCV_DIR%\x64\vc16\bin;%PATH%"
build\Release\pcie_host.exe
```

Замініть `C:\opencv\build` на каталог `build` розпакованого пакета OpenCV. `sima-pcie-host-env.cmd` змінює лише поточний командний рядок.

Пакет хоста встановлює навчальні посібники в `C:\Program Files\SimaPCIeHost`, тому в Windows їх не потрібно завантажувати окремо. Програми посібників читають архіви моделей і `share\sima-pcie-host\tutorials` з поточного каталогу. Скопіюйте вихідні файли до каталогу з правом запису, додайте архіви моделей, зазначені в [Tutorial Setup](/tutorials/before-you-run), і запускайте програми звідти:

```powershell
$root = "C:\Program Files\SimaPCIeHost"
New-Item -ItemType Directory -Force pcie-tutorials\share\sima-pcie-host | Out-Null
Copy-Item -Recurse "$root\share\sima-pcie-host\tutorials" pcie-tutorials\share\sima-pcie-host\
Set-Location pcie-tutorials
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" share\sima-pcie-host\tutorials\024_run_your_first_model_over_pcie\run_tensor_mode.py
& "$root\bin\sima-pcie-host-run.cmd" "$root\lib\sima-pcie-host\tutorials\tutorial_024_run_tensor_mode.exe"
```

Попередньо зібрані посібники C++ завантажують середовище виконання OpenCV, установлене поруч із ними, тому пакет OpenCV їм не потрібен.

### Видалення у Windows

```powershell
sima-cli packages list
sima-cli packages remove gh:sima-neat/core/pciehost/windows/amd64 --version <version> --yes
& "$env:USERPROFILE\pyneatpcie\Scripts\python.exe" -m pip uninstall -y pyneatpcie
sima-cli playbooks remove neat-pcie-application-builder --yes
```

Використовуйте версію, яку показує `sima-cli packages list`. Команда видаляє Core, а потім Scheduler з одним підтвердженням адміністратора. Вона не видаляє середовище Python; видаліть `%USERPROFILE%\pyneatpcie`, якщо жоден інший застосунок його не використовує.

## Усунення несправностей

Якщо SSH-конфігурація не може автоматично виявити карту, перевірте, чи може хост отримати доступ до її адреси керування, а потім запустіть встановлену програму налаштування, явно вказавши цю адресу.

У Linux:

<ShellCommand prompt="pcie-host">
ping -c 1 10.0.0.2
pcie-setup.sh --hosts "10.0.0.2"
</ShellCommand>

У Windows відкрийте PowerShell:

```powershell
Test-Connection -ComputerName 10.0.0.2 -Count 1
& "C:\Program Files\SimaPCIeHost\bin\pcie-setup.cmd" -Hosts 10.0.0.2
```

Якщо встановлення пакета або запуск у середовищі виконання завершується невдало, переконайтеся, що пакет PCIe host і Neat Library, встановлені на карті, належать до сумісних версій.

## Автономне встановлення {#offline-installation}

:::caution Перевірте залежності Python перед установленням
Офлайн-встановлення зберігає наявні середовища Python, додаткові пакети та файли в них. Перед установленням пакетів виконується `pip check`. Якщо середовище вже пошкоджене, встановлення зупиняється та повідомляє шлях до середовища й помилки залежностей. Виправте зазначені залежності та повторіть спробу. Для офлайн-виправлення потрібні додаткові файли wheel. Перевірка після встановлення повідомляє про наявні або нові конфлікти. Зміни пакетів автоматично не відкочуються.

Лише якщо ви хочете видалити середовище та встановити все заново, явно виконайте `./install.sh --recreate-venv` (окремий Core) або `sudo python3 -B install.py --recreate-venv` (PCIe). Це видаляє пакети та файли у вибраному середовищі без резервної копії. У SDK цей параметр застосовується до спареного DevKit, а не до Python хоста SDK. Спочатку збережіть потрібні файли. Команди попередньої перевірки та перевірки без установлення ніколи не створюють середовище заново.
:::

Автономні пакети Neat PCIe доступні у версії 0.6.0 або новішій.

Пакет PCIe встановлює Neat на хості та всіх підключених сумісних картах.
Для цього встановлення цільовій системі не потрібні Docker або доступ до інтернету.
Хост повинен мати робоче мережеве з’єднання PCIe з кожною картою.

### 1. Підготуйте хост і карти

Виконайте ці завдання перед запуском програми встановлення Neat:

- Встановіть сумісний драйвер хоста Platform.
- Встановіть відповідну мікропрограму Platform 3.0 на кожній карті.
- Налаштуйте виявлення на інтерфейсі PCIe кожної карти.
- Призначте кожній карті унікальну адресу PCIe IPv4.
- Увімкніть сервер SSH на кожній карті та підготуйте пароль для входу.
- Надайте обліковому запису SSH дозвіл використовувати `sudo` на кожній карті.

Програма встановлення Neat не встановлює драйвер Platform і не змінює мікропрограму Platform.
Використовуйте інструкції з налаштування системи, що постачаються з вашим випуском Platform.

### 2. Завантажте пакет

Встановіть `sima-cli` на комп’ютері з доступом до інтернету. Див. [посібник зі встановлення sima-cli](/tools/sima-cli/).

Виберіть версію 0.6.0 або новішу для цільового хоста.
Пакети підтримують хости Ubuntu 22.04 та 24.04 з процесорами `amd64` або `arm64`.

У цьому прикладі версію %%release.core%% завантажують на комп’ютері з доступом до інтернету.
Для цільового хоста Ubuntu 24.04 `amd64` виконайте:

<ShellCommand prompt="host">
sima-cli neat install 'core/pciehost/ubuntu24/amd64@v%%release.core%%' -t offline -d ./pcie-offline
</ShellCommand>

Для Ubuntu 22.04 замініть `ubuntu24` на `ubuntu22`.
Для хоста `arm64` замініть `amd64` на `arm64`.
Команда завантажує та розпаковує пакет. Вона не встановлює Neat.

### 3. Необов’язково: перевірте підготовлену систему

1. Скопіюйте всю теку `pcie-offline` на цільовий хост. Використовуйте шлях без пробілів.
2. Відкрийте розпаковану теку `neat-offline`, яка містить `install.py`.
3. Прочитайте наданий файл `INSTALL.md`, щоб дізнатися про необхідні системні інструменти та налаштування SSH.
4. Якщо доступ SSH уже налаштовано, виконайте перевірки:

<ShellCommand prompt="host">
sudo python3 -B install.py --preflight-only
</ShellCommand>

Програма встановлення автоматично виявляє всі підключені карти. Не вказуйте IP-адреси карт.
Перевірки створюють тимчасові файли, але не встановлюють пакети й не налаштовують SSH.
На новому хості перейдіть до встановлення: програма налаштує SSH в інтерактивному режимі.
Інші повідомлені помилки виправте перед встановленням.

### 4. Встановіть пакет і перевірте результати

Виконайте цю команду з тієї самої теки:

<ShellCommand prompt="host">
sudo python3 -B install.py
</ShellCommand>

На новому хості програма встановлення створює або повторно використовує `~/.ssh/sima_neat_pcie_ed25519` користувача, який викликав `sudo`, і налаштовує доступ SSH до всіх виявлених карт тим самим сценарієм, що й онлайн-встановлення. За потреби введіть пароль для входу на карту. Не потрібно окремо запускати `ssh-keygen` чи `ssh-copy-id` або вводити IP-адреси карт.

Щоб вибрати наявні облікові дані, використовуйте `--ssh-user` і `--ssh-key`. Явно вказаний `--ssh-key` має існувати й не мати парольної фрази. Автоматична реєстрація використовує `~/.ssh/known_hosts`; власний файл `--known-hosts` потрібно налаштувати заздалегідь. Для встановлення без участі користувача доступ SSH потрібно налаштувати заздалегідь. Паролі вводяться через термінал; вони не зберігаються в журналах і не передаються як аргументи команд.

Програма встановлення перевіряє всі карти перед встановленням пакетів.
Спочатку вона встановлює та перевіряє хост, а потім послідовно кожну карту.
Переконайтеся, що підсумковий звіт підтверджує успішне встановлення та перевірку хоста й кожної карти.
Потім виконайте приймальне тестування застосунку.

Якщо встановлення завершилося помилкою, прочитайте діагностичний журнал за вказаним шляхом.
Якщо під час встановлення з’єднання з картою втрачено, перед повторною спробою переконайтеся, що процес встановлення на карті зупинився.
Після помилки програма встановлення не відновлює попередній стан автоматично.

## Наступний крок

Продовжуйте роботу з [PCIe – спільна обробка даних](/develop-apps/hello-neat/pcie/), щоб перевірити повний процес розробки, що охоплює взаємодію між хостом і платою.

Офлайн-встановлення повторно використовує наявне `~/pyneatpcie` на хості або `~/pyneat` на карті чи DevKit, зокрема ціль символічного посилання. Якщо середовища в домашній теці немає, карта або DevKit використовує `/media/nvme/pyneat`, коли користувач, який виконує встановлення, може записувати на NVMe; інакше використовується `~/pyneat`. Нове встановлення на NVMe створює посилання `~/pyneat`, не замінюючи наявне середовище в домашній теці.
