# Вузли візуального фронтенду EV74

Використовуйте операції EV74 через публічні фабрики вузлів `Graph`. Установіть узгоджений набір пакетів Core, Scheduler, Runner, Kernels і прошивки EV74. Застарілі ідентифікатори графів не є перевіркою сумісності з нативною прошивкою; застосункам не потрібні ідентифікатори диспетчера.

Параметри якості зберігають сумісність із наявним початковим кодом і позиції виходів за замовчуванням, але змінюють розкладку `TrackKLTOptions` у C++; наявні бінарні файли C++ не є ABI-сумісними. Перезберіть застосунки C++ і розширення Python із відповідною версією Core. Для запитів трекера v2 використовуйте узгоджений набір Kernels, Runner, Scheduler і прошивки EV74. Наявні нативні запити v1 і далі підтримуються; це не робить запити v2 сумісними зі старішою прошивкою.

| Фабрика вузлів | Призначення |
| --- | --- |
| `nodes::FeatureHistogram` / `pyneat.nodes.feature_histogram` | Гістограма відтінків сірого |
| `nodes::GriderFast` / `pyneat.nodes.grider_fast` | Кути FAST, розподілені за сіткою |
| `nodes::TrackDescriptor` / `pyneat.nodes.track_descriptor` | Кути FAST і дескриптори BRIEF |
| `nodes::TrackKLT` / `pyneat.nodes.track_klt` | Пірамідальне відстеження KLT та необов’язкове виявлення ознак поточного кадру |

## Контракти тензорів

Усі тензори зображень мають логічну форму `[B,H,W]`, де `B` — це `batch_size`. Не згортайте вимір пакета у висоту зображення. Входи в пам’яті пристрою можуть використовувати окремі виділення пам’яті або коректні подання спільного сховища; обхідний шлях із копіюванням через CPU не потрібен.

| Вузол | Входи | Публічні виходи за замовчуванням |
| --- | --- | --- |
| `FeatureHistogram` | UInt8 `[B,H,W]` | Int32 `[B,256]` |
| `GriderFast` | UInt8 `[B,H,W]` | Int32 `[B,1+3*max_features]` |
| `TrackDescriptor` | UInt8 `[B,H,W]` | Int32 `[B,1+3*max_features]`; Int32 `[B,max_features,8]` |
| `TrackKLT` | UInt8 `[B,H,W]`; UInt8 `[B,H,W]`; Int32 `[B,num_points,2]` | Float32 `[B,num_points,2]`; Int32 `[B,num_points,1]` |

Упакований формат ознак для кожного елемента пакета — `[count,x0,y0,score0,...]`. Читайте лише перші `count` записів. Невикористана місткість не є списком ознак. TrackDescriptor потребує `descriptor_words == 8`; кожний рядок дескриптора належить відповідному рядку вибраної ознаки.

## Вибір за сіткою та межі

`grid_x` і `grid_y` ділять усе зображення на комірки. За місткості `K` і кількості комірок `M` кожна має `K / M` місць; перші `K % M` комірок у порядку рядків отримують ще одне. У кожній комірці вибираються найвищі оцінки, а загальний результат упорядковується за спаданням оцінки, за рівності — за зростанням `(y,x)`. Розріджені комірки не передають свої місця іншим. `min_px_dist` пригнічує точки, розташовані ближче за цю відстань, навіть через межі комірок; точна рівність відстані дозволена. Відкинутих кандидатів пригнічення не замінює іншими, тому результат може містити менше ніж `max_features` точок.

Звичайний FAST допускає центри в `x=3`, `y=3`, `x=W-4` і `y=H-4`. Натомість TrackDescriptor потребує повного фрагмента BRIEF 31×31: центри мають бути щонайменше за 15 пікселів від кожного краю. Тому відсутність дескрипторів у рядку 3 є навмисною.

## Входи та виходи KLT

Передавайте впорядкований `TensorList`: **попереднє зображення, поточне зображення, вхідні точки**. На цьому прямому публічному маршруті з кількома входами непорожній логічний `route.name` має відповідати налаштованій позиції; він не змінює порядок списку. Правильно впорядковані безіменні тензори залишаються коректними. Відсутні входи, суперечливі імена, неправильні типи чи форми та недоступні діапазони відхиляються ще до надсилання на виконання, зокрема й у наступних кадрах.

Щоб повторно використати сумісний вихідний тензор, зробіть поверхневу копію та перейменуйте або очистьте лише `route.name` для нової публічної позиції. Залиште без змін його сховище, зсуви та метадані фізичної маршрутизації. Це правило не перейменовує внутрішні зв’язки графа й не замінює явний процесор вхідного маршруту моделі.

За замовчуванням TrackKLT публікує точки та статус. `detect_new_features != 0` додає ознаки, виявлені на **поточному** зображенні. За вимкненого виявлення прихований вихід ознак не виділяється. `publish_error = true` додає Float32 `[B,num_points,1]` після наявних виходів: індекс 2 без виявлення, індекс 3 із виявленням. Позиції наявних виходів не змінюються.

### Приклад C++

Надайте два вектори зображень UInt8 `640×480` і початкові координати Int32 `64×2`. Нижче кожний вхід має незалежне сховище EV74. Функція повертає кортеж: точки, статус, похибка.

```cpp
#include <neat.h>
#include <cstdint>
#include <vector>

using namespace simaai::neat;

TensorList track_pair(const std::vector<std::uint8_t>& previous,
                     const std::vector<std::uint8_t>& current,
                     const std::vector<std::int32_t>& xy) {
  constexpr int width = 640, height = 480, count = 64;
  auto image = [&](const auto& pixels, const char* name) {
    auto tensor = Tensor::from_vector(pixels, {1, height, width}, TensorMemory::EV74);
    tensor.layout = TensorLayout::HW;
    tensor.axis_semantics = {TensorAxisSemantic::N, TensorAxisSemantic::H,
                            TensorAxisSemantic::W};
    tensor.route.name = name;
    return tensor;
  };
  auto points = Tensor::from_vector(xy, {1, count, 2}, TensorMemory::EV74);
  points.route.name = "input_points";
  TensorList inputs{image(previous, "prev_image"), image(current, "cur_image"), points};

  InputOptions input;
  input.payload_type = PayloadType::Tensor;
  input.format = FormatTag::UINT8;
  input.width = input.max_width = width;
  input.height = input.max_height = height;
  input.depth = input.max_depth = 1;
  input.memory_policy = InputMemoryPolicy::Ev74;
  input.buffer_name = "prev_image";
  input.caps_override = "application/vnd.simaai.tensor, representation=(string)tensor-set, "
                        "storage=(string)tensorbuffer";

  TrackKLTOptions klt;
  klt.width = width;
  klt.height = height;
  klt.num_points = count;
  klt.win_half = 7;
  klt.max_level = 2;
  klt.max_iters = 20;
  klt.publish_error = true;

  Graph graph;
  graph.add(nodes::Input(input));
  graph.add(nodes::TrackKLT(klt));
  graph.add(nodes::Output());
  RunOptions options;
  options.output_memory = OutputMemory::Owned;
  Run run = graph.build(inputs, options);
  TensorList outputs;
  try {
    outputs = run.run(inputs, 30000);
  } catch (...) {
    run.close();
    throw;
  }
  run.close();
  return outputs;
}
```

## Керування якістю

| Параметр | За замовчуванням | Значення |
| --- | --- | --- |
| `publish_error` | `false` | Публікує середній абсолютний залишок інтенсивності в кінцевій координаті. `output_error_name` за замовчуванням — `output_error`. |
| `error_threshold` | `-1.0` | `-1` вимикає перевірку; інакше це скінченний поріг у `[0,255]`. Залишок вище порога відхиляється, рівність дозволена. Фільтрування працює й без публікації похибки. |
| `min_eig_threshold` | `0.0` | `0` вимикає перевірку; інакше це скінченний додатний поріг нормалізованого мінімального власного значення, що застосовується до обумовленості текстури. |
| `require_convergence` | `false` | Вимагає, щоб кінцеве оновлення в повній роздільності виконувало критерій збіжності. Коли цей параметр має значення false, вичерпання ліміту ітерацій не означає невдачі. |

Залишок — це різниця інтенсивностей, а не зміщення в пікселях і не впевненість. Його обчислюють у поверненій координаті; `+inf` означає, що коректний залишок не було обчислено. Показник текстури ділить найменше власне значення матриці центральних градієнтів на площу вікна й `255²`; його масштаб не взаємозамінний із порогами OpenCV. Вибирайте пороги на репрезентативних калібрувальних даних, а потім перевіряйте як повноту збережених треків, так і відхилення хибних.

Перевіряйте статус перед використанням координат. Початкові точки, визнані некоректними ще до розв’язання, зберігають свої початкові координати зі статусом 0. Скінченна обчислена точка поза зображенням або кандидат, відхилений порогом якості, може зберігати обчислені координати зі статусом 0. За замовчуванням статус відображає коректність із погляду розв’язувача й геометрії, а не доводить правильність відповідності в реальному світі.

## Рух, межі та фіксована кількість точок

Коли уточнення виходить за межі плитки поточного зображення, її повторно центрують і перезавантажують; рух не обрізається мовчки до вікна пошуку ±4 пікселі. Кількість перезавантажень та ітерацій залишається обмеженою. Граничні плитки повторюють крайні пікселі, використовуючи DMA лише всередині зображення. Це усуває стару смугу виключення, залежну від рівня піраміди, але не гарантує відстеження за довільного руху, перекриття чи неоднозначної текстури.

Початкові точки Core залишаються Int32, результати — Float32. `num_points` фіксується під час побудови графа. Для невикористаної позиції задайте некоректні координати, наприклад `(-1,-1)`, і перевіряйте статус. `(0,0)` є коректною координатою краю, а не маркером неактивності. Обидві піраміди зображень перебудовуються за кожного виклику; повторне використання піраміди попереднього кадру не передбачається.

## Параметри Python

Python надає ті самі параметри. Створюйте вхідні тензори через `Tensor.from_numpy(..., memory="ev74")`, дотримуйтеся контракту впорядкованих входів і будуйте публічний вузол, як у C++.

```python
import pyneat

options = pyneat.TrackKLTOptions()
options.width, options.height = 640, 480
options.num_points = 64
options.win_half, options.max_level, options.max_iters = 7, 2, 20
options.publish_error = True
options.error_threshold = -1.0
options.min_eig_threshold = 0.0
options.require_convergence = False
node = pyneat.nodes.track_klt(options)
```

## Перевірка

Налаштовані імена портів мають бути непорожніми та унікальними. Відхиляються некоректні розміри, кількості, вікна, рівні піраміди й розміри дескрипторів, а також параметри якості, що не є скінченними числами або виходять за допустимий діапазон. Не обходьте ці перевірки й не намагайтеся перетворити значення тензора, переінтерпретувавши його dtype.

## Запуск тестів коректності

На DevKit задайте `CORE_TEST_DIR` як теку встановлених тестів Core або теку тестів нативної збірки, а потім виконайте:

```bash
ctest --test-dir "$CORE_TEST_DIR" \
  -R '^(grider_fast|track_descriptor|track_klt)_ev_test$' --output-on-failure
```

Кожний зареєстрований тест виконує повну матрицю свого ядра. GriderFast перевіряє сітку, відстань і краї FAST; TrackDescriptor — також точну відповідність дескрипторів вибраним точкам; TrackKLT — незалежні входи, повторне використання кадрів, перевірку, якість, рух, межі та детектор. Окремі швидкі пресети — це димові тести гістограми, KLT без виявлення та відхилення пакета некоректного розміру, а не заміна цього числового покриття.

## Глибина Metoak (C++)

`nodes::MetoakDepth` відновлює наявний API `MetoakDepthOptions`.
Вузол приймає шість іменованих тензорів і разом публікує RGB, глибину та XYZ.
Він виконує обчислення EV74, а не захоплення з камери; синтетичні тензори можна використовувати без камери.

На відміну від наведених вище візуальних вузлів із пакетною обробкою, Metoak завжди використовує пакет з одного елемента без початкового виміру пакета.
Установіть парне `W` у межах `[8,2048]` і парне `H` у межах `[8,1536]`.
Збережіть канонічні назви маршрутів і передавайте входи в наведеному порядку.

| Тензор | Тип даних | Форма |
| --- | --- | --- |
| y_src | UInt8 | [H,W] |
| u_src, v_src | UInt8 | [H/2,W/2] |
| disp_src | UInt16 | [H,W] |
| bf_mm_src | Float32 | [1] |
| proj_src | Float32 | [3] |
| rgb_dst | UInt8 | [H,W,3] |
| depth_dst | UInt16 | [H,W] |
| points_dst | Float32 | [H,W,3] |

`y_src`, `u_src` і `v_src` — окремі площини I420. Диспаратність масштабовано з коефіцієнтом 32.
Для кожного кадру передавайте додатне скінченне `bf_mm_src` (база × фокусна відстань, у мм) та
`proj_src = {fx_fy, cx, cy}`. `fx_fy` має бути додатним, а всі три значення — скінченними.
Калібрування можна змінювати між кадрами.

Глибина округлюється до міліметрів з насиченням до діапазону UInt16; XYZ використовує неокруглену глибину в метрах.
Нульова диспаратність дає нульову глибину та NaN у XYZ. Усі три виходи доступні, хоча основний опис виходу відповідає глибині.

```cpp
MetoakDepthOptions depth;
depth.width = 640;
depth.height = 360;
graph.add(nodes::MetoakDepth(depth));
```

Наявні поля `debug`, `num_buffers` і `element_name` залишаються доступними.
`num_buffers = 0` використовує місткість графа за замовчуванням; додатне значення задає місткість виконання цього етапу.
Відновлено публічний інтерфейс C++; ця зміна не додає фабрики Metoak для Python.
