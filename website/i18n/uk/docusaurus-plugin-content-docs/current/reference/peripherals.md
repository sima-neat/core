# Каталог периферійних пристроїв

Використовуйте каталог периферійних пристроїв, щоб переглядати пристрої, які зараз під'єднані до
локального DevKit. API доступний у C++ і Python та повертає однаковий типізований знімок в обох мовах.

Авторитетний каталог належить SiMa Sentinel (`simaai-sentinel.service`) — локальному для плати демону,
який надає його як `GET /v1/peripherals`. Кожен виклик `list()` виконує один обмежений у часі запит
до Sentinel. Core не сканує обладнання,
не кешує другий каталог і не переходить до іншого шляху виявлення.

## Перелік периферійних пристроїв

Python:

```python
import pyneat

catalog = pyneat.peripherals.list()
for peripheral in catalog:
    print(peripheral.id, peripheral.type, peripheral.provider)
```

C++:

```cpp
#include <neat.h>

auto catalog = simaai::neat::peripherals::list();
for (const auto& peripheral : catalog) {
  // Use peripheral.id, peripheral.type, and peripheral.provider.
}
```

Повернений каталог можна перебирати. Він також містить `instance_id` демона, `revision` каталогу,
`sequence` подій, завершений `scan_sequence`, стан актуальності й часові позначки, поточну структуровану
помилку, проблеми провайдерів і колекцію `devices`.

Готовий каталог може не містити жодного пристрою — це успішний результат. Каталог у погіршеному стані
може містити останній успішний список пристроїв; у такому разі `stale` має значення `true`, а `error` та/або
`issues` пояснюють помилку оновлення.

## Відомості про камеру

Коли `peripheral.type == "camera"`, `peripheral.camera` містить:

| Поле | Значення |
| --- | --- |
| `camera_name` | Необов'язкова точна назва libcamera, яку приймає `CameraInputOptions`. Вона відсутня для камери, яку поточний API вводу не може вибрати. |
| `model` | Модель пристрою, якщо її повідомив провайдер. |
| `backend` | Серверна частина виявлення, наприклад `mipi` або `v4l2`. |
| `modes` | Дискретні розміри або явні діапазони розмірів, частота кадрів, ознака підтримки та причина відхилення. |

Підтримку класифікує Sentinel, застосовуючи правила, які цей пакет Core встановлює в `/usr/share/simaai-sentinel/support/neat-core.json`, тож результат відповідає встановленому `CameraInput`. Клієнт зберігає цей результат і не зондує, не перекласифіковує, не захоплює,
не налаштовує та не передає потік із камери. Тому підтримка в каталозі не гарантує, що подальше
ексклюзивне захоплення буде успішним.

Невідомі типи периферійних пристроїв залишаються в каталозі зі спільними `id`, `type` і `provider`.
Старіші клієнти ігнорують необов'язкові поля, додані до протоколу v1. Це стосується й верхньорівневого
журналу `changes`, який Sentinel публікує з кожним знімком; Core приймає його, але не надає.

## Помилки й область дії

`list()` породжує `NeatError` зі стабільним кодом, якщо служба відсутня, доступ заборонено, час запиту
вичерпано, демон не готовий або відповідь неправильна, завелика чи несумісна. Повідомлення містить
наступну операційну дію. Див. [каталог кодів помилок](./error-codes.md).

Якщо Sentinel не встановлено, встановіть його командою `sima-cli neat install sentinel`.
Якщо його встановлено, але не запущено, запустіть `simaai-sentinel.service`.

Цей API під'єднується лише до `/run/simaai-sentinel/api.sock` на локальному DevKit. Він не
використовує SSH і не вибирає віддалену плату. Insight і майбутні клієнти CLI під'єднуються до демона
як рівноправні клієнти, а не через Core.

Цей випуск надає одноразове читання каталогу. Підписки на події, запити оновлення та керування життєвим
циклом демона не входять до публічного API Core.
