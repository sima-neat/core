# Діагностика та налагодження

## GraphReport

`GraphReport` збирає структуровану діагностику:
- рядок конвеєра (для відтворення)
- канонічний `error_code` (машинна класифікація)
- `repro_note` (короткий опис для людини + підказка)
- звіти вузлів та імена елементів, що їм належать
- повідомлення шини та подробиці помилок
- необов’язкові лічильники потоку/часу

Коли виникає помилка, `NeatError` містить `GraphReport`, який можна записати в журнал або
серіалізувати.

## Таксономія помилок

Помилки фреймворку використовують стабільні сімейства кодів:

| Код помилки | Значення | Типове виправлення |
| --- | --- | --- |
| `misconfig.pipeline_shape` | Порушення контракту порядку/форми вузлів | Переконайтеся, що `Input()` стоїть першим у конвеєрах надсилання (push), а `Output()` — останнім у конвеєрах отримання (pull) |
| `misconfig.caps` | Невідповідність перевизначення caps фреймворку або контракту суміжного вузла | Узгодьте `caps_override` і оголошені контракти вузлів |
| `misconfig.input_shape` | Форма або тип даних вхідного тензора/кадру/семпла не відповідає контракту моделі | Надайте очікувані форму й тип даних або налаштуйте попередню обробку моделі |
| `misconfig.runtime_abi_mismatch` | Neat і плагін середовища виконання використовують несумісні ABI | Встановіть Neat Library і середовище виконання відповідних одна одній версій |
| `misconfig.graph_element_name` | Користувацькому елементу неможливо призначити стабільне ім’я вузла | Дайте користувацьким елементам стабільні унікальні імена |
| `misconfig.input_capacity` | Зображення джерела перевищує вхідну місткість попередньої обробки | Збільште `input_max_width` / `input_max_height` або масштабуйте зображення перед етапом моделі |
| `misconfig.media_caps` | Суміжні етапи GStreamer вимагають несумісних медіа-caps | Узгодьте формат, роздільну здатність і частоту кадрів або вставте перетворення |
| `misconfig.media_format` | Етап отримав непідтримуваний медіаформат | Налаштуйте підтримуваний формат або вставте перетворення формату |
| `misconfig.tensor_dtype_missing` | У контракті тензора не вказано dtype/формат | Оголосіть підтримуваний dtype тензора в контракті вище за потоком |
| `misconfig.option_out_of_range` | Параметр етапу неприпустимий для поточного тензора | Виберіть значення з діапазону, показаного в діагностиці |
| `build.parse_launch` | Збій `gst_parse_launch` не має конкретнішої класифікації | Перегляньте долучений звіт, щоб дізнатися контекст парсера |
| `build.pipeline_syntax` | Синтаксис користувацького фрагмента GStreamer неприпустимий | Виправте фрагмент і перевірте його за допомогою `gst-launch-1.0` |
| `build.plugin_missing` | Потрібний елемент GStreamer або плагін кодека не встановлено | Встановіть/замініть його та перевірте за допомогою `gst-inspect-1.0` |
| `build.property_invalid` | Властивість елемента невідома або неприпустима | Перевірте ім’я та значення властивості за допомогою `gst-inspect-1.0` |
| `runtime.pull` | Отримання (pull) завершилося збоєм без конкретнішої першопричини | Перегляньте долучений звіт і першу помилку вище за потоком |
| `runtime.element_failed` | Етап завершився збоєм без конкретнішого зіставлення | Виправте зазначений етап і його вхідні дані вище за потоком |
| `runtime.output_timeout` | Вихідні дані не надійшли до завершення налаштованого тайм-ауту | Перевірте потік даних із джерела або збільште тайм-аут, якщо очікування передбачене |
| `runtime.unexpected_eos` | Конвеєр досяг EOS раніше, ніж з’явилися потрібні вихідні дані | Перевірте, чи джерело не надсилає EOS передчасно, і надайте достатньо вхідних даних |
| `io.parse` | Збій розбору або перевірки схеми JSON чи конфігурації етапу | Перевірте синтаксис конфігурації та обов’язкові поля |
| `io.open` | Збій відкриття/читання/запису файлу під час збереження/завантаження графа | Перевірте наявність шляху, права доступу та стан сховища |
| `io.file_not_found` | Вхідний файл не існує | Виправте шлях і переконайтеся, що файл існує на DevKit |
| `io.permission_denied` | Файл або пристрій недоступний для читання | Виправте власника/права доступу |
| `io.rtsp_connection_failed` | Неможливо зв’язатися з джерелом RTSP | Перевірте URL, досяжність, сервер і облікові дані |
| `io.camera_not_found` | Запитана камера недоступна | Виберіть одну з виявлених камер або використайте типову |
| `io.model_not_found` | Запитаний архів моделі не існує | Виправте шлях до моделі та переконайтеся, що її встановлено |
| `io.source_ended` | Джерело вхідних даних досягло свого звичайного кінця | Припиніть читати з нього або надайте більше вхідних даних |
| `io.response_too_large` | Обмежена відповідь локального протоколу перевищила своє обмеження розміру | Встановіть відповідні одна одній версії клієнта та служби |
| `codec.invalid_h264_stream` | Вхідні дані не містять дійсних кадрів H.264 | Надайте повний потік H.264 або виправте кодек |
| `codec.decode_failed` | Декодер завершився збоєм після прийняття потоку | Перевірте кодек і цілісність вхідних даних |
| `codec.encode_failed` | Кодер не зміг закодувати надані кадри | Перевірте вхідний формат, роздільну здатність і налаштування кодера |
| `resource.memory_allocation_failed` | Потрібне виділення пам’яті завершилося збоєм | Зменште використання пам’яті навантаженням і звільніть пам’ять, яку використовують інші застосунки або конвеєри |
| `resource.device_memory_exhausted` | Виділення пам’яті DMA/CMA пристрою завершилося збоєм | Зменште кількість одночасних потоків, роздільну здатність або буферизацію |
| `resource.output_pool_exhausted` | Усі вихідні буфери залишаються зайнятими | Звільніть вихідні дані без копіювання (zero-copy) або використовуйте власні копії |
| `resource.buffer_too_small` | Буфер менший за оголошене корисне навантаження | Виправте розміри/крок (stride) або виділіть потрібну кількість байтів |
| `resource.disk_full` | Запис завершився збоєм, бо сховище заповнене | Звільніть місце або виберіть інше місце призначення |
| `infra.dispatcher_unavailable` | Неможливо отримати середовище виконання прискорювача | Зупиніть конкурентні навантаження та перевірте сумісність DevKit |
| `infra.accelerator_execution_failed` | Прискорювач не зміг виконати етап моделі | Перезапустіть конвеєр і зменште одночасне навантаження на прискорювач |
| `infra.peripheral_daemon_unavailable` | SiMa Sentinel не може надати каталог периферійних пристроїв | Встановіть або оновіть Sentinel командою `sima-cli neat install sentinel` або запустіть `simaai-sentinel.service` |
| `infra.peripheral_daemon_timeout` | Запит каталогу периферійних пристроїв не завершився вчасно | Перевірте `simaai-sentinel.service` і його журнал, а потім повторіть спробу |
| `DispatcherUnavailable` | Застаріле написання `infra.dispatcher_unavailable` | Перенесіть обробники на канонічний інфраструктурний код |
| `internal.plugin_failure` | Плагін завершився збоєм без класифікації, за якою користувач міг би діяти | Збережіть звіт і зверніться до служби підтримки |

`PullError.code` використовує ту саму таксономію (не лише шляхи винятків).
Див. [Каталог кодів помилок](/reference/error-codes), щоб дізнатися імена констант C++ і Python та
вказівки з міграції для застосунків, які зіставляли попередні загальні коди.

Повідомлення в робочому режимі навмисно не містять внутрішніх подробиць GStreamer. Докладний режим налагодження
плагінів додає сирі домен/код GError, фабрику елемента, повідомлення та
структуровані подробиці плагіна. Розпізнані облікові дані та секретні параметри URL, зокрема
userinfo в URI, `auth`, `playback-token`, `hdnts`, `stream-key` і `tkn`, маскуються, перш ніж будь-яку
з цих форм буде збережено. Рядки конвеєра у звітах, фрагменти вузлів, команди відтворення та
серіалізований JSON маскуються без зміни виконуваного конвеєра, що зберігається всередині.

## Програмна обробка

```cpp
#include "pipeline/ErrorCodes.h"
#include "pipeline/NeatError.h"

try {
  auto run = graph.build(input);
  simaai::neat::Sample out;
  simaai::neat::PullError perr;
  const auto st = run.pull(500, out, &perr);
  if (st == simaai::neat::PullStatus::Error) {
    if (perr.code == simaai::neat::error_codes::kMediaCaps) {
      // Fix the incompatible upstream/downstream media contract.
    } else {
      // Handle another specific code, including future codes, or report it.
    }
  }
} catch (const simaai::neat::NeatError& e) {
  if (e.report().error_code == simaai::neat::error_codes::kPluginMissing) {
    // Install or replace the missing GStreamer component.
  }
}
```

## Параметри налагодження (змінні середовища)

Основні змінні середовища (докладніше див. [Архітектура](/develop-apps/contribute/architecture)):
- `SIMA_GST_DOT_DIR`: записувати графи DOT для збоїв
- `SIMA_GST_BOUNDARY_PROBES`: лічильники потоку даних на межах
- `SIMA_GST_ELEMENT_TIMINGS`: облік часу для кожного елемента
- `SIMA_GST_FLOW_DEBUG`: лічильники потоку даних для кожного елемента
- `SIMA_GST_ENFORCE_NAMES`: забезпечувати дотримання контракту іменування

Щоб додати замаскований сирий контекст GStreamer до `NeatError::what()` і
`GraphReport.repro_note`, задайте обидві змінні для команди, що завершується збоєм:

```bash
SIMA_NEAT_VERBOSE_LEVEL=2 \
SIMA_NEAT_VERBOSE_TOPICS=gstreamer \
./your-neat-application
```

`NEAT_LOG_LEVEL=debug` не є параметром Neat Library. Тримайте докладний вивід вимкненим під час звичайної
роботи; він призначений для коротких діагностичних запусків і може містити шляхи, специфічні для розгортання, або
адреси медіа, хоча розпізнані поля облікових даних маскуються.

## Порядок налагодження

1) Збережіть `GraphReport.error_code` і спершу віднесіть збій до категорії таксономії.
2) Збережіть `GraphReport.repro_note`, щоб отримати конкретний контекст і вбудовану підказку.
3) Збережіть текст конвеєра: `Graph::describe_backend()` або `last_pipeline()`.
4) Збережіть структуровану діагностику: `MeasureReport::to_text()` або `NeatError::report()`.
5) Перегляньте `GraphReport.bus`, щоб знайти джерело та подробиці першої термінальної помилки `ERROR`.
6) Якщо виконання зависає або спрацьовують тайм-аути, увімкніть зонди на межах/елементах, щоб локалізувати місце зупинки потоку даних.

Рекомендований пакет для служби підтримки:
- `error_code`
- `repro_note`
- повний `pipeline_string`
- перші 3-5 термінальних помилок шини (`GraphReport.bus`)
- перевизначення змінних середовища, використані під час run/validate

## Артефакт продуктивності графа для клієнтів

Для звітів про пропускну здатність/затримку/енергоспоживання краще використовувати експорт запуску графа в JSON:

```cpp
RunOptions opt;
opt.enable_board_power();        // graph-level power when supported by the board/SOM
Run run = graph.build(opt);

// run your normal push/pull loop inside a measurement window, then:
auto report = run.start_measurement().stop();
std::cout << report.to_text();
```

Експорт явно розділяє області дії:

- `run.graph_metrics.throughput_fps` і `run.graph_metrics.power` — головні показники рівня графа.
- `run.node_metrics[]` містить лише затримку вузлів/плагінів; потужність вузлів/плагінів навмисно відсутня.
- `latency_semantics` і `aggregation` показують, чи є значення накопиченими за весь час запуску, чи різницями за вимірюване вікно.
- `plugin_metrics_unattributed[]` зберігає рядки ядер/плагінів, які не вдалося зіставити рівно з одним вузлом.

Для вимірюваного вікна використовуйте `Run::start_measurement()` і передайте повернений `MeasureReport` до
`run_to_json(run, report, ...)` / `save_run_json(run, report, ...)`. Значення `min_ms`/`max_ms` вузлів для вимірюваного
вікна позначаються як недоступні, бо накопичувальні лічильники min/max неможливо точно відняти
без лічильників, локальних для вікна.

Примітка щодо потужності: поточна плата DVT дає змогу перевірити передавання параметрів і структуру JSON, але її показники
потужності у ватах не вважаються числово надійними. Цільовою платформою для
перевірки значень потужності є обладнання SOM.

## Поширені збої → виправлення

| Симптом | Імовірна причина | Виправлення |
| --- | --- | --- |
| `missing ... plugin` | Плагін GStreamer не знайдено | Перевірте `GST_PLUGIN_PATH`, виконайте `gst-inspect-1.0 <plugin>` |
| `appsink 'mysink' not found` | Відсутній кінцевий `Output()` | Переконайтеся, що `Output` — останній вузол у конвеєрах run/build |
| `caps_override is set; renegotiation disabled` | caps закріплено | Видаліть `caps_override` або тримайте вхідні caps незмінними |
| `tensor caps change not supported` | Зміна форми/dtype тензора під час виконання | Тримайте форму/dtype тензора незмінними (без повторного узгодження) |

Структуровані помилки плагінів і практичні підказки див. у розділі
[Усунення несправностей](/reference/troubleshooting).

## Відновлення середовища виконання платформи

На Platform 3.0.0 недоступність диспетчера є помилкою, яку потрібно дослідити, а не запитом на запуск застарілих служб. Core не ініціалізує пам’ять MLA й не скидає віддалені процесори у відповідь на помилку диспетчера. Застарілий код і сценарій відновлення видалено; використовуйте процедуру відновлення, схвалену для платформи.

Якщо драйвер повідомляє про невідомий стан завершення, утримуйте його DMA-буфери та початкові позики з пулу. Закриття файлового дескриптора, зупинка застосунку або перезапуск служби не доводять, що апаратне забезпечення припинило доступ до пам’яті. Зберіть звіт про помилку й скористайтеся схваленою процедурою відновлення платформи перед повторною спробою.

### Узгодження Core та Internals

Збирайте та встановлюйте Core з відповідними пакетами Internals B1157. Core окремо перевіряє профіль середовища виконання, ревізію вихідного коду ядра та підтвердження SDK sysroot, незалежно від версії публічного C++ ABI. Старіший пакет з тим самим публічним ABI не є сумісною заміною.

Перед зміною пакетів інсталятор перевіряє профіль включеного `neat-runtime` і відповідну версію `neat-gst-plugins`. Перевизначення перевірки платформи не обходить узгодження середовища виконання. Якщо перевірка не проходить, отримайте відповідний комплект; не підміняйте його підтвердження й не примушуйте встановлювати старіше середовище виконання.

Перед встановленням на платі зупиніть застосунки, що використовують CVU або апаратний кодек. Повний інсталятор активує підготовлену прошивку EV74 після встановлення всіх пакетів і відмовляється скидати EV74, поки ці пристрої відкриті. Задайте
`NEAT_INSTALLER_ACTIVATE_FIRMWARE_ON_BOARD=OFF`, щоб залишити прошивку підготовленою
для пізнішої активації командою
`sudo /usr/libexec/sima-neat-firmware/install.sh --activate`.
