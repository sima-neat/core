# Ресурси навчальних посібників і архіви моделей

Більшості користувачів навчальних посібників достатньо `--model <path>` і `--image <path>`. Ця сторінка призначена для запусків із дерева початкового коду, тестів і повторюваних сеансів налагодження, коли треба керувати тим, звідки беруться архіви моделей і зразки ресурсів.

Не додавайте цей матеріал до посібників для початківців. Він корисний, але це не перший крок.

## Перевизначення архівів моделей

Використовуйте ці змінні середовища, щоб передати шлях до архіву моделі локальним тестам репозиторію або допоміжним скриптам, не змінюючи кожну команду:

| Змінна | Призначення |
| --- | --- |
| `SIMA_RESNET50_TAR` | Перевизначення окремої моделі для навчальних посібників і тестів із ResNet-50. |
| `SIMA_MODEL_TAR` | Спільний резервний архів моделі для тестів і прикладів, яким потрібна модель. |
| `SIMA_YOLO_TAR` | Перевизначення окремої моделі для навчальних посібників і тестів виявлення в стилі YOLO, якщо скрипт це підтримує. |
| `SIMA_NEAT_TUTORIAL_MODEL_RESNET` | Архів ResNet-50 для тестів навчальних посібників. Запуски CTest навчальних посібників C++ і тести навчальних посібників Python передають його навчальному посібнику як `--model`. |
| `SIMA_NEAT_TUTORIAL_MODEL_YOLO` | Архів YOLOv8s для тестів навчальних посібників, використовується так само. |

Команди навчальних посібників і далі приймають явні прапорці. Для одного запуску краще передати `--model <path>`; змінні середовища використовуйте, коли багато команд мають працювати з тим самим артефактом.

<ShellCommand prompt="sdk|devkit">
export SIMA_RESNET50_TAR=/path/to/resnet_50.tar.gz
export SIMA_YOLO_TAR=/path/to/yolo_v8s.tar.gz
export SIMA_NEAT_TUTORIAL_MODEL_RESNET=/path/to/resnet_50.tar.gz
export SIMA_NEAT_TUTORIAL_MODEL_YOLO=/path/to/yolo_v8s.tar.gz
</ShellCommand>

Якщо змінну для тестів навчальних посібників не задано, запуски CTest навчальних посібників C++ використовують `/tmp/resnet_50.tar.gz` і `/tmp/yolo_v8s.tar.gz`. Як їх підготувати, див. на сторінці [Налаштування навчального посібника](/tutorials/before-you-run).

## Поширені шляхи в дереві початкового коду

Локальні тести й приклади репозиторію зазвичай шукають ресурси в теці `tmp/` у корені репозиторію. Найпоширеніші шляхи:

| Ресурс | Поширений шлях у дереві початкового коду |
| --- | --- |
| Архів моделі ResNet-50 | `tmp/resnet_50.tar.gz` |
| Архів моделі YOLOv8s | `tmp/yolo_v8s.tar.gz` |
| Зразок зображення COCO | `tmp/coco_sample.jpg` |

Встановлені навчальні посібники можна натомість запускати з теки доповнень. У такому разі передавайте шляхи до моделі та зображення явно, якщо вони не лежать у `/tmp`.

## Керування видобуванням моделей

Neat видобуває вміст архівів моделей перед запуском. Ці змінні потрібні переважно для перегляду й керування очищенням під час налагодження:

| Змінна | Дія |
| --- | --- |
| `SIMA_MPK_EXTRACT_ROOT=<dir>` | Задає базову теку для видобутих даних моделі. |
| `SIMA_MPK_CLEANUP_EXTRACTED=0` | Залишає кореневу теку видобування `proc_run_*` поточного процесу після його завершення, щоб її можна було переглянути. Інші процеси автоматично не знаходять її й не використовують повторно. |
| `SIMA_MPK_EXTRACT_GC_STALE_PROC=0` | Вимикає очищення на основі блокувань для покинутих тек `proc_run_*` під час запуску. |

Використовуйте їх, коли треба переглянути згенеровані файли конфігурації або порівняти видобуті артефакти між запусками. Для звичайної роботи з навчальними посібниками залишайте значення за замовчуванням.

## Перевизначення зразка зображення

Деякі тести з дерева початкового коду використовують зразок зображення COCO і можуть завантажити його, якщо його немає.
Перевизначте URL, якщо у вашому середовищі потрібне локальне дзеркало:

<ShellCommand prompt="sdk|devkit">
export SIMA_COCO_URL=https://example.com/path/to/coco_sample.jpg
</ShellCommand>

Для одного запуску навчального посібника краще передати `--image <path>`. `SIMA_COCO_URL` використовуйте, коли набір тестів або завдання CI має завантажувати зображення з контрольованого розташування.

## Розбір відсутніх ресурсів

Якщо навчальний посібник виводить `SKIP: missing ...` або не може відкрити модель:

1. Перевірте шлях, указаний у повідомленні.
2. Передайте ресурс явно через прапорець навчального посібника.
3. Якщо ви запускаєте тести з дерева початкового коду, задайте відповідну змінну середовища.
4. Якщо модель отримано з Model Browser, видобудьте архів моделі із завантаженого ZIP-файлу
   і вкажіть навчальному посібнику шлях до цього файлу `.tar.gz`.

Для звичайних запусків не розпаковуйте архів моделі вручну. Neat очікує шлях до скомпільованого архіву й сам виконує видобування.
