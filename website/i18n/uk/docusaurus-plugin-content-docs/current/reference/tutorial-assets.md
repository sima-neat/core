# Навчальні матеріали та архів моделі.

Більшості користувачів, які працюють з навчальними матеріалами, достатньо лише `--model <path>` та `--image <path>`. Ця сторінка призначена для запуску коду з вихідного дерева, проведення тестів і налагодження, коли потрібно контролювати, звідки беруться архіви моделей і зразки ресурсів.

Не включайте ці матеріали в початкові навчальні посібники. Вони корисні, але це не перший крок.

## Перевизначення в архіві моделі.

Використовуйте ці змінні середовища, коли локальні тести репозиторію або допоміжні скрипти потребують шляху до архіву моделі, не змінюючи кожну команду:

| Змінна | Використання |
| --- | --- |
| `SIMA_RESNET50_TAR` | Індивідуальні налаштування для навчальних матеріалів і тестів, що стосуються ResNet-50. |
| `SIMA_MODEL_TAR` | Загальний архів моделі, який використовується для тестів і прикладів, що базуються на моделях. |
| `SIMA_YOLO_TAR` | Можливість індивідуального налаштування для навчальних матеріалів і тестів, що стосуються детектування в стилі YOLO, якщо це підтримується скриптом. |

У навчальних прикладах команди все ще підтримують явне використання прапорців. Для одноразового запуску краще використовувати `--model <path>`; якщо ж потрібно, щоб багато команд використовували один і той самий артефакт, слід використовувати змінні середовища.

<ShellCommand prompt="sdk-or-devkit">
export SIMA_RESNET50_TAR=/path/to/resnet_50.tar.gz
export SIMA_YOLO_TAR=/path/to/yolo_v8s.tar.gz
</ShellCommand>

## Поширені шляхи в структурі коду.

Локальні тести та приклади, що використовуються в репозиторії, зазвичай шукають у папці `tmp/`, яка знаходиться в кореневій директорії репозиторію. Найпоширеніші шляхи до цієї папки:

| Ресурс | Загальний шлях до вихідного дерева |
| --- | --- |
| Архів моделі ResNet-50 | `tmp/resnet_50.tar.gz` |
| Архів моделі YOLOv8s | `tmp/yolo_v8s.tar.gz` |
| Зразок зображення COCO | `tmp/coco_sample.jpg` |

Встановлені навчальні матеріали також можуть запускатися з додаткової теки. У такому разі, якщо шляхи до моделі та зображення ще не вказані, передавайте їх явно, якщо вони не знаходяться в `/tmp`.

## Елементи керування для вилучення моделі.

Neat розпаковує архіви моделей перед їх запуском. Ці змінні в основному призначені для перевірки та керування процесом очищення під час налагодження:

| Змінна | Вплив |
| --- | --- |
| `SIMA_MPK_EXTRACT_ROOT=<dir>` | Встановлює базову директорію для збереження витягнутих даних моделі. |
| `SIMA_MPK_CLEANUP_EXTRACTED=0` | Зберігає локальну для процесу `proc_*` папку для вилучених даних після завершення, щоб її можна було перевірити. Інші процеси не можуть автоматично виявити або повторно використовувати цю папку. |
| `SIMA_MPK_EXTRACT_GC_STALE_PROC=0` | Відключає очищення застарілих `proc_*` каталогів під час запуску. |

Використовуйте їх, коли потрібно перевірити згенеровані файли конфігурації або порівняти отримані артефакти між різними запусками. Залиште налаштування за замовчуванням для звичайних навчальних вправ.

## Приклади заміни зображень.

Деякі тести, що використовують структуру вихідного коду, використовують зразок зображення COCO і можуть завантажити його, якщо він відсутній.
За потреби використання локального дзеркала, змініть URL-адресу:

<ShellCommand prompt="sdk-or-devkit">
export SIMA_COCO_URL=https://example.com/path/to/coco_sample.jpg
</ShellCommand>

Для одного запуску навчального посібника краще використовувати `--image <path>`. Використовуйте `SIMA_COCO_URL`, коли тестовий набір або завдання CI повинні отримувати дані з контрольованого розташування.

## Розподіл відсутніх ресурсів.

Якщо в інструкції відображається повідомлення `SKIP: missing ...` або не вдається відкрити модель:

1. Перевірте шлях, який відображається в повідомленні.
2. Передавайте ресурс явно, використовуючи прапорець для навчального режиму.
3. Якщо ви запускаєте тести для SourceTree, встановіть відповідну змінну середовища.
4. Якщо файл було завантажено з Model Zoo, перевірте назву завантаженого файлу.
   вкажіть у навчальному посібнику шлях до фактичного файлу `.tar.gz`.

Не розпаковуйте архів моделі вручну під час звичайного використання. Neat очікує шлях до скомпільованого архіву та самостійно виконує розпакування.
