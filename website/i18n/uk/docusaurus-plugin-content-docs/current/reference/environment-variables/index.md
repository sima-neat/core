# Змінні середовища

На цій сторінці зібрано змінні середовища, які використовують середовище виконання, засіб збирання та
інструменти SDK. Багато з них — перемикачі налагодження й діагностики; більшість користувачів може не
звертати на них уваги, якщо тільки не усуває несправності.

Вичерпний список виявлених змінних див. у розділі [Перелік змінних середовища](/reference/environment-variables/inventory/).

> Примітка: деякі параметри є внутрішніми або призначені лише для тестування й можуть змінитися. Їх наведено тут,
> оскільки наразі вони трапляються в шляхах виконання коду.

## Вебдоступ до SDK

Для Palette SDK 3.0 або новішої версії `sima-cli sdk setup` передає `CODE_SERVER_PASSWORD` у середовище контейнера. Знову запустіть `neat`, щоб отримати його значення, і введіть його на запит code-server. URL-адреси не містять ні пароля, ні токена. `neat --json` додає `codeUI` з полями `backend`, `auth`, `password`, `localUrl` і `remoteUrl`; вважайте, що цей вивід містить облікові дані. Опублікований порт `codeUIHttps.host` із карти портів SDK має пріоритет над портом контейнера.

Цю поведінку визначає встановлений виконуваний файл code-server; одне лише задання `CODE_SERVER_PASSWORD` не змінює поведінки застарілого OpenVSCode. `CODE_SERVER_HTTPS_PORT` і `CODE_SERVER_WORKSPACE` перевизначають свої застарілі відповідники. З `CODE_SERVER_WITHOUT_PASSWORD=1` повідомляється `auth: "none"`, а значення пароля не виводиться. Застарілі образи OpenVSCode зберігають URL-адреси з токенами.

- `NFS_SERVER_HOST_IP=<address>` — адреса хоста SDK, з якої формуються URL-адреси віддаленого
  Insight і VS Code у браузері. Зазвичай її задає `sima-cli sdk setup`.
- `CONTAINER_HOST_IP=<address>` — застарілий резервний варіант адреси віддаленого хоста,
  якщо `NFS_SERVER_HOST_IP` недоступна.
- `OPENVSCODE_SERVER_HTTPS_PORT=<port>` — HTTPS-порт для VS Code у браузері.
  Якщо змінну не задано, `neat` не показує URL-адреси VS Code.
- `OPENVSCODE_SERVER_TOKEN=<token>` — токен доступу до VS Code у браузері. Значення,
  яке генерує sima-cli, безпечне для URL. URL-адреси з цим токеном вважайте
  обліковими даними й не поширюйте їх.
- `OPENVSCODE_WORKSPACE=<path>` — робочий простір, який відкриває VS Code у браузері
  (за замовчуванням `/workspace`).
- `OPENVSCODE_SERVER_WITHOUT_TOKEN=1` — запускати й оголошувати VS Code у браузері
  без автентифікації токеном. Використовуйте це лише в довіреному локальному середовищі;
  ніколи не вмикайте цю змінну, якщо до служби можна дістатися з недовіреної мережі.

## Уніфікований профіль налагодження (рекомендовано)

- `SIMA_DEBUG_PROFILE=<components>` — єдиний перемикач увімкнення налагодження для поширених видів діагностики.
  - Компоненти: `pipeline`, `graph`, `gst`, `appsink`, `inputstream` або `all`.
  - Кілька компонентів можна розділяти комами або пробілами (наприклад, `pipeline,gst,inputstream`).
- `SIMA_DEBUG_LEVEL=<0..3>` — рівень докладності налагодження, який використовує уніфікований профіль (за замовчуванням `1`).
  - `0`: вимкнено
  - `1`: основні журнали налагодження
  - `2`: докладна діагностика / трасування на рівні буферів
  - `3`: максимальна докладність

Застарілі перемикачі налагодження, що задаються окремими змінними, і далі працюють, а якщо їх задано явно, перевизначають значення профілю за замовчуванням.

## Збирання/запуск: основне

- `SIMA_PIPELINE_STRING_DEBUG=1` — виводити остаточний рядок gst-launch під час збирання.
- `SIMA_PIPELINE_STATE_DEBUG=1` — додаткові журнали змін стану.
- `SIMA_PIPELINE_TEARDOWN_DEBUG=1` — журналювати кроки завершення роботи конвеєра.
- `SIMA_PIPELINE_DRAIN_BEFORE_TEARDOWN_MS=<ms>` — час спорожнення перед завершенням роботи (за замовчуванням 1500).
- `SIMA_PIPELINE_DRAIN_MIN_OUTPUTS=<n>` — мінімальна кількість виходів, які потрібно отримати під час спорожнення перед завершенням роботи (за замовчуванням 1).

## Ініціалізація GStreamer + приглушення

- `SIMA_ALLOW_GST_INIT=1` — дозволити ручний виклик `gst_init`, якщо ініціалізацію вже виконано.
- `SIMA_GST_SUPPRESS_JSON_WARNINGS=0/1` — приглушувати попередження JSON (за замовчуванням true).
- `SIMA_GST_SUPPRESS_GOBJECT_ASSERTS=0/1` — приглушувати журнали assert GLib (за замовчуванням true).
- `SIMA_GST_SUPPRESS_DEVICE_LOGS=0/1` — приглушувати журнали пристрою (за замовчуванням true).

## Тайм-аути GStreamer

- `SIMA_STATE_CHANGE_TIMEOUT_MS=<ms>` — тайм-аут зміни стану конвеєра (за замовчуванням 15000).
- `SIMA_GST_TEARDOWN_TIMEOUT_MS=<ms>` — тайм-аут завершення роботи (за замовчуванням 2000).
- `SIMA_GST_TEARDOWN_REAPER_MS=<ms>` — сторожовий таймер завершення роботи (за замовчуванням 250).
- `SIMA_GST_TEARDOWN_ASYNC=1` — асинхронне завершення роботи.
- `SIMA_GST_POLL_SLICE_MS=<ms>` — інтервал опитування під час отримання даних з appsink (за замовчуванням 200).
- Рекомендовані параметри API:
  - `ValidateOptions.preroll_timeout_ms` — тайм-аут preroll для validate().
  - `RunOptions.input_timeout_ms` — очікування виходу для `Graph::run()` у режимі входу та для підтримуваної попередньої перевірки збирання з початковими даними.
  - `Run::run(..., timeout_ms)` / `Model::run(..., timeout_ms)` — очікування виходу для окремого виклику; `-1` означає без обмеження, як у `Run::pull(-1)`.
- Застарілі резервні змінні середовища (використовуйте лише тоді, коли не можете передати параметри):
  - `SIMA_GST_VALIDATE_TIMEOUT_MS=<ms>` — тайм-аут validate() (за замовчуванням 2000/10000).
  - `SIMA_GST_RUN_INPUT_TIMEOUT_MS=<ms>` — резервне значення для згаданих очікувань виходу `Graph::run()` / попередньої перевірки (за замовчуванням 10000).

- `SIMA_STAGE_DEBUG=1` — журнали налагодження StageRun.

- `SIMA_DISABLE_SYNC_NUMBUFFERS_CVU_MLA=1` — вимкнути обмеження, що синхронізують num-buffers.

## Модель (застарілі назви змінних середовища збережено)
- `SIMA_MLA_NEXT_CPU=<domain>` — перевизначити next_cpu для MLA.
- `SIMA_MPK_EXTRACT_ROOT=<dir>` — базова тека для завантаження архівів моделей. Перетворюється на абсолютний
  шлях один раз на процес, тому шляхи, переписані у видобутий JSON, ніколи не залежать від робочої
  теки. Задане значення є остаточним: якщо до теки не можна записувати, завантаження завершується збоєм,
  а не переходить до резервного варіанта. Якщо змінну не задано, базовим стає перший доступний для запису
  кандидат: змонтована файлова система NVMe, `/data`, `TMPDIR`, а потім робоча тека. Кандидат NVMe має
  бути доступним для запису блоковим пристроєм `/dev/nvme*`, змонтованим як розділ даних: кореневий розділ,
  `/boot`, `/efi` та інші системні точки монтування виключено, як і файлові системи vfat/ISO. Ці перевірки
  стосуються виявлення NVMe; резервні варіанти `/data`, `TMPDIR` і робоча тека зберігають своє звичайне
  розташування у файловій системі. NVMe віддається перевага через обсяг, передбачуване розташування й
  уникнення записів на eMMC. Це не прискорює декодування: ця змінна визначає, куди записуються вихідні дані,
  а декодування обмежене продуктивністю CPU.

  Вибір відбувається за можливістю запису, а не за вільним місцем. Архів `.tar.gz` не обмежує свій розмір
  після декомпресії ні знизу, ні згори, тому до декодування неможливо знати, скільки місця знадобиться;
  наявність місця перевіряється для кожного фрагмента під час декомпресії і ще раз — за маніфестом перед
  видобуванням. Тому придатний NVMe використовується безумовно, а якщо на ньому бракує місця, завантаження
  завершується збоєм `output_storage_unavailable`, а не переходить на eMMC. Розв’язання — вільне місце в цій
  файловій системі або `SIMA_MPK_EXTRACT_ROOT`, що вказує на інше місце.
- `SIMA_MPK_CLEANUP_EXTRACTED=0/1` — видаляти видобуті дані архівів моделей окремого процесу під час звичайного завершення (за замовчуванням `1`).
  Якщо очищення ввімкнено, кожен процес видобуває дані в унікальну кореневу теку `proc_run_*`, захищену блокуванням, і видаляє її під час завершення. Якщо
  очищення вимкнено, ця коренева тека процесу зберігається для огляду й виключається зі збирання сміття
  застарілих кореневих тек. Інший процес не виявляє її й не використовує повторно автоматично; видаліть її вручну,
  коли вона стане непотрібною.

`Model` також приймає вже впорядковану кореневу теку пакета, що містить `etc`, `lib` і `share`. Ця
тека використовується на місці, без декомпресії чи копіювання; часом її існування керує код, що викликає, і вона має
залишатися незмінною, поки модель використовується. Пласка тека, створена `tar -xzf`, не є
впорядкованим пакетом і безпосередньо не приймається.
- `SIMA_MPK_EXTRACT_GC_STALE_PROC=0/1` — під час запуску видаляти покинуті кореневі теки видобування `proc_run_*`, спираючись на блокування власника (за замовчуванням `1`).
  Застарілі кореневі теки `proc_<pid>` слід видаляти вручну, коли вони більше не використовуються.
- `SIMA_MODEL_TAR=<path>` — базовий шлях до пакета моделі, який використовують приклади/тести.
  Перевизначення для окремих моделей (`SIMA_RESNET50_TAR`, `SIMA_YOLO_TAR` тощо) і далі мають пріоритет.
- `SIMA_MPK_EXTRACT_MIN_FREE_BYTES=<bytes>` — вільне місце, що залишається в резерві під час проміжного розміщення й
  видобування вмісту архівів моделей (за замовчуванням 16 МіБ).
- `TMPDIR=<dir>` — розглядається лише як один із пізніх кандидатів на описану вище базову теку і використовується
  безпосередньо для проміжного розміщення, коли код, що викликає, не вибирає власної базової теки. Завантаження моделі
  більше не розміщує тут проміжні дані окремо: декомпресований знімок і видобутий пакет розташовуються
  в одній вибраній базовій теці. Кожне завантаження, зокрема й перегляд лише метаданих, один раз декомпресує
  `.tar.gz` у приватну теку. Під час видобування в цій файловій системі має бути місце для
  декомпресованого знімка, пакета й `SIMA_MPK_EXTRACT_MIN_FREE_BYTES`; знімок еталонного пакета розміром 150 МБ
  займає близько 354 МБ. Використовуйте локальну файлову систему — завантаження завершується збоєм, якщо не вдається
  прочитати обсяг вільного місця, а саме так стається, коли мережеве монтування зникає. Каталог проміжного
  розміщення видаляється після завершення завантаження — як у разі успіху, так і в разі збою; раптове примусове
  завершення процесу чи втрата живлення можуть залишити його.

Резерв вільного місця, заданий `SIMA_MPK_EXTRACT_MIN_FREE_BYTES`, дотримується за можливості, без гарантій.
Його перевіряють для кожного фрагмента під час декомпресії відносно обсягу вільного місця, про який повідомляє
файлова система, тому сторонній процес, що одночасно записує дані, усе ж може вичерпати місце між перевірками;
тоді завантаження завершується збоєм із зазначенням кількості записаних байтів і шляху, який воно використовувало.

## Кваліфікація метаданих обчислювальних ядер (kernel)

Етапи ProcessCVU за замовчуванням виконуються через `neatkernelrunner` середовища виконання.
Жоден параметр збирання чи змінна середовища не вибирає старий плагін ProcessCVU.

- `SIMA_CORE_COMPACT_METADATA=1` — дозволяє компактні метадані TensorSet і типізовані метадані
  поточного кадру на власному прямому ребрі від runner до appsink після узгодження можливостей.
  Потребує відсутності несумісного спостерігача меж, налагодження чи потоку даних. Стандартні власні
  вимірювання часу етапів/елементів лишаються ввімкненими й підтримують обидва подання.
  Розширення, які не мають подання, зберігають застарілі динамічні метадані.

Не під’єднуйте до компактного ребра зонди, що підтримують лише застарілий формат. Без узгодження
можливостей середовище виконання зберігає застарілі метадані для невідомих споживачів і спостерігачів;
виконання все одно відбувається через `neatkernelrunner`. Цей параметр метаданих не дає жодних
гарантій щодо затримки чи пропускної здатності.

## Кваліфікація пакетів і щотижнева кваліфікація (лише для тестування)

- `SIMA_TEST_PACKAGE_INVENTORY=<absolute-path>` — очікувані контрольні дані пакетів та ідентичність
  вмісту, згенеровані з вибраних перевірених архівів дистрибутива за допомогою
  `tools/ci/verify_core_dist.py --write-package-inventory`. Потрібна тесту переліку пакетів,
  встановлених на DevKit. Вона не переспрямовує `dpkg` на приватний префікс і не є звітом про
  результат встановлення.
- `SIMA_TEST_PLATFORM_BASELINE=<absolute-path>` — наявність і відсутність нативних компонентів платформи,
  ідентичність пакетів, а також доступність та ідентичність OTA, зафіксовані **до встановлення**
  за допомогою `tools/ci/verify_core_dist.py --capture-platform-baseline`. Потрібна тесту переліку
  пакетів, встановлених на DevKit, разом із вибраним переліком пакетів. Не створюйте цей базовий
  стан заново зі стану після встановлення.

Про профілі встановлених пакетів див. [Вимоги до тестування](../../develop-apps/contribute/build-test/test_requirements.md).

## Стан хоста й карт PCIe

`NEAT_PCIE_SSH_USER` задає користувача SSH на карті (за замовчуванням `sima`). `NEAT_PCIE_SSH_KEY` задає приватний ключ (за замовчуванням `~/.ssh/sima_neat_pcie_ed25519`); наявна конфігурація SSH і автентифікація через агент лишаються доступними. `--offline` пропускає перевірку оновлень через інтернет, але все одно опитує під’єднані карти через локальний SSH. Під час визначення стану хоста PCIe оновлення артефактів не перевіряються; щоб оновити пакет хоста, використовуйте `sima-cli neat install core/pciehost/<distro>/<arch>@<ref>`. `neat update` не оновлює карти PCIe.
