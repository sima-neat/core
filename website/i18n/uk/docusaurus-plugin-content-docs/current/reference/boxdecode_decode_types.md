# BoxDecode: типи декодування.

`nodes::SimaBoxDecode` перетворює необроблені тензори голів детектора на результати виявлення. Після інференсу моделі він застосовує обчислення декодування для вибраної родини моделей і фільтрує результати. NMS і кодування виходу залежать від вибраної родини. Моделі виявлення можуть розбирати дані як рамки; моделі поз і сегментації також можуть розбирати ключові точки або маски після рамок.

Для звичайного використання пакетів моделей, віддавайте перевагу конструктору, який враховує `Model`. Архів моделі надає порядок, розміщення, квантування тензорів, кількість класів, метадані зміни розміру та підказки щодо діапазону оцінок, необхідні декодеру. Ваш застосунок зазвичай лише вибирає родину декодування та порогові значення фільтрації.

## Бекенд середовища виконання

BoxDecode і SuperPoint використовують `neatkernelrunner` із перевіреними виконуваними ядрами Kernels. Наявні формати виходу детекцій і ознак не змінилися. Для орієнтованих рамок YOLO26 використовується окремий формат із версією. Для прямого тензорного входу використовуйте тензори зі спільною CMA-пам’яттю (`TensorMemory::EV74`), навіть коли декодування виконується на A65: цей вибір пам’яті забезпечує транспорт DMA-BUF, а не визначає ціль виконання.

Перший етап RCNN використовує контракт top-K для кожного рівня, яким володіє ядро: глобальне NMS, потім до `top_k` уцілілих пропозицій на кожний рівень площі моделі. Його вихід — це дротовий формат пропозицій, а не звичайний формат BBOX: чотири групи, кожна з лічильником INT32 та `top_k` записами із шести FP16 (`score, 0, x1, y1, x2, y2`). Перетворення координат зберігає дробову геометрію до остаточної серіалізації. Використовуйте його як вхід пропозицій для другого етапу, а не з `decode_bbox_tensor()`. Застарілий плагін не завантажується.

Голови SuperPoint з доповненням і чергуванням даних INT8, BF16 та FP32 використовують нативний щільний читач з явними кроками пікселів. Доповнення виключається зі згорток детектора та вибірки дескрипторів без етапу Cast або матеріалізації. Порти INT8 зберігають власні задані параметри квантування. Нативні голови з плитковою розкладкою MLA зберігають оголошену фізичну розкладку; щільні скаляри ніколи не позначаються як байтові площини MLA.

## Швидкий старт.

```cpp
using namespace simaai::neat;

Model model("/path/to/yolov8_model.tar.gz");

auto boxdecode = nodes::SimaBoxDecode(
    model,
    BoxDecodeType::YoloV8,
    /* detection_threshold */ 0.25,
    /* nms_iou_threshold */ 0.45,
    /* top_k */ 100);
```

Для використання в окремому середовищі розробки:

```cpp
simaai::neat::stages::BoxDecodeOptions opt(simaai::neat::BoxDecodeType::YoloV8);
opt.detection_threshold = 0.25;
opt.nms_iou_threshold = 0.45;
opt.top_k = 100;
```

## Аргументи

| Аргумент | Значення |
| --- | --- |
| `decode_type` | Тип моделі/формат заголовка, наприклад, `BoxDecodeType::YoloV8` або `BoxDecodeType::YoloX`. Обов’язково. |
| `detection_threshold` | Мінімальний бал, необхідний для збереження результату виявлення. Використовуйте значення, що відповідає конкретній моделі, наприклад, `0.25`. |
| `nms_iou_threshold` | Поріг IoU, який використовується алгоритмом придушення не-максимумів. `0` зберігає значення, упаковане в модель; якщо його немає, YOLO26 пропускає NMS, а інші декодери пригнічують кожну рамку, що перекривається. Задайте значення, що відповідає моделі, наприклад `0.45`. |
| `top_k` | Максимальна кількість виходів. Декодування необроблених обмежувальних рамок потребує явної додатної межі. У вузлі, прив’язаному до моделі, `0` успадковує визначену межу Model. SuperPoint використовує типове значення свого профілю для `0`. |
| `original_width`, `original_height` | Розмір вихідного зображення, що використовується для відображення координат під час застосування конструктора raw-geometry. |
| `model_width`, `model_height` | Замінює розмір вхідних даних моделі. За допомогою `Model` цей конструктор змінює параметри просторового декодування, але не змінює структуру тензора, що використовується. |
| `resize_mode_override` | Використовуйте лише тоді, коли на попередньому етапі обробки `Preproc` не записуються метадані щодо зміни розміру, і вам потрібно явно вказати поведінку для масштабування, заповнення або обрізання. |
| `decode_type_option` | Розширений селектор підпорядкованих макетів. Залиште значення `Auto`, якщо використовуєте пакет моделей, якщо тільки ви не знаєте, який макет заголовка експортується. |

## Вхідні та вихідні дані.

**Вхідні дані:** необроблені тензори виявлення, отримані від моделі. Очікувані розміри тензорів залежать від типу моделі. У випадку з MPK/архівом моделі, Neat зчитує ці деталі з упакованого контракту.

**Вихідні дані:** один тензор BoxDecode, що містить декодовані виявлення. Моделі виявлення використовують стандартний формат `BBOX`. Моделі для визначення поз і сегментації зберігають початкові обмежувальні рамки та додають власні, специфічні для завдання, дані:

| Завдання моделі | Допоміжний код C++ | Допоміжний код Python | Декодовані тензори |
| --- | --- | --- | --- |
| Виявлення | `decode_bbox(...)` | `pyneat.decode_bbox(...)` | `[N, 6]` float32 boxes: `x1, y1, x2, y2, score, class_id` |
| Орієнтоване виявлення | `decode_obb(...)` | `pyneat.decode_obb(...)` | Геометрія з власним сховищем `[N, 5]` float32 (`cx, cy, width, height, angle_radians`), оцінки `[N]` float32, ID класів `[N]` int32 |
| Поза | `decode_pose(...)` | `pyneat.decode_pose(...)` | обмежувальні рамки `[N, 6]` та ключові точки `[N, 17, 3]` float32: `x, y, visibility` |
| Сегментація | `decode_segmentation(...)` | `pyneat.decode_segmentation(...)` | прямокутники `[N, 6]` float32 і маски `[N, 160, 160]` uint8. |
| Сегментація + поза | `decode_segmentation_pose(...)` | `pyneat.decode_segmentation_pose(...)` | рамки `[N, 6]` float32, маски `[N, 160, 160]` uint8, ключові точки `[N, 17, 3]` float32 |
| Segment Anything | `decode_segmentation(...)` | `pyneat.decode_segmentation(...)` | рамки `[N, 6]` float32 і маски `[N, H, W]` uint8 розміром оригінального зображення; для декодера підказок N дорівнює 1 |
| SuperPoint | `decode_superpoint(...)` | `pyneat.decode_superpoint(...)` | ключові точки `[N,2]`, оцінки `[N]`, дескриптори `[N,D]`. |

Графи відображення рамок, паралельних осям, можуть передавати результат у `SimaRender`. Використовуйте `decode_bbox(...)` лише для наявних форматів із рамками на початку; ані він, ані `SimaRender` не приймають орієнтованих рамок.

## Необроблені виходи поруч із декодованим результатом {#raw-outputs}

Задайте `Model::Options::boxdecode_raw_outputs` (Python: `ModelOptions.boxdecode_raw_outputs`), коли застосунку потрібні і декодований результат, і необроблені тензори моделі з одного запуску інференсу. Тоді маршрут спочатку повертає тензор BoxDecode, а за ним усі виходи моделі в порядку MPK — точно так, як та сама Model повертає їх без BoxDecode: з тими самими назвами, типами даних і формами. `Model::output_specs()`, `Model::run`, раннери та `pull` повідомляють той самий список.

- Типове значення — `false`: один тензор BoxDecode без додаткових виходів чи витрат. Наявні маршрути BoxDecode не змінюються.
- З цим параметром кожен необроблений вихід коштує одне перетворення на кадр усередині етапу BoxDecode (наприклад, BF16 у FP32 або деквантування). Етап читає кожен вихід моделі один раз для декодування і один раз для його необробленої копії; повернуті тензори належать результату.
- Виходи моделі, які не читає жодна голова BoxDecode, як-от вказівники об'єктів EdgeTAM, повертаються лише з цим параметром.
- Декодуйте лише перший тензор, наприклад `pyneat.decode_segmentation(outputs[:1])`. Необроблені тензори не мають тегу виявлення.
- Параметр ігнорується, коли маршрут не має BoxDecode, і відхиляється, коли маршрут моделі без BoxDecode не має етапу постобробки, з якого можна повернути тензори.

## Розміщення letterbox {#letterbox-placement}

Профілі BoxDecode перетворюють координати виявлень після letterbox за правилом центрованого розміщення. Нецентроване розміщення, як-от `LetterboxPlacement::TopLeft` у попередній обробці Model, визначається з полів, опублікованих у `tensor.semantic.preprocess`, або, до першого кадру, з політики попереднього `Preproc`. Тоді профілі виявлення (сімейства виявлення YOLO, декодований YOLO, EfficientDet, DETR, DetrFocal, CenterNet і SSD) перетворюють рамки за фактичним афінним перетворенням кожного кадру з координат моделі в координати оригіналу. Профілі пози, сегментації та пропозицій RCNN відхиляють нецентроване розміщення замість того, щоб повертати зсунуті результати. Різниця в один піксель між протилежними полями є залишком центрування; центровані зображення зберігають наявне перетворення. Натомість типи Segment Anything вимагають letterbox із розміщенням у верхньому лівому куті або розтягування; див. [Маски Segment Anything](#segment-anything-masks).

## Класичний DETR {#classic-detr}

Виберіть `Detr` для двох голів на одній сітці запитів: чотириканальних логітів рамок і логітів класів з останнім каналом фону. Залиште `decode_type_option` у стані `Auto`: рецепт вибирає Softmax незалежно від назв тензорів. Фон бере участь у знаменнику, але не входить до кількості передніх класів або вибору результатів. До координат рамок застосовується sigmoid. Це не декодер уже нормалізованих рамок моделей із focal loss.

Використовуйте Stretch і додатне `top_k`. Декодер не застосовує NMS та відновлює координати початкового кадру за метаданими попередньої обробки. Явні макети з імовірностями або несумісні активації оцінок відхиляються.

```python
options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.Detr
options.preprocess.resize.mode = pyneat.ResizeMode.Stretch
options.top_k = 100
options.score_threshold = 0.7
```

## Детектори запитів із focal loss

Для двох упорядкованих тензорів використовуйте `BoxDecodeType::DetrFocal` (Python: `pyneat.BoxDecodeType.DetrFocal`, токен `detr-focal`): нормалізовані координати `cx,cy,width,height` із глибиною4, потім незалежні логіти класів із глибиноюN. Осі запитів і типи даних мають збігатися; N дорівнює1–1024. Підтримуються FP32, BF16 та INT8 із заданими параметрами квантування.

Профіль застосовує sigmoid лише до логітів класів і вибирає глобальні top-K пар «запит/клас». Один запит може дати кілька класів. Немає фонового класу, sigmoid для рамок, argmax для кожного запиту, NMS чи фільтра малих площ. Задайте додатне `top_k`, `detection_threshold=0` для top-K без фільтрації та обов’язкове `nms_iou_threshold=0`. Використовуйте Stretch і фактичні розміри зображення та моделі.

Наявний вихід `BBOX` обрізає рамки до меж зображення й округлює координати XYWH до цілих чисел. `decode_bbox` подає їх як числа з рухомою комою, але не відновлює субпіксельну точність. Окремо вимірюйте вплив цього представлення на точність порівняно з необрізаним еталоном із рухомою комою. Класичний `BoxDecodeType::Detr` не змінено: він очікує логіти рамок і softmax-оцінки з фоновим класом, а не ці тензори.

У Python використовуйте `decode_bbox(..., strict=True)`, щоб зберегти рядки з нульовою площею після округлення замість стандартного фільтра вироджених рамок.

Перевантаження Python raw-geometry відповідає фабриці C++ для явного передавання тензорів голови. Для щільних FP32-голів зберігайте всі вихідні адаптери моделі та явно задавайте фактичне сховище. Не зупиняйтеся на сирому виході MLA й не позначайте байти з доповненням як щільні тензори.

```python
node = pyneat.nodes.sima_box_decode(
    pyneat.BoxDecodeType.DetrFocal,
    original_width=1280, original_height=720,
    model_width=640, model_height=640,
    detection_threshold=0.0, nms_iou_threshold=0.0, top_k=300,
    decode_type_option=pyneat.BoxDecodeTypeOption.InterleavedByHeadLogit,
    source_storage=pyneat.BoxDecodeSourceStorage.DenseHwc,
    detess=False, dequant=False,
    resize_mode=pyneat.ResizeMode.Stretch,
)
```

Скінченні інвертовані розміри наявне обрізання кінцевих точок перетворює на BBOX із нульовою площею, зберігаючи вибрану пару й оцінку. Нескінченні значення або NaN у координатах чи логітах спричиняють помилку до публікації.

## Маски Segment Anything {#segment-anything-masks}

Кожна модель Segment Anything має власний тип декодування. Для декодера підказок BoxDecode перетворює один запуск декодера на одне виявлення: вибрану маску розміром оригінального зображення, її щільну рамку та передбачений IoU. Для моделі зображень концептів EfficientSAM3 він перетворює один запуск на щонайбільше `top_k` виявлень, кожне з власною маскою.

| Модель | `decode_type` (токен) | Попередня обробка Model, що отримує зображення | Параметри декодера |
| --- | --- | --- | --- |
| MobileSAM | `MobileSam` (`mobilesam`) | Кодувальник: `resize.mode=Letterbox`, `resize.placement=TopLeft`, 1024×1024, `pad_value=116`; `preset=ImageNet` | `multimask_output` |
| EdgeTAM | `EdgeTam` (`edgetam`) | Кодувальник зображень: `resize.mode=Stretch`, 1024×1024, без доповнення; `preset=ImageNet` | `multimask_output`; `boxdecode_raw_outputs` для відстеження |
| EfficientSAM-T / -S | `EfficientSam` (`efficientsam`) | Кодувальник: `resize.mode=Stretch`, 1024×1024, без доповнення; без пресета, `normalize.enable=On` (значення 0–1; нормалізацію виконує сам кодувальник) | Залиште `multimask_output` рівним true |
| EfficientSAM3, інтерактивний | `EfficientSam3` (`efficientsam3`) | Кодувальник зображень: `resize.mode=Stretch`, 1008×1008, без доповнення; `normalize.mean` і `normalize.stddev` 0.5 | `multimask_output` |
| EfficientSAM3, концепти | `EfficientSam3` (`efficientsam3`) | Сама модель зображень концептів на тензорному маршруті: застосунок розтягує зображення до 1008×1008, масштабує його до [−1, 1] і додає `semantic.preprocess` з `resize_mode="stretch"` | `top_k`, `score_threshold` |

Python використовує ті самі назви: `pyneat.BoxDecodeType.MobileSam`, `EdgeTam`, `EfficientSam` і `EfficientSam3`. MobileSAM доповнює нулями після нормалізації, що відповідає середньому пікселю ImageNet (124, 116, 104); `pad_value=116` наближає його. Маски ніколи не покривають доповнення. Model EfficientSAM3 вважається моделлю зображень концептів, коли її виходи — виявлення `[Q, 6]` і логіти масок із Q каналами, а інакше — декодером підказок.

`Model::Options::multimask_output` (Python: `ModelOptions.multimask_output`) відповідає висхідному `predict(multimask_output=...)`. Залиште `true` для одного клацання, яке неоднозначне; задайте `false` для рамки або кількох точок.

| `decode_type` | `multimask_output=true` (типово) | `multimask_output=false` |
| --- | --- | --- |
| `MobileSam` | Найкращий передбачений IoU серед масок 1–3 | Маска 0 |
| `EdgeTam` | Найкращий передбачений IoU серед масок 1–3 | Маска 0, якщо вона стабільна, інакше найкраща з масок 1–3 |
| `EfficientSam` | Найкращий передбачений IoU серед масок 0–2 | Відхиляється: EfficientSAM не експортує токен однієї маски |
| `EfficientSam3`, декодер підказок | Найкращий передбачений IoU серед масок 1–3 із чотирьох або 0–2 із трьох | Чотири маски: як `EdgeTam`. Три маски: відхиляється |
| `EfficientSam3`, концепти | Щонайбільше `top_k` запитів понад `score_threshold` | Відхиляється: виявлення концептів не має вибору з кількох масок |

- Як у SAM2, маска 0 стабільна, коли щонайменше 98% її логітів, більших за −0.05, також більші за 0.05.
- Декодер, експортований з одним каналом маски, використовує цю маску за будь-якого значення.
- Інші типи декодування відхиляють `multimask_output=false`. Вибір належить `Model`: дві Model декодера можуть використовувати той самий MPK.

### Що означає кожен вихід {#segment-anything-outputs}

Тензор BoxDecode використовує [версійоване корисне навантаження масок](#versioned-masks-payload). `decode_segmentation` повертає рамки `[N, 6]` і маски `[N, H, W]`:

- **Рамка.** `x1, y1, x2, y2` у пікселях оригінального зображення. Рамка декодера підказок — щільна рамка пікселів маски: `x2` і `y2` вказують на позицію одразу після останнього стовпця й рядка маски, тож `x2 - x1` — ширина маски. Рамка виявлення концепту береться з голови виявлення, масштабується до оригінального зображення й не обрізається.
- **Оцінка.** Передбачений IoU вибраної маски або оцінка запиту концепту.
- **Клас.** Вибраний канал маски (індекс із таблиці вище) або 0 для запиту концепту.
- **Маска.** `uint8`: 255 там, де логіт, перевибраний до розміру оригінального зображення, більший за 0, інакше 0.
- **Кількість.** Для декодера підказок завжди 1: порожня маска має повністю нульову рамку й зберігає оцінку та клас. Як у висхідній реалізації, оцінка об'єкта EdgeTAM 0 або менша робить маску порожньою. Модель концептів повертає залишені запити за спаданням оцінки (за рівності — за індексом запиту).

З `boxdecode_raw_outputs` власні виходи декодера йдуть після тензора BoxDecode; див. [Необроблені виходи поруч із декодованим результатом](#raw-outputs).

### Правила {#segment-anything-rules}

- Голови зіставляються за позицією та формою, а не за назвою. Логіти масок — це вихід із висотою та шириною понад 1 і 1, 3 або 4 використаними каналами. Передбачення IoU — наступний вихід з одним значенням на маску. Одиничне значення після нього — оцінка об'єкта (EdgeTAM). Інші виходи, як-от вказівники об'єктів EdgeTAM, не декодуються. Голови INT8, BF16 і FP32 зберігають власний dtype і квантування. Декодер, кількість каналів якого не відповідає названій моделі, відхиляється, наприклад декодер із трьома масками як `MobileSam`.
- Полотно, розмір оригінального зображення та зміну розміру беруть із `tensor.semantic.preprocess` входів декодера. Передайте вихідні тензори кодувальника декодеру, наприклад через `.cvu()`. Тому Model декодера підказок будується лише зі своїх входів: `build()` і `execution_plan()` без входів завершуються помилкою, тож передайте входи декодера в `execution_plan(inputs)`. Модель зображень концептів EfficientSAM3 також приймає упакований текст, тому Neat запускає її на тензорному маршруті; додайте ці дані до її тензора пікселів. Коли дані не відповідають таблиці, побудова графа завершується помилкою з параметром, який треба змінити, наприклад "MobileSAM needs the image preprocessed with resize.mode=Letterbox and resize.placement=TopLeft on the Model that preprocesses it".
- Побудований runner обслуговує один розмір оригінального зображення, бо маски мають цей розмір. `Model::run` будує інший runner для нового розміру кадру; потоковий граф відхиляє кадр іншого розміру, а не повертає маски неправильного розміру.
- Декодери підказок: залиште `top_k` рівним 0 або 1, а `nms_iou_threshold` — 0; інші значення відхиляються. `score_threshold` має бути меншим за 1 і в іншому ігнорується. `num_classes` — кількість масок або 0.
- Моделі зображень концептів: задайте `top_k` у межах 1..Q.

### MobileSAM {#mobilesam}

```python
encoder_options = pyneat.ModelOptions()
encoder_options.preprocess.resize.mode = pyneat.ResizeMode.Letterbox
encoder_options.preprocess.resize.placement = pyneat.LetterboxPlacement.TopLeft
encoder_options.preprocess.resize.pad_value = 116
encoder_options.preprocess.preset = pyneat.NormalizePreset.ImageNet
encoder = pyneat.Model("/path/to/mobile_sam_image_encoder_mpk.tar.gz", encoder_options)

options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.MobileSam
options.multimask_output = False  # a box prompt; keep True for one click
decoder = pyneat.Model("/path/to/mobile_sam_prompt_decoder_mpk.tar.gz", options)

embeddings = encoder.run([image])[0]
# .cvu() keeps the encoder's preprocess metadata on the embeddings.
outputs = decoder.run([embeddings.cvu(), point_encoding, point_types])
result = pyneat.decode_segmentation(outputs)[0]
box = result.boxes.to_numpy()[0]  # x1, y1, x2, y2, IoU, mask index
mask = result.masks.to_numpy()[0]  # uint8 [H, W], 0 or 255
```

### Відстеження EdgeTAM {#edgetam-tracking}

Кодувальнику пам'яті та банку пам'яті EdgeTAM потрібні два виходи декодера, яких BoxDecode не публікує: вказівник об'єкта та низькороздільні логіти вибраної маски. Задайте `boxdecode_raw_outputs` для Model декодера масок, щоб отримати їх із того самого запуску. Тоді виходами є тензор BoxDecode, `mask_logits` `[1, 256, 256, 4]`, `iou_scores` `[1, 4]`, `object_score_logits` `[1, 1]` і `object_pointers` `[1, 4, 256]`, усі float32.

- Клас виявлення — це вибрана площина: для кодувальника пам'яті візьміть `mask_logits[0, :, :, class]`, збільшене до 1024×1024, як описано в README моделі.
- Для підказки з двох чи більше точок задайте `multimask_output=False`; для одного клацання та відстежуваних кадрів залиште `True`. Клас указує площину, яку вибрало будь-яке з цих правил.
- Для банку пам'яті візьміть `object_pointers[0, class]`, якщо `multimask_output=True`. Якщо `False`, візьміть `object_pointers[0, 0]`: SAM 2 залишає вказівник однієї маски, навіть коли резервне правило стабільності вибирає маску з площин 1–3.
- Оцінка об'єкта 0 або менша робить маску та її рамку порожніми, але клас і далі вказує вибрану площину. Застосуйте правило оцінки об'єкта з README до логітів, які передаєте кодувальнику пам'яті.

```python
encoder_options = pyneat.ModelOptions()
encoder_options.preprocess.resize.mode = pyneat.ResizeMode.Stretch
encoder_options.preprocess.preset = pyneat.NormalizePreset.ImageNet
encoder = pyneat.Model("/path/to/edgetam_image_encoder_mpk.tar.gz", encoder_options)

options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.EdgeTam
options.boxdecode_raw_outputs = True
decoder = pyneat.Model("/path/to/edgetam_mask_decoder_mpk.tar.gz", options)

outputs = decoder.run(decoder_inputs)  # conditioned embeddings, high-res features, prompt
result = pyneat.decode_segmentation(outputs[:1])[0]
plane = int(result.boxes.to_numpy()[0, 5])
logits = outputs[1].to_numpy()[0, :, :, plane]  # [256, 256] low-resolution logits
# With multimask_output=False the memory bank takes pointer 0, whichever plane was chosen.
pointer = outputs[4].to_numpy()[0, plane if options.multimask_output else 0]  # [256]
```

### Концепти EfficientSAM3 {#efficientsam3-concept}

```python
options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.EfficientSam3
options.top_k = 20
options.score_threshold = 0.5
options.preprocess.kind = pyneat.InputKind.Tensor  # two inputs: pixels and packed text
model = pyneat.Model("/path/to/efficientsam3_image_model_mpk.tar.gz", options)

# Stretch to 1008x1008 and scale to [-1, 1], as SAM 3 does, and record that geometry.
stretched = cv2.resize(rgb, (1008, 1008), interpolation=cv2.INTER_LINEAR)
pixels = pyneat.Tensor.from_numpy(stretched.astype(np.float32) / 127.5 - 1, copy=True,
                                  layout=pyneat.TensorLayout.HWC)
facts = pyneat.PreprocessRuntimeMeta()
facts.resize_mode = "stretch"
facts.original_width, facts.original_height = rgb.shape[1], rgb.shape[0]
facts.resized_width = facts.resized_height = 1008
semantic = pixels.semantic
semantic.preprocess = facts
pixels.semantic = semantic

outputs = model.run([pixels, packed_text])
result = pyneat.decode_segmentation(outputs)[0]
boxes = result.boxes.to_numpy()  # [N, 6]: x1, y1, x2, y2, score, 0
masks = result.masks.to_numpy()  # uint8 [N, H, W]
```

## Орієнтовані рамки YOLOv8 та YOLO11 {#yolov8-oriented-boxes}

Виберіть `BoxDecodeType::YoloV8Obb` (Python: `pyneat.BoxDecodeType.YoloV8Obb`; токени `yolov8-obb` або `yolo11-obb`). Передайте дев’ять згрупованих за роллю голів INT8, BF16 або FP32: по три 64-канальні голови DFL для рамок, голови логітів класів та голови логітів кутів, у порядку кроків 8, 16 і 32. Повна кількість класів визначається з голів класів.

BoxDecode застосовує DFL, sigmoid класів, `(sigmoid(angle)-0.25)*pi` та покласове повернуте Fast-NMS з `nms_iou_threshold`. Вхідні дані мають бути необробленими логітами. Геометрія й вихід `BBOX_OBB_V1` відповідають наведеному нижче контракту YOLO26; використовуйте той самий допоміжний метод `decode_obb`.

## Орієнтовані рамки YOLO26 {#yolo26-oriented-boxes}

Явно виберіть `BoxDecodeType::YoloV26Obb` (Python: `pyneat.BoxDecodeType.YoloV26Obb`, токен `yolo26-obb`). Цей профіль приймає дев’ять голів FP32, BF16 або INT8, згрупованих за роллю: три чотириканальні голови відстаней, три голови логітів класів і три одноканальні голови необроблених кутів, із кроками 8, 16 і 32. Усі голови мають узгоджуватися щодо повної кількості класів (1–256). `Auto`, `GroupedByRole` і `GroupedByRoleLogit` вибирають це групування; голови класів зі значеннями ймовірності та перемежовані розміщення відхиляються.

Для голів INT8 потрібні додатні скінченні потензорні метадані квантування та нульова точка INT8. Голови BF16 і FP32 не використовують метадані цілочисельного квантування.

Використовуйте додатне `top_k` і `nms_iou_threshold = 0`. Профіль застосовує sigmoid до логітів класів, вибирає анкери за їхньою найвищою активованою оцінкою, а потім вибирає пари анкер/клас. За однакових оцінок зберігаються порядок першого етапу та порядок класів. Поріг оцінки є строгим (`score > detection_threshold`). Необроблений кут уже задано в радіанах; декодер не застосовує до нього sigmoid і не нормалізує діапазон.

Метадані попередньої обробки мають містити явне скінченне перетворення з координат моделі у вихідні координати з додатними однаковими масштабами X/Y і без зсувної деформації. Явне тотожне перетворення потрібне навіть для плиток розміру моделі. Профіль відхиляє відсутні або анізотропні перетворення, а не наближує повернутий прямокутник. Він зберігає скінченні ширину й висоту зі знаком і не обрізає їх за межами зображення. Для плиткового оцінювання DOTA використовуйте тотожне перетворення для кожної плитки, а відновлення її зміщення та міжплиткове придушення полігонів виконуйте в застосунку.

У графах, керованих джерелом, Core визначає початкову геометрію підготовки з перевіреного контракту попереднього Preproc. Це лише початкове значення для підготовки: кожен кадр і далі має містити скінченне додатне рівномірне афінне перетворення та розміри полотна, що відповідають моделі. Відсутність перетворення кадру є помилкою, а не приводом для підстановки тотожного перетворення.

Вихід має тег `BBOX_OBB_V1`: після 32-байтового заголовка з версією йдуть `top_k` записів по 32 байти. Невикористані записи нульові. `decode_obb_tensor(tensor)` перевіряє один носій; `decode_obb(tensors)` повертає один типізований результат для кожного носія. Обидва копіюють дані в тензори CPU з власним сховищем; ID класів залишаються INT32. Наприклад:

```python
result = pyneat.decode_obb(outputs)[0]
geometry = result.geometry.to_numpy()  # cx, cy, width, height, angle_radians
scores = result.scores.to_numpy()
class_ids = result.class_ids.to_numpy()
```

Цей формат навмисно не є розширенням із BBOX на початку. Використовуйте типізовані допоміжні функції, а не `decode_bbox`, парсери сегментації/поз чи засіб відображення рамок, паралельних осям.

## Суперточка

SuperPoint залишається частиною продукту BoxDecode, але генерує ключові точки, а не намагається видавати їх за прямокутники. Мінімальна конфігурація за замовчуванням A65:

```cpp
BoxDecodeOptions options{BoxDecodeType::SuperPoint};
options.superpoint.descriptor_output_dtype = TensorDType::Float32;

auto decoder = nodes::SimaBoxDecode(model, options);
```

У Python використовуються ті самі значення за замовчуванням:

```python
options = pyneat.BoxDecodeOptions(pyneat.BoxDecodeType.SuperPoint)
options.superpoint.descriptor_output_dtype = pyneat.TensorDType.Float32

decoder = pyneat.nodes.sima_box_decode(model, options=options)
```

`A65V1` є профілем за замовчуванням. Обирайте інший профіль, якщо моделі потрібна інша числова поведінка; Neat не визначає поведінку на основі форми або значень тензора:

| Профіль | Коли його слід обрати | Статус виробництва |
|---|---|---|
| `LightGlueV1` | Детектор, NMS, координати та поведінка дескриптора, сумісні з LightGlue | Підтримується |
| `MagicLeapDemoV1` | Поведінка закріпленої демонстраційної програми Magic Leap | Підтримується |
| `A65V1` | Сумісність зі старим декодером A65 SuperPoint | Підтримується; встановлено за замовчуванням |
| `PaperBicubicV1` | Зарезервовано числовий ідентифікатор для майбутньої повністю визначеної бікубічної політики. | Відхилено до моменту визначення у виробничому середовищі. |

Числовий формат і кодування вихідних даних є незалежними. Наприклад, можна вибрати числовий формат A65 із використанням стандартного вихідного формату V1:

```cpp
BoxDecodeOptions options{BoxDecodeType::SuperPoint};
options.superpoint.profile = SuperPointProfile::A65V1;
options.superpoint.output_format = SuperPointOutputFormat::FeaturePointsV1;
```

Використання застарілої схеми розміщення байтів є опціональним і має додаткові обмеження:

```cpp
options.superpoint.profile = SuperPointProfile::A65V1;
options.superpoint.output_format = SuperPointOutputFormat::LegacyA65InterleavedV0;
options.superpoint.descriptor_output_dtype = TensorDType::Int8;
```

`SuperPointProfile::Auto` спочатку використовує авторитетні метадані MPK `superpoint.profile`. Якщо ні API, `Model::Options.superpoint.profile`, ні MPK не надають профіль, то використовується `A65V1`.
Neat ніколи не визначає профіль на основі розмірів тензорів, значень, імен файлів або наступних вузлів.

Коли їхні загальнодоступні значення-за замовчуванням залишаються незмінними, `detection_threshold=0.0`, `top_k=0`, `nms_radius=-1` і `border_margin=-1` визначаються з обраного профілю. `A65V1` визначає порогове значення `0.1`, Top-K `600`, радіус NMS `4` і межу `0`. LightGlueV1 і MagicLeapDemoV1 використовують порогові значення `0.0005` і `0.015` відповідно; обидва використовують Top-K `600`, радіус NMS `4` і межу `4`.

`nms_iou_threshold` не застосовується до SuperPoint; використовуйте радіус у пікселях `superpoint.nms_radius`. За замовчуванням виводиться структурований масив `FEATURE_POINTS_V1` версії. `LegacyA65InterleavedV0` є явним форматом міграції та вимагає 256-вимірних дескрипторів INT8. Використовуйте `decode_superpoint` замість `decode_bbox` або `BoxDecodeResults`.

Версіоновані записи схеми MPK `superpoint` v1 мають режим відмови за замовчуванням. Вони повинні містити назву профілю, окремі ідентифікатори тензорів детектора та дескриптора, `sha256:` відбиток, що містить 64 шістнадцяткових цифри, і підтримувані вхідні представлення `raw-logits-65` і `coarse-pre-l2`. Схема 0 залишається прийнятною лише як запис для міграції/ручного використання; відсутні поля представлення схеми 0 канонізуються до цих двох представлень необроблених даних і записуються як значення за замовчуванням у діагностиці. Невідомі версії схеми або маркери представлення призводять до помилки під час компіляції.
Якщо перевантаження профілю API суперечить відбитку, який було встановлено для іншого профілю MPK, повторно встановіть відбиток MPK для вибраного профілю; Neat не відкидає та не переінтерпретує ці дані про походження.

## Корисне навантаження BBOX у форматі wire.

Модуль декодування вихідних даних детектора генерує один тензор, позначений як `BBOX`, для кожного вхідного кадру. Цей тензор є буфером байтів першого рангу, що має тип `UInt8`.

| Поле | Значення |
| --- | --- |
| `semantic.detection.format` | `"BBOX"` |
| `dtype` | `UInt8` |
| `shape` | `[N_bytes]`, де `N_bytes` – це обсяг запакованого буфера з архіву моделі. |

Розмір тензора визначається в байтах, а не кількістю виявлених об’єктів. Структура даних використовує порядок байтів little-endian:

```text
offset  size  content
------  ----  -------
  0      4    uint32  N = valid detections in this frame
  4     24    RawBox[0]
 28     24    RawBox[1]
  .      .      ...
  .      .    RawBox[N-1]
                   trailing bytes are padding and must be ignored
```

Кожен запис `RawBox` має розмір 24 байти:

| Зміщення | Розмір | Тип | Поле | Значення |
| --- | --- | --- | --- | --- |
| 0 | 4 | `int32` | `x` | Координата X у верхньому лівому куті у вихідних пікселях. |
| 4 | 4 | `int32` | `y` | Верхня ліва координата y у вихідних пікселях. |
| 8 | 4 | `int32` | `w` | Ширина в пікселях вихідного зображення. |
| 12 | 4 | `int32` | `h` | Висота в пікселях вихідного зображення. |
| 16 | 4 | `float32` | `score` | Впевненість після застосування NMS для `[0.0, 1.0]`. |
| 20 | 4 | `int32` | `class_id` | Ідентифікатор класу, визначений моделлю. |

Відповідний формат Python `struct` для одного запису — `"<iiiifi"`.

Координати вказуються в пікселях вихідного зображення, якщо наявні метадані попередньої обробки. Вони не нормалізовані до `[0, 1]` і не представлені у внутрішньому просторі вхідних даних моделі, який має форму прямокутника.

### Поєднане корисне навантаження сегментації та пози

`yolox-seg-pose` видає один буфер із трьома регіонами. Розміщення кожного регіону визначається однаковою кількістю слотів `top_k`:

| Регіон | Зсув | Крок | Вміст |
| --- | --- | --- | --- |
| заголовок | `0` | 4 | кількість виявлень `int32` |
| рамки | `4` | 24 | записи `BoundingBoxOut`, описані вище |
| маски | `4 + 24*top_k` | `mask_w * mask_h` | `uint8`, одна площина на слот |
| пози | `4 + (24 + mask_w*mask_h)*top_k` | 204 | 17 x `{uint32 x, uint32 y, float32 visibility}` |

Використовуйте `decode_segmentation_pose(...)`, щоб отримати рамки, маски й ключові точки. Рядок `i` кожного тензора описує те саме виявлення. Якщо потрібні лише рамки, використовуйте `decode_bbox(...)` або `BoxDecodeResults(...)`.

Комбінований декодер також приймає застарілий тег `BBOX`. Одночасне відображення масок і поз не підтримується. Не передавайте комбінований буфер до `poseyolo`: цей рендерер очікує ключові точки безпосередньо після рамок, тоді як комбіноване навантаження зберігає там маски.

Кожне виявлення має 17 слотів ключових точок. Бекенд обнуляє невикористані слоти та ключові точки класів, виключених через `pose_classes`. Допоміжна функція копіює ці значення без змін.

Core визначає `num_classes` як глибину голови класів мінус один, оскільки канал 0 містить оцінку наявності об’єкта. Наприклад, 30 каналів означають 29 класів. Явно задане `num_classes` має збігатися з цим значенням.

### Класи ключових точок

Задайте ID класів, які мають ключові точки:

```python
options = pyneat.BoxDecodeOptions(pyneat.BoxDecodeType.YoloXSegPose)
options.yolox_seg_pose.pose_classes = [0, 5]
```

`ModelOptions.yolox_seg_pose` приймає таке саме налаштування.

- Класи поза списком отримують нульові координати ключових точок і видимість.
- Порожній список `BoxDecodeOptions` успадковує налаштування моделі. Якщо список не задано, ключові точки отримують усі класи.
- ID мають бути унікальними та належати діапазону `[0, num_classes)`. Цей параметр підтримується лише для `YoloXSegPose`.

### Версійне корисне навантаження масок {#versioned-masks-payload}

Маски, які не мають розміру 160×160, як-от вихід Segment Anything, використовують версійний заголовок замість початкової кількості. Тензор зберігає тег `BBOX`; `decode_segmentation` і `decode_bbox` розпізнають корисне навантаження за магічним значенням, тому наявні навантаження сегментації не змінюються. Розмітка C++ — `SegmentationMasksHeaderV1` у `pipeline/DetectionTypes.h`:

| Зсув | Розмір | Тип | Поле | Значення |
| --- | --- | --- | --- | --- |
| 0 | 4 | `uint32` | `magic` | `0x3153414D` (`"MAS1"`) |
| 4 | 2 | `uint16` | `version` | `1` |
| 6 | 2 | `uint16` | `header_bytes` | `48` |
| 8 | 4 | `uint32` | `total_bytes` | Розмір усього навантаження |
| 12 | 4 | `uint32` | `count` | Дійсні записи |
| 16 | 4 | `uint32` | `capacity` | Слоти записів і масок |
| 20 | 4 | `uint32` | `mask_height` | Рядки маски (висота оригінального зображення) |
| 24 | 4 | `uint32` | `mask_width` | Стовпці маски (ширина оригінального зображення) |
| 28 | 4 | `uint32` | `records_offset` | `48` |
| 32 | 4 | `uint32` | `record_stride` | `24` (`RawBox`) |
| 36 | 4 | `uint32` | `masks_offset` | Кінець записів, округлений угору до 16 байтів |
| 40 | 4 | `uint32` | `mask_stride` | `mask_height × mask_width` |
| 44 | 4 | `uint32` | `flags` | `0` |

Записи використовують наведену вище розмітку `RawBox`. Кожна маска має тип `uint8` зі значеннями 0 або 255. Неправильний заголовок або розмір відхиляється; записи повертаються, навіть якщо їхня рамка порожня.

## Коли `model.run` повертає необроблені результати.

Деякі маршрути моделі повертають необроблені вихідні дані у вигляді карт ознак замість декодованого тензора `BBOX` з `model.run(...)`. Це не означає, що виконання моделі завершилося з помилкою. Це означає, що модель була виконана, але вказаний маршрут не містив етап декодування обмежувальних рамок (BoxDecode) в точці, де ви зчитуєте вихідні дані.

Використовуйте це правило:

- `detections=...` або тензор `BBOX`: розпакуйте дані BBOX або використовуйте їх.
  допоміжні функції для декодування.
- `raw_output_heads=...`: додайте етап BoxDecode, перевірте маршрут моделі або
  обробляйте необроблені тензори за допомогою спеціалізованої постобробки для конкретної моделі.

Не розглядайте необроблені дані як обмежувальні рамки. Структура необроблених тензорів залежить від експортованої родини моделей та специфікацій архіву моделі.

## Замінити контракт.

MPK надає тензорні контракти та відомості про сімейство декодування. Задавайте параметри фільтрації в `ModelOptions`. Для вузла `SimaBoxDecode(Model, ...)` додатні аргументи фільтрації перевизначають визначені параметри Model; нульові аргументи успадковують їх. `ModelOptions.score_threshold = 0.0` — це справжній нульовий поріг оцінки, а не запит на відновлення порога з пакета.

| Аргумент середовища виконання | Значення, що передається | Поведінка |
| --- | --- | --- |
| `decode_type` | порожньо / `Unspecified` | Зберігайте архів моделі або використовуйте функцію планування маршруту, якщо це підтримується. |
| `decode_type` | конкретний тип | Замініть сімейство декодувань для цього запуску. |
| `original_width` / `original_height` | `0` | Збережіть геометрію, що входить до пакета, або метадані попередньої обробки. |
| `original_width` / `original_height` | додатне ціле число | Замініть вихідні розміри для відображення координат. |
| Вузол, прив’язаний до моделі: `detection_threshold` | `0.0` | Успадкувати визначений поріг оцінки Model. |
| Вузол, прив’язаний до моделі: `detection_threshold` | `> 0.0` | Перевизначити поріг оцінки. |
| Вузол, прив’язаний до моделі: `nms_iou_threshold` | `0.0` | Успадкувати визначений IoU для NMS із Model. |
| Вузол, прив’язаний до моделі: `nms_iou_threshold` | `> 0.0` | Перевизначити IoU для NMS. |
| Вузол, прив’язаний до моделі: `top_k` | `0` | Успадкувати визначену межу виходу Model. |
| Вузол, прив’язаний до моделі: `top_k` | `> 0` | Перевизначити максимальну кількість збережених детекцій. |

Декодування обмежувальних рамок потребує додатного визначеного `top_k`; нуль не означає необмежене сховище виходу. Для необроблених голів без прив’язаної `Model` задайте `top_k` до побудови графа. Вузол, прив’язаний до моделі, може успадкувати додатну межу Model, залишивши власне `top_k` нульовим. Ці параметри не змінюють окремі допоміжні читачі результатів: у них `top_k=0` означає відсутність додаткової межі для вже обмеженого виходу. Нульовий поріг оцінки дозволяє нульові оцінки, але не обходить перевірку геометрії, виключення фону, NMS або межу виходу. За нульового IoU для NMS YOLO26 пропускає NMS. Інші профілі YOLO та SSD із ввімкненим NMS усе ще застосовують придушення за квантованим IoU. Додатні пороги YOLO26 вмикають NMS.

`num_classes` порівнює значення, налаштоване викликачем, із кількістю класів, отриманою з тензорного контракту MPK:

| Сімейство моделей | Налаштоване `num_classes` | `num_classes` з MPK | Поведінка |
| --- | --- | --- | --- |
| Будь-яка підтримувана модель | `0` | додатне значення, яке можна вивести | Використовується кількість класів з MPK. |
| Будь-яка підтримувана модель | додатне ціле число | те саме значення | Використовується налаштована кількість класів. |
| Модель із неоднозначним поділом класів | додатне ціле число | недоступно | Використовується налаштована кількість класів. Це потрібно, коли поділ голови з одним класом не можна надійно вивести. |
| YOLOv5 або YOLO26 | додатне ціле число | інше значення | Помилка до побудови конвеєра з повідомленням обох значень. Ці необроблені розкладки голів виводять кількість класів із глибини тензора. |
| SSD або інше сімейство YOLO до YOLO26 без оцінки пози | додатне ціле число | інше значення | Застосовується наявна поведінка явного перевизначення для цього сімейства. Декодери пози та SuperPoint зберігають свої правила. |

`detection_threshold` – це назва, яка використовується конструкторами вузлів/етапів BoxDecode. `ModelOptions.score_threshold` – це опція моделі, яка передає дані до того ж модуля керування.

## Вибір правильного типу.

- Вибирайте за контрактом експортованих голів: `YoloV6` очікує сирі відстані l/t/r/b та логіти класів. Для пакетів YOLOv6 із декодуванням рамок усередині графа використовуйте `Yolo`; для виходів, згрупованих як `[bbox_0..2, class_prob_0..2]`, задайте `decode_type_option=GroupedByRoleProbability` та `num_classes`, що відповідає кількості навчених класів.
- Якщо рамки відображаються неправильно або їх розміри змінено некоректно, перевірте політику зміни розміру зображення. Використовуйте `resize_mode_override` лише тоді, коли ваш граф не має попереднього етапу `Preproc`, який записує метадані про зміну розміру.
- Якщо ви створюєте власний набір моделей, переконайтеся, що в описі архіву точно вказано характеристики детекторів: порядок тензорів, логічна форма, фізичне зберігання, тип даних/квантування, діапазон значень, кількість класів і будь-які зрізані вихідні дані. Код застосунку не повинен містити жодних налаштувань для врахування цих деталей.

## Рекомендації щодо форми та компонування.

Різні моделі детектування використовують різні схеми організації вихідних даних. Деякі використовують один тензор для кожного рівня ознак; інші розділяють обмежувальні рамки, інформацію про об’єкти, класи, ключові точки або маски на окремі тензори. Вихідні дані деяких моделей представлені у вигляді щільних тензорів HWC; інші тензори пакуються або розбиваються компілятором/середовищем виконання.

Для моделей, що використовують пакетну обробку, це регулюється відповідним контрактом. Для тензорів, з’єднаних вручну, головне правило полягає в тому, щоб точно відповідати експортованому формату вихідних даних. Не слід вибирати тип декодування лише на основі рангу або кількості каналів.

Розширені правила для тензорних контрактів:

- Типи декодування сімейства YOLO, окрім детекції `YoloV5` (`Yolo`, `YoloV7`, `YoloV8`, `YoloV9`, `YoloV10` та варіанти сегментації чи оцінки пози), очікують або роз'єднані голови, або об'єднані голови, що відповідають сімейству моделі.
- Згорнуті шари YOLO повинні зберігати однакову кількість класів і глибину шарів.
  рівні функціональності.
- Детекція `YoloV5` приймає рівно три недекодовані об'єднані голови в порядку P3/P4/P5. Їхні сітки повинні мати геометрію stride 8/16/32, а кожна логічна глибина — дорівнювати `3 * (num_classes + 5)`. BoxDecode застосовує сигмоїду, перетворення сітки та кроку, а також стандартні якорі YOLOv5 (`{10,13},{16,30},{33,23}`; `{30,61},{62,45},{59,119}`; `{116,90},{156,198},{373,326}`). Власні таблиці AutoAnchor і декодовані експорти з шести тензорів боксів/класів мають використовувати інший контракт.
- `YoloV26` використовує згруповані необроблені координати обмежувальних рамок (l/t/r/b) разом із заголовками, що визначають клас і оцінку.
- `Ssd` – це **не** універсальний декодер для SSD-накопичувачів. Він обробляє лише **чотири попередньо налаштовані профілі**.
  з повного впорядкованого набору локальних/конфігураційних змінних H/W/C, визначеного під час компіляції. Будь-який інший набір або порядок змінних відхиляється, і виводиться повідомлення про помилку, яке містить інформацію про виявлений і підтримуваний набори:
  - **SSD300**`dboxes300_coco`): вхідне зображення 300×300, карти ознак.
    `{38,19,10,5,3,1}`, апріорні значення для кожної комірки, `{4,6,6,6,4,4}`, порядок каналів впевненості.
`class*A + anchor`, оцінки класів, отримані за допомогою функції **softmax** для кожного класу (включно з фоном під індексом 0).
  - **SSD-Mobile-300-v1** (`ssd_anchor_generator`): вхідний розмір 300×300, функція:
    карти `{19,10,5,3,2,1}`, апріорні значення для кожної комірки `{3,6,6,6,6,6}`, канал зворотного зв’язку
    замовити `anchor*C + class`, оцінки для кожного класу за допомогою сигмоїдної функції для кожного класу (фон ігнорується).
  - **SSD-Mobile-320-v1** (`ssd_anchor_generator`): вхідне зображення 320×320, вилучення ознак.
    карти `{20,10,5,3,2,1}`, апріорні значення для кожної комірки `{3,6,6,6,6,6}`, канал зворотного зв’язку
    замовити `anchor*C + class`, оцінки для кожного класу за допомогою сигмоїдної функції для кожного класу (фон ігнорується).
  - **SSDlite-Mobile-320-v1** (TorchVision `DefaultBoxGenerator`): 320×320
    вхідні дані, карти ознак `{20,10,5,3,2,1}`, шість апріорних значень на комірку на кожному рівні,
    порядок локалізації `anchor*4 + {dx,dy,dw,dh}`, порядок впевненості
    `anchor*C + class` та оцінки класів за допомогою **softmax** для всіх 91 класу,
    включаючи фон.

Усі рецепти використовують згруповані локалізаційні голови для кожного рівня (глибина =
`4 * priors-per-cell`) у поєднанні з головами для оцінки класу (глибина =
`num_classes * priors-per-cell`), масштабування дисперсії FasterRcnnBoxCoder
(`scale_xy 0.1`, `scale_wh 0.2`) та попередню обробку з розтягуванням (анізотропне)
зміна розміру. Активація оцінки фіксується рецептом (відповідає декодеру на пристрої), а згрупована структура, що базується на ролі, вибирається автоматично — залиште
`decode_type_option` як `Auto`. Незгрупована структура відхиляється.

**Розмір моделі є частиною профілю**, а не лише геометрії голови. SSD300-v1
та SSD-Mobile-300-v1 вимагають 300×300; обидва профілі 320-v1 вимагають 320×320. Будь-яка цільова зміна розміру попередньої обробки або перевизначення розміру моделі
відхиляється під час створення, оскільки таблиці апріорних значень і зворотна проєкція з розтягуванням дійсні лише для цього розміру кадру.

Конструкція `SimaBoxDecode` у сирому/автономному вигляді ніколи не визначає режим зміни розміру. Збережіть вимогу метаданих попередньої обробки `Preproc` або використовуйте явне перевантаження, щоб підтвердити зовнішньо виконану `ResizeMode::Stretch`; Letterbox і Crop відхиляються.

**Контракт `num_classes`.** Кількість закодованих класів завжди визначається з глибини голови впевненості (`conf_depth / priors-per-cell`, фон під індексом 0 включно). SSD300-v1 дозволяє вибір суміжного префіксу, наприклад, підготовлений маршрут 81-to-8; інші три профілі вимагають точної кількості закодованих класів. Недійсний вибір відхиляється під час створення. Залиште його без змін, щоб використовувати значення за замовчуванням профілю.
- `Detr` визначає класи каналів на основі максимальної глибини головного об’єкта та вимагає наявності дійсного
  клас розмірності.
- `EffDet` і `Centernet` використовують контракти своїх сімейств моделей; не спрямовуйте їх через тип декодування YOLO.
- `*-seg` типи декодування генерують вихідні дані, що містять інформацію про межі області, а також маскові дані, специфічні для конкретного завдання.

Якщо набір користувацьких моделей не відповідає жодній із повних замовлених сигнатур, підготуйте новий профіль, який буде явно підтримуватися, замість того, щоб послаблювати алгоритм зіставлення.

## Нотатка про Python.

Під час налаштування параметрів моделі з використанням Python, якщо це можливо, використовуйте перелічуваний тип (enum) замість рядка:

```python
opt = pyneat.ModelOptions()
opt.decode_type = pyneat.BoxDecodeType.YoloV8
```

Аналізуйте результати за допомогою допоміжного інструменту, який відповідає поставленій задачі моделі:

```python
outputs = model.run([image])

boxes = pyneat.decode_bbox(outputs)[0].to_numpy()

pose = pyneat.decode_pose(outputs)[0]
pose_boxes = pose.boxes.to_numpy()
keypoints = pose.keypoints.to_numpy()

seg = pyneat.decode_segmentation(outputs)[0]
seg_boxes = seg.boxes.to_numpy()
masks = seg.masks.to_numpy()
```

## Оновлення

Попередні параметри BoxDecode запровадили ABI 6. Поточні параметри арифметики джерела потребують ABI 10 (`libsima_neat.so.10`). Перезберіть застосунки C++, плагіни й прив’язки Python з відповідними заголовками та бібліотеками. Не завантажуйте бінарні файли ABI 5–9 через посилання для сумісності.


### Допуск комбінованого входу YOLOX

`YoloXSegPose` приймає голови BF16 та INT8 або нативні голови FP32 у неперервному сховищі чи сховищі з додатними кроками без перекриття (включно з планарними поданнями CHW). Адреси та кроки FP32 мають бути вирівняні на чотири байти; FP32 із блокуванням каналів та UINT8 відхиляються. Неявне перетворення FP32 із втратами не додається. Прототип має власний тип даних і потензорне квантування INT8; ролі кожної голови детекції все одно мають узгоджуватися за типом даних. Core зберігає ці відомості для кожного порту для допуску Kernels, а не застосовує тип даних або квантування першої голови до всіх портів. Три рівні детекції мають кроки 8, 16 та 32 по обох осях. Ширина й висота моделі мають бути кратними 32, але не обов’язково рівними. Прототип залишається 160×160×32 і не змінює розмір мовчки разом із розмірами моделі.

Для нецентрованого доповнення або координат обрізання використовуйте метадані попередньої обробки. Афінне перетворення відображає координати **з моделі до оригіналу**; зсув осей, обертання та списки ROI цим комбінованим профілем не підтримуються. Обрізання потребує авторитетних афінних метаданих під час підготовки. Це контракт декодера для зовнішньо попередньо оброблених тензорів, а не нова підтримка створення обрізаного входу в попередній обробці `Model`. Модель із менш ніж 17 ключовими точками все одно публікує фіксований публічний дротовий формат із 17 слотами, заповнюючи невикористані слоти нулями.


## Відображення координат обрізання {#crop-coordinate-mapping}

Керований моделлю Crop передає фактичне обернене перетворення зображення підтримуваним профілям детекції, зокрема класичному DETR, DetrFocal та звичайній детекції YOLO. Відбір і NMS залишаються в координатах моделі; прийняті рамки потім відображаються й обрізаються за межами початкового зображення. Відсутні чи суперечливі метадані перетворення спричиняють явну помилку. Це не вмикає нові поєднання обрізання для масок, поз, пропозицій RCNN чи SSD multiclass. Чинні профілі орієнтованих рамок і далі вимагають однакових масштабів осей; цілочисельні розміри масштабування можуть давати різні масштаби.
