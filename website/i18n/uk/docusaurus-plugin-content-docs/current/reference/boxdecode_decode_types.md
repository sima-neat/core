# BoxDecode: типи декодування

`nodes::SimaBoxDecode` перетворює необроблені тензори голів виявлення на результати виявлення. Він працює після інференсу моделі, застосовує обчислення декодування для вибраної родини моделей і фільтрує результати виявлення. NMS і кодування виходу залежать від вибраної родини. Для моделей виявлення цей вміст можна розібрати як рамки; для моделей пози й сегментації можна також розібрати ключові точки або маски, що йдуть після рамок.

Для звичайної роботи з пакетами моделей віддавайте перевагу конструктору, що враховує `Model`. Архів моделі надає порядок тензорів, розкладку, квантування, кількість класів, метадані зміни розміру й підказки щодо області значень оцінок, потрібні декодеру. Ваш застосунок зазвичай вибирає лише родину декодування та пороги фільтрації.

## Бекенд середовища виконання

BoxDecode і SuperPoint використовують `neatkernelrunner` із перевіреними виконуваними файлами Kernels. Наявні формати виходу для виявлення та ознак не змінилися. Декодування орієнтованих рамок YOLO26 використовує окремий версійований формат. Для прямого тензорного входу використовуйте тензори в спільній пам’яті CMA (`TensorMemory::EV74`), навіть коли декодування виконується на A65: цей вибір пам’яті забезпечує транспорт DMA-BUF, а не задає ціль виконання.

Перший етап RCNN використовує контракт top-K для кожного рівня, яким володіє ядро: глобальне NMS, потім до `top_k` збережених кандидатів на кожен рівень площі моделі. Його вихід — формат передавання пропозицій, а не звичайний формат BBOX: чотири групи, кожна з лічильником INT32 і `top_k` записами із шести значень FP16 (`score, 0, x1, y1, x2, y2`). Перетворення координат зберігає дробову геометрію до остаточної серіалізації. Використовуйте цей вихід як вхідні пропозиції для другого етапу, а не з `decode_bbox_tensor()`. Застарілий плагін не завантажується.

Доповнені голови SuperPoint з чергуванням даних INT8, BF16 і FP32 використовують нативний щільний читач з явними кроками пікселів. Доповнення не потрапляє до редукцій детектора й вибірки дескрипторів, і для цього не потрібні етап Cast чи матеріалізація. Порти INT8 зберігають власне задане квантування. Нативні голови з плитковою розкладкою MLA зберігають оголошену фізичну розкладку; щільні скаляри ніколи не перепозначаються як байтові площини MLA.

## Швидкий старт

```cpp
using namespace simaai::neat;

Model model("/path/to/yolov8_model.tar.gz");

auto boxdecode = nodes::SimaBoxDecode(
    model,
    BoxDecodeType::YoloV8,
    /* detection_threshold */ 0.25,
    /* nms_iou_threshold */ 0.45,
    /* top_k */ 100);
```

Для використання як окремого етапу:

```cpp
simaai::neat::stages::BoxDecodeOptions opt(simaai::neat::BoxDecodeType::YoloV8);
opt.detection_threshold = 0.25;
opt.nms_iou_threshold = 0.45;
opt.top_k = 100;
```

## Аргументи

| Аргумент | Значення |
| --- | --- |
| `decode_type` | Родина моделей / формат голови, наприклад `BoxDecodeType::YoloV8` або `BoxDecodeType::YoloX`. Обов’язковий. |
| `detection_threshold` | Мінімальна оцінка, потрібна, щоб зберегти результат виявлення. Використовуйте значення, що відповідає моделі, наприклад `0.25`. |
| `nms_iou_threshold` | Поріг IoU для придушення немаксимумів (NMS). `0` зберігає значення, упаковане в модель; якщо такого значення немає, YOLO26 пропускає NMS, а інші декодери придушують кожну рамку, що перекривається. Задайте значення, що відповідає моделі, наприклад `0.45`. |
| `top_k` | Максимальна кількість результатів на виході. Для декодування необроблених обмежувальних рамок потрібна явна додатна межа. У вузлі, прив’язаному до моделі, `0` успадковує визначену межу Model. Для `0` SuperPoint використовує типове значення свого профілю. |
| `original_width`, `original_height` | Розмір зображення джерела для відображення координат, коли використовується конструктор із необробленою геометрією. |
| `model_width`, `model_height` | Перевизначення вхідного розміру моделі. З конструктором `Model` воно змінює параметри просторового декодування, а не упакований тензорний контракт. |
| `resize_mode_override` | Використовуйте, лише коли жоден попередній етап `Preproc` не записує метадані зміни розміру і вам потрібно явно задати поведінку розтягування, letterbox або обрізання. |
| `decode_type_option` | Розширений селектор підрозкладки. Для пакетів моделей залиште `Auto`, якщо не знаєте розкладку експортованої голови. |

## Вхідні та вихідні дані

**Вхідні дані:** необроблені тензори виявлення з моделі. Очікувані форми тензорів залежать від родини моделей. З MPK/архівом моделі Neat зчитує ці деталі з упакованого контракту.

**Вихідні дані:** один тензор BoxDecode з декодованими результатами виявлення. Моделі виявлення використовують стандартний вміст `BBOX`. Моделі пози й сегментації зберігають ті самі початкові рамки й додають власний вміст, специфічний для завдання:

| Завдання моделі | Допоміжна функція C++ | Допоміжна функція Python | Декодовані тензори |
| --- | --- | --- | --- |
| Виявлення | `decode_bbox(...)` | `pyneat.decode_bbox(...)` | рамки `[N, 6]` float32: `x1, y1, x2, y2, score, class_id` |
| Орієнтоване виявлення | `decode_obb(...)` | `pyneat.decode_obb(...)` | Геометрія у власному тензорі `[N, 5]` float32 (`cx, cy, width, height, angle_radians`), оцінки `[N]` float32, ID класів `[N]` int32 |
| Поза | `decode_pose(...)` | `pyneat.decode_pose(...)` | рамки `[N, 6]` і ключові точки `[N, 17, 3]` float32: `x, y, visibility` |
| Сегментація | `decode_segmentation(...)` | `pyneat.decode_segmentation(...)` | рамки `[N, 6]` float32 і маски `[N, 160, 160]` uint8 |
| Сегментація + поза | `decode_segmentation_pose(...)` | `pyneat.decode_segmentation_pose(...)` | рамки `[N, 6]` float32, маски `[N, 160, 160]` uint8, ключові точки `[N, 17, 3]` float32 |
| Segment Anything | `decode_segmentation(...)` | `pyneat.decode_segmentation(...)` | рамки `[N, 6]` float32 і маски `[N, H, W]` uint8 розміру оригінального зображення; для декодера підказок N дорівнює 1 |
| SuperPoint | `decode_superpoint(...)` | `pyneat.decode_superpoint(...)` | ключові точки `[N,2]`, оцінки `[N]`, дескриптори `[N,D]` |

Графи відображення виявлень із рамками, паралельними осям, можуть передавати результат у `SimaRender`. Використовуйте `decode_bbox(...)` лише для наявних форматів, що починаються з рамок; ані ця функція, ані `SimaRender` не приймають орієнтованих рамок.

## Розміщення letterbox {#letterbox-placement}

Нецентроване розміщення letterbox, як-от `LetterboxPlacement::TopLeft` (див. [Зміна розміру в Preproc](/reference/nodes/preproc#resize-and-aspect-ratio)), підтримують профілі виявлення, які відображають рамки через афінне перетворення кожного кадру з координат моделі в координати оригіналу: родини виявлення YOLO, декодований YOLO, EfficientDet, DETR, DetrFocal, CenterNet і SSD. Поза, сегментація та 91-класовий багатокласовий SSD роблять те саме, коли встановлений випуск Kernels приймає для них перетворення (див. [Відображення координат обрізання](#crop-coordinate-mapping)); інакше, а для пропозицій RCNN завжди, профіль відхиляє таке розміщення, а не повертає зсунуті результати. Центрований letterbox зберігає своє відображення. Типи Segment Anything мають власні вимоги; див. [Правила Segment Anything](#segment-anything-rules).

## Класичний DETR {#classic-detr}

Виберіть `Detr` для однієї чотириканальної голови логітів рамок і однієї голови логітів класів з останнім каналом фону на тій самій сітці запитів. Залиште `decode_type_option` як `Auto`: рецепт вибирає Softmax без підказок у назвах тензорів. Фон бере участь у знаменнику, але не входить до кількості класів переднього плану й до вибору результатів. До координат рамок застосовується сигмоїда; це не декодер для вже нормалізованих рамок моделей із focal loss.

Використовуйте Stretch і додатне `top_k`. Декодер не застосовує NMS і відображає результати на оригінальний кадр за метаданими попередньої обробки. Явні розкладки зі значеннями ймовірностей або суперечливі активації оцінок відхиляються.

```python
options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.Detr
options.preprocess.resize.mode = pyneat.ResizeMode.Stretch
options.top_k = 100
options.score_threshold = 0.7
```

## Детектори запитів із focal loss

Для двох упорядкованих тензорів використовуйте `BoxDecodeType::DetrFocal` (Python: `pyneat.BoxDecodeType.DetrFocal`, токен `detr-focal`): нормалізовані координати `cx,cy,width,height` із глибиною 4, потім незалежні логіти класів із глибиною N. Їхні осі запитів і типи даних мають збігатися; N — від 1 до 1024. Підтримується зберігання у FP32, BF16 та INT8 із заданим квантуванням.

Профіль застосовує сигмоїду лише до логітів класів і вибирає глобальні top-K пар «запит/клас». Один запит може дати кілька класів. Немає фонового класу, сигмоїди для рамок, argmax для кожного запиту, NMS чи фільтра малих площ. Задайте `top_k` як додатну межу, `detection_threshold=0` для top-K без фільтрації та `nms_iou_threshold=0`. Використовуйте Stretch і фактичні розміри зображення та моделі.

Наявний вихід `BBOX` обрізає рамки до меж зображення й округлює координати XYWH до цілих чисел; `decode_bbox` подає ці координати як числа з рухомою комою, але не відновлює субпіксельну точність. У Python використовуйте `decode_bbox(..., strict=True)`, щоб зберегти рядки з нульовою площею, що виникли через округлення, замість типового фільтра вироджених рамок. Точність цього представлення вимірюйте окремо від необрізаного еталона з рухомою комою. Класичний `BoxDecodeType::Detr` не змінився: він очікує логіти рамок і softmax-оцінки з урахуванням фону, а не ці тензори.

Перевантаження Python з необробленою геометрією відповідає фабриці C++, коли ви самі передаєте тензори голів. Для щільних голів FP32 зберігайте повні вихідні адаптери моделі та явно оголошуйте їхнє фактичне сховище. Не обрізайте вихід до необробленого виходу MLA й не перепозначайте доповнені байти як щільні тензори.

```python
node = pyneat.nodes.sima_box_decode(
    pyneat.BoxDecodeType.DetrFocal,
    original_width=1280, original_height=720,
    model_width=640, model_height=640,
    detection_threshold=0.0, nms_iou_threshold=0.0, top_k=300,
    decode_type_option=pyneat.BoxDecodeTypeOption.InterleavedByHeadLogit,
    source_storage=pyneat.BoxDecodeSourceStorage.DenseHwc,
    detess=False, dequant=False,
    resize_mode=pyneat.ResizeMode.Stretch,
)
```

Скінченні обернені розміри проходять те саме обрізання кінцевих точок і стають порожніми записами BBOX; вибрана пара при цьому не замінюється, а її оцінка не змінюється. Нескінченні значення та NaN у координатах чи логітах, як і раніше, спричиняють помилку до публікації.

## Маски Segment Anything {#segment-anything-masks}

Кожна модель Segment Anything має власний тип декодування. Для декодера підказок BoxDecode перетворює один запуск декодера на один результат виявлення: вибрану маску розміру оригінального зображення, її мінімальну рамку та передбачений IoU. Для моделі зображень концептів EfficientSAM3 він перетворює один запуск на щонайбільше `top_k` результатів виявлення, кожен із власною маскою.

| Модель | `decode_type` (токен) | Попередня обробка Model, що отримує зображення | Параметри декодера |
| --- | --- | --- | --- |
| MobileSAM | `MobileSam` (`mobilesam`) | Кодувальник: `resize.mode=Letterbox`, `resize.placement=TopLeft`, 1024×1024, `pad_value=116`; `preset=ImageNet` | `multimask_output` |
| EdgeTAM | `EdgeTamSeg` (`edgetam-seg`) для маски; `EdgeTamTrack` (`edgetam-track`) для відстеження | Кодувальник зображень: `resize.mode=Stretch`, 1024×1024, без доповнення; `preset=ImageNet` | `multimask_output` |
| EfficientSAM-T / -S | `EfficientSam` (`efficientsam`) | Кодувальник: `resize.mode=Stretch`, 1024×1024, без доповнення; без пресета, `normalize.enable=On` (значення 0–1; нормалізацію виконує сам кодувальник) | Залиште `multimask_output` рівним true |
| EfficientSAM3, інтерактивний | `EfficientSam3` (`efficientsam3`) | Кодувальник зображень: `resize.mode=Stretch`, 1008×1008, без доповнення; `normalize.enable=On` з `normalize.mean` і `normalize.stddev` (0.5, 0.5, 0.5) | `multimask_output` |
| EfficientSAM3, концепти | `EfficientSam3` (`efficientsam3`) | Сама модель зображень концептів на тензорному маршруті: застосунок розтягує зображення до 1008×1008, масштабує його до [−1, 1] і додає `semantic.preprocess` з `resize_mode="stretch"` | `top_k`, `score_threshold` |

Python використовує ті самі назви: `pyneat.BoxDecodeType.MobileSam`, `EdgeTamSeg`, `EdgeTamTrack`, `EfficientSam` і `EfficientSam3`. MobileSAM доповнює нулями після нормалізації, а це відповідає середньому пікселю ImageNet (124, 116, 104); `pad_value=116` наближено відтворює його. Маски ніколи не покривають доповнення. Model EfficientSAM3 є моделлю зображень концептів, коли її виходи — виявлення `[Q, 6]` і логіти масок із Q каналами, а інакше — декодером підказок. Повний робочий процес кожної моделі описано в її README у [sima-neat/models](https://github.com/sima-neat/models), наприклад у [README EdgeTAM](https://github.com/sima-neat/models/tree/develop/models/edgetam).

`Model::Options::multimask_output` (Python: `ModelOptions.multimask_output`) відповідає параметру `predict(multimask_output=...)` в оригінальній реалізації. Залиште `true` для одного клацання, яке є неоднозначним; задайте `false` для рамки або кількох точок.

| `decode_type` | `multimask_output=true` (типово) | `multimask_output=false` |
| --- | --- | --- |
| `MobileSam` | Найкращий передбачений IoU серед масок 1–3 | Маска 0 |
| `EdgeTamSeg`, `EdgeTamTrack` | Найкращий передбачений IoU серед масок 1–3 | Маска 0, якщо вона стабільна, інакше найкраща з масок 1–3 |
| `EfficientSam` | Найкращий передбачений IoU серед масок 0–2 | Відхиляється: EfficientSAM не експортує токен однієї маски |
| `EfficientSam3`, декодер підказок | Найкращий передбачений IoU серед масок 1–3 із чотирьох або 0–2 із трьох | Чотири маски: як EdgeTAM. Три маски: відхиляється |
| `EfficientSam3`, концепти | Щонайбільше `top_k` запитів з оцінкою понад `score_threshold` | Відхиляється: виявлення концептів не має вибору з кількох масок |

- Як і в SAM2, маска 0 стабільна, коли щонайменше 98% її логітів, більших за −0.05, також більші за 0.05.
- Декодер, експортований з одним каналом маски, використовує цю маску за будь-якого значення.
- Інші типи декодування відхиляють `multimask_output=false`. Вибір належить `Model`: дві Model декодера можуть використовувати той самий MPK.

### Що означає кожен вихід {#segment-anything-outputs}

Тензор BoxDecode використовує [версійований вміст масок](#versioned-masks-payload). `decode_segmentation` повертає рамки `[N, 6]` і маски `[N, H, W]`:

- **Рамка.** `x1, y1, x2, y2` у пікселях оригінального зображення. Рамка декодера підказок — мінімальна рамка пікселів маски: `x2` і `y2` вказують на позицію одразу після останнього стовпця й рядка маски, тож `x2 - x1` — ширина маски. Рамка виявлення концепту береться з його голови виявлення, масштабується до оригінального зображення й не обрізається.
- **Оцінка.** Передбачений IoU вибраної маски або оцінка запиту концепту.
- **Клас.** Вибраний канал маски (індекс із таблиці вище) або 0 для запиту концепту.
- **Маска.** `uint8`: 255 там, де логіт, передискретизований до розміру оригінального зображення, більший за 0, інакше 0.
- **Кількість.** Для декодера підказок завжди 1: порожня маска має повністю нульову рамку й зберігає оцінку та клас. Як і в оригінальній реалізації, оцінка об’єкта EdgeTAM, що дорівнює 0 або менша, робить маску порожньою. Модель концептів повертає збережені запити за спаданням оцінки (за рівності — за індексом запиту).

`EdgeTamSeg` і всі інші типи Segment Anything повертають лише тензор BoxDecode. З `EdgeTamTrack` після нього йдуть власні виходи декодера; див. [Відстеження EdgeTAM](#edgetam-tracking).

`SimaRender` не малює ці маски: він малює лише вміст сегментації без заголовка, маски якого менші за кадр. Малюйте маски Segment Anything за результатом `decode_segmentation`.

### Правила {#segment-anything-rules}

- **Виходи декодера.** Декодер підказок експортує логіти масок із кількістю масок названої моделі (1, 3 або 4), один передбачений IoU на маску та, для EdgeTAM, оцінку об’єкта; приймаються виходи INT8, BF16 і FP32. Модель зображень концептів експортує виявлення `[Q, 6]` і логіти масок для кожного запиту.
- **Параметри.** Декодери підказок: залиште `top_k` рівним 0 або 1, а `nms_iou_threshold` — 0; `score_threshold` має бути меншим за 1, а інакше ігнорується; `num_classes` — кількість масок або 0. Моделі зображень концептів: задайте `top_k` у межах 1..Q.
- **Геометрія зображення.** Полотно, розмір оригінального зображення та зміна розміру беруться з `tensor.semantic.preprocess` входів декодера й мають відповідати таблиці; інакше побудова завершується помилкою, у якій названо параметр, що його треба змінити. Передавайте виходи кодувальника декодеру через `.cvu()` і будуйте декодер підказок з його входів через `build(inputs)` або `execution_plan(inputs)`. На тензорному маршруті моделі зображень концептів додайте ці дані до її тензора пікселів.
- **Ціле зображення з одноразовою зміною розміру.** Обрізання або ROI перед зміною розміру відхиляється, так само як і масштабований розмір, який декодер не відтворює. Для MobileSAM застосовуйте letterbox із `resize.placement=TopLeft` у Model, що виконує попередню обробку зображення й округлює так само, як Segment Anything, а не окремим вузлом `Preproc`. Дані, які ви додаєте самі, мають містити афінне перетворення: `affine_m00` = оригінальна ширина / масштабована ширина, `affine_m11` = оригінальна висота / масштабована висота.
- **Один розмір зображення на runner.** Маски мають розмір оригінального зображення, тому побудований runner обслуговує один розмір. `Model::run` будує інший runner для нового розміру; потоковий граф відхиляє кадр іншого розміру.

### Кодувальник і декодер {#segment-anything-example}

Приклад для MobileSAM; для іншої моделі використовуйте її параметри кодувальника та тип декодування з таблиці.

```python
encoder_options = pyneat.ModelOptions()
encoder_options.preprocess.resize.mode = pyneat.ResizeMode.Letterbox
encoder_options.preprocess.resize.placement = pyneat.LetterboxPlacement.TopLeft
encoder_options.preprocess.resize.pad_value = 116
encoder_options.preprocess.preset = pyneat.NormalizePreset.ImageNet
encoder = pyneat.Model("/path/to/mobile_sam_image_encoder_mpk.tar.gz", encoder_options)

options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.MobileSam
options.multimask_output = False  # a box prompt; keep True for one click
decoder = pyneat.Model("/path/to/mobile_sam_prompt_decoder_mpk.tar.gz", options)

embeddings = encoder.run([image])[0]
# .cvu() keeps the encoder's preprocess metadata on the embeddings.
outputs = decoder.run([embeddings.cvu(), point_encoding, point_types])
result = pyneat.decode_segmentation(outputs)[0]
box = result.boxes.to_numpy()[0]  # x1, y1, x2, y2, IoU, mask index
mask = result.masks.to_numpy()[0]  # uint8 [H, W], 0 or 255
```

### Відстеження EdgeTAM {#edgetam-tracking}

Кодувальнику пам’яті й банку пам’яті EdgeTAM потрібні логіти вибраної маски низької роздільності та її вказівник об’єкта, яких BoxDecode не декодує. `EdgeTamTrack` повертає тензор BoxDecode, а за ним виходи декодера з того самого запуску — точно так, як та сама Model повертає їх без BoxDecode: `mask_logits` `[1, 256, 256, 4]`, `iou_scores` `[1, 4]`, `object_score_logits` `[1, 1]` і `object_pointers` `[1, 4, 256]`, усі float32. Кожен із них коштує одне перетворення на кадр. Декодуйте лише перший тензор; необроблені тензори не мають тегу виявлення. `EdgeTamTrack` відхиляється, коли маршрут моделі без BoxDecode не може повернути ці тензори.

- Клас виявлення — це вибрана площина: для кодувальника пам’яті візьміть `mask_logits[0, :, :, class]`, масштабоване до 1024×1024, як описано в README моделі.
- Для підказки з двох чи більше точок задайте `multimask_output=False`; для одного клацання та відстежуваних кадрів залиште `True`. Клас указує площину, яку вибрало відповідне правило.
- Для банку пам’яті візьміть `object_pointers[0, class]`, якщо `multimask_output=True`. Якщо `False`, візьміть `object_pointers[0, 0]`: SAM 2 залишає вказівник однієї маски, навіть коли резервне правило стабільності вибирає маску з площин 1–3.
- Оцінка об’єкта 0 або менша робить маску та її рамку порожніми, але клас і далі вказує вибрану площину. Застосуйте правило оцінки об’єкта з README до логітів, які передаєте кодувальнику пам’яті.

```python
options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.EdgeTamTrack
decoder = pyneat.Model("/path/to/edgetam_mask_decoder_mpk.tar.gz", options)

outputs = decoder.run(decoder_inputs)
result = pyneat.decode_segmentation(outputs[:1])[0]
plane = int(result.boxes.to_numpy()[0, 5])
logits = outputs[1].to_numpy()[0, :, :, plane]  # [256, 256] low-resolution logits
pointer = outputs[4].to_numpy()[0, plane if options.multimask_output else 0]  # [256]
```

### Концепти EfficientSAM3 {#efficientsam3-concept}

```python
options = pyneat.ModelOptions()
options.decode_type = pyneat.BoxDecodeType.EfficientSam3
options.top_k = 20
options.score_threshold = 0.5
options.preprocess.kind = pyneat.InputKind.Tensor  # two inputs: pixels and packed text
model = pyneat.Model("/path/to/efficientsam3_image_model_mpk.tar.gz", options)

# Stretch to 1008x1008 and scale to [-1, 1], as SAM 3 does, and record that geometry.
stretched = cv2.resize(rgb, (1008, 1008), interpolation=cv2.INTER_LINEAR)
pixels = pyneat.Tensor.from_numpy(stretched.astype(np.float32) / 127.5 - 1, copy=True,
                                  layout=pyneat.TensorLayout.HWC)
facts = pyneat.PreprocessRuntimeMeta()
facts.resize_mode = "stretch"
facts.original_width, facts.original_height = rgb.shape[1], rgb.shape[0]
facts.resized_width = facts.resized_height = 1008
facts.affine_m00 = facts.original_width / 1008  # model-to-original scale
facts.affine_m11 = facts.original_height / 1008
semantic = pixels.semantic
semantic.preprocess = facts
pixels.semantic = semantic

outputs = model.run([pixels, packed_text])
result = pyneat.decode_segmentation(outputs)[0]
boxes = result.boxes.to_numpy()  # [N, 6]: x1, y1, x2, y2, score, 0
masks = result.masks.to_numpy()  # uint8 [N, H, W]
```

## Орієнтовані рамки YOLOv8 та YOLO11 {#yolov8-oriented-boxes}

Виберіть `BoxDecodeType::YoloV8Obb` (Python: `pyneat.BoxDecodeType.YoloV8Obb`; токени `yolov8-obb` або `yolo11-obb`). Передайте дев’ять згрупованих голів INT8, BF16 або FP32: три 64-канальні голови рамок DFL, три голови логітів класів і три голови логітів кутів, у порядку кроків 8/16/32. Повна кількість класів визначається за головами класів.

BoxDecode застосовує DFL, сигмоїду до класів, `(sigmoid(angle)-0.25)*pi` і Fast-NMS для повернутих рамок з урахуванням класів, використовуючи `nms_iou_threshold`. Вхідні дані мають бути необробленими логітами. Геометрія й вихід `BBOX_OBB_V1` відповідають наведеному нижче контракту YOLO26; використовуйте ту саму допоміжну функцію `decode_obb`.

## Орієнтовані рамки YOLO26 {#yolo26-oriented-boxes}

Явно виберіть `BoxDecodeType::YoloV26Obb` (Python: `pyneat.BoxDecodeType.YoloV26Obb`, токен `yolo26-obb`). Цей профіль приймає дев’ять голів у FP32, BF16 або INT8, згрупованих як три чотириканальні голови відстаней, три голови логітів класів і три одноканальні голови необроблених кутів, із кроками 8, 16 і 32. Усі голови мають узгоджуватися щодо повної кількості класів (1–256). `Auto`, `GroupedByRole` і `GroupedByRoleLogit` вибирають цю згруповану розкладку; голови класів зі значеннями ймовірностей і розкладки з чергуванням відхиляються.

Для голів INT8 потрібні додатні скінченні потензорні метадані квантування та нульова точка INT8. Голови BF16 і FP32 не використовують метадані цілочисельного квантування.

Використовуйте додатне `top_k` і `nms_iou_threshold = 0`. Профіль застосовує сигмоїду до логітів класів, вибирає якорі за їхньою найвищою активованою оцінкою, а потім вибирає пари якір/клас. За однакових оцінок зберігаються ранг першого етапу й порядок класів. Поріг оцінки строгий (`score > detection_threshold`). Необроблений кут уже задано в радіанах; декодер не застосовує до нього сигмоїду й не нормалізує його діапазон.

Метадані попередньої обробки мають містити явне скінченне перетворення з координат моделі в координати оригіналу з додатними однаковими масштабами за X/Y і без деформації зсуву. Явне тотожне перетворення потрібне навіть для плиток розміру моделі. Профіль відхиляє відсутні або анізотропні перетворення, а не наближує повернутий прямокутник. Він зберігає скінченні ширину й висоту зі знаком і не обрізає їх до меж зображення. Для плиткового оцінювання на DOTA використовуйте тотожне перетворення для кожної плитки, а відновлення зміщень плиток і міжплиткове придушення полігонів виконуйте в застосунку.

У графах, керованих джерелом, Core виводить початкову геометрію допуску з перевіреного контракту попереднього Preproc. Це лише початкове значення для підготовки: кожен кадр і далі має містити скінченне додатне рівномірне афінне перетворення й відповідне полотно моделі. Відсутнє перетворення кадру — це помилка, а не привід підставити тотожне перетворення.

Вихід має тег `BBOX_OBB_V1`: 32-байтовий версійований заголовок, за яким ідуть `top_k` записів по 32 байти. Невикористані записи нульові. `decode_obb_tensor(tensor)` перевіряє один носій; `decode_obb(tensors)` повертає один типізований результат для кожного носія. Обидві функції копіюють дані у власні тензори CPU; ID класів залишаються INT32. Наприклад:

```python
result = pyneat.decode_obb(outputs)[0]
geometry = result.geometry.to_numpy()  # cx, cy, width, height, angle_radians
scores = result.scores.to_numpy()
class_ids = result.class_ids.to_numpy()
```

Цей формат навмисно не є розширенням формату з BBOX на початку. Використовуйте типізовані допоміжні функції, а не `decode_bbox`, парсери сегментації/пози чи засіб відображення рамок, паралельних осям.

## SuperPoint

SuperPoint залишається частиною продуктової поверхні BoxDecode, але видає точки ознак, а не вдає, що вони є рамками. Мінімальна конфігурація з типовим профілем A65:

```cpp
BoxDecodeOptions options{BoxDecodeType::SuperPoint};
options.superpoint.descriptor_output_dtype = TensorDType::Float32;

auto decoder = nodes::SimaBoxDecode(model, options);
```

Python використовує ті самі типові значення:

```python
options = pyneat.BoxDecodeOptions(pyneat.BoxDecodeType.SuperPoint)
options.superpoint.descriptor_output_dtype = pyneat.TensorDType.Float32

decoder = pyneat.nodes.sima_box_decode(model, options=options)
```

`A65V1` — типовий профіль. Явно вибирайте інший профіль, коли моделі потрібна інша числова поведінка; Neat не виводить поведінку з форм чи значень тензорів:

| Профіль | Коли вибирати | Стан для виробничого використання |
|---|---|---|
| `LightGlueV1` | Поведінка детектора, NMS, координат і дескрипторів, сумісна з LightGlue | Підтримується |
| `MagicLeapDemoV1` | Закріплена поведінка демонстраційної програми Magic Leap | Підтримується |
| `A65V1` | Сумісність із колишнім декодером SuperPoint для A65 | Підтримується; типовий |
| `PaperBicubicV1` | Зарезервований числовий ID для майбутньої повністю визначеної бікубічної політики | Відхиляється, доки не визначений для виробничого використання |

Числова поведінка та кодування виходу незалежні. Наприклад, виберіть числову поведінку A65 із типовим виходом V1:

```cpp
BoxDecodeOptions options{BoxDecodeType::SuperPoint};
options.superpoint.profile = SuperPointProfile::A65V1;
options.superpoint.output_format = SuperPointOutputFormat::FeaturePointsV1;
```

Застаріла розкладка байтів вмикається лише явно й має додаткові обмеження:

```cpp
options.superpoint.profile = SuperPointProfile::A65V1;
options.superpoint.output_format = SuperPointOutputFormat::LegacyA65InterleavedV0;
options.superpoint.descriptor_output_dtype = TensorDType::Int8;
```

`SuperPointProfile::Auto` спершу використовує авторитетні метадані MPK `superpoint.profile`. Якщо ні API, ні `Model::Options.superpoint.profile`, ні MPK не задають профіль, він зводиться до `A65V1`.
Neat ніколи не вгадує профіль за формами тензорів, значеннями, іменами файлів чи наступними вузлами.

Якщо їхні публічні сигнальні значення залишено без змін, `detection_threshold=0.0`, `top_k=0`, `nms_radius=-1` і `border_margin=-1` визначаються з вибраного профілю. Для `A65V1` це поріг `0.1`, Top-K `600`, радіус NMS `4` і відступ від краю `0`. LightGlueV1 і MagicLeapDemoV1 використовують пороги `0.0005` і `0.015` відповідно; обидва використовують Top-K `600`, радіус NMS `4` і відступ від краю `4`.

`nms_iou_threshold` не застосовується до SuperPoint; використовуйте радіус у пікселях `superpoint.nms_radius`. Типовий вихід — версійований вміст `FEATURE_POINTS_V1` у вигляді структури масивів. `LegacyA65InterleavedV0` — явний формат для міграції, що потребує 256-вимірних дескрипторів INT8. Використовуйте `decode_superpoint`, а не `decode_bbox` чи `BoxDecodeResults`.

Версійовані записи `superpoint` у MPK за схемою v1 перевіряються суворо: будь-яка невідповідність спричиняє відмову. Вони мають називати профіль, різні ID тензорів детектора й дескриптора, відбиток `sha256:` із 64 шістнадцяткових цифр і підтримувані вхідні представлення `raw-logits-65` та `coarse-pre-l2`. Схема 0 і далі приймається лише як запис для міграції або ручного заповнення; пропущені поля представлень схеми 0 канонізуються до цих двох представлень необроблених входів і записуються в діагностиці як типові значення. Невідомі версії схеми або токени представлень спричиняють помилку компіляції контракту.
Якщо перевизначення профілю через API суперечить відбитку, проставленому для іншого профілю MPK, повторно проставте відбиток у MPK для вибраного профілю; Neat не відкидає й не переінтерпретує ці дані про походження.

## Вміст BBOX у форматі передавання

Декодування виявлень видає один тензор із тегом `BBOX` на кожен вхідний кадр. Цей тензор — байтовий буфер `UInt8` рангу 1:

| Поле | Значення |
| --- | --- |
| `semantic.detection.format` | `"BBOX"` |
| `dtype` | `UInt8` |
| `shape` | `[N_bytes]`, де `N_bytes` — місткість запакованого буфера з архіву моделі |

Форма тензора — це кількість байтів, а не кількість виявлень. Вміст використовує порядок байтів little-endian:

```text
offset  size  content
------  ----  -------
  0      4    uint32  N = valid detections in this frame
  4     24    RawBox[0]
 28     24    RawBox[1]
  .      .      ...
  .      .    RawBox[N-1]
                   trailing bytes are padding and must be ignored
```

Кожен запис `RawBox` має розмір 24 байти:

| Зміщення | Розмір | Тип | Поле | Значення |
| --- | --- | --- | --- | --- |
| 0 | 4 | `int32` | `x` | Координата x лівого верхнього кута в пікселях джерела. |
| 4 | 4 | `int32` | `y` | Координата y лівого верхнього кута в пікселях джерела. |
| 8 | 4 | `int32` | `w` | Ширина в пікселях джерела. |
| 12 | 4 | `int32` | `h` | Висота в пікселях джерела. |
| 16 | 4 | `float32` | `score` | Оцінка впевненості після NMS у діапазоні `[0.0, 1.0]`. |
| 20 | 4 | `int32` | `class_id` | ID класу, визначений моделлю. |

Відповідний формат Python `struct` для одного запису — `"<iiiifi"`.

Координати подано в пікселях оригінального зображення, якщо є метадані попередньої обробки з попереднього етапу. Для кадру, попередньо обробленого з ROI, оригінальне зображення — це повний кадр джерела, а не ROI (див. [Відображення координат обрізання](#crop-coordinate-mapping)). Вони не нормалізовані до `[0, 1]` і не виражені у внутрішньому вхідному просторі моделі з letterbox.

### Поєднаний вміст сегментації та пози

`yolox-seg-pose` видає один буфер із трьома областями. Крок кожної області розраховано на ту саму кількість слотів — `top_k`:

| Область | Зміщення | Крок | Вміст |
| --- | --- | --- | --- |
| заголовок | `0` | 4 | кількість виявлень `int32` |
| рамки | `4` | 24 | записи `BoundingBoxOut`, описані вище |
| маски | `4 + 24*top_k` | `mask_w * mask_h` | `uint8`, одна площина на слот |
| пози | `4 + (24 + mask_w*mask_h)*top_k` | 204 | 17 x `{uint32 x, uint32 y, float32 visibility}` |

Використовуйте `decode_segmentation_pose(...)`, щоб отримати рамки, маски й ключові точки. Рядок `i` кожного тензора описує те саме виявлення. Якщо потрібні лише рамки, використовуйте `decode_bbox(...)` або `BoxDecodeResults(...)`.

Комбінований декодер також приймає застарілий тег `BBOX`. Одночасне відображення масок і поз не підтримується. Не передавайте комбінований буфер до `poseyolo`: цей рендерер очікує ключові точки безпосередньо після рамок, тоді як комбінований вміст зберігає там маски.

Кожне виявлення має 17 слотів ключових точок. Бекенд обнуляє невикористані слоти та ключові точки класів, виключених через `pose_classes`. Допоміжна функція копіює ці значення без змін.

Core визначає `num_classes` як глибину голови класів мінус один, оскільки канал 0 містить оцінку наявності об’єкта. Наприклад, 30 каналів означають 29 класів. Явно задане `num_classes` має збігатися з цим значенням.

### Класи ключових точок

Задайте ID класів, які мають ключові точки:

```python
options = pyneat.BoxDecodeOptions(pyneat.BoxDecodeType.YoloXSegPose)
options.yolox_seg_pose.pose_classes = [0, 5]
```

`ModelOptions.yolox_seg_pose` приймає таке саме налаштування.

- Для класів поза списком координати й видимість ключових точок дорівнюють нулю.
- Порожній список `BoxDecodeOptions` успадковує налаштування моделі. Якщо список не задано, ключові точки отримують усі класи.
- ID мають бути унікальними й належати діапазону `[0, num_classes)`. Цей параметр підтримується лише для `YoloXSegPose`.

### Версійований вміст масок {#versioned-masks-payload}

Маски, розмір яких не 160×160, як-от вихід Segment Anything, використовують версійований заголовок замість початкового лічильника. Його розкладка — [`SegmentationMasksHeaderV1`](/reference/cppapi/structs/simaai-neat-segmentationmasksheaderv1) у `pipeline/DetectionTypes.h`: заголовок, потім записи `RawBox`, потім одна маска `uint8` на запис зі значеннями 0 або 255. Читайте його за допомогою `decode_segmentation`, яка повертає рамки й маски та відхиляє неправильний заголовок або розмір. Тензор зберігає тег `BBOX`, а `decode_segmentation` і `decode_bbox` розпізнають цей вміст за магічним числом, тому наявний вміст сегментації не змінюється. `SimaRender` його не приймає.

## Коли `model.run` повертає необроблені голови

Деякі маршрути моделі повертають з `model.run(...)` необроблені голови карт ознак замість декодованого тензора `BBOX`. Це не збій запуску. Це означає, що модель виконалася, але маршрут не містив BoxDecode у точці, де ви читаєте вихід.

Використовуйте таке правило:

- `detections=...` або тензор `BBOX`: розберіть запакований вміст BBOX або скористайтеся
  допоміжними функціями декодування.
- `raw_output_heads=...`: додайте етап BoxDecode, перевірте маршрут моделі або
  обробіть необроблені тензори постобробкою, специфічною для моделі.

Не розбирайте необроблені голови як рамки. Розкладка необроблених тензорів залежить від експортованої родини моделей і контракту архіву моделі.

## Контракт перевизначення

MPK надає тензорні контракти та відомості про родину декодування. Задавайте параметри фільтрації в `ModelOptions`. Для вузла `SimaBoxDecode(Model, ...)` додатні аргументи фільтрації перевизначають визначені параметри Model; нульові аргументи успадковують їх. `ModelOptions.score_threshold = 0.0` — це справжній нульовий поріг оцінки, а не запит на відновлення порога з пакета.

| Аргумент середовища виконання | Передане значення | Поведінка |
| --- | --- | --- |
| `decode_type` | порожньо / `Unspecified` | Зберегти визначення з архіву моделі або планувальника маршруту, де це підтримується. |
| `decode_type` | конкретний тип | Перевизначити родину декодування для цього запуску. |
| `original_width` / `original_height` | `0` | Зберегти упаковану геометрію або метадані попередньої обробки з попереднього етапу. |
| `original_width` / `original_height` | додатне ціле число | Перевизначити розміри джерела для відображення координат. |
| Вузол, прив’язаний до моделі: `detection_threshold` | `0.0` | Успадкувати визначений поріг оцінки Model. |
| Вузол, прив’язаний до моделі: `detection_threshold` | `> 0.0` | Перевизначити поріг оцінки. |
| Вузол, прив’язаний до моделі: `nms_iou_threshold` | `0.0` | Успадкувати визначений IoU для NMS із Model. |
| Вузол, прив’язаний до моделі: `nms_iou_threshold` | `> 0.0` | Перевизначити IoU для NMS. |
| Вузол, прив’язаний до моделі: `top_k` | `0` | Успадкувати визначену межу виходу Model. |
| Вузол, прив’язаний до моделі: `top_k` | `> 0` | Перевизначити максимальну кількість збережених виявлень. |

Декодування обмежувальних рамок потребує додатного визначеного `top_k`; нуль не означає необмежене сховище виходу. Для необроблених голів без прив’язаної `Model` задайте `top_k` до побудови графа. Вузол, прив’язаний до моделі, може успадкувати додатну межу Model, залишивши власне `top_k` нульовим. Ці параметри не впливають на окремі допоміжні функції читання результатів: у них `top_k=0` означає відсутність додаткової межі для вже обмеженого виходу. Нульовий поріг оцінки дозволяє нульові оцінки, але не обходить перевірку геометрії, виключення фону, NMS або межу виходу. За нульового IoU для NMS YOLO26 пропускає NMS. Інші профілі YOLO і SSD з увімкненим NMS і далі застосовують придушення за квантованим IoU. Додатні пороги YOLO26 вмикають NMS.

`num_classes` порівнює значення, задане у виклику, із кількістю класів, отриманою з тензорного контракту MPK:

| Родина моделей | Задане `num_classes` | `num_classes` з MPK | Поведінка |
| --- | --- | --- | --- |
| Будь-яка підтримувана модель | `0` | додатне значення, яке можна вивести | Використовується кількість класів з MPK. |
| Будь-яка підтримувана модель | додатне ціле число | те саме значення | Використовується задана кількість класів. |
| Модель із неоднозначним поділом класів | додатне ціле число | недоступно | Використовується задана кількість класів. Це потрібно, коли поділ голови з одним класом не можна надійно вивести. |
| YOLOv5 або YOLO26 | додатне ціле число | інше значення | Помилка до побудови конвеєра; у повідомленні наведено обидва значення. Ці розкладки необроблених голів виводять кількість класів із глибини тензора. |
| SSD або інша родина YOLO до YOLO26 без пози | додатне ціле число | інше значення | Застосовується наявна поведінка явного перевизначення, специфічна для родини. Декодери пози та SuperPoint зберігають свої специфічні для родини правила. |

`detection_threshold` — назва, яку використовують конструктори вузла/етапу BoxDecode. `ModelOptions.score_threshold` — параметр маршруту моделі, що задає той самий поріг.

## Вибір правильного типу

- Вибирайте за контрактом експортованих голів: `YoloV6` очікує необроблені відстані l/t/r/b і логіти класів. Для пакетів YOLOv6 із декодуванням рамок усередині графа використовуйте `Yolo`; для згрупованих виходів `[bbox_0..2, class_prob_0..2]` задайте `decode_type_option=GroupedByRoleProbability` і `num_classes`, що дорівнює кількості класів, на яких навчено модель.
- Якщо рамки зсунуті або неправильно масштабовані, перевірте політику зміни розміру зображення. Використовуйте `resize_mode_override` лише тоді, коли у вашому графі немає попереднього етапу `Preproc`, який записує метадані зміни розміру.
- Якщо ви створюєте власний пакет моделі, переконайтеся, що архів точно описує голови виявлення: порядок тензорів, логічну форму, фізичне зберігання, тип даних/квантування, область значень оцінок, кількість класів і всі зрізані виходи. Коду застосунку не має бути потреби компенсувати ці деталі.

## Рекомендації щодо форми та розкладки

Різні моделі виявлення мають різні розкладки голів. Деякі використовують один тензор на рівень карти ознак; інші розділяють рамки, оцінку наявності об’єкта, класи, ключові точки або маски на окремі тензори. Виходи деяких моделей — щільні тензори HWC; інші пакуються або розрізаються компілятором/середовищем виконання.

Для потоків із пакетами моделей це забезпечує упакований контракт. Для тензорів, з’єднаних вручну, головне правило таке: точно відповідайте формату експортованих голів. Не вибирайте тип декодування лише за рангом чи кількістю каналів.

Розширені правила тензорних контрактів:

- Типи декодування родини YOLO, крім виявлення `YoloV5` (`Yolo`, `YoloV7`, `YoloV8`, `YoloV9`, `YoloV10` і варіанти сегментації/пози), очікують або роз’єднані голови, або упаковані голови, що відповідають родині моделей.
- Упаковані голови YOLO мають зберігати узгоджену кількість класів і глибину голів на всіх рівнях ознак.
- Виявлення `YoloV5` приймає рівно три недекодовані упаковані голови в порядку P3/P4/P5. Їхні сітки повинні мати геометрію з кроками 8/16/32, а кожна логічна глибина має дорівнювати `3 * (num_classes + 5)`. BoxDecode застосовує сигмоїду, перетворення сітки й кроку, а також стандартні якорі YOLOv5 (`{10,13},{16,30},{33,23}`; `{30,61},{62,45},{59,119}`; `{116,90},{156,198},{373,326}`). Власні таблиці AutoAnchor і декодовані експорти із шести тензорів рамок/класів мають використовувати інший контракт.
- `YoloV26` використовує згруповані необроблені голови рамок l/t/r/b разом із головами оцінок класів.
- `Ssd` — **не** універсальний декодер SSD. Під час компіляції він визначає рівно **чотири підготовлені профілі** за повною впорядкованою сигнатурою H/W/C голів loc/conf. Будь-який інший набір чи порядок голів відхиляється з помилкою, що виводить спостережену й підтримувані сигнатури:
  - **SSD300** (`dboxes300_coco`): вхід 300×300, карти ознак
    `{38,19,10,5,3,1}`, апріорних рамок на комірку `{4,6,6,6,4,4}`, порядок каналів впевненості
    `class*A + anchor`, оцінки класів через **softmax** за виміром класів
    (включно з фоном під індексом 0).
  - **SSD-Mobile-300-v1** (`ssd_anchor_generator`): вхід 300×300, карти
    ознак `{19,10,5,3,2,1}`, апріорних рамок на комірку `{3,6,6,6,6,6}`, порядок каналів
    впевненості `anchor*C + class`, оцінки класів через покласову **сигмоїду** (фон
    ігнорується).
  - **SSD-Mobile-320-v1** (`ssd_anchor_generator`): вхід 320×320, карти
    ознак `{20,10,5,3,2,1}`, апріорних рамок на комірку `{3,6,6,6,6,6}`, порядок каналів
    впевненості `anchor*C + class`, оцінки класів через покласову **сигмоїду** (фон
    ігнорується).
  - **SSDlite-Mobile-320-v1** (TorchVision `DefaultBoxGenerator`): вхід
    320×320, карти ознак `{20,10,5,3,2,1}`, шість апріорних рамок на комірку на кожному рівні,
    порядок локалізації `anchor*4 + {dx,dy,dw,dh}`, порядок впевненості
    `anchor*C + class` та оцінки класів через **softmax** за всіма 91 класами,
    включно з фоном.

  Усі рецепти використовують згруповані голови локалізації на кожному рівні (глибина =
  `4 * priors-per-cell`) у парі з головами впевненості класів (глибина =
  `num_classes * priors-per-cell`), масштабування дисперсії FasterRcnnBoxCoder
  (`scale_xy 0.1`, `scale_wh 0.2`) і зміну розміру з **розтягуванням** (анізотропну) під час
  попередньої обробки. Активацію оцінок фіксує рецепт (відповідно до декодера на
  пристрої), а розкладка з групуванням за роллю вибирається автоматично — залиште
  `decode_type_option` як `Auto`. Токен незгрупованої розкладки відхиляється.

  **Кадр моделі є частиною профілю**, а не лише геометрія голів. SSD300-v1
  і SSD-Mobile-300-v1 потребують 300×300; обидва профілі 320-v1 потребують 320×320.
  Визначена ціль зміни розміру під час попередньої обробки або перевизначення розмірів моделі
  з будь-яким іншим розміром відхиляється під час побудови, бо таблиці апріорних рамок
  і зворотна проєкція розтягування дійсні лише для цього кадру.

  Необроблене/автономне створення `SimaBoxDecode` ніколи не вигадує режим зміни розміру.
  Збережіть вимогу щодо метаданих попереднього `Preproc` або використайте явне необроблене
  перевантаження, щоб засвідчити зовнішньо виконаний `ResizeMode::Stretch`; Letterbox і Crop
  відхиляються.

  **Контракт `num_classes`.** Закодована кількість класів завжди визначається з
  глибини голови впевненості (`conf_depth / priors-per-cell`, включно з фоном під
  індексом 0). SSD300-v1 дозволяє вибрати суцільний префікс, як-от у підготовленому
  маршруті 81-to-8; інші три профілі потребують точної закодованої кількості. Недійсний
  вибір відхиляється під час побудови. Не задавайте значення, щоб використати типове
  значення профілю.

  **Експорти MobileNet із 91 класом.** Із рівно 91 закодованим класом SSD-Mobile-300-v1
  (MobileNet V1 і V2) і SSDlite-Mobile-320-v1 (TorchVision MobileNet V3) декодуються
  так само, як оригінальні моделі: зберігаються всі пари якір/клас переднього плану, а NMS
  виконується для кожного класу окремо з рухомою комою (SSDlite залишає до 300 кандидатів
  на клас перед NMS). Вихід — той самий вміст BBOX. Інші профілі SSD і кількості класів
  зберігають наявну поведінку.
- `Detr` виводить кількість каналів класів із максимальної глибини голови й потребує
  дійсного виміру класів.
- `EffDet` і `Centernet` використовують контракти своїх родин моделей; не спрямовуйте
  їх через тип декодування YOLO.
- Типи декодування `*-seg` видають вихід, що починається з рамок, плюс дані масок, специфічні для завдання.

Якщо власний пакет моделі не відповідає жодній із повних упорядкованих сигнатур, підготуйте
новий явно підтримуваний профіль, а не послаблюйте зіставлення.

## Примітка щодо Python

Налаштовуючи параметри моделі з Python, використовуйте типізований enum замість рядка, якщо він доступний:

```python
opt = pyneat.ModelOptions()
opt.decode_type = pyneat.BoxDecodeType.YoloV8
```

Розбирайте виходи допоміжною функцією, що відповідає завданню моделі:

```python
outputs = model.run([image])

boxes = pyneat.decode_bbox(outputs)[0].to_numpy()

pose = pyneat.decode_pose(outputs)[0]
pose_boxes = pose.boxes.to_numpy()
keypoints = pose.keypoints.to_numpy()

seg = pyneat.decode_segmentation(outputs)[0]
seg_boxes = seg.boxes.to_numpy()
masks = seg.masks.to_numpy()
```

## Оновлення

Попередні параметри BoxDecode запровадили ABI 6. Поточні параметри арифметики джерела потребують ABI 7 (`libsima_neat.so.7`). Перезберіть застосунки C++, плагіни й прив’язки Python з відповідними заголовками та бібліотеками. Не завантажуйте бінарні файли ABI 5 або 6 через символьні посилання для сумісності.


### Допуск комбінованого входу YOLOX

`YoloXSegPose` приймає голови BF16 та INT8 або нативні голови FP32 у неперервному сховищі чи сховищі з додатними кроками без перекриття (включно з планарними поданнями CHW). Адреси та кроки FP32 мають бути вирівняні на чотири байти; FP32 з блоками каналів і UINT8 відхиляються. Неявне перетворення FP32 з утратами не додається. Прототип має власний тип даних і потензорне квантування INT8; ролі кожної голови виявлення все одно мають збігатися за типом даних. Core зберігає ці відомості для кожного порту для допуску в Kernels, а не застосовує тип даних чи квантування першої голови до всіх портів. Три рівні виявлення мають кроки 8, 16 і 32 за обома осями. Ширина й висота моделі мають бути кратними 32, але не обов’язково рівними. Прототип залишається 160×160×32 і не змінює розмір непомітно разом із розмірами моделі.

Для нецентрованого доповнення або координат обрізання використовуйте метадані попередньої обробки. Афінне перетворення відображає координати **з моделі в оригінал**; деформацію зсуву, обертання та списки ROI з кількома слотами цей комбінований профіль не підтримує. Обрізання потребує авторитетних афінних метаданих під час підготовки. Це контракт декодера для тензорів, попередньо оброблених зовні, а не нова підтримка створення обрізання в попередній обробці `Model`. Модель із менш ніж 17 ключовими точками однаково публікує фіксований публічний формат передавання з 17 слотами, у якому невикористані слоти заповнено нулями.


## Відображення координат обрізання {#crop-coordinate-mapping}

Crop, керований моделлю, передає фактичне обернене перетворення зображення підтримуваним профілям виявлення, зокрема класичному DETR, DetrFocal і звичайному виявленню YOLO. Відбір і NMS виконуються в координатах моделі; прийняті рамки потім відображаються на оригінальне зображення й обрізаються до його меж. Відсутні чи суперечливі метадані перетворення спричиняють явну помилку. Це не вмикає обрізання для пропозицій RCNN. Наявні профілі орієнтованих рамок і далі вимагають однакових масштабів осей; цілочисельні розміри після зміни розміру можуть зробити масштаби неоднаковими.

Preproc, який вирізає область інтересу (ROI) і вписує її в полотно моделі з letterbox або розтягуванням, для кожного кадру публікує афінне перетворення, що відображає координати моделі назад на повний кадр джерела. Профілі виявлення декодують кожен кадр за афінним перетворенням, яке опублікувала його попередня обробка, тому рамки виходять у пікселях кадру джерела однаково для одного ROI, центрованого чи нецентрованого letterbox, розтягування й цілого кадру. Кадр джерела — це необрізане зображення, а не ROI. Виявлення на цілому кадрі подаються в пікселях кадру джерела. Вхідний етап, який публікує лише розміри зображення без афінного перетворення, зберігає відображення для цілого кадру.

Передавайте один ROI на кожен виклик BoxDecode. Для буфера зі списком ROI задайте місткість 1.

| Профіль | Один ROI, обрізання або розтягування |
| --- | --- |
| YOLO26, YOLOv5, YOLOv6, YOLOv7, YOLOv8–YOLOv11, YOLOX, декодований YOLO, EfficientDet, CenterNet, DETR, DetrFocal, SSD (крім 91-класових багатокласових рецептів SSD) | Рамки в пікселях кадру джерела |
| Сегментація й поза YOLOX, орієнтовані рамки | Рамки в пікселях кадру джерела (орієнтованим рамкам потрібні однакові масштаби осей) |
| Поза (YOLOv8, YOLO26), сегментація (YOLOv5, v7, v8, v9, v10, YOLO26), 91-класовий багатокласовий SSD | Рамки й ключові точки в пікселях кадру джерела, якщо встановлений випуск Kernels приймає перетворення для профілю; інакше помилка з назвою профілю |
| Пропозиції RCNN | Помилка з назвою профілю |
| Segment Anything | Помилка: йому потрібне ціле зображення з одноразовою зміною розміру |

Маски сегментації залишаються в просторі моделі: кожна маска 160×160 покриває все полотно моделі, а не рамку чи кадр джерела, і обрізається рамкою в координатах моделі. Тому маска не зсувається й не масштабується разом з ROI, на відміну від рамки. Щоб відобразити піксель маски на кадр джерела, використайте те саме афінне перетворення, яке Preproc опублікував для цього кадру.

Профіль завершується помилкою, а не декодує в координатах цілого кадру, коли його ядро не приймає перетворення: для пропозицій RCNN завжди, для пози, сегментації та багатокласового SSD — у випуску Kernels, що передує перетворенню. Цілі кадри він і далі декодує. Зміна розміру Crop, запитана для такого профілю, завершується помилкою під час побудови графа.
