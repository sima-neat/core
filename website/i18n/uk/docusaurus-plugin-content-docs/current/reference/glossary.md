# Глосарій

Терміни та абревіатури, які трапляються в документації та коді фреймворку.

## Поняття фреймворку

| Термін | Визначення |
|---|---|
| **Neat (фреймворк)** | Бібліотека, яку описує ця документація: фреймворк на C++/Python для створення, перевірки та запуску конвеєрів AI-інференсу на основі GStreamer, що працюють на Modalix. |
| **Node (вузол)** | Найменша складова конвеєра. Типізована обгортка над елементом GStreamer. Див. `include/builder/Node.h`. |
| **Повторно використовуваний фрагмент графа** | `Graph`, який слугує багаторазовою одиницею композиції, наприклад фрагмент із попередньою обробкою, інференсом і постобробкою моделі або допоміжний блок введення/виведення. |
| **Graph (граф)** | Етап збирання, на якому з вузлів утворюється Run, готовий до запуску. |
| **Run** | Активний, запущений конвеєр. На вхід подаються зразки, з виходу забираються зразки. |
| **Model (модель)** | Спрощена точка входу для завантаження й запуску скомпільованої моделі з архіву `.tar.gz`. |
| **MPK** | JSON із контрактом інференсу моделі (`mpk.json` або `*_mpk.json`), вбудований в архів моделі `.tar.gz`. |
| **Sample (зразок)** | Одиниця даних конвеєра у фреймворку: містить тензор або закодовані медіадані разом із метаданими. |
| **Tensor (тензор)** | Типізоване подання буфера з пікселями, аудіо або результатами інференсу у фреймворку. |
| **TensorBuffer** | Буфер пам’яті, у якому зберігаються дані `Tensor`; містить трійку `(buffer_id, paddr, vaddr)`. |
| **Segment (сегмент)** | Іменована область пам’яті з метаданими розподільника та доступу. Буфери виділяються із сегментів. |

## Апаратне забезпечення

| Термін | Визначення |
|---|---|
| **Modalix** | Платформа SoC від SiMa для edge AI. Фреймворк орієнтований на неї. |
| **MLA** | Machine Learning Accelerator, прискорювач машинного навчання: основний рушій інференсу в SoC. |
| **MLASHM** | MLA Shared Memory, спільна пам’ять MLA: область пам’яті з низькою затримкою, з якої читає MLA. |
| **EV74 / CVU** | Compute Vision Unit: цифровий сигнальний процесор, орієнтований на SIMD-обчислення, для обчислювальних ядер (kernel) попередньої обробки та постобробки. |
| **A65** | Прикладні ядра ARM, на яких працює Linux. |
| **APU** | Audio Processing Unit, блок обробки аудіо. |
| **M4** | Ядро Cortex-M4 для низькорівневої координації (RPMsg, керування послідовністю апаратних операцій). |
| **TVM** | Apache TVM: резервний компілятор фреймворку на боці CPU для операцій, які MLA не може виконати. |
| **VCCM** | Когерентна область пам’яті всередині SoC, яку використовують деякі прискорювачі. |
| **OCM** | Пам’ять на кристалі, яку використовує MLA. |
| **DMS** | Direct Memory Server: служба контролера та розподільника пам’яті SoC. |
| **RPMsg** | Remote-processor messaging, обмін повідомленнями з віддаленим процесором: канал IPC між A65 і M4. |
| **IOMMU** | I/O memory-management unit, блок керування пам’яттю введення/виведення: відображає фізичні адреси у віртуальні для апаратури. |

## Формати даних

| Термін | Визначення |
|---|---|
| **BF16** | Brain Float 16: IEEE 754 binary16 з повним діапазоном експоненти FP32. Переважний тип даних з рухомою комою для MLA. |
| **NV12** | YUV 4:2:0 з площиною Y та однією площиною з почерговими U і V. Формат декодованого відео за замовчуванням у фреймворку. |
| **I420** | YUV 4:2:0 з окремими площинами Y, U і V. |
| **HWC / CHW** | Розкладки тензора (висота-ширина-канали чи канали-висота-ширина). |
| **Теселяція** | Перестановка плиток, яка розкладає тензор у геометрію, що її очікує вхідна scratchpad-пам’ять MLA. Лише зміна розкладки: ті самі байти в іншому порядку. |
| **Квантування** | Відображення значень FP32 в INT8 за допомогою масштабу та нульової точки. |

## Терміни роботи фреймворку

| Термін | Визначення |
|---|---|
| **Generic Preproc** | Розширення попередньої обробки, яке об’єднує довільні перетворення, надані користувачем, зі стандартним графом попередньої обробки. |
| **BoxDecode** | Об’єднаний етап постобробки, який виконує NMS / декодування для моделей виявлення на EV74. |
| **DetectionMeta** | Структура метаданих, яку BoxDecode додає до вихідних зразків моделі виявлення. |
| **GstSimaMeta** | Структура метаданих GStreamer у фреймворку; додається до кожного буфера, яким керує фреймворк. |
| **План маршрутизації** | Рішення фреймворку під час компіляції: який процесор виконує кожен етап і в яких сегментах розміщується кожен буфер. |
| **Рядок запуску для відтворення конвеєра** | Детермінований текст команди `gst-launch`, що відтворює конвеєр; його видає `Graph::describe()`. |
