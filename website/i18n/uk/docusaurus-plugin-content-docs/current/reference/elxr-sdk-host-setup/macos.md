Скористайтеся цим посібником, якщо ваша хост-машина працює під керуванням macOS і ви хочете запускати Palette SDK із DevKit-Sync.

## Необхідні умови

- Хост із macOS.
- `sima-cli`, встановлений на хості.
- Modalix DevKit, доступний у тій самій мережі.

:::info Топологія мережі
У macOS DevKit можна під’єднати до хоста безпосередньо через USB/Ethernet або розмістити хост і DevKit окремо в наявній мережі. Якщо вони перебувають у наявній мережі, спеціально налаштовувати спільний доступ не потрібно, за умови що хост і DevKit доступні одне одному для трафіку SSH і NFS.
:::

## Встановіть і запустіть Colima

Встановіть і запустіть Colima, щоб на macOS можна було запускати робочі навантаження Docker.

```bash
brew install colima docker
colima start
docker ps
```

Якщо Colima вже встановлено, переконайтеся, що Colima запущено, перш ніж використовувати `sima-cli sdk setup`.

## Дозволи NFS у macOS

Під час налаштування SDK DevKit-Sync використовує NFS-експорт хоста. У macOS переконайтеся, що `nfsd` має дозвіл Full Disk Access, інакше експорт або монтування робочого простору хоста може завершитися помилкою.

Кроки:

1. Відкрийте System Settings.
2. Перейдіть до Privacy & Security > Full Disk Access.
3. Натисніть `+`, потім натисніть `Cmd + Shift + G` і введіть `/sbin/`.
4. Виберіть `nfsd` і переконайтеся, що доступ для нього дозволено.
5. Після надання дозволу знову запустіть налаштування SDK.

## Internet Sharing для прямого з’єднання Mac із DevKit

Використовуйте цей порядок дій, коли DevKit не може під’єднатися безпосередньо до вашої звичайної мережі й мусить виходити в інтернет через пряме підключення USB/Ethernet до вашого Mac.

1. На DevKit встановіть для підключеного мережевого інтерфейсу режим `DHCP` (зазвичай він і так використовується за замовчуванням).
2. У macOS відкрийте `System Settings > General > Sharing > Internet Sharing`.
3. Для параметра **Share your connection from** виберіть `Wi-Fi`.
4. Увімкніть спільний доступ для інтерфейсу адаптера USB/Ethernet, під’єднаного до DevKit.
5. На боці Mac переконайтеся, що інтерфейс адаптера USB/Ethernet теж налаштовано на `DHCP`.

Після ввімкнення Internet Sharing активний інтерфейс USB/Ethernet на Mac має отримати адресу (наприклад, `en0` або `en1`, залежно від адаптера та налаштувань хоста).

### Обхідне рішення для DNS на DevKit

У цьому сценарії з прямим підключенням DNS на DevKit може залишатися неправильно налаштованим навіть після того, як DHCP спрацював успішно. Якщо розпізнавання імен не працює, оновіть `/etc/resolv.conf` на DevKit:

```bash
sudo nano /etc/resolv.conf
```

Вкажіть:

```text
nameserver 8.8.8.8
nameserver 127.0.0.1
```

## Усунення несправностей із відео Insight і переадресацією UDP у Colima

Якщо Insight відкривається в браузері, але відео наживо не з’являється, можливо, UDP-пакети не доходять до контейнера SDK. У macOS із Colima таке трапляється, коли Colima використовує переадресацію портів через SSH. Docker при цьому все одно може показувати очікувані зіставлення UDP-портів, але шлях переадресації Colima від хоста до віртуальної машини може не доставляти UDP-трафік у контейнер.

Зазвичай SDK публікує такі діапазони UDP:

- `9000-9079/udp` для відео
- `9100-9179/udp` для метаданих
- `40000-40199/udp` для WebRTC

Якщо контейнер SDK запущено і ці зіставлення UDP-портів наявні, перевірте механізм переадресації портів Colima. Переадресація через SSH підтримує лише TCP, а переадресація через gRPC — і TCP, і UDP.

Переналаштуйте Colima на переадресацію через gRPC:

```bash
colima stop
colima start --edit
```

У редакторі замініть:

```yaml
portForwarder: ssh
```

на:

```yaml
portForwarder: grpc
```

Потім перезапустіть SDK:

```bash
sima-cli sdk stop
sima-cli sdk start
sima-cli sdk neat
```

Перевірте, що Docker і далі публікує UDP-порти:

```bash
docker ps --format 'table {{.Names}}\t{{.Ports}}'
```

Переконайтеся, що для контейнера SDK вказано `9000-9079/udp`, `9100-9179/udp` і діапазон UDP для WebRTC.

Під час надсилання відео перевірте зсередини SDK, чи бачить Insight вхідні пакети:

```bash
curl -k 'https://127.0.0.1:9900/api/ingest/stats?all=1&verbose=1'
```

Перевірте, чи зростає значення `packets_received` на очікуваному каналі. Переконайтеся, що відправник надсилає дані на IP-адресу хоста Mac і правильний UDP-порт, а не на IP-адресу контейнера SDK. Канал 0 використовує UDP `9000`, канал 1 — UDP `9001` і так далі.

Якщо після перемикання Colima на переадресацію через gRPC UDP-трафік і далі не доходить до Insight, перевірте роботу з Docker Desktop або на хості з Linux. У такому разі зіставлення портів SDK і Docker, імовірно, правильні, а підозрілим залишається лише один рівень — шлях переадресації UDP у Colima на macOS.
