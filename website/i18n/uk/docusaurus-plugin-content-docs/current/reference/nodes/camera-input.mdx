# Вузол CameraInput

`CameraInput` — це вузол-джерело для камер MIPI, доступних через libcamera і GStreamer `libcamerasrc`. Використовуйте його на початку графа з власним джерелом, коли кадри мають надходити зі стеку камер DevKit, а не з `run.push(...)`.

Покроковий посібник див. на сторінці [Використання камери MIPI](/develop-apps/advanced-concepts/mipi-camera-input).

## Необхідні умови

Перш ніж використовувати `CameraInput`, запустіть камеру поза Neat:

- під’єднайте камеру, коли Modalix DevKit вимкнено;
- виберіть оверлей `.dtbo`, що відповідає платі-носію, виробнику камери, сенсору й порту;
- переконайтеся, що libcamera показує камеру в списку;
- переконайтеся, що `libcamerasrc` може передавати потік саме з тими `format,width,height,framerate`, які ви плануєте запитувати.

`camera_name` — це назва камери в libcamera. Не задавайте її, щоб використати типову камеру, або скопіюйте назву з виводу `cam -l`, якщо плата надає більше однієї камери.

## Швидкий старт

<CodeTabs>
<CodeTab label="C++" lang="cpp">

```cpp
#include <neat.h>

namespace neat = simaai::neat;

neat::CameraInputOptions opt;
opt.width = 1920;
opt.height = 1080;
opt.framerate_num = 30;
opt.framerate_den = 1;
opt.format = "NV12";
opt.buffer_name = "camera0";
opt.allow_cpu_fallback = true;

neat::Graph graph;
graph.add(neat::nodes::CameraInput(opt));
graph.add(neat::nodes::Output("frames"));

neat::Run run = graph.build();
std::optional<neat::Sample> frame = run.pull(/*timeout_ms=*/5000);
```

</CodeTab>
<CodeTab label="Python" lang="python">

```python
import pyneat

opt = pyneat.CameraInputOptions()
opt.width = 1920
opt.height = 1080
opt.framerate_num = 30
opt.framerate_den = 1
opt.format = "NV12"
opt.buffer_name = "camera0"
opt.allow_cpu_fallback = True

graph = pyneat.Graph()
graph.add(pyneat.nodes.camera_input(opt))
graph.add(pyneat.nodes.output("frames"))

run = graph.build()
frame = run.pull(timeout_ms=5000)
```

</CodeTab>
</CodeTabs>

Оскільки джерелом володіє `CameraInput`, будуйте граф без публічного вузла `Input`, якщо тільки ваш застосунок справді не має ще одного входу, у який він сам надсилає дані.

## Інтерфейс API

```cpp
namespace simaai::neat {
struct CameraInputOptions;
class CameraInput;
}

namespace simaai::neat::nodes {
std::shared_ptr<simaai::neat::Node> CameraInput(
    simaai::neat::CameraInputOptions opt = {});
std::shared_ptr<simaai::neat::Node> CameraInputWithCaptureBuffers(
    simaai::neat::CameraInputOptions opt,
    std::uint32_t capture_buffer_count);
}
```

Python:

```python
opt = pyneat.CameraInputOptions()
node = pyneat.nodes.camera_input(opt, capture_buffer_count=32)
```

## Параметри

| Поле | Типове значення | Опис |
| --- | --- | --- |
| `camera_name` | не задано | Необов’язкова назва камери в libcamera, зазвичай скопійована з `cam -l`. Не задавайте її, щоб libcamera вибрала типову камеру. |
| `width` | `1920` | Запитана ширина кадру в пікселях. Має підтримуватися режимом камери та оверлеєм. |
| `height` | `1080` | Запитана висота кадру в пікселях. |
| `framerate_num` | `30` | Чисельник частоти кадрів. |
| `framerate_den` | `1` | Знаменник частоти кадрів. `0` нормалізується до `1`. |
| `format` | `"NV12"` | Запитаний формат `video/x-raw`. `NV12` — рекомендований шлях для попередньої обробки моделі. |
| `buffer_name` | `"camera"` | Логічна назва буфера, що використовується в метаданих нижче за потоком та в іменуванні маршрутів моделі. |
| `insert_queue` | `true` | Вставляє невелику чергу живого джерела після узгодження розподільника й перевірки режиму без копіювання. |
| `leaky_queue` | `true` | Вмикає для черги відкидання кадрів (leaky downstream), щоб живі графи надавали перевагу свіжим кадрам, а не застарілим, що накопичилися в черзі. |
| `queue_depth` | `2` | Максимальна кількість буферів у черзі, коли `insert_queue` має значення true. |
| `allow_cpu_fallback` | `false` | Якщо `false`, DMA-BUF камери передається далі, а будь-який кадр, що потребував би копіювання, спричиняє помилку. Установлюйте `true`, лише щоб дозволити приватному мосту Neat копіювати такі кадри в DMA-BUF CMA. |

`capture_buffer_count` — це аргумент `CameraInputWithCaptureBuffers`, а не поле `CameraInputOptions`. Типово він дорівнює `0`, що зберігає власне типове значення конвеєра камери. Конвеєр камери сам перевіряє свою межу; провайдер Neat підтримує щонайбільше `128`.

## Контракт входу й виходу

| Елемент контракту | Поведінка |
| --- | --- |
| Роль входу | Вузол-джерело. Граф отримує кадри з камери; застосунок не надсилає зразки в цей вузол. |
| Тип медіа на виході | `video/x-raw`. |
| Формат виходу | Запитаний `format`, зазвичай `NV12`. |
| Контракт пам’яті | Власний DMA-BUF камери передається нижче за потоком без копіювання. Якщо резервний варіант увімкнено, кадр, який не є одним DMA-BUF, копіюється в DMA-BUF CMA для етапів CVU/MLA нижче за потоком. |
| Визначеність caps | Статична підказка на основі запитаних параметрів. Узгодження caps під час виконання все одно залежить від стеку камер. |

## Режим без копіювання й резервний варіант

`allow_cpu_fallback = false` — типове значення, яке вимагає строгого режиму без копіювання: камера записує кожен кадр у власний DMA-BUF, і кожен етап нижче за потоком читає ту саму пам’ять. Neat ніколи не володіє пам’яттю камери, тому не потрібно задавати жодної властивості `libcamerasrc`. Будь-який фізично неперервний DMA-BUF є допустимим входом EV74; перевірка допуску EV74 у Neat приймає його, якщо він походить із купи CMA або з неперервного розподільника буферів захоплення камери (`videobuf2_dma_contig`).

Neat завжди розміщує свій приватний міст камери одразу після capsfilter і перед живою чергою. Міст просить джерело додавати `GstVideoMeta` через `GST_QUERY_ALLOCATION`, а потім передає кожен кадр, площини якого розташовані впритул одна до одної в одному DMA-BUF, як один блок пам’яті, утримуючи буфер камери, доки всі споживачі його не звільнять. У строгому режимі кадр, який неможливо так передати, спричиняє збій конвеєра; якщо резервний варіант увімкнено, такий кадр натомість копіюється в DMA-BUF CMA.

Передавайте `capture_buffer_count` у фабрику камери з огляду на те, хто утримує кадри нижче за потоком. Часовому кодувальнику або глибокому асинхронному ML-графу може знадобитися 32 буфери; граф CV із низькою затримкою може використовувати менше буферів і відкидати застарілі кадри. Цей параметр керує лише циклом між виходом ISP і застосунком. Він не збільшує приватний кільцевий буфер ядра для передавання RAW із CSI до ISP і не залежить від політики відкидання `queue_depth` у GStreamer. На Platform 3.0 `libcamerasrc` не має властивості `buffer-count`, тому там залишайте `capture_buffer_count` рівним `0`.

Оскільки міст передає власні буфери камери, кожен кадр, який ще утримує етап нижче за потоком, забирає один буфер із кільцевого буфера захоплення libcamera (8 буферів для 1080p NV12 з IMX477 на Platform 3.0). Граф, що утримує стільки кадрів, зупиняє захоплення замість того, щоб відкидати кадри, тому вчасно звільняйте отримані кадри.

Явно встановіть `allow_cpu_fallback = true`, щоб дозволити вже наявному мосту копіювати кадр, який не є одним DMA-BUF із площинами, розташованими впритул одна до одної. Кадри, які є одним DMA-BUF із площинами, розташованими впритул одна до одної, міст і далі передає напряму. Інші кадри він копіює в DMA-BUF CMA з приватного пулу й додає метадані, яких очікують етапи нижче за потоком. Цей пул за потреби зростає до 128 буферів, а не обмежується `queue_depth`, тож черга з відкиданням нижче за потоком встигає позбутися застарілих кадрів раніше, ніж міст заблокується.

Слово fallback у назві означає, що міст може приймати буфери ОС/libcamera. Воно не означає, що зміну розміру, перетворення кольору чи нормалізацію слід переносити на CPU. Залишайте ці операції в попередній обробці CVU, якою керує модель, щоразу, коли маршрут це підтримує.

Не додавайте вузол `OsToSima` для `CameraInput` самостійно. Адаптація є частиною шляху джерела камери.

## Типові форми графів

Отримуйте кадри з камери напряму:

```text
CameraInput -> Output
```

Пропустіть потік із камери через модель:

```text
CameraInput -> model.graph({include_input=false, include_output=true})
```

Для конвеєрів моделей налаштовуйте попередню обробку через `Model::Options::preprocess` або `pyneat.ModelOptions.preprocess`, щоб зміна розміру, перетворення кольору, нормалізація, квантування й теселяція залишалися в маршруті CVU, яким керує модель.

## Можливі збої

| Помилка | Імовірна причина |
| --- | --- |
| `build.plugin_missing` | `libcamerasrc` або `neatcamerabridge` відсутній у наборі плагінів середовища виконання. |
| `misconfig.media_caps` / `not-negotiated` | Камера не підтримує запитаний формат, роздільну здатність або частоту кадрів. |
| `misconfig.media_caps` / `gstreamer.camera_configuration_unsupported` | Узгодження в `libcamerasrc` не вдалося, бо камера не пропонує запитаної роздільної здатності або формату пікселів. Захоплюйте кадри підтримуваного розміру; у графах із моделлю доручіть зміну розміру попередній обробці моделі, а в інших графах використовуйте `VideoScale`, а потім `CapsRaw`. |
| Помилка строгого режиму без копіювання | `allow_cpu_fallback` має значення false, і камера передала кадр, який не є одним DMA-BUF із площинами, розташованими впритул одна до одної. |
| Тайм-аут pull | Камера не передала кадри, граф перебуває під зворотним тиском, або стек камер припинив потокову передачу. |
| Зелені, фіолетові кадри або кадри з сильним колірним відтінком | Неправильний формат кадру або перетворення кольору в попередній обробці моделі, або відтінок уже є у виході ISP/libcamera камери. Спершу перевірте захоплення `NV12` поза Neat. |
