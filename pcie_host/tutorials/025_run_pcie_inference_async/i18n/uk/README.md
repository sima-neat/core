## Concept

Синхронний `run()` чудово підходить для першого інференсу, але він чекає на кожен результат, перш ніж надіслати наступне зображення. Якщо виробник викликає `push()`, а споживач тим часом забирає результати через `pull()`, одна модель PCIe працює без простоїв. Пропускну здатність слід рахувати за завершеними результатами після прогріву, а не просто за зображеннями, переданими моделі.

## Walkthrough

У цьому навчальному посібнику повторно використано конфігурацію YOLOv8s із зображенням на вході й декодуванням рамок, а також вуличну сцену розміром 640x480 з навчального посібника 024. Програма надсилає одне й те саме зображення повторно, щоб читання з диска й декодування зображення не спотворювали вимірювання PCIe.

### Налаштування однієї моделі виявлення {#step-configure-model}

Завантажте зображення один раз, налаштуйте попередню обробку COCO на боці карти й декодування рамок YOLOv8, а потім побудуйте одну `Model` у черзі 0. Відсутні файли й помилки запуску карти зупиняють програму до початку вимірювання.

### Прогрів конвеєра {#step-warm-up}

Виконайте кілька повних виявлень без вимірювання часу. Прогрів прибирає з навантаження, про яке звітує програма, вплив запуску моделі й першого буфера.

### Одночасне надсилання й отримання {#step-push-pull}

Один потік надсилає зображення через `push()`, а інший отримує виходи BBOX через `pull()` зі скінченним часом очікування. Невелика черга FIFO, якою володіє застосунок, зберігає час початку кожного впорядкованого надсилання. Будь-яка відмова, перевищення часу очікування або некоректний результат закриває модель і пробуджує інший потік.

Приклад покладається лише на звичайне керування потоком у `Model`; застосунок не налаштовує глибину черги.

### Звіт про виконану роботу {#step-report-results}

Зупиняйте вимірювання часу лише тоді, коли обидва потоки завершилися й усі прийняті зображення отримано. Кількість кадрів за секунду рахується за кількістю завершених виходів. Середня затримка вимірюється від кожної спроби надсилання до надходження відповідного впорядкованого результату.

## Run

Установіть пакет хоста PCIe і завантажте пакет навчальних матеріалів, як описано в розділі [Налаштування навчального посібника](/tutorials/before-you-run). З кореневої теки розпакованих додаткових матеріалів PCIe завантажте YOLOv8s, якщо його там ще немає:

```bash
sima-cli models download --id yolov8s --variant w8a8
unzip -p models/yolov8s/w8a8/yolov8s_w8a8_default.zip yolov8s_w8a8_mpk.tar.gz > yolo_v8s_mpk.tar.gz
```

Програмі потрібен саме шлях `yolo_v8s_mpk.tar.gz` у цій теці. Друга команда видобуває цей файл із завантаженого ZIP-файлу.

Запустіть версію для Python:

```bash
source ~/pyneatpcie/bin/activate
python3 share/sima-pcie-host/tutorials/025_run_pcie_inference_async/run_pcie_inference_async.py
```

Запустіть попередньо зібрану версію для C++:

```bash
./lib/sima-pcie-host/tutorials/tutorial_025_run_pcie_inference_async
```

Або зберіть її заново:

```bash
./build.sh --target tutorial_025_run_pcie_inference_async
./build/tutorials-standalone/tutorial_025_run_pcie_inference_async
```

Точні значення часу залежать від хоста й карти, але обидві програми використовують однакові межі вимірювання й виводять:

```text
completed=1000
elapsed_seconds=...
throughput_fps=...
average_latency_ms=...
total_detections=...
[OK] 025_run_pcie_inference_async
```

Навчальний посібник завжди виконує прогрів на п’яти кадрах, а потім вимірює 1000 завершених кадрів. Передавайте `--card N` лише тоді, коли використовуєте іншу карту.

## In Practice

Тримайте надсилання й отримання збалансованими. Якщо застосунок безкінечно надсилає дані й не забирає результати, звичайний зворотний тиск зрештою сповільнить надсилання. Окремий споживач також спрощує обробку збоїв: скінченний час очікування виявляє результат, що застряг, а закриття моделі звільняє чергу 0, навіть якщо виробник чекає.

Для показового бенчмарку замініть повторюваний кадр фіксованим набором зображень і залиште читання з диска поза вимірюваною ділянкою. Далі перейдіть до навчального посібника [Запуск кількох моделей](/tutorials/run-multiple-models), щоб одночасно виконувати дві різні моделі.
