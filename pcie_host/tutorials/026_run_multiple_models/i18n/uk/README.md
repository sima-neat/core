# 026 Запуск кількох моделей

## Metadata

| Field | Value |
| --- | --- |
| Category | PCIe Co-Processing |
| Difficulty | Beginner |
| Estimated Read Time | 15 хвилин |
| Model | resnet_50, yolo_v8s |
| Labels | PCIe, queues, concurrency, classification, detection |

## Concept

PCIe-карта Modalix надає черги співобробки з 0 по 5. Кожна активна `Model` володіє однією чергою, тому незалежні моделі можуть виконуватися одночасно, якщо кожному екземпляру призначити окреме значення `ConnectionOptions.queue`. У цьому навчальному посібнику ResNet-50 працює в черзі 0, а YOLOv8s — у черзі 1, без глобального координатора.

## Walkthrough

Дві моделі навмисно використовують різні зображення: ResNet-50 класифікує чітку фотографію лабрадора, а YOLOv8s виявляє людей і автомобілі на жвавій вуличній сцені.

### Завантаження зображень для кожної моделі {#step-load-assets}

Перевірте обидва архіви моделей і декодуйте обидва упаковані ресурси, перш ніж займати чергу. Окремі зображення роблять кожен результат змістовним і не дають використати портрет для класифікації як навантаження для виявлення об’єктів.

### Призначення однієї моделі кожній черзі {#step-assign-queues}

Створіть два звичайні об’єкти `Model`. Налаштуйте ResNet-50 на попередню обробку зображень ImageNet у черзі 0, а YOLOv8s — на попередню обробку зображень COCO з декодуванням рамок у черзі 1. Помилка побудови вказує чергу й модель, на яких стався збій; якщо не вдається побудувати другу модель, уже побудовану модель закривають.

### Одночасний запуск обох черг {#step-run-concurrently}

Запустіть по одному блокувальному інференсу зображення для кожної моделі в окремих потоках хоста. Кожен виклик, як і раніше, має просту синхронну поведінку `run`, але виклики перекриваються в часі, бо звертаються до різних фізичних черг.

### Окрема інтерпретація кожного результату {#step-read-results}

Черга 0 повертає один тензор класифікації FP32 і виводить клас ImageNet із найвищою оцінкою. Черга 1 повертає декодовані записи BBOX і виводить клас виявленого об’єкта, упевненість і координати на вхідному зображенні. Закриття будь-якої з моделей звільняє лише призначену їй чергу.

## Run

Установіть пакет хоста PCIe і завантажте набір навчальних матеріалів, як описано в розділі [Налаштування навчального посібника](/tutorials/before-you-run). З кореневої теки розпакованих додаткових матеріалів PCIe завантажте обидві моделі:

```bash
sima-cli models download --id resnet_50 --variant w8a8
unzip -p models/resnet_50/w8a8/resnet_50_w8a8_default.zip resnet_50_w8a8_mpk.tar.gz > resnet_50_mpk.tar.gz
sima-cli models download --id yolov8s --variant w8a8
unzip -p models/yolov8s/w8a8/yolov8s_w8a8_default.zip yolov8s_w8a8_mpk.tar.gz > yolo_v8s_mpk.tar.gz
```

Програмі потрібні саме шляхи `resnet_50_mpk.tar.gz` і `yolo_v8s_mpk.tar.gz` у цій теці. Кожна команда `unzip` видобуває один із цих файлів із відповідного завантаженого ZIP-файлу.

Запустіть версію для Python:

```bash
source ~/pyneatpcie/bin/activate
python3 share/sima-pcie-host/tutorials/026_run_multiple_models/run_multiple_models.py
```

Запустіть попередньо зібрану версію для C++:

```bash
./lib/sima-pcie-host/tutorials/tutorial_026_run_multiple_models
```

Або зберіть її заново:

```bash
./build.sh --target tutorial_026_run_multiple_models
./build/tutorials-standalone/tutorial_026_run_multiple_models
```

Із задокументованими моделями й ресурсами обидві версії виводять приблизно такий результат:

```text
queue=0 model=resnet_50 output_shape=[1, 1000] top1=208 (Labrador retriever)
queue=1 model=yolo_v8s detections=...
  person score=... box=(...)
[OK] 026_run_multiple_models
```

У навчальному посібнику ResNet-50 навмисно закріплено за чергою 0, а YOLOv8s — за чергою 1. Передавайте `--card N` лише тоді, коли використовуєте іншу карту.

## In Practice

Призначення черг — це рішення застосунку щодо ресурсів: дві активні моделі не можуть володіти однією фізичною чергою. Будуйте моделі до початку роботи, у разі збою вказуйте конкретну чергу й закривайте кожну успішно побудовану модель як за звичайного завершення, так і в разі помилки. Окремі екземпляри `Model` ізолюють результати й збої кожної моделі, і їхню поведінку при цьому легко зрозуміти.

Діагностику розгортання описано далі на сторінках [Співобробка через PCIe](/develop-apps/development-workflow/pcie-model/) і [Усунення несправностей](/reference/troubleshooting/).
