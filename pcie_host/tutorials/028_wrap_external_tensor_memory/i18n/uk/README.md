## Concept

`Tensor::from_external()` дає змогу застосунку C++ обгорнути наявну неперервну ділянку пам’яті замість копіювати її в новий тензор на боці хоста. Тензор зберігає власника `std::shared_ptr<void>`, тож базова ділянка пам’яті залишається дійсною, поки її використовують PCIe і GStreamer. Крім того, застосунок не повинен змінювати ці байти, доки не буде отримано відповідний результат інференсу.

Так для одного неперервного входу зникає додаткове проміжне копіювання на хості. Наскрізної роботи без копіювання це не дає: транспорт PCIe однаково копіює корисні дані в пам’ять, що належить карті.

## Walkthrough

Програма створює три вхідні слоти для повторного використання й надсилає вісім синтетичних кадрів FP32. Слот повертається до черги доступних лише після того, як отримано впорядкований результат для цього слота.

### Огляд контракту моделі {#step-inspect-contract}

Створіть модель і прочитайте `info().inputs`, перш ніж виділяти пам’ять. У цьому навчальному посібнику використано архів YOLOv8s з одним входом; програма перевіряє, що його оголошений dtype — FP32, а форма відповідає рівно `size_bytes` байтам.

Зовнішнє подання має відповідати dtype, формі, розміру в байтах та імені відповідного `TensorInfo`. Не визначайте ці значення за іншою збіркою моделі.

### Обгортання пам’яті, що належить застосунку {#step-wrap-memory}

Кожен слот кільцевого буфера володіє `std::shared_ptr<std::vector<float>>`. Виклик `Tensor::from_external()` отримує базовий вказівник, повну кількість елементів у базовій пам’яті, спільного власника, форму моделі та ім’я маршруту. Оскільки подання неперервне, хост PCIe може обгорнути його напряму, не створюючи проміжної ділянки пам’яті.

Зберігати лише сирий вказівник недостатньо. Спільний власник обов’язковий, бо транспорт може утримувати тензор і після того, як `push()` поверне керування.

### Побудова моделі {#step-build-model}

Будуйте модель після того, як перевірено контракт моделі й виділену для кільцевого буфера пам’ять. Приклад задає `max_inflight` рівним розміру кільцевого буфера, тож застосунок і транспорт мають однакову явну межу.

### Надсилання й безпечне повторне використання кільцевого буфера {#step-submit-ring}

Заповніть доступний слот, викличте `push()` і перенесіть цей слот до черги запитів в обробці. Не змінюйте й не використовуйте повторно його пам’ять лише через те, що `push()` повернув керування. Коли доступного слота немає, приклад викликає `pull()` і повертає найстаріший слот до черги доступних лише після надходження відповідного впорядкованого результату.

Кожному прийнятому надсиланню відповідає одне отримання, включно із завершальним спорожненням черги. У разі тайм-ауту модель закривається, а пам’ять, запит до якої ще може бути активним, повторно не використовується.

## Run

Установіть пакет хоста PCIe і завантажте набір навчальних матеріалів, як описано в розділі [Налаштування навчального посібника](/tutorials/before-you-run). Завантажте YOLOv8s у кореневу теку розпакованих додаткових матеріалів PCIe:

```bash
sima-cli models download --id yolov8s --variant w8a8
unzip -p models/yolov8s/w8a8/yolov8s_w8a8_default.zip yolov8s_w8a8_mpk.tar.gz > yolo_v8s_mpk.tar.gz
```

**C++ (prebuilt):**

```bash
./lib/sima-pcie-host/tutorials/tutorial_028_wrap_external_tensor_memory
```

**C++ (build from source):**

```bash
./build.sh --target tutorial_028_wrap_external_tensor_memory
./build/tutorials-standalone/tutorial_028_wrap_external_tensor_memory
```

За замовчуванням використовуються карта 0 і черга 0. Передавайте `--card N` лише тоді, коли використовуєте іншу карту. Успішний запуск виводить:

```text
input=images
ring_slots=3
completed=8
[OK] 028_wrap_external_tensor_memory
```

## In Practice

Для прямого обгортання на хості потрібна неперервна пам’ять. Тензор із кроками, що задають нещільне розміщення, однаково приймається, якщо його дескриптор коректний, але хост ущільнює його в проміжну ділянку пам’яті. Кілька окремо виділених входів також пакуються в проміжну пам’ять.

Для моделі з кількома входами такого проміжного виділення пам’яті можна уникнути лише тоді, коли всі тензори є послідовними поданнями однієї спільної упакованої ділянки пам’яті. Надсилайте їх у порядку, який повідомляє `info().inputs`, і використовуйте ім’я та форму кожного входу. Наприклад, коли обидва входи мають тип FP32:

```cpp
const auto& first = info.inputs.at(0);
const auto& second = info.inputs.at(1);
const std::size_t first_count = first.size_bytes / sizeof(float);
const std::size_t second_count = second.size_bytes / sizeof(float);

auto packed =
    std::make_shared<std::vector<float>>(first_count + second_count);
pcie::Tensor input0 = pcie::Tensor::from_external(
    packed->data(), packed->size(), packed, first.shape, first.name);
pcie::Tensor input1 = pcie::Tensor::from_external(
    packed->data(), packed->size(), packed, second.shape, second.name,
    static_cast<std::int64_t>(first.size_bytes));

model.push({input0, input1});
```

Ця оптимізація усуває лише копіювання для пакування на боці хоста. Перед інференсом PCIe однаково копіює упаковані корисні дані в транспортну пам’ять, що належить карті.
