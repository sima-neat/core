# 027 Запуск лише MLA з тензорами INT8

## Metadata

| Field | Value |
| --- | --- |
| Category | PCIe Co-Processing |
| Difficulty | Intermediate |
| Estimated Read Time | 15 хвилин |
| Model | yolo26n w8a8 (Model Browser, скомпільовано для прямого входу й виходу MLA) |
| Labels | PCIe, MLA, INT8, quantization, tensor |

## Concept

Маршрут PCIe за замовчуванням надсилає на карту тензори FP32: там вхід квантується, виконується MLA, а вихід деквантується, перш ніж повернутися на хост як FP32. Застосунок, який уже має дані INT8 або хоче сам керувати кроком квантування, може задати `ModelOptions.mla_only`. Тоді карта виконує тільки MLA: хост надсилає тензори INT8, що відповідають контракту входу MLA, і отримує необроблені виходи INT8. `model.info()` публікує параметри квантування кожного тензора, тож хост може квантувати й деквантувати за однією формулою:

```text
x = (q - zero_point) * scale
q = clamp(round(x / scale) + zero_point, -128, 127)
```

У цьому навчальному посібнику показано варіант INT8. `mla_only` також підтримує сумісні архіви BF16; тензори BF16 не мають параметрів квантування.

## Walkthrough

Одна програма квантує зображення на хості, виконує маршрут лише з MLA, деквантує виходи й звіряє їх із результатами маршруту за замовчуванням на тій самій черзі.

### Огляд контракту маршруту лише з MLA {#step-inspect-contract}

Створіть `Model` з увімкненим `mla_only`. Тепер `info()` повідомляє про входи й виходи INT8, кожен із `quant.scale` і `quant.zero_point`. Еталонна модель має один вхід `images` — тензор INT8 `[640, 640, 3]` у форматі HWC.

### Квантування на хості {#step-quantize-on-host}

Еталонна модель очікує одне зображення RGB зі значеннями пікселів у діапазоні `[0, 1]`. Змініть розмір зображення до `640x640`, перетворіть BGR на RGB, поділіть на 255 і застосуйте формулу квантування з параметрами входу. Ця попередня обробка залежить від моделі, а не від контракту архіву: для іншої моделі потрібен власний рецепт. Збережіть деквантовані значення тих самих кодів: це саме той вхід FP32, який потрібен маршруту за замовчуванням для порівняння за однакових умов.

### Виконання маршруту INT8 {#step-run-int8}

`build()` запускає на карті конвеєр, що містить лише MLA. `run()` приймає тензори INT8 і повертає по одному щільному тензору INT8 на кожен вихід — у тому порядку й з тими іменами, які повідомив `info().outputs`. Маршрут відхиляє будь-який інший dtype: надсилання тензора FP32 завершується помилкою, а не квантуванням на карті.

### Деквантування й порівняння {#step-dequantize-and-compare}

Створіть другу `Model` без `mla_only` і надішліть деквантовані значення FP32 маршрутом за замовчуванням. Деквантуйте виходи INT8 за параметрами кожного з них і виведіть найбільше відхилення для кожного виходу в одиницях його масштабу. Обидва маршрути виконують ту саму програму MLA на тих самих кодах, тому похибка дорівнює нулю.

## Run

Установіть пакет хоста PCIe і завантажте набір навчальних матеріалів, як описано в розділі [Налаштування навчального посібника](/tutorials/before-you-run).

У навчальному посібнику використовується пакет YOLO26n `w8a8` з Model Browser, скомпільований для прямого входу й виходу MLA. Завантажте його в кореневу теку розпакованих додаткових матеріалів PCIe і видобудьте архів MPK:

```bash
sima-cli models download --id yolo26n --variant w8a8
unzip -p models/yolo26n/w8a8/yolo26n_w8a8_default.zip yolo26n_w8a8_mpk.tar.gz > yolo26n_w8a8_mpk.tar.gz
```

Інші архіви теж підходять, якщо їх скомпільовано в Model SDK з параметром `tessellate_parameters` `enable_mla=True`, розкладкою DRAM `HWC` на кожному вході та `HWC16` на кожному виході. Архіви, які натомість виконують теселяцію на CVU, відхиляються, коли ввімкнено `mla_only`:

```text
mla_only does not support stage 'tessellate_quantize_0_MLA_0/...' (tess)
```

**Python:**

```bash
source ~/pyneatpcie/bin/activate
python3 share/sima-pcie-host/tutorials/027_run_mla_only_int8/run_mla_only_int8.py \
  --model yolo26n_w8a8_mpk.tar.gz
```

**C++ (prebuilt):**

```bash
./lib/sima-pcie-host/tutorials/tutorial_027_run_mla_only_int8 \
  --model yolo26n_w8a8_mpk.tar.gz
```

**C++ (build from source):**

```bash
./build.sh --target tutorial_027_run_mla_only_int8
./build/tutorials-standalone/tutorial_027_run_mla_only_int8 \
  --model yolo26n_w8a8_mpk.tar.gz
```

Обидві версії виводять контракт і нульове відхилення для кожного виходу:

```text
MLA-only contract:
  input images INT8 [640, 640, 3] scale=0.00391965 zero_point=-128
  output bbox_0 INT8 [80, 80, 4] scale=0.0331556 zero_point=-108
  ...
Dequantized MLA-only outputs vs the default route (error in scale units):
  bbox_0 [80, 80, 4] max_err=0.0000
  ...
[OK] 027_run_mla_only_int8
```

За замовчуванням використовуються карта 0 і черга 0. Передавайте `--card N` лише тоді, коли використовуєте іншу карту.

## In Practice

Для архіву INT8 вмикайте `mla_only`, коли квантуванням керує сам застосунок: він уже видає дані INT8 із сенсора або попередньої моделі, йому потрібні необроблені виходи INT8 для власної постобробки або він хоче прибрати етапи квантування й деквантування із затримки на боці карти. Читайте кожен масштаб і кожну нульову точку з `model.info()`; ніколи не копіюйте їх з іншої збірки моделі.

Маршрут працює за принципом «усе або нічого». Кожен вхід має відповідати dtype, формі та розміру в байтах свого запису в `info().inputs`, а попередню обробку зображень чи декодування рамок не можна поєднувати з `mla_only`. Залишайте маршрут за замовчуванням, коли хост має дані FP32 і йому не потрібно самому керувати перетворенням.

Діагностику розгортання описано далі на сторінці [Співобробка через PCIe](/develop-apps/development-workflow/pcie-model/).
