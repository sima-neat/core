## Concept

Безпечно зчитуйте результат із `run.pull()` або `model.run()`. Кожен запуск повертає `Sample` — невеликий тип-суму, який може бути тензором, набором іменованих полів або і тим, і іншим, — тож класифікуйте його, перш ніж звертатися до корисних даних.

## Walkthrough

Перш ніж оптимізувати пропускну здатність або додавати складну логіку графа, вам потрібен стабільний, захисний спосіб читати все, що повертає запуск. Вихід — це завжди `Sample`, але його форма буває різною: це може бути один тензор або набір іменованих полів (як у розділі 009). Звернення до `.tensor` у наборі — або припущення про форму, якої там немає, — і є тією помилкою, якої вчить уникати цей розділ.

Ми будуємо той самий мінімальний синхронний граф, що й раніше, запускаємо один кадр, а потім методично *аналізуємо* результат: його `kind`, чи є в ньому тензор, скільки в нього полів і який ранг тензора. Наприкінці у вас буде шаблон зчитування виходу для повторного використання, який працює з будь-якою моделлю, що її обслуговує середовище виконання.

### Налаштування входу {#step-configure-input}

Оголосіть контракт входу — `format` пікселів, `width`, `height`, `depth` — відповідно до кадру, який ми передаватимемо. Це той самий контракт межі, що використовується в усіх цих розділах.

### Складання й побудова графа {#step-compose-graph}

З’єднайте вузол входу з вузлом виходу й за допомогою `build()` побудуйте синхронний `Run`, передавши кадр, щоб `build()` міг узгодити конкретні форми. Оскільки між ними немає моделі, вихід віддзеркалює вхід — саме тому тут структуру виходу видно в чистому вигляді.

### Запуск одного кадру {#step-run-frame}

Передайте один кадр і синхронно отримайте один результат. Один виклик `run(...)` — це скорочений шлях для одного кадру; те, що він повертає, — саме той об’єкт, який ми тут розбираємо.

**C++:** `run.run(...)` повертає `TensorList` — для виходу з одним тензором це один елемент, який наступний крок перевіряє через `out.size()` і `out.front()`.

**Python:** `run.run(...)` повертає `Sample`, який безпосередньо надає `.kind`, `.tensor`, `.tensors` і `.fields`.

### Аналіз зразка {#step-inspect-sample}

У цьому й полягає урок: спершу читайте структуру, а потім корисні дані. Спочатку перевірте наявність і вид (kind), потім обчисліть ранг із `shape` тензора. Саме перевірка на кожному кроці (непорожній вихід, непорожня форма) робить читання виходу стійким до моделей, форму яких ви не контролюєте.

**C++:** Виведіть `out.size()` і наявність тензора, згенеруйте виняток, якщо вихід порожній або якщо порожнє `out.front().shape`, а потім виведіть `rank` як `shape.size()`. (Рядок `fields=0` — лише заповнювач: `TensorList` не несе структури полів набору, яку має `Sample` у Python.)

**Python:** Виведіть `sample.kind`, `sample.tensor is not None`, `len(sample.fields)` і ранг першого тензора — увесь інтерфейс типу-суми в одному місці. Для результату виду Tensor присутній `.tensor`; для результату виду TensorSet читайте `.tensors`; для набору розгалужуйтеся за `.kind` і читайте `.fields`.

## Run

Команди **Python** і **C++ (prebuilt)** запускайте з **кореневої теки встановлення Neat** (теки, що містить `share/` і `lib/`), а команди **build from source** — з **кореневої теки репозиторію**. Для цього розділу архів моделі не потрібен.

**Python:**
```bash
python3 share/sima-neat/tutorials/011_interpret_model_output/interpret_model_output.py
```

**C++ (prebuilt):**
```bash
./lib/sima-neat/tutorials/tutorial_011_interpret_model_output
```

**C++ (build from source):**
```bash
./build.sh --target tutorial_011_interpret_model_output
./build/tutorials-standalone/tutorial_011_interpret_model_output
```

Очікуваний результат (C++):

```text
outputs=1 has_tensor=yes fields=0
rank=3
[OK] 011_interpret_model_output
```

Версія для Python виводить ті самі відомості через інтерфейс `Sample`:

```text
sample_kind=SampleKind.TensorSet
has_tensor=False
num_fields=0
output_rank=3
```

Щоб інтегрувати початковий код C++ цього розділу у свій проєкт із власним файлом `CMakeLists.txt` (тека extras не потрібна), див. розділ [Як запускати навчальні посібники](/tutorials#compile-a-copy-yourself) на головній сторінці.

## In Practice

Захисний контрольний список для читання виходу будь-якої моделі.

### Класифікація перед читанням

- Спершу перевірте `kind`. Результат з одним тензором — це `SampleKind.Tensor`; результат із кількома полями — `SampleKind.Bundle`.
- Для виду Tensor `tensor` присутній, а `fields` порожній. Для виду Bundle читайте `fields` і не розраховуйте на `tensor`.

### Перевірка контракту

- Перш ніж розіменовувати тензор, переконайтеся, що він присутній.
- Перш ніж обчислювати ранг чи індексувати виміри, переконайтеся, що `shape` непорожній.
- Перевіряйте `tensor.dtype`, коли споживач очікує певного типу елементів.
