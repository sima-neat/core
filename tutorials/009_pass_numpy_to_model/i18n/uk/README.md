## Concept

Переміщуйте дані між тензорами Neat і структурами, які у вас уже є, — масивами NumPy, тензорами PyTorch або `cv::Mat` — і керуйте розкладкою, dtype та семантикою копіювання, щоб вбудувати Neat у наявний стек інференсу.

## Walkthrough

Якщо ви інтегруєте Neat у наявний стек інференсу, вам потрібна саме ця межа взаємодії: як дані хоста стають `Tensor` Neat і як `Tensor` Neat знову стає даними хоста. Якщо зробити це правильно від самого початку, ви уникнете класичних помилок інтеграції — неправильної розкладки, мовчазного приведення dtype, неочікуваного спільного використання пам’яті двома світами.

Саме тут дві мови розходяться найбільше. Користувачі Python приходять із NumPy/PyTorch, користувачі C++ — з OpenCV. *Концепції* перетворення однакові, але назви API й типи різняться, тож пояснення для кожної мови нижче мають значення. Наприкінці ви перетворите дані хоста на тензор Neat, перевірите його корисні дані без копіювання й отримаєте власну копію, яку можна безпечно використовувати й після того, як буфер-джерело перестане існувати.

### Обгортання даних хоста в тензор {#step-to-tensor}

Перший крок перетворює дані, які у вас уже є, на `Tensor` Neat. Ви явно позначаєте розкладку зображення (`RGB`), щоб середовище виконання правильно інтерпретувало байти, а не вгадувало. `copy=True` (або вибір пам’яті CPU в C++) визначає, чи тензор володіє своїми байтами, чи посилається на пам’ять джерела, — явне володіння є безпечним варіантом за замовчуванням, коли буфер-джерело може змінитися або бути звільненим.

**C++:** `simaai::neat::from_cv_mat(mat, ImageSpec::PixelFormat::RGB, TensorMemory::CPU)` обгортає `cv::Mat` у тензор, що зберігається в пам’яті CPU.

**Python:** `pyneat.Tensor.from_numpy(arr, copy=True, image_format=pyneat.PixelFormat.RGB)` обгортає масив NumPy типу `uint8` у розкладці HWC.

### Перевірка корисних даних {#step-map-and-inspect}

Коли дані стали тензором, їх можна прочитати назад. Це зворотна половина взаємодії: перш ніж передавати щось далі за потоком, переконайтеся, що форма й байти пережили перетворення без змін.

**C++:** `tensor.map_read()` повертає `Mapping`, що надає сирий вказівник `data` і `size_bytes`. Це *подання* сховища тензора — без копіювання, — тому приклад може напряму обчислити контрольну суму початкових байтів.

**Python:** `tensor.to_numpy(copy=True)` створює з тензора масив NumPy; приклад виводить його `.shape`, щоб підтвердити, що розкладка HWC пройшла шлях туди й назад без змін.

### Отримання власної копії {#step-own-a-copy}

Нарешті, отримайте дані, повністю відокремлені від початкового буфера-джерела, — їх можна безпечно зберігати й тоді, коли вхідних даних уже немає. Саме таку копію ви передаєте довготривалим споживачам.

**C++:** `tensor.clone()` копіює дані в нове сховище у пам’яті CPU, яке не залежить від `cv::Mat`, звідки вони походять.

**Python:** ту саму ідею показано через PyTorch: `pyneat.Tensor.from_torch(t, copy=True, ...)` і `tensor.to_torch(copy=True)` проводять дані туди й назад через власний тензор PyTorch. (Якщо `torch` не встановлено, цей крок коректно пропускається.)

## In Practice

Стисла довідка про інтерфейс взаємодії — для тих випадків, коли ви вже вийшли за межі демонстрації перетворення туди й назад.

### API перетворення

- NumPy: `pyneat.Tensor.from_numpy(array, copy=..., image_format=...)` — у Neat; `tensor.to_numpy(copy=...)` — з Neat.
- PyTorch: `pyneat.Tensor.from_torch(tensor, copy=..., image_format=...)` — у Neat; `tensor.to_torch(copy=...)` — з Neat.
- OpenCV (C++): `simaai::neat::from_cv_mat(mat, pixel_format, memory)` — у Neat; `tensor.map_read()` — для подання без копіювання; `tensor.clone()` — для власної копії.

### Копія чи подання

- `copy=True` (Python) / `clone()` (C++) дає дані, відокремлені від джерела, — їх можна безпечно зберігати після того, як джерело звільнено або змінено.
- `copy=False` / `map_read()` дає подання, що посилається на пам’ять джерела. Це дешевше, але дійсне лише доти, доки джерело існує й не змінюється.

### Розкладка й dtype

- Для даних зображення завжди явно передавайте `image_format` / `PixelFormat`, щоб розкладку було інтерпретовано, а не вгадано.
- Neat не приводить dtype мовчки — перш ніж подавати тензор моделі, узгодьте його dtype із контрактом входу моделі.
