## Concept

Побудуйте найменший корисний публічний `Graph` Neat — один *іменований* `Input`, з’єднаний з *іменованим* `Output`, — потім передайте через нього зразок за ім’ям і переконайтеся, що метадані зразка зберігаються під час проходження графом.

## Walkthrough

У розділі 003 ми побудували анонімний граф Input → Output і керували ним позиційними викликами `run()`. Справжня оркестрація — розгалуження, злиття, маршрутизація для кожного потоку — потребує звернення до кінцевих точок *за іменем*, а не за позицією. Цей розділ знайомить з інтерфейсом іменованих кінцевих точок на найменшому можливому графі, щоб ви побачили механіку іменування й з’єднання окремо, перш ніж розділи про кілька потоків і вбудовані моделі спиратимуться на неї.

Публічний `Graph` — це інтерфейс композиції застосунку: ви додаєте вузли через `add(...)`, з’єднуєте іменовані кінцеві точки через `connect(...)`, один раз викликаєте `build()`, щоб отримати `Run` для повторного використання, а потім викликаєте `push("image", ...)` і `pull("out", ...)` за іменем. Наприкінці ви передасте один тензорний `Sample` через іменований граф і переконаєтеся, що його `stream_id`, `frame_id` і `pts_ns` вийшли незмінними, — це доказ того, що середовище виконання наскрізно зберігає метадані.

### Складання графа {#step-compose-graph}

Додайте два вузли. `Input("image")` оголошує кінцеву точку push з ім’ям `image`; `Output("out")` оголошує кінцеву точку pull з ім’ям `out`. Імена — це контракт: саме ці рядки ви згодом передаватимете в `push(...)` і `pull(...)`. Саме іменування кінцевих точок (а не покладання на порядок додавання) робить більші графи з кількома входами чи виходами однозначними в керуванні.

**C++:** Вузли беруться з `simaai::neat::nodes::Input("image")` і `nodes::Output("out")`.

**Python:** Вузли беруться з `pyneat.nodes.input("image")` і `pyneat.nodes.output("out")`.

### З’єднання кінцевих точок {#step-connect-endpoints}

`connect("image", "out")` оголошує ребро: кадри, передані в `image`, надходять до `out`. Коли вузлів лише два, це вся топологія, але `connect(...)` — той самий виклик, яким ви будували б гілки й злиття в більшому графі. Потім ми виводимо `graph.describe()`, щоб показати складену топологію, — це швидка перевірка того, що граф з’єднано саме так, як ви задумали, ще до побудови.

### Побудова й передавання зразка {#step-build-and-push}

`build()` (тут зразок для ініціалізації не потрібен) перетворює опис на готовий до запуску `Run`. Потім ми створюємо один детермінований тензорний `Sample` — RGB-зображення 8×8×3 з відомими `stream_id`, `frame_id` і `pts_ns` — і за допомогою `push(...)` передаємо його в кінцеву точку `image` за іменем. Саме метадані зразка ми перевірятимемо на іншому боці.

**C++:** `push(...)` повертає bool; у разі збою ми виводимо `run.last_error()`. Зразок створює `make_sample()`.

**Python:** `push("image", [sample])` приймає список зразків. Зразок створює `make_rgb_sample()`.

### Отримання виходу й перевірка метаданих {#step-pull-and-verify}

`pull("out", ...)` отримує результат з іменованої кінцевої точки виходу з тайм-аутом, після чого ми закриваємо запуск викликом `close()`. Оскільки між входом і виходом немає перетворень, правильний конвеєр повертає той самий логічний зразок, тож якщо прочитати `stream_id`, `frame_id` і `pts_ns` і побачити передані значення, це підтверджує, що середовище виконання зберегло метадані кожного зразка під час проходження графом. Саме ця гарантія дає змогу наступним етапам довіряти ідентичності кадрів і міткам часу.

## Run

Запустіть програму — ви маєте побачити опис графа, а за ним метадані, що пройшли шлях туди й назад. Команди **Python** і **C++ (prebuilt)** запускайте з **кореневої теки встановлення Neat** (теки, що містить `share/` і `lib/`), а команди **build from source** — з **кореневої теки репозиторію**. Для цього розділу архів моделі не потрібен.

**Python:**
```bash
python3 share/sima-neat/tutorials/013_build_a_custom_data_graph/build_a_custom_data_graph.py
```

**C++ (prebuilt):**
```bash
./lib/sima-neat/tutorials/tutorial_013_build_a_custom_data_graph
```

**C++ (build from source):**
```bash
./build.sh --target tutorial_013_build_a_custom_data_graph
./build/tutorials-standalone/tutorial_013_build_a_custom_data_graph
```

Очікуваний результат (перед ним виводиться дамп `graph.describe()`):

```text
stream=graph frame=42 pts_ns=123456789
[OK] 013_build_a_custom_data_graph
```

(Версія для Python виводить `stream_id=graph frame_id=42 pts_ns=123456789`.) Щоб інтегрувати початковий код C++ цього розділу у свій проєкт із власним файлом `CMakeLists.txt` (тека extras не потрібна), див. розділ [Як запускати навчальні посібники](/tutorials#compile-a-copy-yourself) на головній сторінці.
