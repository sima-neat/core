## Concept

Об’єднайте кілька іменованих тензорів в один `Sample` і передайте його як одну подію інференсу — це шаблон для моделей, які приймають більше ніж один вхід, наприклад стереокадри, зображення + метадані або об’єднання даних датчиків.

## Walkthrough

Багато реальних застосунків передають більше ніж один вхід на одну подію інференсу. Neat подає це як **зразок-набір** (bundle): один `Sample`, список `fields` якого містить корисні дані кількох іменованих тензорів, і до кожного з них можна звернутися за `port_name`. Середовище виконання тримає іменовані поля разом як одну логічну подію, тож `left` і `right` (або зображення й метадані) залишаються узгодженими на всьому шляху конвеєром.

У цьому розділі ви побудуєте граф «тензор на вході — тензор на виході», об’єднаєте два іменовані тензори з рухомою комою в набір, передасте його через граф і прочитаєте іменовані поля на виході. Наприкінці ви складете зразок із кількома полями й переконаєтеся, що обидва поля пройшли шлях туди й назад, зберігши свої імена портів.

### Налаштування тензорного входу {#step-configure-tensor-input}

Цей граф споживає сирі тензори, а не декодовані зображення, тому контракт входу оголошено як тензорні корисні дані (`FP32`, з `width`/`height`/`depth`), а не як формат пікселів. Це вказує вузлу входу приймати буфери тензорів безпосередньо.

**C++:** Установіть `in.payload_type = PayloadType::Tensor`.

**Python:** Установіть `inp.payload_type = pyneat.PayloadType.Tensor` і `inp.format = pyneat.Format.FP32`.

### Побудова графа й запуску з початковим тензором {#step-build-seed-run}

Ми складаємо ту саму мінімальну топологію `Input -> Output`, що й у розділі 004, і за допомогою `build()` перетворюємо її на `Run`. Для `build()` потрібен репрезентативний зразок, щоб зафіксувати узгоджені форми, тому ми передаємо один початковий тензор (усі нулі) тієї самої форми, яку матимуть справжні поля. Початковий тензор потрібен лише для узгодження форм — справжні дані надійдуть далі.

### Складання набору {#step-make-bundle}

Тепер зберіть подію з кількома входами. Кожен вхід отримує ім’я через `make_tensor_sample(port_name, tensor)`, і саме до цих іменованих полів модель звертається за портом. Тут `left` заповнено значенням `1.0`, а `right` — значенням `2.0`, щоб на виході їх можна було розрізнити.

**C++:** `make_bundle_sample({...})` обгортає іменовані поля в один `Sample`, у якого `kind` дорівнює `Bundle`.

**Python:** Список іменованих зразків передається безпосередньо в `push(...)`; pyneat сам створює для вас обгортку набору.

### Передавання набору й зчитування результату {#step-push-and-read}

Нарешті, передайте набір через граф і перевірте результат. Вихід — це теж `Sample`-набір, тому ми читаємо `out.fields`, а не розглядаємо його як один тензор: `out.fields.size()` має дорівнювати `2`, а кожне поле містить `port_name` і тензор як корисні дані.

**C++:** `run.run(Sample{bundle}, timeout_ms)` повертає один `Sample`. Оскільки логічний результат має кілька полів, повернутий `Sample` сам є `Bundle`, тому ми перевіряємо `out.kind == SampleKind::Bundle` і перебираємо `out.fields`, а не викликаємо `front()` (що означало б «перше поле всередині набору»).

**Python:** `run.push(fields)`, а потім `run.pull(timeout_ms=...)` повертає вихідний зразок; переберіть `out.fields` і прочитайте `field.port_name` і `field.tensor` кожного поля.

## Run

Команди **Python** і **C++ (prebuilt)** запускайте з **кореневої теки встановлення Neat** (теки, що містить `share/` і `lib/`), а команди **build from source** — з **кореневої теки репозиторію**. Для цього розділу архів моделі не потрібен.

**Python:**
```bash
python3 share/sima-neat/tutorials/010_feed_multi_input_model/feed_multi_input_model.py \
  --width 64 --height 48
```

**C++ (prebuilt):**
```bash
./lib/sima-neat/tutorials/tutorial_010_feed_multi_input_model \
  --width 64 --height 48
```

**C++ (build from source):**
```bash
./build.sh --target tutorial_010_feed_multi_input_model
./build/tutorials-standalone/tutorial_010_feed_multi_input_model \
  --width 64 --height 48
```

Очікуваний результат (C++):

```text
bundle_fields=2
  field=left has_tensor=yes
  field=right has_tensor=yes
[OK] 010_feed_multi_input_model
```

(Версія для Python виводить ту саму кількість полів і рядки на кшталт `port=left has_tensor=True`.) Щоб інтегрувати початковий код C++ цього розділу у свій проєкт із власним файлом `CMakeLists.txt` (тека extras не потрібна), див. розділ [Як запускати навчальні посібники](/tutorials#compile-a-copy-yourself) на головній сторінці.

## In Practice

Як застосовувати шаблон набору поза межами цієї демонстрації з двома полями.

### Іменування й маршрутизація

- `port_name` — це контракт з’єднання: саме за ним модель із кількома входами звертається до кожного поля. Узгодьте імена з оголошеними портами входу моделі.
- Вихідний набір зберігає структуру полів, тож результати можна зіставити зі входами за іменем, а не за позицією.

### Аналіз вихідних наборів

- Завжди спершу перевіряйте `kind`: результат із кількома полями має тип `SampleKind.Bundle`, і прочитати його як один тензор не вийде.
- Перш ніж звертатися до корисних даних, перевірте наявність тензора в кожному полі (`field.tensor is not None` / `field.tensor.has_value()`) — поле може містити метадані, а не тензор.
