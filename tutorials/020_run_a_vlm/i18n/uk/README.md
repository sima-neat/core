## Concept

Ставте кілька запитань про те саме зображення, не кодуючи його заново для кожного запиту.

## Walkthrough

Візуально-мовні моделі можуть приймати текст разом із тензорами зображень. Для одного запитання додайте зображення безпосередньо до `GenerationRequest.images`. Для кількох запитань закодуйте зображення один раз і повторно використовуйте кешовані векторні представлення зображення в наступних запитах.

### Завантаження VLM і зображення {#step-load-inputs}

Завантажте `VisionLanguageModel` з розгорнутої теки моделі LLiMa та декодуйте зображення з диска.

**C++:** Зчитайте зображення за допомогою OpenCV. Neat вважає триканальні вхідні `cv::Mat` зображеннями BGR і внутрішньо перетворює їх на RGB.

**Python:** Декодуйте зображення через OpenCV, перетворіть BGR на RGB і передайте масив NumPy у запит.

### Запитання з прямим зображенням {#step-direct-image}

Додайте зображення безпосередньо до першого запиту. Це найпростіший шлях, і його часто достатньо для разових запитань про зображення.

### Кешування векторного представлення зображення {#step-cache-image}

Викличте `encode(...)`, щоб закешувати векторні представлення зображення в моделі. Виклик повертає `true`, якщо зображення прийнято й закешовано.

### Уточнювальні запитання {#step-follow-up}

Задайте `use_cached_images = true` у кожному запиті, який має повторно використати кешоване зображення. Про одне кешоване зображення можна поставити кілька запитань. Запити без цього прапорця поводяться як звичайно: суто текстові запити не використовують зображення, запити з прямим зображенням використовують власні `images`, а ще один виклик `encode(...)` замінює кешоване зображення.

### Зображення в повідомленні чату {#step-message-image}

Коли використовуєте `messages`, додавайте зображення до того повідомлення користувача, якому воно потрібне. Так зображення залишається поруч із тим самим текстом, до якого належить.

## Run

На DevKit без NVMe перед `llima pull` задайте в `LLIMA_MODELS_PATH` теку з правом запису й використовуйте її замість `/media/nvme/llima/models` у командах нижче.

На Modalix DevKit завантажте VLM LFM2-VL 1.6B з Hugging Face за допомогою LLiMa CLI:

```bash
llima pull LFM2-VL-1.6B-a16w4
```

Запустіть посібник на Modalix із локальною текою моделі на DevKit і локальним зображенням:

**Python:**
```bash
python3 share/sima-neat/tutorials/020_run_a_vlm/run_a_vlm.py \
  --model /media/nvme/llima/models/LFM2-VL-1.6B-a16w4 \
  --image tests/images/people.jpg
```

**C++ (prebuilt):**
```bash
./lib/sima-neat/tutorials/tutorial_020_run_a_vlm \
  --model /media/nvme/llima/models/LFM2-VL-1.6B-a16w4 \
  --image tests/images/people.jpg
```

**C++ (build from source):**
```bash
./build.sh --target tutorial_020_run_a_vlm
./build/tutorials-standalone/tutorial_020_run_a_vlm \
  --model /media/nvme/llima/models/LFM2-VL-1.6B-a16w4 \
  --image tests/images/people.jpg
```

Очікуваний результат — одна відповідь на запит із прямим зображенням, кілька уточнювальних відповідей, що повторно використовують кешоване зображення, і одна відповідь на запит із зображенням на рівні повідомлення.

## In Practice

Використовуйте кешування зображень, коли користувач ставить кілька запитань про той самий кадр, зображення товару, діаграму чи сторінку документа. Не кешуйте, якщо кожен запит використовує інше зображення: шлях із прямим зображенням простіший, і стан промпту залишається очевидним.

Деякі сімейства моделей можуть не підтримувати повторне використання кешу. У такому разі передавайте зображення безпосередньо в кожному запиті.

Використовуйте `ChatMessage.images`, коли будуєте розмову і зображення має бути лише в одному повідомленні. Для простішої форми з одним промптом використовуйте `GenerationRequest.images` верхнього рівня.
