## Concept

Додайте модель до `Graph` за допомогою `model.graph()` і `model.graph(options)` — двох шаблонів композиції, які відрізняються тим, наскільки ви самі контролюєте з’єднання. Так ви знатимете, який із них підходить для швидкого запуску, а який — для розгортання з кількома камерами.

## Walkthrough

У розділі 003 граф будувався вузол за вузлом. Це найбільш явний спосіб, але коли у вас уже є `Model`, вручну з’єднувати її внутрішні елементи зазвичай не хочеться. `model.graph(...)` повертає конвеєр моделі як групу, яку ви додаєте до `Graph` одним викликом `add(...)`. Цікаве питання — *яку частину* межі ця група приносить із собою, і саме це визначає `ModelRouteOptions`.

У цьому розділі зіставлено дві конфігурації маршруту для однієї й тієї самої моделі: самодостатній граф, готовий до запуску, з власними публічними межами входу й виходу, і приєднуваний граф без входу, який можна під’єднати до джерела вище за потоком (наприклад, до камери) під явно заданим ім’ям. Наприкінці ви складете обидва графи й виведете для кожного рядок GStreamer бекенду, щоб точно побачити, чим відрізняються з’єднання.

### Складання графа моделі, готового до запуску {#step-model-graph}

Перший шаблон запитує в моделі повністю готовий до запуску граф. Значення `include_input = true` і `include_output = true` у параметрах маршруту вказують `model.graph(opts)` додати явні публічні межі входу й виходу навколо групи моделі, тож отриманий `Graph` можна побудувати й запустити самостійно, нічого більше до нього не під’єднуючи. Уся композиція — це `graph.add(model.graph(opts))`: саме до цього єдиного `add` зрештою зводиться кожен шаблон. Виведення `describe_backend()` показує згенерований рядок конвеєра GStreamer.

**C++:** Параметри маршруту — `Model::RouteOptions`; граф — `simaai::neat::Graph`.

**Python:** Параметри маршруту — `pyneat.ModelRouteOptions`; граф — `pyneat.Graph`.

### Налаштування параметрів маршруту для приєднання {#step-route-options}

Другий шаблон приєднує модель до джерела вище за потоком, а не дає їй власного входу. Тут `include_input = false` прибирає публічну межу входу (кадри надходитимуть з іншого місця), `include_output = true` залишає вихід, а `upstream_name`, `name_suffix` і `buffer_name` роблять з’єднання та імена елементів явними. Саме таке послідовне іменування робить графи бекенду зрозумілими й придатними до діагностики в розгортаннях із кількома камерами чи кількома моделями.

### Приєднання групи моделі {#step-attached-graph}

Із цими параметрами `graph.add(model.graph(opts))` додає ту саму групу моделі, але тепер вона під’єднується до названого джерела вище за потоком, а не має власного джерела. Це той самий виклик `add`, що й у першому шаблоні, — змінилися лише параметри маршруту, і в цьому вся суть: композиція — це одна операція, а `ModelRouteOptions` — регулятор, який визначає, яку межу група приносить із собою.

**C++:** Кожен варіант виводить свій `describe_backend()`, щоб ви могли порівняти два рядки бекенду; потім файл ще будує й запускає вручну з’єднаний прямий граф `Input -> Output`, щоб перевірити наскрізний шлях, і виводить `direct_rank=`.

**Python:** Приєднаний варіант виводить `attached_graph_built=True` на підтвердження того, що композиція вдалася.

## Run

Команди **Python** і **C++ (prebuilt)** запускайте з **кореневої теки встановлення Neat** (теки, що містить `share/` і `lib/`), а команди **build from source** — з **кореневої теки репозиторію**.

**Python:**
```bash
python3 share/sima-neat/tutorials/008_plug_model_into_pipeline/plug_model_into_pipeline.py \
  --model /tmp/yolo_v8s.tar.gz
```

**C++ (prebuilt):**
```bash
./lib/sima-neat/tutorials/tutorial_008_plug_model_into_pipeline \
  --model /tmp/yolo_v8s.tar.gz
```

**C++ (build from source):**
```bash
./build.sh --target tutorial_008_plug_model_into_pipeline
./build/tutorials-standalone/tutorial_008_plug_model_into_pipeline \
  --model /tmp/yolo_v8s.tar.gz
```

Очікуваний результат (версія для C++ виводить рядок кожного графа бекенду, а потім ранг прямого графа):

```text
model_graph_backend=
...
attached_graph_backend=
...
direct_rank=3
[OK] 008_plug_model_into_pipeline
```

(Версія для Python виводить `direct_graph_backend=` і рядок бекенду, а потім `attached_graph_built=True`.) Щоб інтегрувати початковий код C++ цього розділу у свій проєкт із власним файлом `CMakeLists.txt` (тека extras не потрібна), див. розділ [Як запускати навчальні посібники](/tutorials#compile-a-copy-yourself) на головній сторінці.
